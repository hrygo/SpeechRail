Task 18: complete — the Xcode post-test hang, previously attributed to the app test host, diagnosed to the real cause and fixed.
Task 18 method: the earlier mechanism was wrong. The unit-test target is `bundle.unit-test` with no `TEST_HOST` and no `BUNDLE_LOADER`, it depends only on ControlKit and AgentCore, and the wrapper already passes `-skip-testing:SpeechRailAppUITests`, so the app is never launched and the tests run in a plain `xctest` process. Bisected instead of theorised: single-suite runs (`AppModelTests`, `TeleprompterReplayEvaluatorTests`, `TeleprompterSessionLifecycleTests`) each exited cleanly, while the full run froze; a 420 s run was killed and its log showed exactly one started-but-never-finished test, `explicit voice start uses the current segment and old failures cannot move it`, and two suites with no completion line.
Task 18 cause: `TestGate` in `TeleprompterSessionLifecycleTests.swift` had no memory of being opened. The test calls `await drainGate.open()` to release the stop path, but `drainAndClear` only reaches `TestGate.wait()` later; the `open()` landed while no continuation was registered and was discarded, so the later `wait()` suspended forever. It is load-sensitive — in isolation the ordering happens to hold, under full parallel load it flips — which is exactly why it had been misread as a host-lifecycle problem.
Task 18 fix: test helper only, no production change. `TestGate` now latches (`wait()` returns immediately once open, `waitUntilWaiting()` also honours the open state). Production `TeleprompterSession.stopCapture()` awaits `client.drainAndClear` directly and has no equivalent race. New named regression `a gate that was opened before the wait arrived still releases the wait` pins the ordering; the detached waiter records into a `GateProbe` actor so a regression fails the assertion instead of hanging the suite.
Task 18 evidence: `swift test --package-path macos/SpeechRailApp` → 201 tests / 16 suites passed. `scripts/macos_app_build.sh --configuration Debug --test-unit --timeout 900` → `** TEST SUCCEEDED **`, XCTest 344 tests and Swift Testing 201 tests / 16 suites, 0 failures, `test-unit: passed`, exit 0, ~53 s wall clock; run twice with identical results. Task 19 gap: #111 step 5 requires "reuse the existing trial/calibrationFactor … when there is no valid trial reading, fall back to the default estimate and say so", and its acceptance requires the evidence source of the calibration to be clear. `calibrationFactor` defaulted to 1.0, which is indistinguishable from a trial that genuinely measured 1.00x; `estimateDuration` only flagged uncertainty for text reasons (digits, URLs, non-Latin), so a session that never ran a trial received a point estimate and a 0.8–1.25 range that looked exactly like a measured one.
