# 换声影响范围确认与发音上下文试听：设计稿

本稿对应 [ElevenLabs 吸收方案](../audits/2026-10-17-speechrail-elevenlabs-absorption-plan.md) 的 **E3** 与 **E1**。两者都落在 macOS App 的界面层，因此本稿只给设计与验收条件，不含实现；实现前须复核当前代码，并与并行的有声书 UI 改动排期协调。

## 1. 现状核实（2026-10-17 静态核对）

- **E3 的数据层已存在**：`AudiobookCastImpactPreview` 已携带 `affectedChapterIDs`、`affectedAtomIDs`、`affectedQuotesCount`（`AudiobookCastController.swift:48-62`）。缺口在界面是否于换声**之前**把影响范围讲清楚，以及是否把"已生成候选/已采用版本"计入影响面——现有字段只数到台词，不数已生成音频。
- **E1 没有可依附的界面**：`macos/SpeechRailApp/SpeechRailApp/` 下不存在任何发音集（pronunciation）编辑视图。服务端有完整的版本化发音集能力（`/v1/speechrail/pronunciation-sets`，见 [用户契约 §5.8](../users/api-contract.md)），但 App 侧从未暴露。因此 E1 不是"给现有编辑器加一个试听按钮"，而是"先有编辑器，才谈试听"，成本从吸收方案表里的「中」上调为「中高」。

## 2. E3：换声影响范围确认

### 2.1 要解决的问题

换角色音色会让该角色已生成的音频失效。当前用户按下确认前，无法知道"会作废多少、要重做多少、已采用的版本会不会丢"。竞品的做法是先清空该角色音频、确认、再只重生成受影响段落。

### 2.2 交互

触发点为三种会改变发声身份的显式动作：更换角色音色绑定、合并角色、重新指派角色。

确认面板只回答三个问题，顺序固定：

1. **会作废什么**：`N` 个已生成片段、覆盖 `M` 个章节。
2. **要重做什么**：这些片段需要重新生成，已采用的章节版本不受影响，仍可收听与导出。
3. **能不能反悔**：取消则零变更；确认后可在候选比较区逐个采用新候选。

文案按用户语言组织，不出现 `stale`、`invalidation`、`atom`、`SHA` 等内部术语。已采用的章节版本是"保留历史、不删除"，不是"丢失"，文案必须让这一点无歧义。

### 2.3 数据

- 章节数与台词数复用 `AudiobookCastImpactPreview`。
- 片段数需要新增：按 `AudiobookInvalidation` 判定为失效的 `AudiobookFragment` 计数。该计数必须与换声后实际被标为待重做的集合同源，不能用台词数近似——否则用户看到的数字和实际重做量对不上。
- 计数在面板打开时计算一次，确认时以同一快照执行；期间若发生其他编辑，按既有修订比较拒绝并重新提示，不静默使用过期数字。

### 2.4 验收条件

1. 三种触发动作在改变任何状态前都展示影响面板；取消后作品、候选、已采用版本零变更。
2. 面板中的片段数与确认后实际待重做片段数一致（同一快照）。
3. 已采用章节版本在换声后仍可收听与导出，文案不暗示丢失。
4. 键盘可达、VoiceOver 可朗读、支持 Reduce Motion；不使用颜色作为唯一信息入口。
5. 面板文案不含内部术语，普通用户读一遍即可判断是否继续。

## 3. E1：发音集编辑与上下文试听

### 3.1 拆成两步

**步骤 A：发音集编辑界面（前置）**

- 列表展示规则：原文片段、朗读文本、语言、大小写与词边界开关。
- 增删改走现有 `PUT /v1/speechrail/pronunciation-sets`（CAS + 不可变 revision），保存后回显新 revision；撤销走 revoke 端点，不删除历史。
- 必须展示"当前 revision"以及合成请求固定的 `set_id@revision`——这是本能力的核心语义：合成不会自动套用最新 revision。
- 空规则不可保存（`spoken` 不得为空白），停用一条规则只能写入不含该条目的新 revision；界面上应表现为"删除规则"，而不是"清空读音"。

**步骤 B：上下文试听**

- 每条规则可"用规则所在的原文句子试听"，而不是只念孤立的词。
- 试听走正常渲染路径并绑定当前 revision，不引入特例合成；试听音频不落盘、不进入候选、不改变任何采用状态。
- 同一句命中多条规则时按已文档化的匹配语义取最长匹配（见 [用户契约 §5.8](../users/api-contract.md)），试听结果必须与正式合成一致。

### 3.2 验收条件

1. 可对任一规则播放其所在原文句子的试听，且试听与正式合成使用同一 revision。
2. 试听不产生持久音频、不写入候选库、不改变采用状态。
3. 保存后 revision 变化可见；撤销后该 revision 不可再被合成引用。
4. 键盘可达、VoiceOver 可朗读；播放/停止状态可播报。
5. 无发音集时，普通合成路径行为与现在完全一致。

## 4. 顺序、依赖与未决项

- **顺序**：E3 先做（数据已就绪，只差界面与片段计数）；E1 步骤 A 是独立工作量，须与 UI 排期一起评估。
- **冲突面**：当前工作区正被有声书导出与音量相关的 UI 改动占用（`AudiobookWorkflowModel`、`AudiobookWorkshopView`、`AudiobookExportController`）。在那些改动落地前，本稿的实现不应与它们并行修改同一批文件。
- **授权**：任何会接管前台窗口、焦点或输入的 UI 自动化验证，都需逐次明确授权；本稿不构成授权。
- **未决**：E1 步骤 A 的入口位置（设置页 / 书籍级 / 全局）尚未确定，取决于 App 信息架构，需要产品决策后再细化。
