# SpeechRail v1.6.5 性能基准与资源监控报告 (Performance Baseline Report)

> **测试版本**：`SpeechRail v1.6.5`（预量化 `-8bit` MLX 快照；`snapshot_is_quantized` 统一检测 + `resolve_backend_dtype` 统一 ASR/streaming/TTS 三处 dtype 接线；量化失败按实际加载精度上报身份 fail-closed on truth）
> **报告时间**：2026-09-03
> **测试环境**：Apple M5 Max (18 核 CPU / 128GB 统一内存)，macOS 26.6.2，Python 3.12，MLX (MPS)
> **测量工具**：macOS 系统原生 `footprint -f bytes`（采集 `phys_footprint` 物理内存）、`examples/perf/bench_asr.py`、`bench_tts.py`、`bench_realtime.py`、`sample_resources.py`
> **模型配置**：Qwen3-ASR-1.7B `-8bit` + Qwen3-TTS VoiceDesign `-8bit`（均为仓库外绝对路径 snapshot）；`SPEECHRAIL_DTYPE=float16`（`-8bit` 快照自动解析为 int8 直接加载，不二次量化）
> **当前状态**：`/health`（version=1.6.5, asr/tts/diarization 全 ready）、`/readyz`、`/v1/models`（canonical + alias）、`/v1/voices`（4 全 available）全绿；Diarization (Sortformer) 就绪。本机部署为 `127.0.0.1:8201` loopback（`.env` 已配置 API key）。
> **验证范围**：非流式 ASR（4 段时长 + 并发）、TTS（短/长句）、Realtime 连续 3 会话、资源 footprint 压测；所有推理端点经真实模型 smoke 通过。

## 1. 真实物理内存与 CPU 资源基线 (Physical Footprint Baseline)

> **统计口径**：Apple Silicon 统一内存下，MLX/Metal 显存分配计入物理内存池。严格采用 `footprint` 采集 `phys_footprint` 与压测峰值 `phys_footprint_peak`。
> **采样说明**：`sample_resources.py` 通过命令行区分 worker；本次采样窗口含 ASR batch 压测（30s 音频 × 5 次，mode=all，含 warmup）与 TTS 合成，无 streaming/realtime 会话（realtime 懒启动，未计入 streaming worker 增量）。

| 进程组件 | 运行配置 | 冷启待机 | 预热常驻物理内存 (Footprint) | 压测峰值物理内存 (Peak) | 峰值 CPU | 运行与显存行为分析 |
|---|---|---|---|---|---|---|
| **主服务进程 (Host FastAPI)** | `speechrail serve` | - | **540.1 MB** | **540.1 MB** | 0.4% | 路由、协议解析、ffmpeg 解码与调度；含指标中间件 |
| **ASR Worker (batch)** | `qwen3_worker.py` int8（U32 packed） | 2,499.2 MB | **2,503.1 MB (~2.50 GB)** | **3,905.3 MB (~3.91 GB)** | 74.9% | `-8bit` 快照直接加载 int8（无 bf16→fp16 深拷贝），峰值来自 30s 长音频并发负载 |
| **Qwen3 TTS Worker** | `qwen3_tts_worker.py` int8 | 3,408.1 MB | **3,556.5 MB (~3.56 GB)** | **3,978.3 MB (~3.98 GB)** | 1.7% | VoiceDesign 1.7B `-8bit`，`speech_tokenizer` codec 恒为 FP32，显存池限额 |
| **全系统总物理常驻 (Total)** | -- | -- | **6,599.7 MB (~6.60 GB)** | **7,272.2 MB (~7.27 GB)** | -- | 峰值后回落正常，无泄漏滞留 |

> **说明**：ASR batch 压测峰值 CPU 74.9% 为采样瞬间读数（前向计算活跃期），不代表持续负载。
> **真同时口径**：`Peak(Total)` = 逐采样 tick 的（当前 footprint 之和）的最大值，**不为**逐进程 all-time high-water 之和。本次测量窗口 total 峰值 7.27 GB。

## 2. 非流式 ASR 延迟与 RTF 实测基线 (`POST /v1/audio/transcriptions`)

> **测试配置**：`model=speechrail/qwen3-asr-1.7b`, `response_format=json`, 重复 $N=3$ 取均值。16kHz 单声道 PCM16 中文语音样本。**时长以 ffprobe 实测为准**（TTS 生成样本语速不同，非严格 3/10/30/60s）。

| 音频时长 (Duration) | 平均处理耗时 (Mean Latency) | 实时率 (RTF) | 最小 / 最大耗时 | 转写文本 |
|---|---|---|---|---|
| **2.8 秒** (短音频) | **0.30 s** | **0.11x** | 0.12s / 0.66s | “你好，这是本地语音识别与合成。” |
| **9.2 秒** (中音频) | **0.23 s** | **0.03x** | 0.23s / 0.24s | “你好，这是本地语音识别与合成服务的性能基准测试…” |
| **15.8 秒** (长音频) | **0.43 s** | **0.03x** | 0.41s / 0.46s | 长语音连续转写，吐字对齐清晰 |
| **34.6 秒** (超长音频) | **0.87 s** | **0.03x** | 0.86s / 0.87s | 长音频吞吐极稳（比播放快 ~40 倍） |

> **预热说明**：2.8s 音频遍历中首行 0.66s 为 warm-up（含权重 fault-in / Metal kernel 编译），其均值拉高（Mean 0.30s）；稳态均值（后 2 次）为 0.12s，即 RTF 稳态 **0.04x**。下表按稳态值口径，与前三行（无冷启动影响）一致。

### 并发吞吐实测 (4 Workers, N=8)
- **9.2s 音频切片**：Wall time = **1.91s**，成功率 = **8/8 (100%)**，平均延迟 **0.78s** (P95 = **0.94s**)，系统吞吐量 **4.19 req/s**（等效总 RTF = **0.03x**）

## 3. 语音合成 (TTS) 性能实测基线 (`POST /v1/audio/speech`)

> **测试配置**：`model=speechrail/qwen3-tts`, `voice=default`, 24 kHz 单声道 PCM16。预热 1 次后采样。

| 句长 | 平均耗时 (Mean) | 实时率 (RTF) | 最小 / 最大耗时 | 音频时长 (output) |
|---|---|---|---|---|
| **短句 (20 字符)** | **2.18 s** | **0.69x** | 0.78s / 4.79s | 2.7-3.4s |
| **长句 (50 字符)** | **2.27 s** | **0.27x** | 2.10s / 2.39s | 7.8-9.0s |

> **预热说明**：短句首行 4.79s 为 warm-up（TTS worker 首次 kernel 编译），稳态为 0.78s ~ 0.97s。稳态短句 RTF ≈ 0.25x，稳定长句 RTF ≈ 0.27x，均较 bf16 基线更优。

## 4. Realtime 双工流式实测基线 (`WS /v1/realtime`)

> **测试配置**：`.qwenpaw` venv（openai SDK）`client.realtime.connect(model="whisper-1")`，9.2s 16kHz PCM 样本逐块推流，3 独立会话（共享单个 streaming worker，懒启动）。

| 会话 | 握手 setup | ASR Commit 延迟 | RTF | TTS 首包 (TTFA) | TTS 字节 | 结果 |
|---|---|---|---|---|---|---|
| session 1 | 39 ms | 827 ms | 0.09x | 44 ms | 138,240 | ✅ 完成 |
| session 2 | 0 ms | 370 ms | 0.04x | 34 ms | 153,600 | ✅ 完成 |
| session 3 | 0 ms | 372 ms | 0.04x | 38 ms | 143,360 | ✅ 完成 |

> **说明**：session 1 ASR commit 较高（827ms）为 streaming worker 首会话冷启动 / Metal kernel 编译；session 2-3 稳态达到 **370-372ms**（RTF 0.04x）。TTFA 稳态 **34-44ms**。3 会话全部完成、无 `backend_busy`、无空转写、无死锁。流式转写为 windowed 增量提交，文本存在词级切分特征（正常 windowed 行为，须以 `commit` 终结）。

## 5. 与历史版本对比结论

| 指标 | v1.6.3 (bf16/int8 内存量化) | **v1.6.5 (`-8bit` 预量化直接加载)** | 变化 |
|---|---|---|---|
| ASR batch 常驻 | 2,603.0 MB | **2,503.1 MB** | ↓ ~100 MB |
| TTS 常驻 | 4,940.5 MB | **3,556.5 MB** | ↓ ~1.38 GB |
| 总常驻 | 8,082.4 MB | **6,599.7 MB** | ↓ ~1.48 GB |
| ASR 超长音频 RTF | 0.03x | **0.03x** | 持平 |
| ASR 并发吞吐 | 3.87 req/s | **4.19 req/s** | ↑ ~8% |
| Realtime TTS TTFA | 45-64 ms | **34-44 ms** | ↓ 稳定 |
| Realtime ASR commit | 0.34-0.42 s | **0.37-0.83 s** | 首会话冷启动略高，稳态 0.37 s |

> **测量注意**：v1.6.5 资源峰值（总 7.27 GB、ASR batch peak 3.91 GB）因采样窗口同时含 TTS 合成与 30s ASR 并发负载，且 streaming worker 未会话激活；与上一轮"仅 ASR batch 单测"口径不同，不作为同口径对比。常驻（idle）口径可直接对比：v1.6.5 总常驻 6.60 GB，是 v1.6.3 的 8.08 GB 的 **-18%**，得益于 `-8bit` 快照绕过 bf16→fp16 深拷贝与整树量化瞬时占用。
