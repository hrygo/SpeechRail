## 测量身份与可比性

- 当前 manifest SHA-256 前缀 `980cab9c`（相对 v2.0.3 仅 `software.speechrail` 由 2.0.3 → 2.1.0），包含 36 个固定 fixture：ASR 3.12/9.36/16.88/37.04s 各 6 次，TTS short/long 各 6 次；ASR fixture digest 前缀沿用 `4075ad` 等与 v2.0.3 完全一致，Realtime 使用同一固定 16 kHz mono PCM16 fixture。
- 每个 profile 的 `-cold` 行发生在 profile apply 的公共 smoke 之后；因此本轮不把它们宣称为严格 cold，正式分位数只使用 `w01`–`w05` 的 warm N=5。冷态 gate 为 `cold_unavailable`，避免把前置 smoke 后的首次请求误报成冷启动。
- HTTP 通过 `bench_profiles.py` 运行；Realtime 通过本例新增固化的项目脚本 `examples/perf/bench_realtime_json.py`（sha256 `4aead839`）运行，对 `bench_realtime.run_session` 包一层真实 `ProcessResourceMonitor` 并落盘 `speechrail-bench-realtime` schema v1 JSON。RTF 使用 ffprobe/返回 PCM 实测时长，不使用 fixture 名称推断。
- 资源峰值使用完整同 tick 的 PID+start-time 集合求和；HTTP/Realtime 采样窗口均无缺样且 `sampling_complete=true`。TTS `output_seconds` 来自返回 PCM 字节换算（24 kHz mono PCM16），与 v2.0.3 口径一致。
- 三档实际身份均通过 `/health`、`/readyz`、`/v1/models`、`/v1/voices` 复核：`quality` 为 `asr-1.7b-q8` + `tts-1.7b-design-q8` VoiceDesign；`balanced` 为 `asr-1.7b-q8` + `tts-0.6b-custom-q8` CustomVoice；`light` 为 `asr-0.6b-q8` + `tts-0.6b-custom-q8` CustomVoice；量化均为 8-bit MLX。
- 与 v2.0.3 共用机器、manifest、fixture、runner 与资源窗口，纵向数字可作方向性比较；但两轮运行时的背景负载、切换时点和 worker 预热状态不完全相同，不设置临时回归阈值。

## 纵向：与 v2.0.3 的方向性对照

`delta = v2.1.0 - v2.0.3`；延迟/RTF 下降表示更快。百分比只在口径可作方向性比较时计算，不是冻结回归 gate。

| profile | 指标 | v2.0.3 | v2.1.0 | Δ | Δ% | 判断 |
|---|---|---:|---:|---:|---:|---|
| quality | ASR 9.36s warm p50 RTF ↓ | 0.0239 | 0.0314 | +0.0075 | +31.6% | 方向性变慢 |
| balanced | ASR 9.36s warm p50 RTF ↓ | 0.0240 | 0.0294 | +0.0054 | +22.5% | 方向性变慢 |
| light | ASR 9.36s warm p50 RTF ↓ | 0.0154 | 0.0206 | +0.0052 | +33.5% | 方向性变慢 |
| quality | TTS short warm p50 RTF ↓ | 0.2572 | 0.3868 | +0.1296 | +50.4% | 方向性变慢 |
| balanced | TTS short warm p50 RTF ↓ | 0.2302 | 0.2588 | +0.0286 | +12.4% | 方向性变慢 |
| light | TTS short warm p50 RTF ↓ | 0.2289 | 0.2818 | +0.0529 | +23.1% | 方向性变慢 |
| quality | Realtime ASR commit p50 ↓ | 0.3442s | 0.4049s | +0.0607s | +17.6% | 方向性变慢 |
| balanced | Realtime ASR commit p50 ↓ | 0.3389s | 0.4146s | +0.0757s | +22.3% | 方向性变慢 |
| light | Realtime ASR commit p50 ↓ | 0.2434s | 0.2890s | +0.0456s | +18.7% | 方向性变慢 |

已确认的因果边界：

1. `bda6e89` 相对 v2.0.4（及上一份 v2.0.3 基准）**没有修改 `src/speechrail/backends`、`src/speechrail/runtime` 或 `src/speechrail/realtime`**；源码改动集中在 `domain/voice_quality.py`（新增 575 行质量门控域）、`domain/voice_quality_metrics.py`（新增 125 行）、`http/routes/system.py`（+453 行质量门控路由）与 `domain/tts.py`（仅 `VoiceProfile.quality` 字段与 `skip_signal_validation` 参数，不改变 TTS 推理图）。这些改动不改变 ASR/TTS 权重、量化或推理实现。
2. 因此 v2.1.0 相对 v2.0.3 的 RTF 波动不能归因于“2.1.0 推理变慢”。最可能的解释是两轮运行时的背景负载、切换时点和 worker 预热状态不同，且本轮三档在同一天连续切换测量时机器存在并发后台活动。资源峰值也未出现一致放大（balanced HTTP 5919.6→5826.6 MB -1.6%，light 4450.9→4145.5 MB -6.8%），与“全面变重”不一致。
3. 若要冻结性能回归门值，下一步应在同一 runner 中连续重复两版本并预先固定噪声带；本轮仍只作方向性观察，不设置回归结论。
4. `balanced/light` CustomVoice 的返回 PCM 时长有自然波动（short 3.92–4.24s、long 16.0–16.96s，v2.0.3 为 short 4.08–5.04s、long 14.72–16.72s）；报告 RTF 已按每次实际输出时长计算，但 TTS 延迟变化不能单独解释成模型计算变化。

## 本版增量工具与验收说明

- 新增 `examples/perf/bench_realtime_json.py`（sha256 `4aead839`）：对 `bench_realtime.run_session` 包一层真实 `ProcessResourceMonitor`，输出 `speechrail-bench-realtime` schema v1 JSON（含 `warmup_completed`、sessions 分位数、`sampling_complete`）。无绝对路径、无凭据；`--warmup`/`--no-warmup` 显式区分冷/暖口径，`--app-home` 只用于 API key 自动发现且不回显。

## 限制与未验证

- 未执行独立 CER/WER、VAD FAR/FRR、MOS/ABX、speaker embedding、跨重启音色稳定性。
- 未执行 4 workers × 8 requests 吞吐、长时 soak 或并发上限专项；Realtime 仅覆盖显式 warm-up 后连续 3 session。
- v2.0.3 的纵向数字只用于方向性对照；两轮运行 background 不同，且本轮 RTF 相对 v2.0.3 波动但代码差异未修改推理实现，不能把单轮差异写成代码回归。
- CLI 脚手架相关常态项（`speechrail service --help`、plist lint）已由发布门覆盖，不在此报告展开。
- 未把任何报告值同步到 README；性能索引会更新，README 按项目约定保持不变。

## 复现

原始制品在仓库外，命令中的 `$APP_HOME` 仅表示本机 managed app home：

```bash
APP_HOME="${SPEECHRAIL_APP_HOME:-$HOME/Library/Application Support/SpeechRail}"
uv run speechrail service preflight --app-home "$APP_HOME"
uv run speechrail profile apply quality --app-home "$APP_HOME" --yes
uv run python examples/perf/bench_profiles.py \
  --base-url http://127.0.0.1:8201 \
  --app-home "$APP_HOME" \
  --manifest <external-manifest.json> \
  --profile quality \
  --phase warm \
  --output <external-quality.json>
uv run python examples/perf/bench_realtime_json.py <external-16khz-pcm> \
  --profile quality --output <external-quality-realtime.json> \
  --app-home "$APP_HOME"
```

正式发布按 `quality → balanced → light → quality` 串行切档；每次切档前后检查外部连接和 profile identity，并在最终恢复后复查单 listener、`/health`、`/readyz`、`/v1/models`、`/v1/voices`、公共 smoke 与 `/metrics`。
