## 音色稳定性研究

### 方法

每档、每个角色覆盖 3 类文本，每类生成 3 次。第一组为统一中文压力文本，第二组按官方 speaker 的母语选择中文、英文、日文或韩文。使用固定 WeSpeaker 模型提取 embedding，报告：

- `within-role p05/median`：同一角色跨文本与跨轮相似度；
- `between-role p95`：不同角色相似度的高位值；
- `separation margin`：样本到本角色中心与最近其他角色中心的差；
- 最近中心准确率：诊断角色是否被固定 embedding 模型混淆。

这些数值没有预先冻结 release 阈值，只作相对诊断。

### 统一中文压力集

| profile | within p05 / median ↑ | between p95 ↓ | margin p05 / median ↑ | 最近中心准确率 |
|---|---:|---:|---:|---:|
| `quality` | 0.5388 / 0.8185 | 0.8174 | -0.0763 / 0.0595 | 88.89% |
| `balanced` | 0.6613 / 0.8301 | 0.4711 | 0.2866 / 0.4395 | 100% |
| `light` | 0.5137 / 0.8213 | 0.4641 | 0.2557 / 0.4200 | 98.77% |

### 官方建议的母语集

| profile | within p05 / median ↑ | between p95 ↓ | margin p05 / median ↑ | 最近中心准确率 |
|---|---:|---:|---:|---:|
| `quality` | 0.4902 / 0.7853 | 0.7122 | -0.0026 / 0.1116 | 88.89% |
| `balanced` | 0.6308 / 0.8278 | 0.4561 | 0.2079 / 0.4215 | 100% |
| `light` | 0.6749 / 0.8273 | 0.4553 | 0.3133 / 0.4489 | 100% |

官方 CustomVoice 模型卡建议每个 speaker 优先使用母语，并明确九个 speaker 均支持其他语言：[Qwen3-TTS CustomVoice 模型卡](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice)。本轮结果支持将母语集作为角色稳定性主基准，但跨语言能力仍应保留单独测试。

### 跨档同名角色

| 对比 | 同名中心 p05 / median / min |
|---|---:|
| `quality` vs `balanced` | 0.3254 / 0.5079 / 0.3146 |
| `quality` vs `light` | 0.3263 / 0.5026 / 0.2892 |
| `balanced` vs `light` | 0.9563 / 0.9839 / 0.9415 |

`balanced/light` 使用同一 CustomVoice speaker 权重，同名角色声学中心高度一致。`quality` 的 VoiceDesign 角色只保证语义设定相近，不能声明与 CustomVoice 同名角色是同一声纹。

### `quality` 为什么仍会漂移

当前 `quality` 已固定九条 instruction、九个 seed 和 `temperature=0.1`。这解释了同文本进程内及跨重启的字节级复现；它无法把 VoiceDesign 变成持久 speaker identity。模型每次仍根据“角色描述 + 当前文本”重新设计声线，文本内容、语言和韵律会改变 speaker embedding。

当前架构内可立即坚持的规则是：

1. 将 instruction、seed、temperature、top-p 和 runtime revision 作为一个不可分割的角色配方版本；任一变化都重跑 9×3×3 embedding 和跨重启门。
2. 角色主稳定性集使用各角色母语，同时保留统一中文和跨语言压力集；不能只测单句 hash。
3. 新版本以本报告作为首个候选基线，先冻结噪声带，再设置 `within p05`、margin 和最近中心准确率门值。
4. seed 设置失败必须 fail closed 或显式暴露，不能静默退化为随机采样。

若目标是显著提高“不同文本仍像同一个人”，Qwen 官方推荐的工作流是：先用 VoiceDesign 生成参考片段，再由 **Base checkpoint** 创建可复用的 voice-clone prompt，后续使用该 prompt 合成多句：[Qwen3-TTS 官方 Voice Design then Clone](https://github.com/QwenLM/Qwen3-TTS#voice-design-then-clone)。官方实现把 `create_voice_clone_prompt`/`generate_voice_clone` 定义在 Base 模型路径，不能把 VoiceDesign 私有 `_generate_icl` 能被调用等同于受支持的生产能力。

该方案会改变 `quality` 的权重组合与运行流程，还要解决参考音频版本、Base 权重内存、创建自定义音色时如何暂时加载 VoiceDesign，以及回退兼容。它应作为独立架构变更实施和验收，不能在本轮报告中宣称已经具备。

## 运行中发现的问题

1. v1.7.0 切换 smoke 将单次随机 TTS 输出直接作为 ASR 非空门，`balanced` 在长固定句下仍连续两次产生空转写并安全回滚。v1.7.1 仅对“HTTP、request ID 和 JSON 均有效但文本为空”有界重试，最多三次；其他错误立即失败。
2. `examples/perf/sample_resources.py` 原先在 worker 懒加载前固定 PID。若 TTS 尚未驻留，首轮 `--warmup` 会加载 TTS，但采样集合不会补入新 PID，仍可能错误显示 `gate_complete=True`。后续修复改为预热后重新发现受管进程；服务冷重启后的真实复验正确发现新 TTS PID，13 项资源测试、Ruff 和 Mypy 通过。
3. `quality` seed 调用当前实现捕获全部异常并静默继续。当前实测可复现，但该实现会在 MLX API 或 runtime 异常时隐藏稳定性退化，应改为 fail closed 并补回归测试。

## 限制

- 没有人工 MOS、偏好测试或 ABX；speaker embedding 不能替代人的同一人判断。
- 真人 ASR 仅两条官方样本；没有覆盖 240 段多口音、混读、静音和噪声集。
- 没有执行 60 分钟热稳定性与真实前台应用共存压力。
- 当前 embedding 门值为首次诊断结果，不能看完数据后反向选择有利阈值。

## 复现边界

原始音频、逐请求 JSON、embedding 数组和模型文件只保存在仓库外私有 benchmark 目录。报告仅记录公开 fixture digest、脱敏汇总和可移植方法；不保存 API key、用户音频、完整私人转写或模型绝对路径。
