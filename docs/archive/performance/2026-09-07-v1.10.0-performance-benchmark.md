## `backend_busy` 根因与修复证据

首轮从 quality 切 balanced 时，服务并非模型制品损坏。外部 Sona 的 `sona-ui`（PID 30518）仍保持到 8201 的 established realtime WebSocket；当时 `/metrics` 报告 `speechrail_realtime_active_sessions 1`、streaming worker active，batch ASR 因共享资源约束返回 `429 backend_busy`，profile smoke 因此不 ready。

关闭 Chrome 的 Sona 页面后，`sona-ui` 进程仍保持连接；在用户明确授权下只对已核验的精确 PID 发送终止信号，随后 `lsof -nP -iTCP:8201` 不再显示该 established connection，active session 归零，直接 ASR 恢复 HTTP 200。之后 balanced 的资源采样与 realtime 3/3 均通过，light 切换和最终 quality 恢复也通过。

这次故障不应通过放宽 `backend_busy` 或循环重试掩盖。服务/发布/性能 skill 已补充外部客户端隔离前置检查：切档或基准前必须核对 8201 的 established connections、`realtime_active_sessions` 和 governor active requests；发现外部客户端占用时先关闭客户端，必要时按精确 PID 规则结束其进程，确认连接和 session 清零后才继续。
