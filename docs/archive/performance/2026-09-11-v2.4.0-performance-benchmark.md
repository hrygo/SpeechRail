## 纵向：与 v2.2.0 的方向性对照

`delta = v2.4.0 - v2.2.0`；延迟/RTF/内存下降表示更快或更省。百分比只在同口径下作方向性参考，不是冻结回归 gate；本轮存在“重叠开启”与“背景负载未受控”两处混淆项。

已确认的因果边界：

1. 本报告范围（`e015648..08f942e`）**未修改** ASR/TTS 的模型权重、量化或推理图；改动为新增可配置的 ASR∥TTS 重计算重叠（`config/__init__.py`、`application/services.py` 的准入策略）、版本材料与测试。
2. 本轮在**重叠开启**状态下采集，`v2.2.0` 基线为重叠关闭；重叠允许 ASR 与 TTS 的 GPU 工作并发，在单 GPU 上可能引入争用，尤其影响 Realtime（ASR+TTS 同会话）与 `quality` 的重负载窗口。同时后台负载未受控，`quality` 窗口出现单次重载级别离群值。
3. 因此三档 RTF 与 commit 的一致上升**不能**单独归因于“v2.4.0 推理变慢”，也不能单独归因于重叠开关；内存基本持平则与“未改权重/量化/推理图”一致。若要冻结性能回归门值，需在同一 runner 中、在重叠开/关两种状态下连续重复并预先固定噪声带。

## 限制与未验证

- 未执行独立 CER/WER、VAD FAR/FRR、MOS/ABX、speaker embedding、跨重启音色稳定性。
- 未执行 4 workers × 8 requests 吞吐、长时 soak 或并发上限专项；Realtime 仅覆盖显式 warm-up 后连续 3 session。
- `cold` 为 `cold_unavailable`：各档 `profile apply` 的公共 smoke 已在采集前触发推理。
- 本轮采集在 **ASR∥TTS 重叠开启**状态下进行，基线为重叠关闭；这是本次纵向差异的主要混淆项，不能据此断言代码回归或改进。
- 后台 GPU 负载未隔离控制；`quality` 窗口出现单次 worker 重载/争用级别的 p95 离群（`asr-30s` 1.9551 s、`tts-long` 21.2163 s），warm p50 更稳健。
- 本版 `/metrics` 未暴露 `speechrail_realtime_active_sessions`；隔离结论由 `lsof`、governor active requests 与 streaming worker 状态共同支撑。
- `quality` 的 managed 音色状态除 9 个 system canonical role 外，可能保留既有非 system 自定义 voice（历史测试残留）；本基准未修改或删除该状态。
- 未把任何报告值同步到 README；性能索引会更新，README 按项目约定保持不变。

## 复现

原始制品在仓库外（`<app-home>/benchmarks/20260911-v2.4.0/`），命令中的 `$APP_HOME` 仅表示本机 managed app home：

```bash
APP_HOME="${SPEECHRAIL_APP_HOME:-$HOME/Library/Application Support/SpeechRail}"
PYBIN="$APP_HOME/runtime/current/.venv/bin/python"
"$PYBIN" -m speechrail profile apply quality --app-home "$APP_HOME" --yes
uv run python examples/perf/bench_profiles.py \
  --base-url http://127.0.0.1:8201 \
  --app-home "$APP_HOME" \
  --manifest <external-manifest.json> \
  --profile quality \
  --phase warm \
  --output <external-quality.json>
uv run python examples/perf/bench_realtime_json.py <external-16khz-pcm> \
  --profile quality --output <external-quality-realtime.json> \
  --app-home "$APP_HOME"
```

正式发布按 `quality → balanced → light → quality` 串行切档；每次切档前后检查外部连接、governor active requests 与 profile identity，并在最终恢复后复查单 listener、`/health`、`/readyz`、`/v1/models`、`/v1/voices`、公共 smoke 与 `/metrics`。分位数按 nearest-rank 计算；RTF 使用 ffprobe（ASR）与返回 PCM 字节（TTS）实测时长。
