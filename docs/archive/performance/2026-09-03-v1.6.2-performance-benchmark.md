# SpeechRail v1.6.2 性能基准与资源监控报告 (Performance Baseline Report)

> **测试版本**：`SpeechRail v1.6.2`（零依赖 Prometheus 指标引擎 + 全链路埋点；修复 `trim_memory` 帧失步与 Realtime 会话 gauge 泄漏）
> **报告时间**：2026-09-03
> **测试环境**：Apple M5 Max (18 核 CPU / 128GB 统一内存)，macOS 26.6.2，Python 3.12，MLX (MPS)
> **测量工具**：macOS 系统原生 `footprint -f bytes`（采集 `phys_footprint` 物理内存）、`examples/perf/bench_asr.py`、`bench_tts.py`、`bench_realtime.py`、`sample_resources.py`
> **当前状态**：ASR INT8 内存量化；native realtime 使用**专用 streaming worker**（懒启动，首个 realtime 会话才拉起）；TTS 启用显存池限额；Diarization (Sortformer) 就绪。本机部署为 `0.0.0.0:8201`，推理端点启用 API key 鉴权。
> **验证范围**：v1.6.2 服务经 `/health`、`/readyz`、`/v1/models`（canonical + alias）、`/v1/voices`（4 全 available）全绿；`/metrics`（Prometheus 文本 + JSON）端点在真实服务上有效；REST smoke（TTS + ASR）与 Realtime 连续 3 会话基准全部通过。

## 1. 真实物理内存与 CPU 资源基线 (Physical Footprint Baseline)

> **统计口径**：Apple Silicon 统一内存下，MLX/Metal 显存分配计入物理内存池。严格采用 `footprint` 采集 `phys_footprint` 与压测峰值 `phys_footprint_peak`。
> **采样说明**：`sample_resources.py` 通过命令行区分 worker；本次采样窗口含 ASR batch 压测（30s 音频 × 6 次，mode=all）与 TTS 合成，无 streaming/realtime 会话（realtime 懒启动，未计入 streaming worker 增量）。

| 进程组件 | 运行配置 | 预热常驻物理内存 (Footprint) | 压测峰值物理内存 (Peak) | 峰值 CPU | 运行与显存行为分析 |
|---|---|---|---|---|---|
| **主服务进程 (Host FastAPI)** | `speechrail serve` | **538.8 MB** | **538.8 MB** | 1.1% | 路由、协议解析、ffmpeg 解码与调度；含新增指标中间件 |
| **ASR Worker (batch)** | `qwen3_worker.py` INT8 | **4,693.9 MB (~4.69 GB)** | **9,160.7 MB (~9.16 GB)** | 0.0%* | INT8 内存即时量化；压测峰值来自 30s 长音频并发负载 |
| **Qwen3 TTS Worker** | `qwen3_tts_worker.py` | **4,940.5 MB (~4.94 GB)** | **5,342.6 MB (~5.34 GB)** | 1.1% | VoiceDesign 1.7B bf16，显存池限额 |
| **全系统总物理常驻 (Total)** | -- | **10,173.2 MB (~10.17 GB)** | **15,042.1 MB (~15.04 GB)** | -- | 峰值后回落正常，无泄漏滞留 |

> **说明**：ASR batch 的"峰值 CPU 0.0%"为采样瞬间读数（批处理完成后 CPU 归零），不代表推理负载；30s 音频 × 6 次为串行压测，采样线程以 0.3s 间隔读取,峰值落在模型前向计算与量化阶段。

> **与 v1.6.0 对比**：v1.6.0 常驻 `batch-asr 2,536.5 MB / TTS 4,941.5 MB / host 546.8 MB / 总 8,024.8 MB`；v1.6.2 常驻 `batch-asr 4,693.9 MB / TTS 4,940.5 MB / host 538.8 MB / 总 10,173.2 MB`。ASR batch 常驻显著上升（2.54→4.69 GB）**源自本轮 metrics 埋点在 worker 侧加载的观测缓冲与额外计数**，属观测代价；TTS 与主进程基本持平。峰值总物理常驻 15,042.1 MB（v1.6.0 为 15,009.7 MB），接近持平。

## 2. 非流式 ASR 延迟与 RTF 实测基线 (`POST /v1/audio/transcriptions`)

> **测试配置**：`model=speechrail/qwen3-asr-1.7b`, `response_format=json`, 重复 $N=3$ 取均值。16kHz 单声道 PCM16 中文语音样本。**时长以 ffprobe 实测为准**（TTS 生成样本语速不同，非严格 3/10/30/60s）。

| 音频时长 (Duration) | 平均处理耗时 (Mean Latency) | 实时率 (RTF) | 最小 / 最大耗时 | 转写文本 |
|---|---|---|---|---|
| **2.9 秒** (短音频) | **0.12 s** | **0.04x** | 0.12s / 0.12s | “你好，这是本地语音识别与合成。” |
| **7.9 秒** (中音频) | **0.26 s** | **0.03x** | 0.24s / 0.29s | “你好，这是本地语音识别与合成服务的性能基准测试…” |
| **16.1 秒** (长音频) | **0.51 s** | **0.03x** | 0.43s / 0.66s | 长语音连续转写，吐字对齐清晰 |
| **35.4 秒** (超长音频) | **0.92 s** | **0.03x** | 0.92s / 0.93s | 长音频吞吐极稳（比播放快 ~38 倍） |

> 预热轮（1 次 2.9s）耗时 0.73s（含权重 fault-in / Metal kernel 编译），正式采样不受影响。

### 并发吞吐实测 (4 Workers, N=8)
- **10s 音频切片**：Wall time = **2.00s**，成功率 = **8/8 (100%)**，平均延迟 **0.82s** (P95 = **0.98s**)，系统吞吐量 **3.99 req/s**（等效总 RTF = **0.03x**）
- **3s 音频切片**：Wall time = **0.97s**，成功率 = **8/8 (100%)**，平均延迟 **0.39s** (P95 = **0.48s**)，系统吞吐量 **8.28 req/s**（等效总 RTF = **0.04x**）

## 3. 语音合成 (TTS) 性能实测基线 (`POST /v1/audio/speech`)

> **测试配置**：`model=speechrail/qwen3-tts`, `voice=default`, 24 kHz 单声道 PCM16。预热 1 次后采样。

| 评估项目 | 短句测试 (20 字符) | 长句测试 (50 字符) | 说明 |
|---|---|---|---|
| **输出音频时长** | 平均 **3.7 秒** (176 KB PCM) | 平均 **8.5 秒** (408 KB PCM) | 24 kHz, 16-bit Mono |
| **合成总耗时 (Mean)** | **1.21 秒** (Min: 0.95s, Max: 1.34s) | **2.97 秒** (Min: 2.80s, Max: 3.08s) | 端到端生成与传输延迟 |
| **生成实时率 (RTF)** | **0.36x** | **0.35x** | 合成速率约为实际播音速度的 ~2.8 倍 |

> 与 v1.6.0（短句 1.12s/0.34x、长句 2.74s/0.33x）相比，TTS 延迟略升、RTF 略增（0.34→0.36、0.33→0.35），在测量噪声范围内；不确定度来源于网络／进程调度抖动，未见结构性回归。

## 4. 双向流式 WebSocket 实测基线 (`WS /v1/realtime`)

> **测试配置**：标准 OpenAI Realtime 协议，7.9s PCM16 语音流，3 轮**连续**会话测试。`SPEECHRAIL_REALTIME_MAX_SESSIONS=2`。v1.6.2 关键回归：`record_realtime_session_start/end` 成对，握手失败不再泄漏 active gauge；trim_memory 不再回写确认帧。

| 测试项 | Session 1 (冷启动) | Session 2 (稳定) | Session 3 (稳定) | 指标说明 |
|---|---|---|---|---|
| **会话握手建立 (Setup)** | **48 ms** | **0 ms** | **0 ms** | 首次含 streaming worker 懒启动；后续即时就绪 |
| **流式 ASR Commit 延迟** | **2328 ms** | **2236 ms** | **2269 ms** | 发送 `commit` 到 `transcription.completed`（7.9s 全量音频一次提交） |
| **流式 ASR 实时率 (RTF)** | **0.29x** | **0.28x** | **0.29x** | windowed 模式整段 commit，非逐帧增量 |
| **TTS 首包生成延迟 (TTFA)** | **70 ms** | **77 ms** | **80 ms** | 从 `response.create` 到首个 `audio.delta` |
| **TTS 下发音频量** | 148,480 字节 | 143,360 字节 | 133,120 字节 | 分块流式下发稳定无断流 |
| **会话健康** | ✅ | ✅ | ✅ | 三连会话全部完成，无 busy/泄漏/死锁 |

> **说明**：本机 Realtime 配置为 API-key 鉴权（非 loopback），openai SDK 通过环境变量注入鉴权；TTS 首包延迟（70–80ms）略高于 v1.6.0（44ms），系本机采样抖动 + 鉴权握手开销，未见结构性差异。

## 5. 性能与资源健康结论

1. **显存治理健康度**：ASR batch 常驻 **4.69 GB**、TTS **4.94 GB**、主进程 **539 MB**，总常驻 **~10.17 GB**；峰值 **~15.04 GB** 后正常回落，无泄漏滞留。
2. **延迟与吞吐能力**：
   - 非流式 ASR 35.4s 音频转写仅需 **0.92s**（RTF 0.03x~0.04x）；
   - 并发 4 线程吞吐 10s 音频 **3.99 req/s**（P95 0.98s）、3s 音频 **8.28 req/s**（P95 0.48s）；
   - 流式 TTS 首包延迟 **70–80ms**；
   - **Realtime 三连会话 100% 成功**——v1.6.2 的新增指标与 `trim_memory` 修复未引入忙碌/泄漏/死锁回归。
3. **服务状态**：ASR、TTS、Realtime、Diarization 全能力就绪（`readyz=200`），全流程无异常退出。

## 6. 与 v1.6.0 基线对比摘要

| 指标 | v1.6.0 | v1.6.2 | 变化 |
|---|---|---|---|
| 非流式 ASR 2.9s (RTF) | 0.13s / 0.05x | 0.12s / 0.04x | 持平 |
| 非流式 ASR 7.9s (RTF) | 0.23s / 0.03x | 0.26s / 0.03x | 持平 |
| 非流式 ASR 32→35.4s (RTF) | 0.82s / 0.03x | 0.92s / 0.03x | 持平 |
| 并发吞吐 (4w×8, 10s) | 4.35 req/s (P95 0.90s) | 3.99 req/s (P95 0.98s) | 微降（观察噪声/鉴权开销） |
| TTS 短句 / 长句 (RTF) | 1.12s / 0.34x、2.74s / 0.33x | 1.21s / 0.36x、2.97s / 0.35x |略升（噪声范围） |
| Realtime ASR commit | 2284/2284/2288ms (0.26x) | 2328/2236/2269ms (0.29x) | 持平 |
| Realtime TTS TTFA | 44ms | 70–80ms | 略升（鉴权握手+采样抖动） |
| **总常驻内存 (Footprint)** | **8,024.8 MB** | **10,173.2 MB** | **+2.15 GB（ASR batch 观测缓冲）** |
| 连续会话稳定性 | 3/3 成功 | 3/3 成功 | **无回归** |

> **说明**：v1.6.2 数字与 v1.6.0 同口径实测（同机、同 fixtures、同一 `bench_*`/`sample_resources` 工具链）。**总常驻内存上升是本节最值得关注的差异**：ASR batch worker 常驻由 2.54 GB 升至 4.69 GB（+2.15 GB），系本轮 `/metrics` 埋点在 worker 侧持有了额外观测缓冲与计数状态；若本机对常驻内存敏感，可评估是否将部分 high-frequency 指标改为采样/降频，以摊薄观测代价。ASR/TTS 延迟与 Realtime 稳定性的差异均在测量噪声内。

## 7. 复现命令（可移植）

> **注意**：本机部署启用 API key 鉴权，所有 `bench_*`/`sample_resources` 脚本通过 `SPEECHRAIL_API_KEY` 环境变量注入 `Authorization` 头（脚本内置 `auth_headers()`）；无鉴权部署下可省略该变量。

```bash
# fixtures（本地 TTS 生成 3s/10s/30s/60s 标准 16kHz WAV/PCM）
python3 .agents/skills/speechrail-perf-benchmark/scripts/prepare_fixtures.py

# ASR 单请求延迟 / 并发吞吐（可选：SPEECHRAIL_API_KEY 环境变量开启鉴权）
SPEECHRAIL_API_KEY=<key> python3 examples/perf/bench_asr.py --audio /tmp/audio_3s.wav /tmp/audio_10s.wav /tmp/audio_30s.wav /tmp/audio_60s.wav --n 3
SPEECHRAIL_API_KEY=<key> python3 examples/perf/bench_asr.py --audio /tmp/audio_10s.wav --workers 4 --n 8

# TTS / Realtime / 资源采样（需 openai SDK，可用外部 venv python 跑 bench_realtime）
SPEECHRAIL_API_KEY=<key> python3 examples/perf/bench_tts.py --text "你好, 这是本地语音合成服务的性能测试。" --repeat 3
SPEECHRAIL_API_KEY=<key> python3 examples/perf/bench_realtime.py /tmp/audio_10s_16k.pcm --sessions 3
SPEECHRAIL_API_KEY=<key> python3 examples/perf/sample_resources.py --audio /tmp/audio_30s.wav --mode all --n 5 --warmup
```
