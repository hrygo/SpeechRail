## 安装与运行态

安装前 active profile 为 `quality`。按 managed SOP 停用旧 LaunchAgent，使用本地 wheel 执行隔离 preflight，并原子切换 `runtime/current`；安装后重新启用 `com.speechrail`。旧的 v1.8.1 release 未删除。

安装后实测：

- `/health` 返回 `version=1.9.0`、`profile=quality`、`asr_ready=true`、`tts_ready=true`、`diarization_ready=true`。
- `speechrail service status` 显示 LaunchAgent `com.speechrail` 为 running，端口为 `127.0.0.1:8201`。
- `scripts/verify_release.py` 的 wheel、CLI、plist、health、readyz、models、voices 检查全部通过。
- 当前 `quality` 的模型为 `asr-1.7b-q8` + `tts-1.7b-design-q8`；profile generation 为 21。

推理 smoke 使用 managed 配置中的 API key，但 key 未写入报告或命令输出。实际结果如下：

| 请求 | HTTP | Content-Type | 响应大小 |
|---|---:|---|---:|
| `POST /v1/audio/transcriptions` | 200 | `application/json` | 145 bytes |
| `POST /v1/audio/speech` | 200 | `audio/wav` | 46,124 bytes |
| `POST /v1/voices/previews` | 200 | `audio/wav` | 92,204 bytes |

两份 WAV 均为 24 kHz、16-bit、mono PCM。未把转写正文、prompt 或音频内容写入仓库。

## quality warm 观测

使用外部 fixture manifest 的三个 fixture，通过公共 HTTP API 运行一轮真实 warm evidence；原始 JSON 保存在 app home 外部 benchmark 目录。该结果用于证明新安装可推理，不构成完整 release gate。

| fixture | 实际音频秒数 | latency | RTF | HTTP | inference observed |
|---|---:|---:|---:|---:|---|
| `asr-zh` | 6.817250 | 0.2466s | 0.0362 | 200 | yes |
| `asr-en` | 5.969625 | 0.2210s | 0.0370 | 200 | yes |
| `tts-zh` | 4.480000 | 1.2742s | 0.2844 | 200 | yes |

本轮主机识别为 Apple Silicon `arm64`，物理内存为 128 GiB。默认 harness 资源采样器不可用，因此没有可用于发布门禁的 simultaneous `phys_footprint` 证据。

## 三档切换结果

| profile | 操作 | 结果 | 当前证据 |
|---|---|---|---|
| `quality` | 安装后 smoke + warm | pass | 公共 ASR/TTS/preview 成功；服务保持 active |
| `balanced` | `profile apply balanced --yes` | rolled back | `state/profile-transaction.json` 为 `ROLLED_BACK`；服务日志报告候选 worker `worker_load_error` |
| `light` | `profile apply light --yes` | rolled back | 自动恢复前一档；服务最终回到 `quality` |

切换失败没有覆盖原 selection，也没有删除任何模型或 release。由于候选档位没有通过内置公共 smoke，本轮不执行对应 benchmark 请求，也不把 v1.8.0 的历史指标复制为 v1.9.0 结果。

## 限制与后续

- v1.9.0 的新公共能力已经在 `quality` 实例上通过真实 HTTP smoke；三档 MINOR 性能验收仍未完成。
- balanced/light 的 `worker_load_error` 需要单独排查候选模型 worker 启动原因；本次安装没有绕过回滚保护，也没有改变 active profile。
- 质量、自然度、音色身份和 Realtime 没有在本轮重新测量；历史基线仍见 v1.8.1 与 v1.8.0 报告。

## 复现

原始 JSON、fixture 音频和日志位于仓库外 app home 的 benchmark 目录。quality warm evidence 可用以下命令复现；API key 只从私有环境读取：

```bash
uv run python examples/perf/bench_profiles.py \
  --base-url http://127.0.0.1:8201 \
  --manifest <repo-external-manifest.json> \
  --profile quality \
  --phase warm \
  --output <repo-external-result.json>
```
