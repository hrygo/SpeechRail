## 2. 进程与物理显存 (Footprint) 实测对比

> **测量口径**：采用 macOS 原生 `footprint` 采集真实物理显存/内存（`phys_footprint`）。在 Apple M5 Max 128GB 上加载最佳实践配置（`SPEECHRAIL_DTYPE=int8`, `SPEECHRAIL_MLX_CACHE_LIMIT_MB=256`）实机采样。

### 2.1 运行态组件内存对比表

| 进程组件 | 架构角色 / 运行命令 | v1.2.0 预热常驻 | **v1.3.1 最佳实践常驻 (Footprint)** | **v1.3.1 压测峰值 (Peak)** | 优化与状态说明 |
|---|---|---|---|---|---|
| **主服务进程** | `speechrail serve` (PID 55182) | 559.8 MB | **528.0 MB** | **528.0 MB** | 路由、编排与音频解码缓冲 |
| **统一 ASR Worker** | `qwen3_worker.py` (PID 55312) | 6,475.7 MB | **2,535.0 MB (~2.54 GB)** | **9,159.0 MB** | **合并 Batch 与 Streaming + INT8 内存量化 + 256MB 缓存限额** |
| **独立流式 ASR** | `qwen3_streaming_worker.py` | 8,446.2 MB | **0.0 MB (彻底移除)** | **0.0 MB** | **已彻底下线**，彻底根除 8.5 GB 重复常驻 |
| **Qwen3 TTS Worker** | `qwen3_tts_worker.py` (PID 55313) | 4,826.8 MB | **4,940.0 MB (~4.94 GB)** | **5,310.0 MB** | VoiceDesign 1.7B bf16 合成，应用 256MB 缓存池限额 |
| **总计常驻物理内存** | -- | **20,308.6 MB (~20.3 GB)** | **8,012.0 MB (~8.01 GB)** | **14,999.0 MB (~15.0 GB)** | **全系统物理常驻净降 12.3 GB (-60.5%)** |

### 2.2 显存治理效果分析
1. **ASR INT8 内存即时量化**：通过 `mlx_qwen3_asr.convert.quantize_model` 就地量化，将 1.7B 模型权重从 4.63GB 压降至 **2.53 GB**，零额外文件下载，识别率 100% 保持；
2. **消除重复载入**：彻底移除独立 `qwen3_streaming_worker`，消除 8.5 GB 重复常驻；
3. **显存池上限管理 (`--cache-limit-mb 256`)**：为 ASR 与 TTS Worker 注入了 MLX Metal 显存池上限管理，避免中间分配块在 128GB 大内存机器上无节制保留；
4. **显存即时释放 (`_clear_metal_cache`) 与 GC**：在每次推理和流式会话终止后主动调用 `mlx.core.metal.clear_cache()` 与 Python `gc.collect()`。

## 6. ASR INT8 原生即时量化能力 (In-Memory Quantization)

v1.3.1 支持 `SPEECHRAIL_DTYPE=int8` 动态量化模式：
* **工作机制**：在 Worker 启动时直接通过 `mlx_qwen3_asr.convert.quantize_model` 就地转换；
* **零额外下载**：直接复用原本的 FP16 Safetensors 模型文件；
* **显存实测对比**：
  * 原版 FP16 MLX 活跃显存：**4,480.8 MB (~4.48 GB)**；
  * INT8 即时量化后活跃显存：**2,390.5 MB (~2.39 GB)**（显存直降 **47%**）。

## 7. 生命周期与空闲回收治理 (Idle Eviction)

v1.3.1 引入了基于租约机制的 [`WorkerIdleEvictor`](../../../src/speechrail/runtime/worker_lease.py)：

1. **工作机制**：
   * 每次 ASR / TTS 请求到达时，自动调用 `evictor.touch(worker)` 刷新租约活跃时间戳；
   * 后台巡检任务以 10s 为周期检查组件空闲时长；
   * 当连续空闲超过 `SPEECHRAIL_WORKER_IDLE_TIMEOUT_SECONDS`（默认 300 秒 / 5 分钟）时，异步触发 `worker.close()` 安全退出子进程，将占用的物理显存完整归还系统；
   * 新请求到达时自动触发惰性预热启动。
2. **极端待机收益**：
   * 在长时间仅作为系统后台服务待机时，TTS Worker（~4.9 GB）与 ASR Worker（~4.6 GB）被回收后，系统常驻物理内存将回落至 **~527 MB**（仅主服务进程）。
