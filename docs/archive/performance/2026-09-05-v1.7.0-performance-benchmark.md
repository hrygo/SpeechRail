# SpeechRail v1.7.0 性能与质量基准

> 状态：本机三档基础基准通过；目标设备、完整语音质量与跨文本说话人稳定性 gate 未设置
> 范围：MINOR，`quality`、`balanced`、`light` 三档串行测试，结束恢复 `quality`
> 基线：v1.6.9 三档可行性结果；资源口径一致，延迟样本统计不同，属于部分可比

## 一眼结论

| 结论 | 结果 | 证据 |
|---|---|---|
| 发布运行态 | `quality` | `1.7.0` wheel；`asr-1.7b-q8` + `tts-1.7b-design-q8` |
| 三档公共能力 | 通过 | 每档 ASR/TTS 5/5，九个系统角色全部 available |
| 最大同时物理占用 | `quality` 6943.9 MB；`balanced` 6085.9 MB；`light` 4462.9 MB | 同一 tick `phys_footprint`，各档 batch/TTS 场景取较大值 |
| ASR p50 RTF（中/英） | `quality` 0.0243/0.0302；`balanced` 0.0250/0.0313；`light` 0.0174/0.0216 | 独立 macOS 系统语音 fixture，warm N=5 |
| TTS p50 RTF | `quality` 0.2731；`balanced` 0.2405；`light` 0.2394 | 同一文本、`serena`、warm N=5 |
| 同文本音色复现 | `quality` 进程内与重启后 PCM hash 相同；低档 hash 不同 | 只证明同输入字节复现，不等于跨文本同一人验收 |
| 相对 v1.6.9 | 内存基本持平；延迟呈改善/小幅波动 | 旧基线每项单次 warm，当前为 N=5 p50，只作描述性比较 |

## 纵向：v1.6.9 → v1.7.0

下表中的延迟变化是“旧单次 warm → 当前 N=5 p50”，不能单独判定回归；资源使用相同工具和场景，但仍只有单轮。箭头表示指标期望方向。

| profile | ASR RTF 中 / 英 ↓ | TTS RTF ↓ | 稳定物理占用 ↓ | 同时峰值 ↓ | 判断 |
|---|---:|---:|---:|---:|---|
| `quality` | 0.0243（-29.8%）/ 0.0302（-14.5%） | 0.2731（+2.1%） | 6599.7 MB（-0.4%） | 6943.9 MB（-0.8%） | 内存持平；延迟描述性改善/波动 |
| `balanced` | 0.0250（-24.7%）/ 0.0313（-5.2%） | 0.2405（+4.4%） | 5562.7 MB（+0.0%） | 6085.9 MB（+3.5%） | 稳定占用持平；单轮峰值波动 |
| `light` | 0.0174（-30.2%）/ 0.0216（-10.1%） | 0.2394（+5.4%） | 4142.7 MB（-0.6%） | 4462.9 MB（-0.5%） | 内存持平；延迟描述性改善/波动 |

没有预先冻结性能噪声带，因此不把 `+2.1%` 到 `+5.4%` 的 TTS RTF 或 `balanced` 的单轮峰值写成回归。下一版本使用本报告的 N=5 p50/p95 作为同口径纵向基线。

## 音色稳定性

| profile | 同文本进程内 | 服务重启后 | 跨文本 embedding | ABX 盲听 | 当前结论 |
|---|---|---|---|---|---|
| `quality` | 5 次 PCM hash 相同 | 重启前 2 次与重启后 1 次 hash 相同 | 未执行 | 未执行 | 同一输入可字节级复现；尚未证明跨文本始终是同一人 |
| `balanced` | 5 次得到 5 个 hash | 未执行 | 未执行 | 未执行 | 固定 speaker 绑定正常；随机输出差异不能直接解释为身份漂移 |
| `light` | 5 次得到 5 个 hash | 未执行 | 未执行 | 未执行 | 与 balanced 同一 TTS artifact；身份稳定性仍需量化/盲听 |

`quality` 的强复现来自固定 role instruction、seed 和低温采样。真正的“不同内容、不同轮次仍听起来是同一个人”需要固定 speaker embedding 模型的组内 p05/median、角色间 separation margin 和 ABX 盲听；本轮没有这些证据，因此该 gate 保持 unset。

## 运行中发现并修复

旧 wheel 的 profile smoke 使用“语音服务冒烟测试。”这一过短 TTS 句子。切换到 `balanced` 和 `light` 时分别出现一次 HTTP 200 但空转写，事务均正确回退；第二次尝试成功。v1.7.0 最终 wheel 将固定句改为“这是语音服务的切换验证，请清楚朗读这段普通话。”，相关回归测试通过，最终从 `light` 一次切回 `quality` 并通过公共 smoke。

## 限制与未验证

- M1 Air 8GB 与 12GB Apple Silicon 的内存压力、系统响应和长时间稳定性。
- 固定真人 ASR 集、TTS MOS/偏好听测、九角色跨文本 speaker embedding 与 ABX。
- cold start、并发吞吐、Realtime、soak 与故障恢复完整套件。
- 本轮所有数值来自单台机器的一轮发布测量；版本趋势需要后续同口径重复数据。

## 复现

```bash
python3 examples/perf/bench_profiles.py \
  --base-url http://127.0.0.1:8201 \
  --manifest <repo-external-manifest.json> \
  --profile <quality|balanced|light> \
  --phase warm \
  --output <repo-external-result.json>

python3 examples/perf/sample_resources.py \
  --host http://127.0.0.1:8201 \
  --audio <independent-audio.wav> \
  --model whisper-1 \
  --mode <batch|tts> \
  --n 3 \
  --warmup
```
