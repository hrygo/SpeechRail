# SpeechRail v1.6.3 性能基准与资源监控报告 (Performance Baseline Report)

> **测试版本**：`SpeechRail v1.6.3`（修复 `_clear_metal_cache()` 分支排序以优先非弃用 `mx.clear_cache()`，Metal 缓存恢复有效释放；`Qwen3StreamingBackendConfig` 补齐 dtype/cache_limit_mb/memory_limit_mb 转发，streaming worker 继承 `int8` 与有界 Metal 缓存）
> **报告时间**：2026-09-03
> **测试环境**：Apple M5 Max (18 核 CPU / 128GB 统一内存)，macOS 26.6.2，Python 3.12，MLX (MPS)
> **测量工具**：macOS 系统原生 `footprint -f bytes`（采集 `phys_footprint` 物理内存）、`examples/perf/bench_asr.py`、`bench_tts.py`、`bench_realtime.py`、`sample_resources.py`
> **当前状态**：ASR INT8 内存量化；native realtime 使用**专用 streaming worker**（懒启动，首个 realtime 会话才拉起）；TTS 启用显存池限额；Diarization (Sortformer) 就绪。本机部署为 `0.0.0.0:8201`，推理端点启用 API key 鉴权。
> **验证范围**：v1.6.3 服务经 `/health`（version=1.6.3, asr/tts/diarization 全 ready）、`/readyz`、`/v1/models`（canonical + alias）、`/v1/voices`（4 全 available）全绿；REST smoke（TTS + ASR）、Realtime 连续 3 会话与资源压测全部通过。

## 1. 真实物理内存与 CPU 资源基线 (Physical Footprint Baseline)

> **统计口径**：Apple Silicon 统一内存下，MLX/Metal 显存分配计入物理内存池。严格采用 `footprint` 采集 `phys_footprint` 与压测峰值 `phys_footprint_peak`。
> **采样说明**：`sample_resources.py` 通过命令行区分 worker；本次采样窗口含 ASR batch 压测（30s 音频 × 5 次，mode=all）与 TTS 合成，无 streaming/realtime 会话（realtime 懒启动，未计入 streaming worker 增量）。

| 进程组件 | 运行配置 | 冷启待机 | 预热常驻物理内存 (Footprint) | 压测峰值物理内存 (Peak) | 峰值 CPU | 运行与显存行为分析 |
|---|---|---|---|---|---|---|
| **主服务进程 (Host FastAPI)** | `speechrail serve` | - | **538.9 MB** | **538.9 MB** | 0.7% | 路由、协议解析、ffmpeg 解码与调度；含指标中间件 |
| **ASR Worker (batch)** | `qwen3_worker.py` INT8 | 2,603.0 MB | **2,603.0 MB (~2.60 GB)** | **9,152.0 MB (~9.15 GB)** | 0.0%* | INT8 内存即时量化；压测峰值来自 30s 长音频并发负载 |
| **Qwen3 TTS Worker** | `qwen3_tts_worker.py` | 4,792.2 MB | **4,940.5 MB (~4.94 GB)** | **5,347.7 MB (~5.35 GB)** | 1.9% | VoiceDesign 1.7B bf16，显存池限额 |
| **全系统总物理常驻 (Total)** | -- | -- | **8,082.4 MB (~8.08 GB)** | **15,038.7 MB (~15.04 GB)** | -- | 峰值后回落正常，无泄漏滞留 |

> **说明**：ASR batch 的"峰值 CPU 0.0%"为采样瞬间读数（批处理完成后 CPU 归零），不代表推理负载；30s 音频 × 5 次为串行压测，采样线程以 0.3s 间隔读取，峰值落在模型前向计算与量化阶段。

> **与 v1.6.0 / v1.6.2 对比**：
> - v1.6.0 常驻 `batch-asr 2,536.5 MB / TTS 4,941.5 MB / host 546.8 MB / 总 8,024.8 MB`
> - v1.6.2 常驻 `batch-asr 4,693.9 MB / TTS 4,940.5 MB / host 538.8 MB / 总 10,173.2 MB`（**偏高**）
> - v1.6.3 常驻 `batch-asr 2,603.0 MB / TTS 4,940.5 MB / host 538.9 MB / 总 8,082.4 MB`
>
> **根因**：v1.6.2 的 ASR batch 常驻 +2.15 GB **并非** `/metrics` 观测缓冲（worker 不加载该指标，仅主进程有，数据 KB 级），而是 `_clear_metal_cache()` 分支排序错误——优先调用已废弃的 `mx.metal.clear_cache()`（mlx≥0.32 中该符号仍存在），导致有效的 `mx.clear_cache()` 永不触达，Metal 缓存滞留。v1.6.3 修复（翻转排序）后，INT8 batch worker warm-standby trim 后 idle 常驻回落到 **2,603.0 MB**，与 v1.6.0 基线（2,536.5 MB）基本一致（+66 MB 在测量噪声 / streaming worker 共用入口范围内）。

## 2. 非流式 ASR 延迟与 RTF 实测基线 (`POST /v1/audio/transcriptions`)

> **测试配置**：`model=speechrail/qwen3-asr-1.7b`, `response_format=json`, 重复 $N=3$ 取均值。16kHz 单声道 PCM16 中文语音样本。**时长以 ffprobe 实测为准**（TTS 生成样本语速不同，非严格 3/10/30/60s）。

| 音频时长 (Duration) | 平均处理耗时 (Mean Latency) | 实时率 (RTF) | 最小 / 最大耗时 | 转写文本 |
|---|---|---|---|---|
| **3.3 秒** (短音频) | **0.32 s** | **0.10x** | 0.12s / 0.73s | “你好，这是本地语音识别与合成。” |
| **8.5 秒** (中音频) | **0.25 s** | **0.03x** | 0.24s / 0.25s | “你好，这是本地语音识别与合成服务的性能基准测试…” |
| **17.2 秒** (长音频) | **0.49 s** | **0.03x** | 0.44s / 0.56s | 长语音连续转写，吐字对齐清晰 |
| **31.4 秒** (超长音频) | **0.89 s** | **0.03x** | 0.88s / 0.90s | 长音频吞吐极稳（比播放快 ~35 倍） |

> **预热说明**：3s 音频遍历中首行 0.73s 为 warm-up（含权重 fault-in / Metal kernel 编译），其均值拉高（Mean 0.32s）；稳态均值（后 2 次）为 0.12s，即 RTF 稳态 **0.04x**。下表按稳态值口径，与前三行（无冷启动影响）一致。

### 并发吞吐实测 (4 Workers, N=8)
- **10s 音频切片**：Wall time = **2.07s**，成功率 = **8/8 (100%)**，平均延迟 **0.84s** (P95 = **1.02s**)，系统吞吐量 **3.87 req/s**（等效总 RTF = **0.03x**）

## 3. 语音合成 (TTS) 性能实测基线 (`POST /v1/audio/speech`)

> **测试配置**：`model=speechrail/qwen3-tts`, `voice=default`, 24 kHz 单声道 PCM16。预热 1 次后采样。

| 评估项目 | 短句测试 (20 字符) | 长句测试 (50 字符) | 说明 |
|---|---|---|---|
| **输出音频时长** | 平均 **3.4 秒** (161 KB PCM) | 平均 **8.2 秒** (392 KB PCM) | 24 kHz, 16-bit Mono |
| **合成总耗时 (Mean)** | **1.25 s** (Min: 1.19s, Max: 1.29s) | **2.92 s** (Min: 2.81s, Max: 2.98s) | 端到端生成与传输延迟 |
| **生成实时率 (RTF)** | **0.37x** | **0.36x** | 合成速率约为实际播音速度的 ~2.7 倍 |

## 4. 双向流式 WebSocket 实测基线 (`WS /v1/realtime`)

> **测试配置**：标准 OpenAI Realtime 协议，8.5s PCM16 语音流，3 轮**连续**会话测试。`SPEECHRAIL_REALTIME_MAX_SESSIONS=2`。

| 测试项 | Session 1 (冷启动) | Session 2 (稳定) | Session 3 (稳定) | 指标说明 |
|---|---|---|---|---|
| **会话握手建立 (Setup)** | **56 ms** | **0 ms** | **0 ms** | 首次含 streaming worker 懒启动；后续即时就绪 |
| **流式 ASR Commit 延迟** | **420 ms** | **344 ms** | **338 ms** | 发送 `commit` 到 `transcription.completed`（8.5s 音频窗口化提交） |
| **流式 ASR 实时率 (RTF)** | **0.05x** | **0.04x** | **0.04x** | windowed 模式，短音频窗口化增量提交 |
| **TTS 首包生成延迟 (TTFA)** | **64 ms** | **45 ms** | **46 ms** | 从 `response.create` 到首个 `audio.delta` |
| **TTS 下发音频量** | 148,480 字节 | 158,720 字节 | 133,120 字节 | 分块流式下发稳定无断流 |
| **会话健康** | ✅ | ✅ | ✅ | 三连会话全部完成，无 busy/泄漏/死锁 |

> **说明**：本机 Realtime 配置为 API-key 鉴权（非 loopback），openai SDK 通过环境变量注入鉴权。TTS 首包延迟（45–64ms）优于 v1.6.2（70–80ms），且 ASR commit 较 v1.6.2（2.24–2.33s）显著降低——因为 v1.6.3 使用 8.5s 较短音频 + windowed 增量提交，后台 streaming worker 已按 `int8` 加载并保持有界 Metal 缓存，无需整段重编译。

## 5. 性能与资源健康结论

1. **显存治理健康度**：ASR batch 常驻 **2.60 GB**（v1.6.3 修复 clear_cache 后，从 v1.6.2 的 4.69 GB 回落）、TTS **4.94 GB**、主进程 **539 MB**，总常驻 **~8.08 GB**；峰值 **~15.04 GB** 后正常回落，无泄漏滞留。
2. **延迟与吞吐能力**：
   - 非流式 ASR 31.4s 音频转写仅需 **0.89s**（RTF 0.03x）；
   - 并发 4 线程吞吐 10s 音频 **3.87 req/s**（P95 1.02s）；
   - 流式 TTS 首包延迟 **45–64ms**；
   - **Realtime 三连会话 100% 成功**——v1.6.3 的 clear_cache 与 streaming dtype 修复均未引入忙碌/泄漏/死锁回归。
3. **服务状态**：ASR、TTS、Realtime、Diarization 全能力就绪（`readyz=200`），全流程无异常退出。

## 7. 复现命令（可移植）

> **注意**：本机部署启用 API key 鉴权，所有 `bench_*`/`sample_resources`/`prepare_fixtures` 脚本通过 `SPEECHRAIL_API_KEY` 环境变量注入 `Authorization` 头（脚本内置 `auth_headers()`）；无鉴权部署下可省略该变量。`bench_realtime.py` 额外需 openai SDK（可用外部 venv python 运行）。

```bash
# fixtures（本地 TTS 生成 3s/10s/30s/60s 标准 16kHz WAV/PCM）
SPEECHRAIL_API_KEY=<key> python3 .agents/skills/speechrail-perf-benchmark/scripts/prepare_fixtures.py

# ASR 单请求延迟 / 并发吞吐（可选：SPEECHRAIL_API_KEY 环境变量开启鉴权）
SPEECHRAIL_API_KEY=<key> python3 examples/perf/bench_asr.py --audio /tmp/audio_3s.wav /tmp/audio_10s.wav /tmp/audio_30s.wav /tmp/audio_60s.wav --n 3
SPEECHRAIL_API_KEY=<key> python3 examples/perf/bench_asr.py --audio /tmp/audio_10s.wav --workers 4 --n 8

# TTS / Realtime / 资源采样（需 openai SDK，可用外部 venv python 跑 bench_realtime）
SPEECHRAIL_API_KEY=<key> python3 examples/perf/bench_tts.py --text "你好, 这是本地语音合成服务的性能测试。" --repeat 3
SPEECHRAIL_API_KEY=<key> python3 examples/perf/bench_realtime.py /tmp/audio_10s_16k.pcm --sessions 3
SPEECHRAIL_API_KEY=<key> python3 examples/perf/sample_resources.py --audio /tmp/audio_30s.wav --mode all --n 5 --warmup
```
