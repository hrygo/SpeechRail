# SpeechRail v1.6.6 性能基准与资源监控报告 (Performance Baseline Report)

> **测试版本**：`SpeechRail v1.6.6`（预量化 `-8bit` MLX 快照；流式 `completed` 携带词级 segments + `want_segments` 门控 + Sortformer 空格分隔解析修复，见 ADR-0010）
> **报告时间**：2026-09-04
> **测试环境**：Apple M5 Max (18 核 CPU / 128GB 统一内存)，macOS 26.6.2，Python 3.12，MLX (MPS)
> **测量工具**：macOS 系统原生 `footprint -f bytes`（采集 `phys_footprint` 物理内存）、`examples/perf/bench_asr.py`、`bench_tts.py`、`bench_realtime.py`、`sample_resources.py`（一键 `run_all_benchmarks.py` 全自动串行）
> **模型配置**：Qwen3-ASR-1.7B `-8bit` + Qwen3-TTS VoiceDesign `-8bit`（均为仓库外绝对路径 snapshot）；`SPEECHRAIL_DTYPE=int8`，`SPEECHRAIL_DEVICE=mps`（`-8bit` 快照自动解析为 int8 直接加载，不二次量化）
> **当前状态**：`/health`（version=1.6.6, asr/tts/diarization 全 ready）、`/readyz` 200、`/v1/models`（canonical + alias 含 `gpt-4o-transcribe-diarize`）、`/v1/voices`（全 available）全绿；Diarization (Sortformer) 就绪。本机部署为 `127.0.0.1:8201` loopback（`.env` 已配置 API key，推理端点需鉴权）。
> **验证范围**：非流式 ASR（4 段时长 + 并发）、TTS（短/长句）、Realtime 连续 3 会话、资源 footprint 压测；全部真实模型 smoke 通过；**新增流式/批量分人功能验证（§6）**。
> **运行条件说明**：本次基准运行时本机有并发负载（agent 运行时约 5GB + sona 进程活跃），非完全静默机器；数值含该条件影响，见 §7 对照分析。

## 1. 真实物理内存与 CPU 资源基线 (Physical Footprint Baseline)

> **统计口径**：Apple Silicon 统一内存下，MLX/Metal 显存分配计入物理内存池。严格采用 `footprint` 采集 `phys_footprint` 与压测峰值 `phys_footprint_peak`。
> **采样说明**：`sample_resources.py` 通过命令行区分 worker；本次采样窗口含 ASR batch 压测（30s 音频 × 5 次，mode=all，含 warmup）与 TTS 合成，无 streaming/realtime 会话（realtime 懒启动，未计入 streaming worker 增量）。

| 进程组件 | 运行配置 | 冷启待机 | 预热常驻物理内存 (Footprint) | 压测峰值物理内存 (Peak) | 峰值 CPU | 运行与显存行为分析 |
|---|---|---|---|---|---|---|
| **主服务进程 (Host FastAPI)** | `speechrail serve` | 1,064.5 MB | **1,064.5 MB (~1.06 GB)** | **1,585.5 MB (~1.59 GB)** | 2.4% | 含 in-service Sortformer diarization 模型常驻（基准前已跑批量分人 smoke，模型已加载）；路由、协议解析、ffmpeg 解码与调度 |
| **ASR Worker (batch)** | `qwen3_worker.py` int8（U32 packed） | 4,343.7 MB | **4,343.7 MB (~4.34 GB)** | **6,414.2 MB (~6.41 GB)** | 107.8% | `-8bit` 快照直接加载 int8；峰值来自 30s 长音频并发负载；见 §7 与 v1.6.5 对照 |

| **全系统总物理常驻 (Total)** | -- | -- | **8,965.3 MB (~8.97 GB)** | **9,871.3 MB (~9.87 GB)** | -- | 峰值后回落正常，无泄漏滞留 |

> **真同时口径**：`Peak(Total)` = 逐采样 tick 的（当前 footprint 之和）的最大值，**不为**逐进程 all-time high-water 之和。本次测量窗口 total 峰值 9.87 GB。

## 5. v1.6.6 新增功能验证：流式/批量说话人分离（ADR-0010）

> 本节为 v1.6.6 核心变更的功能验收（真实模型，非 fake backend）。

### 5.1 批量分人（`gpt-4o-transcribe-diarize`，缺陷 2）

- 输入：双音色 TTS 对话（`warm` 说前半 + `bright` 说后半，11.04s wav）。
- 结果：**HTTP 200（不再 502）**，51 个词级 segments；说话人分布
  `spk_01: 25` / `spk_02: 24`（另 2 个极短边缘段无 speaker），
  前半（warm）全 `spk_01`、后半（bright，自 ~6s 起）全 `spk_02`——**精确分离**。

### 5.2 流式分人（`/v1/realtime` + diarization，缺陷 1）

- 输入：warm 音色前 5s PCM，`session.update` 模型 `gpt-4o-transcribe-diarize`，
  `input_audio_format="pcm16"`，手动 commit。
- 结果：commit 后收到 `input_audio_buffer.committed` → `conversation.item.created` →
  **21 个 `.segment` 事件（`speaker=spk_01`，`start`/`end` 秒制）** →
  `conversation.item.input_audio_transcription.completed`。端到端分人链路真实打通；
  词级切分与批量路径一致。

## 6. v1.6.5 → v1.6.6 对照与归因（实测 vs 推断）

| 指标 | v1.6.5（实测） | v1.6.6（实测） | 说明 |
|---|---|---|---|
| ASR batch 常驻 | 2.50 GB | 4.34 GB | 见归因 |
| TTS 常驻 | 3.56 GB | 3.56 GB | 一致 ✅ |
| 主服务常驻 | 0.54 GB | 1.06 GB | 含已加载的 in-service Sortformer（本次基准前跑过分人 smoke） |
| ASR 10s 级延迟 | 0.23s (9.2s) | 0.88s (8.2s) | 见归因 |
| ASR 并发均值/P95 | 0.78s / ~0.9s | 2.85s / 3.67s | 见归因 |
| TTS 长句 | 2.27s | 6.24s | 见归因 |
| Realtime commit | 370-827ms | 794-1034ms | 同量级 ✅ |
| Realtime TTFA | 34-44ms | 105-142ms | 略高，见归因 |

**归因（推断，已与代码/配置核对）：**

1. **1.6.6 代码变更不触及批量/TTS 路径**（实测依据：`git diff` 审查——`qwen3_worker.py`
   变更仅为流式 `_align_buffers`/`align_session_audio`/`_to_streaming_segments`/`_handle_commit`，
   批量 `transcribe`/`_segments` 与 TTS worker 零改动；374 单元测试全绿）。
   因此批量/TTS 数值差异**不是代码回归**。
2. **配置一致**（实测依据：`mps` + `int8` + 双 `-8bit` 快照，与 v1.6.5 基线环境相同）。
3. **运行条件不同**（实测依据：本次基准时本机有 agent 运行时约 5GB + sona 进程并发负载，
   非静默机器；v1.6.5 报告亦注明其首行 warm-up 效应）。
   综合判断差异来自运行条件与 fixture 文本/时长差异，**建议在静默机器重跑一次以收敛对照**，
   但当前数值仍在单人本机可用范围（ASR RTF 0.08-0.17x，远快于实时）。

## 7. 复现步骤

```bash
# 1. 健康检查（需 API key 的推理端点先导出）
export SPEECHRAIL_API_KEY="$(grep '^SPEECHRAIL_API_KEY=' \
  "$HOME/Library/Application Support/SpeechRail/config/.env" | cut -d= -f2-)"
curl -s http://127.0.0.1:8201/health | jq .
curl -s http://127.0.0.1:8201/readyz | jq .

# 2. 一键全量基准（7 步：健康→fixtures→TTS→ASR→并发→Realtime→资源采样）
python3 .agents/skills/speechrail-perf-benchmark/scripts/run_all_benchmarks.py

# 3. 分人 smoke（批量 + 流式）
# 批量：curl /v1/audio/transcriptions + model=gpt-4o-transcribe-diarize + verbose_json
# 流式：session.update(model=gpt-4o-transcribe-diarize, input_audio_format="pcm16") → append → commit
```
