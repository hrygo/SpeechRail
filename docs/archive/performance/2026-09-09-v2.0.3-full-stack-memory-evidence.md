# v2.0.3 全链路内存证据与三档场景基准

日期：2026-09-09  
版本：`v2.0.3`  
状态：**有条件通过**

本轮三档功能场景全部通过；但涉及短生命周期 CoreML 分人进程的资源采样未全部闭合，因此只把采样完整的场景用于内存数字，不把部分观测值冒称服务上限。最终运行态已恢复 `quality`。

## 1. 范围与环境

- 设备：Apple Silicon M5 Max，macOS `26.5.1`，物理内存 `128 GB`。
- 服务：managed runtime，单实例、单 ASGI worker，测试期间隔离外部 Sona 连接。
- 档位：
  - `quality`：ASR `1.7B q8`；TTS `1.7B VoiceDesign q8`。
  - `balanced`：ASR `1.7B q8`；TTS `0.6B CustomVoice q8`。
  - `light`：ASR `0.6B q8`；TTS `0.6B CustomVoice q8`。
- 输入：同一份 10 秒真人 PCM/WAV fixture。
- 采样：每档行为场景 N=5，资源采样间隔 `0.1s`；生命周期场景额外执行 10 次连接关闭循环和 600 秒持续会话。
- 工具：`examples/perf/benchmark_scenarios.py`、schema v2 resource monitor、共享鉴权 resolver；原始 JSON 保存在仓库外，不提交音频、日志或凭据。

本报告将三个维度分开：`scenario_coverage`（行为是否执行并通过）、`sample_completeness`（资源证据是否覆盖完整）和 `resource_budget_verdict`（是否可以作预算结论）。三者不能互相替代。

## 2. 场景结果

| 场景 | 实际路径 | `quality` | `balanced` | `light` |
|---|---|---:|---:|---:|
| A | manual Realtime ASR → TTS | 5/5 通过 | 5/5 通过 | 5/5 通过 |
| B | `server_vad`（含静音尾）→ ASR → TTS | 5/5 通过 | 5/5 通过 | 5/5 通过 |
| C | REST `gpt-4o-transcribe-diarize` + `diarized_json` | 5/5 通过 | 5/5 通过 | 5/5 通过 |
| D | `server_vad` + Realtime diarization + TTS 共存 | 5/5 通过 | 5/5 通过 | 5/5 通过 |
| E | 10 次连接关闭循环 + 600 秒持续会话 | 11/11 通过 | 11/11 通过 | 11/11 通过 |

没有场景行为错误、超时、取消泄漏或残留 session/governor 状态。C 的匿名 speaker label 符合当前服务契约；D 实际收到分人和对齐事件后仍完成 TTS。上述结果只说明功能路径通过，不等于资源证据闭合。

## 4. 资源证据限制

- A/B 的物理角色为 `host-fastapi`、`batch-asr`、`tts`，角色集合稳定，资源采样完整，可作为本轮有效的 A/B footprint 证据。
- C/D 观察到了 `diarization`，但 CoreML worker 在重复请求/会话间发生进程身份变化；采样器记录了约 9–10 次 transition，无法证明每个 active window 的同时峰值，所以严格 gate 保持关闭。不能用部分峰值、跨身份求和或单个 PID 猜测替代完整证据。
- E 的行为通过，但正式资源摘要未在要求的完整采样窗口中稳定观察到 `diarization` 角色；因此不采纳其部分观测峰值，资源结论为 N/A。
- 这不是功能失败，而是测量失败闭合：资源 monitor 现在会保留空 tick、缺失角色和身份 transition，并在证据不全时 fail closed。

## 5. 结论、ROI 与后续决策

### 已交付

1. P0：资源采样不再因丢失进程/空 tick 而错误判定 complete；角色、身份、相对时间和 transition 进入 schema v2。
2. P1：公共 runner 覆盖 VAD、REST 分人、Realtime 分人共存、TTS 和生命周期；共享鉴权发现与错误快速失败已固化；fake HTTP/WebSocket 回归已补齐。
3. 三档真实行为套件均通过，最终 profile 恢复 `quality`；报告不提交原始音频、token、日志或模型路径。

### 本轮不做 P2 运行时字节 reservation

当前没有压力、swap、OOM 或持续增长证据；A/B 的完整证据也没有显示需要立即改变调度契约。直接引入动态 reservation 的成本包括生命周期计费、共享 ASR/aligner 重复计费、嵌套资源获取和误拒绝风险，ROI 不足。

下一步最高 ROI 是只补测 C/D/E 的资源证据：按 CoreML worker incarnation/active window 关联采样，并确保生命周期场景在分人角色实际存活窗口内取得完整 tick。只有在该证据显示目标设备预算被合法场景稳定超出、pressure/OOM 可复现或存在持续增长时，才开启 P2；优先修复具体泄漏/无界缓冲，再评估 reservation。

因此，`light` 的“8 GiB 能力”本轮仍保持 `unset`：当前设备是 128 GB，不能替代目标低内存设备验收；A/B 小于 8 GiB 也不能代表 C/D/E 全链路峰值。

## 6. 与旧报告的可比性

旧版 v2.0.3 HTTP 流程曾记录 `quality/balanced/light` 约 `6779.1/5919.6/4450.9 MB`。旧流程未以本轮统一口径覆盖 VAD、CoreML 分人、对齐和生命周期窗口，且场景、角色发现和完整性 gate 不同；这些数字保留为历史证据，不与本轮 A/B 或未闭合的 C/D/E 直接作回归或绝对上限比较。

## 7. 复现与产物

单档复现（将 `<APP_HOME>`、fixture 和输出路径替换为本机授权路径）：

```bash
uv run --extra dev python examples/perf/benchmark_scenarios.py \
  --base-url http://127.0.0.1:8201/v1 \
  --profile light \
  --pcm-file '<APP_HOME>/benchmarks/fixtures/human-10s.pcm' \
  --audio-file '<APP_HOME>/benchmarks/fixtures/human-10s.wav' \
  --app-home '<APP_HOME>' \
  --iterations 5 \
  --lifecycle-loops 10 \
  --soak-seconds 600 \
  --sample-interval 0.1 \
  --output '<APP_HOME>/benchmarks/20260909-v2.0.3-full-stack/light.json'
```

三档脱敏 JSON 产物位于本机仓库外的 `benchmarks/20260909-v2.0.3-full-stack/`；本仓库只保存本报告和可复现工具，不保存 raw benchmark artifact。
