# SpeechRail v1.6.8 性能基准与资源监控报告 (Performance Baseline Report)

> **测试版本**：`SpeechRail v1.6.8`（发布后 LaunchAgent wheel runtime；核心变更：有界音频 decode/encode、标准 multipart timestamp 字段、batch aging、Qwen3 worker session 校验/清理、IPC framed read 优化）
> **报告时间**：2026-09-05
> **测试环境**：Apple M5 Max (18 核 CPU / 128GB 统一内存)，macOS 26.6.2，Python 3.12，MLX (MPS)
> **测量工具**：macOS 系统原生 `footprint -f bytes`（采集 `phys_footprint` 物理内存）、`examples/perf/bench_asr.py`、`bench_tts.py`、`bench_realtime.py`、`sample_resources.py`（`run_all_benchmarks.py` 全自动串行）
> **模型配置**：Qwen3-ASR-1.7B `-8bit` + Qwen3-TTS VoiceDesign `-8bit`（仓库外 snapshot）；`SPEECHRAIL_DTYPE=int8`，`SPEECHRAIL_DEVICE=mps`（`-8bit` 快照自动解析为 int8 直接加载，不二次量化）；私有 snapshot 路径和凭据不记录。
> **当前状态**：LaunchAgent 服务运行于 v1.6.8；`/health`（version=1.6.8，ASR/TTS/diarization 全部 ready）、`/readyz` 200、`/v1/models` 返回 13 个 canonical/alias 条目、`/v1/voices` 返回 4 个可用 voice。
> **测量口径说明**：本轮重新按组件角色区分 host、batch ASR、streaming ASR 和 TTS；内存使用物理 footprint，不以 RSS 替代。历史数据仅作为描述性对照，不据此单独判定回归原因。

本轮结果证明新版本可在真实本机模型与已安装服务 runtime 上完成完整基准流水线。内存数据采用 `footprint` 的物理 footprint，而不是 `ps` RSS；音频 RTF 采用 `ffprobe` 的实际时长，而不是 fixture 的名义标签。

## 1. 真实物理内存与 CPU 资源基线 (Physical Footprint Baseline)

### 1.1 测量说明

> **统计口径**：Apple Silicon 统一内存下，MLX/Metal 显存分配计入物理内存池。严格采用 `footprint` 采集 `phys_footprint` 与压测峰值 `phys_footprint_peak`。
> **采样说明**：`sample_resources.py` 通过 worker 的 `--worker-role` 自描述参数区分 batch 与 streaming；本次采样窗口包含真实 TTS、REST ASR、并发 ASR 和 Realtime 负载。经修正后进程被正确区分为 4 个组件。

### 1.2 组件级资源读数

| 进程组件 | 运行配置 | 冷启待机 | 预热常驻物理内存 (Footprint) | 压测峰值物理内存 (Peak) | 峰值 CPU | 运行与显存行为分析 |
|---|---|---:|---:|---:|---:|---|
| Host FastAPI | `speechrail serve` | 537.3 MB | 538.5 MB | 538.7 MB | 0.9% | 与 v1.6.7 常驻约 0.54 GB 基本一致；主要承载 API、队列和生命周期。 |
| Batch ASR Worker | `qwen3_worker.py`，`--worker-role batch` | 2501.8 MB | 2502.7 MB | 4060.6 MB | 92.4% | 待机约 2.50 GB；本轮峰值发生在一次 batch 加载/推理窗口，不能单独归因于某一代码变更。 |
| Streaming ASR Worker | `qwen3_worker.py`，`--worker-role streaming` | 2560.1 MB | 2556.3 MB | 3424.8 MB | 0.0% | 独立承载 Realtime native streaming；与 batch worker 分开采样。 |
| TTS Worker | `qwen3_tts_worker.py` | 3557.4 MB | 3557.3 MB | 3979.1 MB | 1.6% | VoiceDesign worker 常驻约 3.56 GB；峰值与待机接近。 |
| **合计 (Total)** | 四个组件 | — | **9154.9 MB（约 9.15 GB）** | **10355.3 MB（约 10.36 GB）** | — | 合计只用于描述当前部署的整体 footprint，不代表可直接相加的独立显存分配。 |

> `Peak(Total)` 是本轮负载窗口内四个组件 footprint 的合计峰值；各组件峰值不一定发生在同一时刻，因此不能把它解释为同一瞬间的物理内存快照。

## 2. 非流式 ASR 延迟与 RTF 实测基线 (`POST /v1/audio/transcriptions`)

### 2.1 单请求延迟

> 测试配置：`POST /v1/audio/transcriptions`，16 kHz / mono / PCM16，N=3；音频时长使用 `ffprobe` 实测值，而不是 fixture 文件名中的名义时长。报告只保留非敏感的转写结果摘要，不记录完整转写正文。

| 音频时长（实测） | 平均耗时 (Mean) | RTF | min / max | 转写文本 |
|---:|---:|---:|---:|---|
| 3.36s（`audio_3s`） | 0.35s | 0.10x | 0.14s / 0.77s | 非空，内容与短句 fixture 一致 |
| 8.24s（`audio_10s`） | 0.32s | 0.04x | 0.30s / 0.36s | 非空，含中文及英文片段 |
| 15.68s（`audio_30s`） | 0.79s | 0.05x | 0.68s / 0.88s | 非空，长句连续转写 |
| 34.96s（`audio_60s`） | 1.38s | 0.04x | 1.25s / 1.51s | 非空，长音频持续转写 |

本轮 fixture 的 `ffprobe` 实测时长为：`audio_3s=3.36s`、`audio_10s=8.24s`、`audio_30s=15.68s`、`audio_60s=34.96s`。

3.36s 案例的最大值 0.77s 是本轮短音频首次请求的冷路径样本；同一案例后两次为 0.14s 和 0.14s。其余样本用于展示当前部署的实际延迟，不用于推断长期趋势。

### 2.2 并发吞吐

| 指标 | v1.6.8 本轮实测 | v1.6.7 历史读数 |
|---|---:|---:|
| 并发 worker / 请求数 | 4 / 8 | 4 / 8 |
| Wall time | 2.92s | 2.02s |
| 成功数 | 8 / 8 | 8 / 8 |
| Mean latency | 1.17s | 0.81s |
| P95 latency | 1.48s | 1.02s |
| Throughput | 2.74 req/s | 3.97 req/s |
| Total RTF | 0.04x | 0.03x |

本轮并发阶段 8/8 请求成功且均返回非空文本。由于两版读数均为单轮运行，且无法证明测试时系统背景负载完全相同，历史差异仅作为后续复测的基线，不作为回归结论。

## 5. v1.6.8 运行态与本轮测量说明（本轮关键观察）

### 5.1 已确认

- v1.6.8 wheel 已安装到用户级 LaunchAgent，`com.speechrail` 运行态检查通过。
- 标准 benchmark runner 的 7 个阶段均完成：健康检查、fixture 生成、TTS、REST ASR、并发 ASR、Realtime WS 和 footprint 资源采样。
- 本轮 REST ASR、并发 ASR、TTS 和 3 个 Realtime 会话均获得成功结果；资源采样能区分 host、batch、streaming 和 TTS 四个组件。
- 内存表采用物理 footprint，保留冷启、稳定待机和负载峰值三个口径，避免将 RSS 或单个进程的瞬时读数当作整体基线。

### 5.2 可比性与验证边界

- 本轮结果用于确认发布后运行态和建立 v1.6.8 基线；v1.6.7 数值是历史单轮读数，仅作描述性对照。
- 尚未执行多轮、静默环境下的趋势复测，因此不能仅凭本报告判定 ASR、TTS 或 Realtime 的性能回归。
- 本报告不包含音频主观质量、WER/CER、diarization DER/JER、长时间 leak/soak、故障恢复和安全压力测试结论。

## 6. 归因结论与 v1.6.7 → v1.6.8 对照

| 指标 | v1.6.7 历史读数 | v1.6.8 本轮 | 说明 |
|---|---:|---:|---|
| Host 稳定待机 | 约 0.54 GB | 538.5 MB | 基本一致 |
| Batch ASR 稳定待机 | 约 2.51 GB | 2502.7 MB | 基本一致 |
| Streaming ASR 稳定待机 | 约 2.56 GB | 2556.3 MB | 基本一致 |
| TTS 稳定待机 | 约 3.56 GB | 3557.3 MB | 基本一致 |
| Total 稳定待机 | 约 9.17 GB | 9154.9 MB（约 9.15 GB） | 差异约 11.6 MB，仍在同一量级 |
| ASR 短音频平均 | 约 0.25s（稳定样本约 0.12s） | 0.35s | 单轮冷路径与系统噪声，需复测 |
| ASR 长音频平均 | 约 0.90s（约 34.7s 音频） | 1.38s（34.96s 音频） | 单轮差异，不能单独归因 |
| 并发吞吐 | 3.97 req/s | 2.74 req/s | 需静默环境多轮复测 |
| 并发 P95 | 1.02s | 1.48s | 需静默环境多轮复测 |
| TTS 长句平均 | 2.26s | 3.28s | 输入与运行态需对齐后再比较 |
| Realtime 稳定 ASR commit | 375–395ms | 457–592ms | 首会话/单轮差异，需重复测量 |
| Realtime TTFA | 34–41ms | 44–78ms | 需重复测量 |

归因结论：

1. **已实测**：v1.6.8 发布后的稳定待机内存与 v1.6.7 基本一致，Total footprint 约 9.15 GB；本轮所有主要推理路径均完成。
2. **已实测**：本轮负载窗口中的 ASR/TTS/Realtime 延迟和并发吞吐低于历史单轮读数，但测试次数和背景负载不足以证明代码回归。
3. **已实测**：并发 ASR 为 8/8 成功，Realtime 为 3/3 完成，健康端点和模型/voice 清单检查通过。
4. **后续建议**：若要形成版本趋势结论，应在相同机器、相同私有模型配置和静默背景负载下连续执行至少 3 轮，并分别报告中位数、P95、峰值 footprint 和冷/热路径。

```bash
cd /Users/hrygo/Documents/SpeechRail
set -a
source "$HOME/Library/Application Support/SpeechRail/config/.env"

curl http://127.0.0.1:8201/health
curl http://127.0.0.1:8201/readyz

curl http://127.0.0.1:8201/v1/voices
```
