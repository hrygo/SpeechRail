# SpeechRail v2.0.2 性能与质量基准

> 状态：有条件通过
> 范围：显式三档完整性能套件（`quality → balanced → light → quality`）
> 测量：2026-09-09（Asia/Shanghai）
> 安装 commit：`a6d3051`；版本：`v2.0.2`
> 基线：`v1.13.0`（部分可比，仅作方向性对照）

## 一眼结论

| 结论 | 结果 | 证据 |
|---|---|---|
| 三档运行与恢复 | pass | `quality → balanced → light → quality`；generation `47 → 48 → 49 → 50`，最终恢复 `quality` |
| 公共性能请求 | pass | 每档 4 组 ASR × 6 次、short/long TTS × 6 次，均 36/36 返回 200、非空 |

| 独立质量与音色稳定性 | unset | 未提供独立标注语料、CER/WER、MOS/ABX 或 speaker embedding |

实测环境：Apple M5 Max、128 GiB Unified Memory、macOS 26.6.2、Python 3.12.14；vendor runtime 的 `mlx=0.32.2`、`mlx-qwen3-asr=0.3.5`、`mlx-audio=0.4.8`。原始 JSON、fixture 和采样制品仅保存于仓库外 `<app-home>/benchmarks/20260909-v2.0.2-full/`；本报告不保留音频、转写、输入文本、API key、PID 或绝对路径。

## 测量身份与可比性

- 固定外部 fixture 的 SHA-256 前缀为：`asr-3s=5ab6f44c`、`asr-10s=4075ad`、`asr-30s=5cde37`、`asr-60s=03cb627`、Realtime PCM=`a1bdbc`；实测时长为 3.12/9.36/16.88/37.04s。
- 每档先以 controller 做一次服务重启；重启后序列首个 ASR（`asr-3s`）和首个 TTS（short）作为 process-reset cold observation，其余为 warm。每个 ASR 时长和 TTS 文本集各有 warm N=5。
- Realtime 使用相同的 16 kHz mono PCM16、连续 3 session；server VAD 使用同一输入追加静音尾段。
- 资源使用 macOS `footprint -p <pid> -f bytes` 的 `phys_footprint`，按完整同 tick 的 PID+start-time 集合求峰值；不以 RSS 代替，不相加不同时间的进程峰值。
- v1.13.0 使用同一组 ASR fixture 和同一机器，但上一报告采用的聚合 runner、TTS 输出长度和资源采样窗口与本轮不完全一致；因此纵向结果只作方向性观察，不设性能回归 gate。

| 性能回归 | unset | 没有预冻结噪声带；v1.13.0 runner/资源窗口与本轮不完全一致，不能形成硬性回归结论 |

最终恢复期间第一次独立 ASR smoke 曾在 Realtime 客户端短暂未释放时返回 `429 backend_busy`；诊断确认该连接随后自然清零，连接清零后仅重新做一次最终 smoke，ASR/TTS 均为 200。该瞬态不计入三档采集结果，但保留在交接限制中。

## 限制与未验证

- 未执行独立 CER/WER、VAD FAR/FRR、MOS/ABX、speaker embedding、跨重启音色稳定性。
- 未执行长时 soak、4 workers × 8 requests 吞吐和并发上限专项；本轮 Realtime 为连续 3 个 session，不等同于长时并发压测。
- `quality`、`balanced`、`light` 的横向结果来自同一机器和同一 fixture；由于模型档位不同，只作档位比较，不声明跨档同名角色为同一声纹。
- 代表性纵向数值显示当前 RTF 多数高于 v1.13.0；基线口径未完全一致且没有冻结阈值，建议后续以同一 runner/同一采样窗口复测后再归因。

## 复现

HTTP 与资源采样使用正式入口；manifest 和输出均位于仓库外：

```bash
uv run python examples/perf/bench_profiles.py \\
  --base-url http://127.0.0.1:8201 \\
  --manifest <app-home>/benchmarks/20260909-v2.0.2-full/manifest.json \\
  --profile <quality|balanced|light> \\
  --phase warm \\
  --output <app-home>/benchmarks/20260909-v2.0.2-full/results/<profile>-all-auth.json
```

每档执行前通过 managed controller 完成 `profile apply <profile> --yes`、外部连接隔离和一次 `service restart`；Realtime 使用外部固定 PCM fixture、16 kHz mono PCM16、3 个串行 session 和一次 `server_vad` smoke。API key 只从本机私有环境读取，不写入命令、报告或日志。
