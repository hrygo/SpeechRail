## 纵向：与 v2.1.0 的方向性对照

`delta = v2.2.0 - v2.1.0`；延迟/RTF/内存下降表示更快或更省。百分比只在同口径下作方向性参考，不是冻结回归 gate。

| profile | 指标 | v2.1.0 | v2.2.0 | Δ | Δ% | 判断 |
|---|---|---:|---:|---:|---:|---|
| quality | ASR 9.36s warm p50 RTF ↓ | 0.0314 | 0.0257 | −0.0057 | −18.2% | 方向性变快 |
| quality | TTS short warm p50 RTF ↓ | 0.3868 | 0.2678 | −0.1190 | −30.8% | 方向性变快 |
| quality | HTTP 同 tick 峰值 ↓ | 7470.3 MB | 6709.8 MB | −760.5 | −10.2% | 方向性下降 |
| quality | Realtime commit p50 ↓ | 404.9 ms | 396.0 ms | −8.9 ms | −2.2% | 方向性变快 |
| balanced | ASR 9.36s warm p50 RTF ↓ | 0.0294 | 0.0268 | −0.0026 | −8.8% | 方向性变快 |
| balanced | TTS short warm p50 RTF ↓ | 0.2588 | 0.2575 | −0.0013 | −0.5% | 持平 |
| balanced | HTTP 同 tick 峰值 ↓ | 5826.6 MB | 5798.2 MB | −28.4 | −0.5% | 持平 |
| balanced | Realtime commit p50 ↓ | 414.6 ms | 369.3 ms | −45.3 ms | −10.9% | 方向性变快 |
| light | ASR 9.36s warm p50 RTF ↓ | 0.0206 | 0.0160 | −0.0046 | −22.3% | 方向性变快 |
| light | TTS short warm p50 RTF ↓ | 0.2818 | 0.2366 | −0.0452 | −16.0% | 方向性变快 |
| light | HTTP 同 tick 峰值 ↓ | 4145.5 MB | 4206.7 MB | +61.2 | +1.5% | 方向性上升 |
| light | Realtime commit p50 ↓ | 289.0 ms | 253.3 ms | −35.7 ms | −12.4% | 方向性变快 |

已确认的因果边界：

1. 本报告测量范围 `bda6e89..84b12d4` 未修改 ASR/TTS 的模型权重、量化或推理图。涉及的 `src/speechrail` 改动为：`application/lifecycle.py`、`application/realtime_openai.py`、`application/services.py`、`backends/qwen3_shared.py`、`compatibility/openai_realtime.py`、`domain/tts.py`、`http/routes/{audio,jobs,system}.py`、`mcp/*`、`runtime/{job_runner,jobs,local_file_processor,worker_lease}.py`；其中 `backends/qwen3_shared.py` 的改动是 ASR worker 空闲淘汰时钟修复（`a114ef3`），不属于推理算力变化。工作树另有 2.1.1→2.2.0 版本材料和 CHANGELOG/openapi/契约同步（未提交）。
2. 因此上述 RTF 与 commit 时间下降不能单独归因于“2.2.0 推理变快”，最可能混入两轮运行的背景负载、切换时点与 worker 预热状态差异；`light` HTTP 峰值 +1.5% 与其余档下降方向不一致，也不支持“全面变重/变轻”的单因解释。
3. 若要冻结性能回归门值，应在同一 runner 中连续重复两版本并预先固定噪声带；本轮仍只作方向性观察。

## 限制与未验证

- 未执行独立 CER/WER、VAD FAR/FRR、MOS/ABX、speaker embedding、跨重启音色稳定性。
- 未执行 4 workers × 8 requests 吞吐、长时 soak 或并发上限专项；Realtime 仅覆盖显式 warm-up 后连续 3 session。
- `cold` 为 `cold_unavailable`：各档 `profile apply` 的公共 smoke 已在采集前触发推理，不把预热后的首次请求当成严格冷启动。
- 本版 `/metrics` 未暴露 `speechrail_realtime_active_sessions`；隔离结论由 `lsof`、governor active/pending 与 streaming worker 状态共同支撑。
- 纵向数字只用于方向性对照，不能把单轮差异写成代码回归或改进结论；本版范围未改推理权重/量化/推理图，但改动了空闲淘汰与 job/realtime 协议相关代码。
- `quality` 的 managed 音色状态除 9 个 system canonical role 外，还保留 1 个既有非 system 自定义 instruction voice（测试残留，非本基准创建）；本基准未修改或删除该状态。
- 未把任何报告值同步到 README；性能索引会更新，README 按项目约定保持不变。

## 复现

原始制品在仓库外（`<app-home>/benchmarks/20260910-v2.2.0/`），命令中的 `$APP_HOME` 仅表示本机 managed app home：

```bash
APP_HOME="${SPEECHRAIL_APP_HOME:-$HOME/Library/Application Support/SpeechRail}"
PYBIN="$APP_HOME/runtime/current/.venv/bin/python"
"$PYBIN" -m speechrail profile apply quality --app-home "$APP_HOME" --yes
uv run python examples/perf/bench_profiles.py \
  --base-url http://127.0.0.1:8201 \
  --app-home "$APP_HOME" \
  --manifest <external-manifest.json> \
  --profile quality \
  --phase warm \
  --output <external-quality.json>
uv run python examples/perf/bench_realtime_json.py <external-16khz-pcm> \
  --profile quality --output <external-quality-realtime.json> \
  --app-home "$APP_HOME"
```

正式发布按 `quality → balanced → light → quality` 串行切档；每次切档前后检查外部连接、governor active/pending 与 profile identity，并在最终恢复后复查单 listener、`/health`、`/readyz`、`/v1/models`、`/v1/voices`、公共 smoke 与 `/metrics`。分位数按 nearest-rank 计算；RTF 使用 ffprobe（ASR）与返回 PCM 字节（TTS）实测时长。
