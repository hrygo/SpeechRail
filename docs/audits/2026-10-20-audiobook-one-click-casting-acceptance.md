# 有声书一键配声准备验收记录

## 目标与边界

全书分析后，一键完成需要朗读角色的声音分配，无需逐个配置；精细调音与声音创作按需打开，章节音频另行启动。保护人工选声、明确独占要求、声音归属、制作验收与既有音频。

本记录使用合成书稿、fake renderer 与临时存储。没有调用真实模型、安装 App、操作服务或修改真实作品。用户明确授权后，通过 Computer Use 操作仓库包装脚本构建的临时 App；所有书稿、会话记录与配声数据使用隔离夹具。补充测量采用 Release 配置、`-O`、arm64，并仅为启用隔离夹具设置 `SWIFT_ACTIVE_COMPILATION_CONDITIONS=DEBUG`；不等同于未启用测试夹具的正式发行包。

## 功能验收

| 场景 | 结果与证据 |
| --- | --- |
| 54 个角色、7 个推断主角、2 个合格声音 | 全部发声角色可得到方案；旁白独占，推断重要程度不再强制独占 |
| 54 个角色跨章分布、已有人工旁白绑定 | 一键保存全书配声并确认准备完成；再次点击保留原选择 |
| 明确独占政策超出容量 | 保留政策与原绑定，整批不提交 |
| 同章角色必须共用声音 | 集中展示撞音风险，一键共享同意不替代风险确认；确认后完成准备 |
| 一键准备的音频边界 | 音色创建、试听与章节 render 调用均为 0，制作状态仍为 idle |
| 重复点击、取消、准备期间切书 | 同时只有一次准备，取消不提交，旧书结果不覆盖当前投影 |
| 大量未配声角色 | 提示未配声数量与一键操作，不在错误横幅列出整本人物名单 |

相关新增用例在修改前复现失败，修复后通过；明确独占、目录隔离、参数、过期方案和事务回滚的既有回归保留。

## UX/UI 检查

- 默认路径使用已有合格音色，分析与普通配声不批量创建专属声音。
- 常规共享方案直接显示一键主动作；确需确认的风险集中显示，避免重复主动作和逐角色确认。
- 配声期间显示读取、匹配、保存、核对制作条件四个阶段；忙碌时阻止重复触发。
- 主按钮、帮助文字与准备完成文案明确区分配声准备与章节生成；精细创作保留在角色与次级菜单。
- 复用现有 Button、ProgressView、语义 Token 与 accessibilityIdentifier，没有新增视觉裸值。
- 顶部主动作与侧栏调用同一一键准备动作；有风险时改为「查看配声方案」，分析完成横幅同步指向该动作。
- 实际桌面复核：1280 × 960 窗口下分析进度可见；集中确认浮层完整显示，未确认风险时「应用配声方案」禁用；确认后 3 章全部为「可制作」，0 章成片，仍停留「准备与角色」。
- 实测修正了窄窗口浮层锚定整个工作区、出现于屏幕外的问题；浮层改为锚定「人物与声音」按钮。
- 补充桌面复核：54 个角色、53 章、2 个合格声音的一键操作完成后，章节显示「可制作」，仍停留「准备与角色」，0 章成片。
- 默认系统「键盘导航」关闭，进程启动参数不能替代系统偏好。用户另行明确授权后，临时开启该设置：Tab 顺序到达工作台头部及「一键智能配声」，空格执行准备；当前章角色选声、详情、更多整理及下一阶段按钮均可遍历。集中确认路径中，两项风险复选框可用 Tab / 空格操作，全部勾选前应用按钮禁用；Shift-Tab 可返回，空格应用后仍为 0 章成片。Escape 关闭菜单与浮层。结束后已恢复关闭，并以系统设置界面与 `AppleKeyboardUIMode=0` 双重核对。
- 上述键盘证据覆盖一键准备、风险确认及当前章精调入口；不宣称全部 App 页面、54 张角色卡逐一遍历或实际 VoiceOver 朗读均已验收。
- 一次重复采样尝试中菜单状态变化，后续键盘确认进入隔离作品的制作页；fake renderer 拒绝生成，0 段音频，任务暂停后关闭该进程。该次不计入配对样本，随后每次使用新建作品；一键准备本身没有触发制作。
- XCUITest 定向入口在启动测试前报 `No test bundle product`（exit 70）；不把此入口记作通过。上述界面证据来自随后获授权的 Computer Use 操作。

## 性能与资源证据

80 人物、900 段功能夹具经 Store 的完整规划路径暴露了深度修复热点。一次复现持续超过三分钟后中断，对该自有测试进程的栈采样定位到 `AudiobookCastingPlanner.assign` 内的递归 `solve`；候选计数预算不足以约束每次排序和图遍历的实际工作。

共享角色超过 12 个时保留完整初案，不做递归修复；剩余直接对白撞音报告为 `residualConflicts`，不宣称已证明无解。小规模搜索、既有候选预算和取消检查继续生效。80 角色、每角色 2 个候选的回归将评估次数限制在 160 以内。

修复后的同一长篇功能夹具在一次 Debug 回归中用时约 1.7 秒。该数值是单次功能测试观察，不是 Release 性能基准、P95 或稳定加速比。不据此宣称达到全部性能目标；下述独立规划器测量补充了优化编译后的配对证据。

### 规划器配对测量

2026-10-20 本机实测 Apple M5 Max、128 GiB、macOS 27.0.1、Swift 6.4 / arm64。基线为 `822e02b2` 的规划器，改后为本分支规划器；直接从源码提取 `AudiobookCastingPlanner`、策略枚举与图的存储/权重计算代码，使用 `swiftc -O`，不改算法。外壳仅提供未触发的错误类型与合成输入。每规模 3 组 before/after 配对，每进程预热 1 次、测量 5 次（每版本 N=15）；奇数环、每角色 2 个声音、稳定 UUID。第二轮测量时没有本任务构建、测试或 UI 进程并发运行。

### App 进程配对观测

2026-10-20 至 21（Asia/Shanghai），同一设备与工具链。两版使用相同隔离夹具：54 角色、53 章、265 个文本 atom、2 个声音，角色跨章分布，没有待确认的同章撞音。对照源码包含本次工作流与 UI 改动，仅撤去规划器的 `roles.count <= maximumRepairRoleCount` 条件；这是搜索护栏的对照，不是整个功能改造前的 App。两版 `App.swift` 夹具逐字一致，均已通过 Release 构建和 XPC 打包核验。

两版各先用独立进程预热一次完整准备，再按 before/after 交替运行 3 组，每次新建相同规模作品。每个 App PID 采集 15 s、1 s 间隔的 `proc_pid_rusage` CPU / RSS / physical footprint，同时以 Instruments SwiftUI 模板记录主线程更新。第三组改后操作使用 Tab / 空格，其余使用鼠标。每次均观察到「可制作」且没有自动生成音频。原始 trace、XML、采样 JSON 与统计脚本保留在仓库外。

| --- | --- | --- |
| 每次 CPU 平均值的中位数（单核 100%） | 0.1574% | 0.1552% |
| 各次 1 s CPU p95 的最大值 | 1.4187% | 1.4960% |

| 各次整组更新事务 p99 的最大值 (ms) | 0.383125 | 0.344792 |

每次单项更新包含 36,058–36,515 条主线程记录，其中 View Body 各 75 条；完整事务包含系统布局成本，不能把单项更新耗时冒充整次配声耗时。该路径的观测值低于自有主线程 p95 5 ms / p99 16 ms 的预算，整组事务未观察到超过 100 ms。普通跨章准备的 CPU / 内存没有明显退化，不据此宣称显著加速；大量撞音的搜索收益由独立规划器测量支持。实际音质、模型推理、其他 App 功能及长时稳定性不由这些夹具证明。

### 空闲观测

准备完成后单独采集 300 s，每秒一个进程样本。前台 54 角色作品：对照平均 CPU 0.00025%、p95 0.00131%；改后平均 0.03012%、p95 0.22052%，均低于平均 ≤1%、p95 ≤3% 的预算。改后前台观测在首轮 Instruments 附加之后，不能将其内存与未附加 Instruments 的对照空闲内存作回归比较；内存配对以同条件的上表为准。空闲数据各为一次 5 分钟观察，不冒充三组空闲配对基准。

改后窗口隐藏、4 角色风险确认作品准备完成后的另一次 300 s 观察：平均 CPU 0.000228%、p95 0.001429%，峰值 RSS 245.13 MiB、physical footprint 135.85 MiB，同样低于空闲 CPU 预算。该输入是 3 章 / 4 角色，不能与前台 53 章 / 54 角色样本推导隐藏窗口的性能提升比例。

10 项 `AudiobookWorkspacePerformanceTests` 验证标注/边访问次数、限定章节候选读取、缓存容量、取消、快速选择与过期结果隔离；它们是确定性预算证据。

## 验收结论与覆盖范围

一键配声准备的功能、默认路径和风险确认路径的键盘操作，以及 App 进程的定向 Release 优化观测已通过。普通路径无需逐角色选声，精细创作仍可选，准备完成与音频生成保持独立动作。

本记录不是所有 App 功能的发布验收：实际 VoiceOver 朗读、全部页面与角色卡逐一遍历、真实音质、模型推理与长时稳定性未覆盖。取消、防重复、过期结果及工作区任务上限使用确定性回归证明；没有将这些逻辑断言冒充 App 实际队列计数或取消后 2 s 释放的墙钟测量。
