## 迁移、故障与回退

- SQLite backup API 包含已提交 WAL 页；每步先备份，再事务推进 user_version。schema 2→3 保存政策/画像与可空实际身份列，3→4 新增登记意图及配声修订。旧占位身份保留待确认，实际事实未知保持 NULL。注入 DDL 冲突后版本与记录不前进，移除临时故障后可重试；未来版本拒绝写入。
- 目录旧文件首次成功修改前保留原始副本，成功原子替换后才更新内存和通知。未来/损坏文件不重建为空，写入失败保持磁盘和投影。未知嵌套画像及合集字段保留；旧 archived 无法证明原范围时保持 unknown/archived，须先确认范围。
- 登记阶段为 registered、catalogPersisted、bindingCommitted、completed。四个边界注入中断并重启恢复，重复恢复不重复绑定；绑定提交和阶段推进同事务。期间改选或归属冲突进入 needsReview，书籍专用资产保留，推广/归档/收藏不被回滚。
- 算法回退在支持 SQLite schema 4 和目录 schema 2 的实现内选择 `baseline`，保留 P0 守卫、锁定、历史音频和版本，不降级数据。配声撤销在当前合法条件下新增修订，其他操作已改变状态时拒绝旧撤销。
- 源码撤回必须按本轮前快照与当前文件做三方比对，只撤回本轮片段；不整文件还原，不覆盖原有或并行修改。已有迁移后作品时，不能用旧数据库/目录快照覆盖。真实恢复及 App 回滚须另行明确授权。

`frag_dep_v2` 按来源文本、区间和有效角色归属计算，重分块不改变相同输出语义。旧摘要重新规划时可能需要重新生成候选；旧音频和已采用版本仍保留，不据摘要版本差异删除历史。
