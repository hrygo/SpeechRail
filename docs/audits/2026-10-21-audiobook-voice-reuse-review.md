# 有声书音色复用修复验证

核验日期：2026-10-21。范围为 macOS App 候选、重新配声、创建资料与当前《彷徨》的配声恢复。

## 行为与影响

- 已确认来源的活跃音色可跨小说和历史文稿复用；来源 ID 不再限制使用。归档、来源未确认、未验收和不支持参数仍分别拒绝。
- 普通自动配声保留已有选择；“按角色特征重新配声”显式规划替换，通过完整方案确认、事务校验与可撤销记录保存。
- 共享池按性别、年龄需求预留匹配音色，保护明确独占要求；自动重要程度不能先占走共享角色唯一匹配的声部。共享仍可能有同场冲突，不能宣称听感验收通过。
- 创建资料先计算已有声音的可行覆盖；完整方案容量不足不等于所有角色都缺声。归档、来源未确认及验收问题提示恢复、确认或检查已有声音。选中草稿尚未完成时不自动改绑其角色，以保留重试身份。
- 分析完整且说话人已确认时，无台词角色显示“无台词，无需配声（可选）”。

## 验证证据

定向命令：

```bash
swift test --package-path macos/SpeechRailApp \
  --filter 'AudiobookCastTests|VoiceCatalogPerformanceTests|AudiobookWorkflowTests'
scripts/macos_app_build.sh --configuration Debug
git diff --check
```

- 190 项相关 fake 回归通过，0 失败。跨书复用、稀缺声部预留和局部缺口计算均观察到修复前失败、修复后通过。
- 新增覆盖确认前不保存、其他书籍绑定与来源不变、未知/归档/未验收拒绝、已有声音不重复创建。最终 Debug App 包装构建通过，临时 bundle 由脚本收尾清理。
- 只读独立审查发现共享声部被自动独占耗尽、整批失败误判为全部缺声两项 P2；均补回归并修复。测试另暴露批量创建失败后自动改绑使重试失效的问题，修复后定向与相关套件通过。

## 当前作品实测

操作前使用 SQLite backup API 保存一致性副本与原音色目录，在仓库外临时副本演练；实际应用调用当前 Swift Store/Controller 的生产规划与原子提交路径，未直接重写绑定 SQL。

- 52 个实际发声角色均有绑定，缺失数为 0，使用 13 种已有音色。保留原先仅提及角色的绑定；仍有 31 个无台词角色无需配声。
- 11 个相关旧剧组音色通过目录 API 设为通用复用，使已安装旧客户端也可选用；原书籍、角色来源字段均保留。
- 正文来源、章节、标注、文本单元、既有音频候选和制作版本逐表核对不变；配声修订由 1 条变为 2 条，支持撤销。当前书库没有其他作品；跨作品不变另由临时双书回归验证。
- 方案仍报告 53 对同章共享风险，保存配声不等于试听或正式制作确认。未创建新音色，未合成、播放或重新生成章节音频，未重启服务或切换模型。

## 关联模块复核与补修

2026-10-21 对来源准入、音色库分类、资料准备、注册恢复、试听及正式制作关联链复核后完成以下补修：

- 缺声资料不再因目录任意音色存在信息级异常而整体清空。按必需特征及独占/共享约束计算已有资产覆盖，可修复的声音仅参与诊断预留，不生成可提交绑定；剩余缺口独立准备资料。
- 活跃的未知来源记录提示确认来源；归档记录提示恢复，不再混淆。身份冲突的重复记录不计入覆盖。
- “通用来源”明确排除剧组来源，“剧组来源”保持来源分类；两者跨作品准入仍统一。创建成功及待重新确认的返回提示均说明可跨作品复用。
- 注册恢复测试各故障边界改为验证跨作品可用，保留克隆来源、原书及角色来源，并校验同库另一作品角色与绑定不变。恢复幂等、外键检查仍保留。
- 新增混合目录回归，覆盖来源未知、归档、未验收、不支持默认制作参数和身份冲突；覆盖异常声音不满足角色必需特征时仍为真正缺口准备资料。过程不自动创建声音、提交部分配声或修改目录。
- 对话试听使用历史文稿来源声音；新增正式制作和重录的跨作品回归，检查来源与绑定不变，归档后不再发送渲染请求。

定向失败回归先观察到来源误报、来源筛选混入、混合目录阻断和旧返回文案的失败，再完成修复。注册恢复的旧跨书隔离断言已在前轮实测失败，本轮同步为新规则并加强隔离验证。
