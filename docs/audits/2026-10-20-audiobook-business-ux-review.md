# 有声书业务流程与用户体验审查

本轮只审查 macOS「有声书工坊」的业务闭环与用户旅程，重点回答三个问题：用户是否总知道下一步；失败是否发生在点击之后才暴露；可恢复操作是否真的容易恢复。审计基线为 `1811c744`，工作区含本轮改动。

## 1. 证据边界

- 读取范围：`AudiobookWorkflowModel.swift`、`AudiobookBookShelfView.swift`、`AudiobookWorkshopView.swift`、`AudiobookBookWorkspaceView.swift`、`AudiobookListeningView.swift`、`AudiobookExportController.swift`，以及用户/架构/开发者三份有声书文档。
- 代码事实：主链路为导入 → 分章 → 全书分析 → 配声 → 逐章制作 → 听声 → 导出；书架与工作台已有唯一主动作、暂停/续作、失败码持久化与章节跳过。
- 未实测：真实桌面观感、VoiceOver 顺序、真实长篇书稿回归。项目规则禁止未经逐次授权的 UI 自动化，本轮未运行。
- 结论分层：下文「已实施」均由代码与确定性测试支撑；「建议」是尚未实现的推断。

## 2. 业务流程判断

### 2.1 旅程摩擦矩阵

| 阶段 | 用户目标 | 审查发现的摩擦 | 本轮处理 |
|---|---|---|---|
| 导入 | 把手里的书稿放进工坊 | 只能通过文件面板，拖放无反馈；文案仍以 TXT 为主 | 书架支持 TXT/EPUB 拖放，拖入时显示投放提示 |
| 分章/整理 | 确认章节边界 | 主链路已闭合 | 不改 |
| 全书分析 | 等分析完成并处理未知说话人 | 分析完成后的自动配声/音量信息集中在长横幅 | 不改 |
| 配声 | 确认角色与音色 | 角色卡仍用整卡点击选择，不符合设计系统的「选择用 Button」约定 | 记录为残留项 |
| 章节制作 | 逐章生成并返修 | 已完成/待更新/跳过状态可见 | 不改 |
| 听书 | 听已完成的章节 | 没有任何成品音频时仍可切入听书模式，看到一排禁用章节和空播放器；已跳过章节仍出现在可收听列表 | 空态引导 + 只听未跳过且有音频的章节 |
| 导出 | 导出整本或已选章节 | 整本 M4B 的就绪门槛在点击后才由控制器抛错；错误横幅被 sheet 遮住；MP3 默认勾选未就绪章节 | 面板内前置就绪概览、禁用不可用动作、内联错误 |
| 移入废纸篓 | 移除一本不再制作的书 | 操作可恢复，但恢复入口藏在废纸篓里，没有即时撤销 | 顶部撤销横幅，只撤销刚移走的一本 |

### 2.2 三个结构性问题

1. **门禁后置**：导出控制器是唯一真相，但界面在准备前不展示“整本还差几章”。用户点主按钮后才知道失败，且失败横幅在 modal 后面。
2. **状态与动作不一致**：听书模式在无成品音频时仍可进入；跳过章节只从分析/制作/导出排除，没有从收听排除，用户会看到自己明确跳过的内容。
3. **可恢复操作的恢复成本高**：废纸篓本身可恢复，但误移走后要先返回书架、打开废纸篓、再找同一本；缺少就近撤销。

## 3. 本轮已实施

### 3.1 导出门禁前置与内联错误

- 新增 `AudiobookExportReadiness`：只统计未跳过章节，区分“已有当前章节版本”和“缺当前版本”；整本 M4B 要求没有阻塞章节，MP3 只允许选择已有版本的章节。
- 导出面板新增就绪概览：整本 M4B 未齐时禁用主按钮并显示“去制作「首章」…”；MP3 默认全选已就绪章节，未就绪/跳过项不可勾选，并说明会进入遗漏清单。
- 准备/保存失败写入 `exportErrorMessage`，在面板内用 NoticeBar 展示；切换格式、勾选或响度选项会作废已准备的导出，避免拿旧包保存。
- **边界**：前置门禁只基于章节当前版本，不替代 `prepare` 的标注、候选资产、媒体帧与 SHA-256 核验；最终失败仍以后者为准，只是现在会显示在当前面板里。

### 3.2 听书空态与跳过一致性

- 新增 `hasListenableChapter`：只认未跳过且存在当前或上一版本音频的章节。
- `startListening` 默认从上述章节中选择；没有可听章节时进入听书模式但不启动播放器，让空态可见。
- 听书章节列表过滤跳过章节，标题计数同步；空态提供“去制作章节”，直接回到制作台。

### 3.3 废纸篓即时撤销

- 移入废纸篓后记录本次作品与标题，书架顶部显示“已移入废纸篓”横幅和 **撤销**；撤销只恢复这一本，不触碰更早的作品。
- 从废纸篓手动恢复同一本时清空撤销状态；恢复失败保留撤销入口，可重试。
- 未改变“废纸篓不是删除”的数据语义，也未增加新的持久化字段。

### 3.4 拖放导入

- 书架接受 TXT/EPUB 拖放，按扩展名筛选，拖入时显示“松开以导入书稿 / 支持 TXT 与无 DRM 的 EPUB”。
- 拖放与文件面板复用同一个 `prepareImport` 预览流程，编码、目录页和重复内容检查不绕过。
- 一次拖入多个文件时只取第一个受支持文件；批量导入仍未实现。

## 4. 验证

- 有声书测试：309 个通过（1 个既有跳过），新增 3 个测试覆盖导出就绪投影、废纸篓撤销、无成品音频的听书空态。
- 全量 XCTest：1820 个通过（1 个既有跳过）；Swift Testing：659 个通过。
- App Debug 构建：`scripts/macos_app_build.sh --configuration Debug` 成功。
- 未验证：前台 UI 观感、键盘/VoiceOver 走查、真实长篇书稿、真实 FFmpeg 导出与媒体核验。

## 5. 未实施与建议

1. **资产级导出预检**：当前就绪投影只看章节版本；要彻底消除“按了才知道”，需要把候选资产存在性、SHA-256、标注完整性纳入只读预检，或由控制器提供轻量 dry-run。
2. **批量补齐未就绪章节**：现在“去制作”只定位第一处；长篇作品仍要逐章操作。可在制作台增加“制作所有未就绪章节”，但必须复用单本串行队列与取消语义。
3. **角色卡选择语义**：整卡 `.onTapGesture` + `.focusable` 仍不符合设计系统“选择用 Button”的约定；需要把角色标题区改成 Button，同时保留卡内音色/试听/展开等叶面控件。
4. **真实长篇与 UI 验收**：外部语料仍是云端占位，未执行；UI 自动化未获逐次授权。
5. **导入批量与拖放安全**：一次只处理第一个文件；拖放路径的 security-scoped 语义在非沙盒构建下未单独验证。

## 6. 回退

- 导出：回退 `AudiobookExportReadiness`、面板就绪卡与 `exportErrorMessage` 即可恢复“点击后由控制器报错”的旧行为；无 schema 变化。
- 听书：回退 `hasListenableChapter`、`startListening` 的目标选择与列表过滤即可；不涉及持久化。
- 废纸篓：撤销状态只在内存，回退后恢复入口仍由废纸篓 sheet 提供。
- 拖放：移除 `.dropDestination` 与遮罩即可，文件面板导入不受影响。
