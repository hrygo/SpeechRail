# 有声书工坊流程、算法与用户旅程审查记录

本记录覆盖 TXT 导入、章节规划、全书分析、角色确认、章节制作、返修恢复、收听和导出。证据来自当前源码、公共行为文档、定向 fake / 合成音频回归及隔离 App 编译；前台 UI、真实模型质量、真实性能和长时稳定性不在本次实测范围内。

用户授权直接按审查结果实施优化。修改沿用现有 SwiftUI、WorkflowModel 和控制器边界，不改变服务公共 API、持久化格式、用户数据库、模型、安装或运行态。

## 2. 用户旅程检查

## 4. 未验证范围与恢复

没有运行前台 UI 自动化、真实 LLM / TTS、音质基准、长篇真实制作或安装验收。定向 fake 回归通过只能证明被断言的流程和边界，不能替代这些验证。

本轮完成的遗留项：

- M4B 实际章节读取已实现；合成媒体同时覆盖可播放但无章节、标题/顺序/数量/边界不符以及正确双章容器。正例使用 AVAudioFile 合成 AAC，经 PATH 中的 FFmpeg 写入实际章节，不下载工具；本机该测试实际通过，未跳过。
- 启动恢复只处理 Store 打开时遗留且未被新工作更新的分析/制作任务；恢复失败后可重试，重复资产核查不暂停当前任务。
- 目录提供重命名、分析前按现有段落拆分与相邻合并；已有采用版本的章节提供单段重录及显式采用，保持既有音频与历史。

策略影响：旧 v1 分析检查点在下次主动分析时重新计算；旧 v1 渲染候选在下次主动制作时生成新策略候选，以避免继续复用采样率错误的音频。旧资产和历史采用版本保留，没有批量处理真实书籍。

本任务没有操作真实书籍、音频、配置、模型、服务或正式安装，没有执行暂存或提交。另一并行任务先后将共享差异纳入 `faa1fabd` 与 `6ae7b369`；后者包含本轮 RED 临时占位，不能单独作为修复已完成的证据。恢复时以完成后的差异和验证记录为准，仅逆向目标变更，先核对并行修改；不得整文件还原或重置工作区。

审查期间保留了独立并行提交 `e655228e`（版本发布材料）和 `061d32e8`（已有轮廓 API 编译修正）；本任务没有覆盖这些改动。

工作台文件另出现人物卡片、音色选择器布局/hover 的并行差异；用户已确认来自另一任务，要求保留并纳入编译。Debug 构建覆盖共享工作树中的这些差异；它们不归为本次代理实现，编译通过也不表示视觉验收通过。

共享工作树中的音色目录刷新、六类群像音色和相关 Cast 集成用例亦为并行改动，已保留并包含在最终 Swift 回归内；`tests/test_voice_validation_policy.py` 的并行新增用例未由本任务运行。

用户另明确确认并行制作校验改动已获授权，要求保留并单独记录风险。当前 `ProductionController` 仅要求音色 `available`；`ProductionWiring` 对非 `productionReady` 音色省略严格输出门禁，严格调用失败时可用宽松选项重试，并允许至少 44 字节的音频被标为回执已验证。此规则不保证服务端回执确已核验，也不保证输出达到正式制作质量门禁；本地 WAV 格式、摘要和导出媒体校验不能替代该证据。本轮保留这些差异，没有以 fake 测试通过宣称真实回执可信度或音质通过。

独立静态复核还提示，角色合并的角色保存与对白重派分属两次事务，后者失败时可能留下未完成的归属更新。该故障路径尚未注入复现，未纳入本轮目录整理、单段重录和绑定保存修复的验收结论。
