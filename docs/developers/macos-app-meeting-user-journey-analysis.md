# SpeechRail 会议助手模块深入用户旅程分析与 UX/UI 优化规范

**文档状态**：Active
**版本**：1.1.0
**适用对象**：macOS App 架构师、交互设计师、前端工程师
**设计基线**：macOS 26 Liquid Glass、SpeechRail Design Tokens、OpenAI Realtime/ASR 契约

---

## 1. 业务与用户心智模型 (Mental Model)

SpeechRail 会议助手定位于 **Apple Silicon Mac 本地第一方多人对话与会议智能伴侣**。它承载着单机共享 ASR/TTS 引擎在会议场景下的最重负荷应用。

### 1.1 核心价值主张
1. **零数据泄露与本地隐私**：原始 PCM 音频不落盘，文字记录安全沉淀至本地 SQLite，不依赖任何第三方云端转写。
2. **多路音频无缝合流**：无需安装虚拟声卡驱动（如 BlackHole/Loopback），原生接管“麦克风环境声”与“Mac 本机出声应用（腾讯会议、Zoom、飞书等）”，自动对齐时钟与合流转写。
3. **多人发言人区分与无损修订**：基于本地声纹分离自动标注会中发言人，支持任意时刻合并、改名，正文与时间码严格保真。
4. **多版本纪要与证据闭环**：通过大模型提炼结构化纪要、决议与未完成事项，每一条结论可追溯至原文对话时间码与发言人证据链。

## 2. 全生命周期用户旅程深度剖析 (User Journey Deep-Dive)

我们将用户的全流程划分为四个相辅相成的关键阶段：

```mermaid
journey
    title 会议助手完整用户旅程 (End-to-End User Journey)
    section 会前准备 (Pre-Meeting)
      打开会议助手，感知服务与拾音环境: 5: 用户
      确认音频来源(麦克风+应用): 4: 用户
      调阅会前准备稿或输入轻量标题直启: 5: 用户
    section 会中记录 (Live In-Meeting)
      专注浏览实时流式字幕与时间码: 5: 用户
      一键标记会议重点时刻(⌘B/星标): 5: 用户
      临时静音麦克风或暂停录制: 4: 用户
      快捷更正/命名说话人归属: 5: 用户
      遇到意外中断时从容恢复: 4: 用户
    section 会后整理 (Post-Meeting)
      结束会议并触发智能整理: 5: 用户
      凭代表句与占比条快速认领说话人: 5: 用户
      审阅多版本纪要或局部重试失败片段: 5: 用户
      按重点或发言人筛选记录并分层复制: 5: 用户
    section 知识沉淀 (Cross-Meeting Knowledge)
      检索往期会议与关键结论: 4: 用户
      跨会议追踪未完成事项与待办: 4: 用户
      发现跨会议矛盾并裁定结论: 5: 用户
      开启新一轮会议闭环: 4: 用户
```

---

### 阶段一：会前进入与准备 (Pre-Meeting Phase)

#### 1. 用户目标与心理状态
- **用户目标**：快速准备开会，确认当前麦克风是否正常工作、线上会议软件（如腾讯会议）的声音是否能被录入；需要时一眼回顾上场遗留待办；输入一个轻量标题（或直接留空），一键开始录制。
- **心理状态**：会议即将开始或已经开始，用户时间紧迫，极其厌恶复杂的表单和吓人的技术报错。

#### 2. 原有 UX/UI 痛点分析
1. **键盘操作心流断裂**：用户输入标题后，按下回车键（Return）无响应，必须移动鼠标去点击右上角的按钮或记忆快捷键 `⌘⇧N`。
2. **排障噪音干扰常态**：在来源选择展开后，常驻显示大面积的黄色“来源不可用时”卡片（“列表为空”、“未授权”），即使系统运行完全正常，也给用户造成“是不是出故障了”的心理恐慌。
3. **会前准备稿入口深藏**：知识库虽支持自动汇总「会前准备稿」，但在会议助手首屏缺少直达入口。

#### 3. 优化设计
- **回车键直启会议 (Enter-to-Start)**：标题输入框接入 `.onSubmit`，并提供轻量视觉回车符号（`↵`），实现“输入即开会”的极速心流。
- **渐进式智能音频环境卡**：将来源状态收拢为“音频环境”，常态下优雅显示麦克风与应用声音状态，仅在真正检测到无权限或来源异常时才以轻量提示展开出口。
- **会前准备稿与历史记录双入口**：在会议记录库卡片头部提供「会前准备稿」与「全部知识库」快捷入口，在看历史记录时提供常驻醒目的“返回会议主页”主出口。

---

### 阶段二：会中进行与实时协同 (Live In-Meeting Phase)

#### 1. 用户目标与心理状态
- **用户目标**：会议发言中，专注查看大字号实时转写与说话人区分；听到关键决策或任务时一键打星标留痕；能够快速静音自己或临时暂停录制；随时随地修正说话人名字。
- **心理状态**：注意力集中在会议讨论上，操作必须瞬时、确定、零干扰。

#### 2. 原有 UX/UI 痛点分析
1. **说话人行内改名需二次点击**：点击转写行上的说话人标签选择重命名后，打开面板仍需再次寻找对应说话人的编辑按钮。
2. **会中重点留痕缺失**：开会过程中听到关键结论时无法打书签，会后面对上百段文字记录难以快速定位核心段落。
3. **流式预览单帧回退闪烁**：滑动窗口边界偶发出现单帧末尾缩短或标点跳变。

#### 3. 优化设计
- **流式预览防缩回稳定化**：接入 `CaptionPartialStability` 过滤单帧尾部回退，保持实时上屏顺滑稳定。
- **会中一键记重点（`⌘B` / 行内星标）**：状态带提供「记重点」按钮（支持未落定首句预约标记），转写行支持点击星标或右键标记重点，表头支持「★ 仅看重点」实时过滤。
- **行内说话人全功能直达菜单**：点击转写流中的任何说话人 Chip，选择「重命名说话人…」即打开面板并自动聚焦至该说话人的姓名输入框；同时支持一键「标记为我」与「合并到其他说话人」。
- **高质感悬浮回看胶囊**：采用 `Surface.floatingToolbarMaterial` 与同心胶囊几何，清晰标出“有 N 句新发言”，一键平滑滚动回到底部。

---

### 阶段三：会后收尾与纪要提炼 (Post-Meeting & Synthesis Phase)

#### 1. 用户目标与心理状态
- **用户目标**：结束会议，确保每一句话都安全存盘；在没有录音回放的情况下快速认出每位说话人是谁；审阅核心决议与结论，必要时局部重试未完成窗口并按需分层复制导出。
- **心理状态**：会议刚结束，期望快速交割会议成果，最担心长时等待不知所措或认不出匿名说话人编号。

#### 2. 原有 UX/UI 痛点分析
1. **无音频条件下认人困难**：因不落盘原始音频，会后无法听音辨人，仅看 `说话人 1 (12 段)` 无法回忆身份。
2. **分窗失败缺少局部重试按钮**：长会议若个别窗口超时失败，底层虽有 `retryFailedWindows` 能力，但界面未暴露局部重试按钮。
3. **复制与筛选粒度单一**：缺乏仅看重点发言筛选及「纪要 + 文字记录」组合复制能力。

#### 3. 优化设计
- **无音频「代表句 + 首次时间码 + 占比条」认人卡片**：在 `SpeakerTextStatistics` 中自动过滤口语寒暄，提取每位说话人最具信息量的代表句摘录与首次发言时间码展示于 `SpeakerLabelingPanel`，并在 `SpeakerTextSharePanel` 提供可视化水平占比进度条。
- **分窗失败局部重试与重点加权**：会中重点标记自动传入纪要生成补充上下文；当长会议存在失败分窗时，会后直接展示「重试未完成片段」按钮。
- **文字记录双向搜索、重点过滤与分层复制**：支持按关键词、说话人及「★ 仅看重点」实时筛选；表头支持「复制纪要全文」、「复制纪要 + 文字记录」与「仅复制重点记录」。

---

### 阶段四：跨会议知识库沉淀 (Knowledge & Cross-Meeting Phase)

#### 1. 用户目标与心理状态
- **用户目标**：长期追踪项目未完成事项（Action Items）；跨会议检索谁在什么时候做了什么承诺；如果两个会议出现矛盾结论，明确裁定哪一条作数。
- **心理状态**：办公复盘、项目管理与深度回顾，需要高确定性与高信息密度。

#### 2. 优化设计
- 强化会前、会中、会后与知识库之间的统一契约；
- 在会前记录库卡片与知识库顶栏显式暴露「会前准备稿」、「未完成事项」与「跨会议冲突」入口；
- 全量对齐 `SpeechRailDesignTokens` 字体与尺寸规范。

---

## 3. 设计 Token 与组件契约规范 (Design Token Alignment)

所有组件严格遵循 `SpeechRailDesignTokens.swift`：
- **布局间距**：外围采用 `Spacing.gutter` (20pt)，卡片内边距采用 `Spacing.md` (16pt)，紧凑元组采用 `Spacing.sm` (12pt)。
- **同心几何**：容器采用 `Corner.containerShape` (12pt)，可交互卡片与控件采用 `Corner.controlShape` (8pt)，微型胶囊与标签采用 `Corner.compactShape` (4pt)。
- **字体排版**：全面使用 `Typography.sectionTitle`、`body`、`bodyMedium`、`callout`、`calloutMedium`、`caption`、`captionMedium`、`technicalValue`，严禁裸写系统字号。
- **辅助功能**：全交互动作具备清晰语义的 `accessibilityLabel`、焦点守卫与 Escape 键退出，动效在 `reduceMotion` 下干净降级。

## 4. 实测体验问题闭环记录 (Live Experience Issue Resolution)

1. **状态带降噪与渐进披露**：剔除常态下无差别倾倒的 6 轴状态日志；常态仅保留核心要素，仅在真正故障/降级时渐进展示告警项。
2. **转录流说话人视觉闭环**：当单句尚未聚类出说话人标签时，以轻量语义胶囊补齐视觉断层，并支持行内直达指定归属或改名。
3. **右栏信息架构与严谨人话**：区分“发言人数”与“发言人区分”；会中“整理”明确为“会后自动提炼”；隐藏底层物理文件名。
4. **会中私聊助手重塑**：将“内心 OS”命名对齐为“会中私聊 / 私密助手”，明确“私下提问 · 仅你可见 · 答案不入会议公频”。
5. **无音频代表句认人与话量占比可视化**：过滤寒暄短语并提取每位说话人的高信息量代表原话与首次发言时间码，在标注面板展示代表句辅助认人，并提供可视化占比进度条。
6. **会中实时重点留痕（`⌘B`）与会后纪要/局部重试闭环**：支持会中一键标记重点行（含未落定句预约标记）、会中/会后「★ 仅看重点」筛选、纪要生成重点关注提示、分窗失败局部重试入口及会前准备稿直达入口。
