# SpeechRail 会议助手模块深入用户旅程分析与 UX/UI 优化规范

**文档状态**：Active
**版本**：1.0.0
**适用对象**：macOS App 架构师、交互设计师、前端工程师
**设计基线**：macOS 26 Liquid Glass、SpeechRail Design Tokens、OpenAI Realtime/ASR 契约

---

## 1. 业务与用户心智模型 (Mental Model)

SpeechRail 会议助手定位于 **Apple Silicon Mac 本地第一方多人对话与会议智能伴侣**。它承载着单机共享 ASR/TTS 引擎在会议场景下的最重负荷应用。

### 1.1 核心价值主张
1. **零数据泄露与本地隐私**：原始 PCM 音频不落盘，文字记录安全沉淀至本地 SQLite，不依赖任何第三方云端转写。
2. **多路音频无缝合流**：无需安装虚拟声卡驱动（如 BlackHole/Loopback），原生接管“麦克风环境声”与“Mac 本机出声应用（腾讯会议、Zoom、飞书等）”，自动对齐时钟与合流转写。
3. **多人发言人区分与无损修订**：基于本地声纹分离自动标注会中发言人，支持任意时刻合并、改名，正文与时间码严格保真。
4. **多版本纪要与证据闭环**：通过大模型提炼结构化纪要、决议与未完成事项，每一条结论可追溯至原文对话时间码与发言人证据链。

## 2. 全生命周期用户旅程深度剖析 (User Journey Deep-Dive)

我们将用户的全流程划分为四个相辅相成的关键阶段：

```mermaid
journey
    title 会议助手完整用户旅程 (End-to-End User Journey)
    section 会前准备 (Pre-Meeting)
      打开会议助手，感知服务与拾音环境: 5: 用户
      确认音频来源(麦克风+应用): 4: 用户
      输入轻量标题或直接启会: 4: 用户
    section 会中记录 (Live In-Meeting)
      专注浏览实时流式字幕与时间码: 5: 用户
      感知麦克风/系统出声状态: 5: 用户
      临时静音麦克风或暂停录制: 4: 用户
      快捷更正/命名说话人归属: 3: 用户
      遇到意外中断时从容恢复: 4: 用户
    section 会后整理 (Post-Meeting)
      结束会议并触发智能整理: 5: 用户
      等待纪要生成时的进度预期: 3: 用户
      审阅多版本纪要与决议: 4: 用户
      对照文字记录原文与引用验证: 3: 用户
      采纳纪要并一键导出/分享: 5: 用户
    section 知识沉淀 (Cross-Meeting Knowledge)
      检索往期会议与关键结论: 4: 用户
      跨会议追踪未完成事项与待办: 4: 用户
      发现跨会议矛盾并裁定结论: 5: 用户
      开启新一轮会议闭环: 4: 用户
```

---

### 阶段一：会前进入与准备 (Pre-Meeting Phase)

#### 1. 用户目标与心理状态
- **用户目标**：快速准备开会，确认当前麦克风是否正常工作、线上会议软件（如腾讯会议）的声音是否能被录入；输入一个轻量标题（或直接留空），一键开始录制。
- **心理状态**：会议即将开始或已经开始，用户时间紧迫，极其厌恶复杂的表单和吓人的技术报错。

#### 2. 原有 UX/UI 痛点分析
1. **键盘操作心流断裂**：用户输入标题后，按下回车键（Return）无响应，必须移动鼠标去点击右上角的按钮或记忆快捷键 `⌘⇧N`。
2. **排障噪音干扰常态**：在来源选择展开后，常驻显示大面积的黄色“来源不可用时”卡片（“列表为空”、“未授权”），即使系统运行完全正常，也给用户造成“是不是出故障了”的心理恐慌。
3. **主次视觉动线模糊**：会前中央主区同时平铺了“直接开始就能记结论带”、“标题输入框”、“折叠的来源选择”和“最近会议记录库”，开会主线任务与历史回顾挤在一起。

#### 3. 优化设计
- **回车键直启会议 (Enter-to-Start)**：标题输入框接入 `.onSubmit`，并提供轻量视觉回车符号（`↵`），实现“输入即开会”的极速心流。
- **渐进式智能音频环境卡**：将来源状态收拢为“音频环境”，常态下优雅显示“🎙️ 麦克风已就绪”或“🎙️ 麦克风 + 💻 腾讯会议 (合流)”。仅在真正检测到无权限或来源异常时才以轻量提示展开出口，拒绝无谓焦虑。
- **历史记录轻量化分层**：将“会议记录库”清晰定位为“最近会议快捷回顾”，在看历史记录时提供常驻醒目的“返回新建会议”主出口。

---

### 阶段二：会中进行与实时协同 (Live In-Meeting Phase)

#### 1. 用户目标与心理状态
- **用户目标**：会议发言中，专注查看大字号实时转写与说话人区分；能够快速静音自己（如咳嗽或私聊时）或临时暂停录制；随时随地修正说话人名字；应对网络抖动或合盖休眠时心中有数。
- **心理状态**：注意力集中在会议讨论上，操作必须瞬时、确定、零干扰。

#### 2. 原有 UX/UI 痛点分析
1. **控制入口散落在四处**：
   - “暂停录制”位于状态带右侧极小按钮；
   - “静音麦克风”位于窗口顶部工具栏；
   - “结束会议”位于工具栏尾部；
   - “标注说话人”位于主内容卡片表头。
   会中高频动作层级各异，手忙脚乱。
2. **说话人行内无法重命名**：
   用户点击转写行上的说话人标签（如“说话人 1”），弹出的菜单只有“与 Speaker 2 合并”和“标记为我”，根本没有“重命名”选项！必须点表头弹出一个巨大的 Sheet 才能改名，打断了看转录的视线。
3. **回看最新提醒粗糙**：
   向上回看历史转录时，底部的“回到最新”提示条样式简陋，缺乏对新发言句数的动态感知与 macOS 26 原生精致感。

#### 3. 优化设计
- **行内说话人全功能快速菜单**：点击转写流中的任何说话人 Chip，菜单直达：
  1. `标注与重命名…`（唤起轻量改名）；
  2. `标记为「我」`；
  3. `合并到其他说话人…`。
- **高质感悬浮回看胶囊**：采用 `Surface.floatingToolbarMaterial` 与同心胶囊几何，清晰标出“有 N 句新发言”，搭配下行箭头微动效，一键平滑滚动回到底部。
- **状态带与控制流高内聚呼应**：实时状态带与工具栏按钮建立明确的联动语义映射，“录音中 / 已静音 / 已暂停”状态与图标一目了然。

---

### 阶段三：会后收尾与纪要提炼 (Post-Meeting & Synthesis Phase)

#### 1. 用户目标与心理状态
- **用户目标**：结束会议，确保刚刚会议说的每一句话都安全存盘；了解纪要生成进展；纪要出来后，快速审阅核心决议、结论，核实出处，采纳满意的版本并导出。
- **心理状态**：会议刚结束，期望快速交割会议成果，最担心大模型生成失败导致转写丢失，或长时等待不知所措。

#### 2. 原有 UX/UI 痛点分析
1. **整理中（Processing）黑盒等待焦虑**：
   结束会议后，界面仍然显示“实时记录”卡片，仅在状态带留有一句文字“正在整理…”。用户无法确切知道“录音到底停了没有”、“文字存好了没有”、“还要等多久”。
2. **纪要与原文割裂**：
   会后通过 Segmented Control 切换“纪要”与“文字记录”，无法在看纪要的同时对照原文对话；遇到“需复核”标记时，用户很难定位到原文。
3. **缺少“开启新会议”闭环出口**：
   会后归档后，用户看完了纪要，想开始下一场会议，界面上竟然没有“开启新会议”按钮，只能手动刷新或去侧边栏重新点。

#### 3. 优化设计
- **结构化会议整理中专属界面 (Processing State View)**：
  明确展示：“文字记录已全部安全落库（N 段对话已定稿，0 丢损）”；“大模型正在梳理对话脉络并生成结构化纪要…”；随时提供“先导出文字记录…”和“停止整理”，给用户 100% 的确定感。
- **纪要全功能生产力工具栏**：
  - 自动渲染 Markdown 样式（粗体、列表项与结构化排版），告别无排版纯文本；
  - 表头集成“复制全文”按钮（点击变对勾并提供 2.5 秒状态提示）与实时字数统计，极大提升分发流转效率；
- **文字记录双向搜索与发言人过滤**：
  在“文字记录”页签提供紧凑搜索条（`.speechRailSingleLineInput(.compact)`），支持按正文关键词与发言人名字实时筛选，快速查验承诺与事实；
- **纪要多版本与采纳视觉增强**：
  在右栏清晰呈现各版本的状态（当前采用、最新生成、需复核），“采用此版”使用系统原生边框按钮高亮可达，采纳后给出即时反馈；
- **会后开启新会议主动作**：
  归档态在页头显著位置提供“开启新会议”动作，一键重置当前视图回到会前准备态，实现完美生命周期闭环。

---

### 阶段四：跨会议知识库沉淀 (Knowledge & Cross-Meeting Phase)

#### 1. 用户目标与心理状态
- **用户目标**：长期追踪项目未完成事项（Action Items）；跨会议检索谁在什么时候做了什么承诺；如果两个会议出现矛盾结论，明确裁定哪一条作数。
- **心理状态**：办公复盘、项目管理与深度回顾，需要高确定性与高信息密度。

#### 2. 原有 UX/UI 痛点分析
1. **未完成事项与冲突面板入口隐藏过深**：
   位于知识库顶部的微小链接，很多用户并不知道 SpeechRail 具备追踪跨会议 Action Items 和自动发现冲突的强大能力。
2. **单场回看与全库浏览逻辑割裂**：
   主界面回看单场会议与打开全量知识库 Sheet 之间心智模型不一致。

#### 3. 优化设计
- 强化会前、会中、会后与知识库之间的统一契约；
- 在会前与会后显式暴露未完成事项与知识库入口；
- 保持单场回看具备明确的“返回当前会议”锚点。

## 3. 设计 Token 与组件契约规范 (Design Token Alignment)

所有优化组件严格遵循 `SpeechRailDesignTokens.swift`：
- **布局间距**：外围采用 `Spacing.gutter` (20pt)，卡片内边距采用 `Spacing.md` (16pt)，紧凑元组采用 `Spacing.sm` (12pt)。
- **同心几何**：容器采用 `Corner.containerShape` (12pt)，可交互卡片与控件采用 `Corner.controlShape` (8pt)，微型胶囊与标签采用 `Corner.compactShape` (4pt)。
- **表面系统**：编辑槽采用 `.speechRailSingleLineInput()`，浮动控件采用 `Surface.floatingToolbarMaterial`，无多余外描边与视觉杂音。
- **辅助功能**：全交互动作具备清晰语义的 `accessibilityLabel` 与快捷键，动效在 `reduceMotion` 下干净降级。

## 4. 实测体验问题闭环记录 (Live Experience Issue Resolution)

针对 2026-10 实测运行暴露的关键痛点，已完成以下闭环修复与验证：

1. **状态带降噪与渐进披露**：剔除常态下无差别倾倒的 6 轴 `就绪/采集/识别/保存/索引/审阅：正常` 及防御性电平免责文案；常态仅保留核心三要素（`正在录音 · 时长`、`拾音源`、`已记录段数`），仅在真正故障/降级时渐进展示告警项。
2. **转录流说话人视觉闭环**：当单句尚未聚类出说话人标签时，以轻量语义胶囊（`[+ 未指定]`）补齐 96pt 视觉断层，并支持行内直达指定归属或改名，彻底解决用户“分人功能没有启用吗”的认知迷茫。
3. **右栏信息架构与严谨人话**：修复“说话人”双重同名字段 Bug，区分“发言人数”（暂未区分 / N 位）与“发言人区分”（实时识别中 / 声纹降级）；会中“整理”明确为“会后自动提炼”；隐藏底层 `sessions.sqlite3` 物理文件名。
4. **会中私聊助手重塑**：将“内心 OS”命名对齐为“会中私聊 / 私密助手”，全面清理草稿病句，明确“私下提问 · 仅你可见 · 答案不入会议公频”。
