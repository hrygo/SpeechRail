# SpeechRail 提词器：按用户旅程优化的详细可执行方案

- 方案日期：2026-10-03
- 分析仓库：`hrygo/SpeechRail`
- 固定代码基线：`main` / `be75055cc0a5f7f044ae56c955896812a1d69915`
- 交付类型：只读分析与实施设计；不包含源码修改、Issue、PR、测试执行、模型调用或运行态变更。
- 证据范围：GitHub 连接器读取的关键实现、相关测试、Realtime 契约与 active 开发文档。原生 Git 因 DNS 失败，未取得本地完整 clone；未进行 macOS 实机视觉检查或真人音频测量。
- 阅读约定：**已确认实现**是读到的代码行为；**静态风险**是可由代码路径推导、但尚未运行复现的风险；**新增建议**是目标设计，不表示当前缺陷。文中的性能数值均为建议验收目标，不是现有测量结果。

## 0. 决策摘要

**把提词器做成“打开就能讲、AI 不添乱、跟丢能接管、下次能接着用”的本地阅读工具，而不是需要先完成 AI 加工流程的内容工作流。**

当前实现已经有较完整的基础：手动优先的独立舞台、可选语音跟随、候选版本确认、来源范围、数字归一化、人工读法、资源生命周期和确定性回放。最有价值的方向不是换一套框架，而是让这些能力沿同一条用户旅程一致工作。[S01][S02][S05][S07]

建议依次交付三个结果：

1. **保住用户的内容和控制权**：检查首次即启草稿的持久化闭环；修正稳定前缀截断换算；区分 final 的同位确认与向后重读；给空 final 明确的未确认结果。
2. **让默认路径更短、更易理解**：原稿开台成为主动作；AI 整理可选；段落审核轻量可撤销；试读与正式上台分离；舞台的状态、焦点和恢复动作语义统一。
3. **用真实阅读质量指导算法**：保留有界确定性匹配；以错误跳转、用户纠正性接管、恢复成功和端到端延迟共同评价，不能只追求更快滚动或更低 WER。

不建议本轮增加：主题生成器、多 Agent 改稿链、录音录像编辑器、自动演讲评分、云端稿件同步、全局裸按键、默认开启语音或 LLM 实时控制游标。

| 假事件测试、回放 CLI、脱敏延迟统计 | FollowControllerTests、Package、active 文档 | 扩展真实场景和指标口径，不再建第二个评测工具 |

### 1.2 优先处理的源码发现

| 编号 | 发现 | 证据等级 | 用户影响 | 优先级 |
|---|---|---|---|---|
| F01 | 初始即启页将“新建并整理”设为 primary，并占用 `⌘⏎`；直接用原稿是 secondary | 已确认实现 [S02] | 与手动优先定位不一致，容易让首次用户认为 AI 是必经步骤 | P1 |
| F02 | 即启页使用 `@State quickDraftText`，编辑器直接绑定；已读路径在提交后才创建文档 | 静态持久化风险 [S02] | 首次未提交输入离开视图、异常退出后的恢复需要单独核实，不能用“已有稿件自动保存”证明安全 | P0 验证；复现后修复 |
| F03 | `receiveSnapshot` 对文本做 `suffix(2048)` 后，用 `min(stablePrefix, retainedScalarCount)` 计算稳定部分 | 已确认坐标换算问题；未运行回归 [S04] | 稳定部分可能被扩大，把仍会修订的尾部当成稳定文本使用 | P0 |
| F04 | `mayConfirm` 将“不在 viewport 前方”的所有 final 都走 `≥0.95 / ≥6 matches`，包括与 viewport 相等的 final | 已确认分支；结果待回归验证 [S04] | 短句已被 partial 推进后，同一句 final 可能不能提交已确认位置 | P0 |
| F05 | 空 final 清掉 partial/candidate 后直接返回；reducer 没有显式产生“本句未确认”结果 | 已确认 reducer 行为；端到端展示待验证 [S04][S08] | 可能保留试探位置却继续呈现已跟上，用户难以判断是否可靠 | P0 |
| F06 | 稳定前缀的 `nil` 与显式 `0` 均进入整段文本匹配分支 | 已确认实现；策略需明确 [S04] | “未提供证据”与“明确没有稳定部分”无法在推进策略中区分；不是说所有 partial 都必须等 final | P1 |
| F07 | `跟读咬合`、`自由发挥中` 等文案由 reducer 映射，测试锁定了这些字符串 | 已确认实现 [S04][S09] | 内部术语难懂；“没匹配上”不等于系统知道用户在自由发挥 | P1 |
| F08 | 已有数字和读法规则有明确保守边界；别名替换显示 token，而不是同时追加两个版本 | 已确认实现 [S05] | 应补场景测试与准确说明，不宜以全局拼音/数字替换追求表面命中率 | P1 |
| F09 | 舞台正文容器根据采集/错误状态条件挂载辅助内容 | 已确认视图结构；是否造成跳位待实机验证 [S06] | 需要证明语音启停、错误出现不改变当前阅读行的位置 | P1 验证 |

F03 的具体反例：原始文本 3000 个 Unicode scalar，保留末尾 2048 个，丢弃前 952 个；原始稳定前缀长度 1500。在保留文本中稳定部分应为 **548**，而当前 `min(1500, 2048)` 得到 **1500**。多出的 952 个 scalar 不属于已证明稳定的范围。这是坐标问题，不是调低匹配阈值能解决的问题。

## 2. 产品定位与用户旅程

### 2.1 主要场景

- **镜头口播、直播**：稿子已准备好，临时上台；会停顿、回答问题、改说一句，不能被滚动拖着走。
- **汇报、教学、讲台阅读**：篇幅更长、专有名词与数字更多；需要定位段落、清楚看下一句，并在中断后恢复。
- **反复录制**：同一稿多次起讲；需要保留位置和显示设置，而不是每次重新配置。

这里按场景组织入口和默认设置，不新增“专业版 / 新手版 / 直播版”等平行产品分支。

### 2.2 主路径与可选路径

```text
进入提词器
   ↓
粘贴 / 导入 / 继续上次稿件
   ↓
本地保存原稿 ────────────────────────┐
   │                                 │
   │ 可选：整理朗读稿                  │ 主路径：直接开台
   ↓                                 │
查看完整候选 → 少量修改 → 采用          │
   └─────────────────────────────────┤
                                     ↓
                         可选：调整显示 / 试读
                                     ↓
                             手动提词舞台
                                     │
                         用户显式开启语音辅助
                                     ↓
                       跟读 / 停顿保位 / 临时脱稿
                                     │
                 手动接管 ← 跟丢、重读或主动定位
                     │               │
                     └──显式恢复语音──┘
                                     ↓
                   用户关闭 → 保存位置 → 下次继续
```

**不做强制向导。** 上图是能力依赖，不是要求用户逐页完成的六步表单。已有可读稿件时，一次明确动作就应能打开手动舞台。试读、AI 和显示调整都不能成为手动阅读的前置条件。

## 3. 阶段一：进入与准备原稿

### 3.1 UX 与 UI

首次工作台保留现在的直接输入区，但调整视觉层级：

| 元素 | 目标表达 | 行为 |
|---|---|---|
| 主按钮 | **打开提词器** | 创建/保存稿件并使用当前可读版本；不触发 LLM、麦克风或 ASR |
| 次按钮 | 整理朗读稿 | 显式进入 AI 路径；首次或数据接收方变化时说明外发内容 |
| 文件入口 | 导入 TXT / Markdown | 支持格式直说，不暗示当前支持原生 PDF/PPT |
| 最近稿件 | 继续《稿名》 | 展示上次位置；恢复手动态，不恢复麦克风 |
| 示例内容 | 试用示例 | 放低优先级；有未保存输入时先保护输入，不能覆盖即启草稿 |
| 保存状态 | 已保存 / 保存中 / 未保存 | 只根据真实持久化结果更新；失败提供重试与复制 |

首次页与已有稿件页使用同一套动作顺序。`⌘⏎` 建议在可编辑原稿阶段对应“打开提词器”；在候选采用阶段只对应“用这份稿”，同一相位只注册一个入口。AI 不再因快捷键而成为默认必经步骤。

### 3.2 即启草稿的持久化闭环

实现之前先验证 F02，禁止直接假设所有首次输入一定会丢失。建议方案：

1. 第一次出现非空有效输入时建立可恢复的本地草稿身份，而不是等点击整理才创建。
2. 编辑缓存可以仍在 View 中，但持久化身份与 dirty 状态归 `TeleprompterSession` / 既有 Store 所有；避免 View 一销毁就没有恢复入口。
3. 防抖保存可从 400–800 ms 的实验区间选取；失焦、切稿、开台等用户操作前显式提交待保存内容。不能把防抖当作原子事务。
4. 保存失败保留内存内容、错误态和可执行的“复制原稿”；重试成功才清掉失败态。
5. 示例加载、剪贴板创建与导入都走相同的安全边界。发生失败不能清空当前编辑内容。
6. 未保存内容恢复策略与正常文档统一，不新增不可管理的多个隐藏缓存目录。涉及持久化格式变化时保留可恢复迁移路径。

**验收**：首次输入后切换页面、正常退出再进入，内容可恢复；强制结束进程的测试另行授权，只要求恢复“最后已确认落盘”的修订，不宣传绝对零字丢失；磁盘写失败时复制可用；加载示例前的草稿仍可找回。

## 4. 阶段二：AI 整理与确认

### 4.1 保留一个加工动作

当前只有“整理成适合口语播报的稿”这一主操作，应保留。不要增设“润色 / 改写 / 智能压缩 / 深度优化 / 再润色”五个相近按钮；这会增加等待、校验和版本理解成本。[S03]

目标是交出完整可读候选，而不是让用户逐句做来源映射。默认界面只呈现：完整朗读稿、每段“照念 / 仅提示 / 跳过”状态、必要的内容风险提示和一次整体采用。

### 4.2 提升结果可信度，而不是堆提示词

现有 grouping/rewrite schema 与来源保留作为主干，在其上补齐下列闭环：

```text
不可变原稿修订
 → 本地分单元和保护事实
 → grouping 只分配连续来源
 → 程序分配 block_id
 → rewrite 生成候选正文与段落用途
 → 结构/来源/事实/完整性校验
 → 失败窗口保留原文
 → 组装候选修订
 → 用户整体采用
```

| 校验层 | 必须检查 | 失败行为 |
|---|---|---|
| 结构 | schema、重复键、未知字段、重复或缺失 block_id | 拒收该结果；可恢复窗口用原文，不把回退计作 AI 成功 |
| 来源 | 覆盖、顺序、越界、重复、源修订是否变化 | 不推测来源；旧任务不得覆盖新稿 |
| 硬事实 | 数值、单位、金额、日期、版本号、URL、否定与限定条件 | 数值/单位用确定性规则；语义限定变化先提示复核，不声称规则能证明语义等价 |
| 可朗读性 | 模板残留、指令泄露、空段、重复开场、过长单句 | 有界修复或原文保留；不能为了整齐删除关键内容 |
| 跨窗口一致性 | 人称、术语、重复承接、结尾遗漏 | 只对检测到的接缝做局部修复，不默认再让模型重写全文 |

改造时先核对既有 `protected_literals` 与验证器覆盖，复用已有保护体系；以上不是要求把全部校验重写一次。规则检查通过也不能显示“事实已核实”，最多表述“未发现数值等受保护内容变化；请确认全文”。

### 4.3 候选审核界面

默认单栏完整朗读稿，原文对照按段展开；宽窗口可以并排，但不强制所有用户面对密集 diff。

段落用途建议由“点击即轮换”改为显式小菜单：`照念 / 仅提示 / 跳过`。当前用途保持可见，修改后提供撤销。不能为了减少一次点击而让误触直接跳过关键业务内容。被标为提示/跳过的段落在准备页保留正文和来源入口。

对于硬事实变化，定位到具体段落与字段，提供“保留原句”，不要只显示红色总数。正文手改、段落用途修改、采用、存储写入属于同一修订事务；保存失败候选仍在、采用仍可重试。

### 4.4 时长策略

复用已有 TimingPolicy 与试读校准来源。不要为了凑目标时长让模型编故事、填充内容或删除承诺边界。

- 未校准显示“约 N 分钟，未试读校准”，或在不确定性过大时直说“暂无法可靠估计”。
- 目标时长只是用户约束，不是精确完成时间保证。
- 整理后超出时长时，提供查看长段/自行删减的入口；自动压缩只在未来单独授权的明确产品决策中考虑。
- 校准可以复用，但必须记录来源、语言与稿件条件；不能拿一次短句试读为所有场景提供伪精确估计。

### 4.5 等待与失败

进度展示“正在整理第 i/n 部分”；未知剩余时间不伪造百分比或倒计时。取消后保留原稿和已验证候选，并清晰说明哪些是原文保留。

错误必须从真实原因映射：网络不可达、认证失败、限流、响应不合规、校验未通过、用户取消、保存失败分别处理。没有 HTTP/错误码证据时，不能声称“最常见原因是请求过于频繁”。

云端整理与本地 ASR 的数据流分开说明。授权记忆应绑定接收方与用途；复核现有 acknowledgment key 是否覆盖路由变化，不能把“同意向 A 发送原稿”默认为同意向 B 发送另一类数据。

## 5. 阶段三：试读与上台准备

### 5.1 两种试读，不能互相冒充

已有手动计时与语音辅助试读，应统一入口而不是新增第三个“智能预检”窗口。[S01]

| 检查 | 能证明 | 不能证明 |
|---|---|---|
| 手动计时试读 | 用户所选片段的读完时间 | 麦克风、ASR 或定位可用 |
| 麦克风有电平 | 采集到了声音 | 声音被正确识别、来自演讲者或定位正确 |
| ASR 返回文字 | 识别链路当时有产出 | 当前稿件位置正确 |
| 试读匹配位置 | 当前样本下定位链路有效 | 全天候、所有数字/口音/长时稳定 |

试读卡默认显示一个简单结论，并能展开“麦克风 / 识别 / 定位”三个阶段。失败时按链路给一个下一步动作；任何语音失败都不能封锁“手动提词”。

### 5.2 设置不抢主任务

继续使用“镜头口播 / 讲台阅读 / 自定义”，保留现在的正文列宽、字号、行数预设。设置页第一层只放场景、字号、显示行数；镜像、行距、透明度和始终显示控制在“显示设置”中。

已有 680pt/820pt 预设作为基线，不凭空换成另一套尺寸；实际可读性在用户的 Apple Silicon Mac 与外接显示器上验证。标题、按钮、错误、辅助文本沿用 `SpeechRailDesignTokens`，不引入网页式 44px 通用触控规范。

### 5.3 开台语义

- “打开提词器”只打开舞台，默认手动态。
- “开启语音跟随”才申请麦克风和会话占用。
- 切稿被禁止时明确提示“提词窗口正在使用这份稿，关闭后即可编辑/切换”，不要只置灰。
- 台前不弹模型配置向导；无法开启语音时保留可读正文和手动控制。
- 不接管其他功能的麦克风租约；资源忙时告诉用户由其他功能占用，并允许继续手动。

## 6. 阶段四：正式提词的 UI 与交互

### 6.1 信息层级

**第一层是台词，第二层是控制权，第三层才是诊断。**

正常阅读只需当前行、前后文和极少辅助信息。沿用现有一至三行布局；三行模式当前行的视觉位置在稿首稿尾不改变。镜像已存在，不重复开发；确认镜像不会把操作含义和键盘方向一并颠倒。

状态与动作分开：系统“正在找位置”不意味着用户必须等待；手动上下行和关闭始终可达。

### 6.2 文案表

| 内部情况 | 面向用户文案 | 不应表达 |
|---|---|---|
| 手动态 | 手动提词 | AI 未就绪、错误 |
| 已获授权、实际采集中但尚未识别 | 麦克风使用中 · 请开始朗读 | 已识别、已跟上 |
| 已有识别但位置不明确 | 正在定位，位置已保持 | 自由发挥中、你读错了 |
| 有当前有效定位证据 | 语音跟随中 | 跟读咬合、置信度 72% |
| 用户手动接管 | 已切到手动 | 暂时自动恢复中 |
| 资源停止失败 | 麦克风尚未确认关闭 · 重试关闭 | 已关闭、等待几秒自动消失 |
| 网络/ASR 暂不可用 | 语音暂不可用，仍可手动提词 | 整个功能不可用 |

纯相似度没有校准为概率，不能将 `confidence=0.72` 显示成“有 72% 把握”。只有能由事实区分的状态才输出确定文案。

### 6.3 几何与动效约束

读取位置使用稿件坐标，不使用旧屏幕行号。字体、列宽、窗口变化后重算显示行，并将同一稿件位置映射到新布局。

对 F09 做几何验收：语音启停、麦克风角标、错误展示、控制条显隐都不能改变当前行的基线。确有跳位时，将临时状态放入固定预留槽或覆盖层，不能用扩大窗口来遮掩。

控制显隐复用现有 InteractionPolicy；鼠标、键盘焦点、菜单、VoiceOver 和“始终显示”都必须可达。减少动态效果开启时停止位移动画，但仍更新阅读位置。Apple 对焦点、键盘和 Reduce Motion 的指导是验证依据，不是新增另一个视觉框架。[E01][E02][E03]

### 6.4 键盘与误触

保留现有手动上下行、Home/End、Esc 与菜单语音快捷键。设置弹层/文本输入获得焦点时，阅读快捷键不得穿透。关闭弹层后只在用户当前仍处于舞台操作路径时恢复阅读焦点，不在 ASR 回调时抢焦点。

新增快捷键前先检查应用菜单和平台冲突。不能将空格改为“自动开麦”，也不能通过手动定位后偷偷重连来让按钮显得更少。

## 7. 阶段五：跟读算法与状态一致性

### 7.1 保留现有主干

已有 Aligner 使用有界窗口、半全局编辑距离、竞争位置差值与近锚连续性；FollowController 管理试探推进、final 确认、重读与人工接管。这比把实时滚动交给 LLM 更容易控制和回放。[S04][S05]

当前默认参数例如匹配阈值 0.72、竞争差 0.12、lookBehind 80 tokens、lookAhead 320 tokens、局部推进半径 24 tokens，是**现有基线**，不是本方案认证的最优值。先修语义与坐标，再用分场景回放调整；不要靠同时放宽多个阈值“让它终于动起来”。

### 7.2 四种位置/状态各司其职

复用已存在的字段，不新建平行布尔状态：

| 概念 | 既有入口 | 应承担的责任 |
|---|---|---|
| 候选位置 | `candidatePosition / hypothesisPosition` | 最新语音可能对应的位置；不等于已确认 |
| 已确认位置 | `committedPosition` | 通过确认规则的位置，用于可信进度 |
| 视口锚点 | `viewportAnchor` | 用户当前看到的位置；允许有界试探但不得无证据跳回 |
| 语音控制权 | `TeleprompterVoiceAssistLifecycle.generation/state` | 只有当前 generation 的合法事件能影响跟随 |

用户显式定位可以作为新的权威位置；不要把系统试探位置与用户选择混为一谈。关闭/恢复保存时要明确保存的是用户阅读锚点还是确认进度，不能同一个字段在不同页面承担两种语义。

### 7.3 修正稳定前缀换算（F03）

`stable_prefix_codepoints` 是原始快照的 Unicode scalar 数。`String.suffix(2048)` 按 Swift Character 截取；截断后要重新计算丢弃的 scalar 数。

```text
rawCount      = rawText.unicodeScalars.count
retainedText  = rawText.suffix(characterLimit)
retainedCount = retainedText.unicodeScalars.count
droppedCount  = rawCount - retainedCount

前提：0 ≤ stablePrefix ≤ rawCount
stableInRetained = clamp(stablePrefix - droppedCount, 0, retainedCount)
```

先验证原始前缀合法，再做截断映射；不能用 retained 长度判定原始前缀越界，也不能直接 `min` 代替坐标平移。

证据分三类：

- `nil`：上游未提供稳定性证明；进入未知稳定性的试探策略。
- `0`：明确当前没有已证明稳定部分；允许计算候选，但不能将其当稳定文本。
- `>0`：只能将换算后的稳定部分当作稳定证据。

试探不必全部等 final：可在同一读行/短距离内进行受限预览，但跨段、向后或远距离移动要更强证据。更新到下一 revision 时，检查同一原文坐标系中已声明稳定的前缀是否被改写；如果上游采用移动窗口，必须先依据明确的偏移/epoch 语义换算，不能比较不同坐标原点。

### 7.4 区分同位确认、前进与重读（F04）

现在 `mayConfirm` 把“相等”也归入强重读门槛。应拆为三个分支：

1. **final 与同 item 的试探位置相等**：这是确认，不是重读。若当前 generation、item 顺序、版本身份与匹配证据都合法，更新 committed，不要求满足专门的向后重读 token 数。
2. **final 在视口前方**：沿用有界前进规则，不能因为是 final 就放开远距离跳跃。
3. **final 在视口后方**：区分修订纠错与真正重读。保留高置信、足够长度、近距和唯一性要求；不因长稿出现一句重复口号就跳回前文。

必须加入短句复现：稿件“欢迎来到今天的直播”，同 item 的 snapshot “欢迎”先产生试探位置，再 final “欢迎”；预期 committed 能确认同位，viewport 不重复移动。相同用例与迟到的旧 item、手动接管、跨版本情况组合，不能修一个问题放开陈旧事件。

### 7.5 空 final 与证据变化（F05）

有语音假设后收到空 final，不得将其等同于“用户没说话”。这也是当前 Realtime 契约的明确边界。[S08]

建议让 reducer 输出可观察的原因，而不只看位置是否变化：

```text
decision:
  candidateChanged
  viewportAdvanced
  committedConfirmed
  evidenceInsufficient
  finalUnconfirmed
  manualAuthorityPreserved
  staleEventIgnored
  transportUnavailable
```

这是建议增加的决策表达，可由现有适配器承接；不必制造一个新的应用级事件总线。

空 final：保持用户当前视图，不突然后退；本次试探不升级为 committed；标记未确认并等待后续定位或人工操作。没有暴露逐字 ASR 的舞台，也要避免继续把旧状态当作新确认。Adapter 的返回值和诊断不能只以 viewport 有没有变化判定“对齐成功”。

### 7.6 重复句、数字与混合语言

继续采用多证据决策，而不是“一次字符串相似度决定跳转”：

| 场景 | 默认策略 | 恢复条件 |
|---|---|---|
| 连续正常朗读 | 局部有界推进 | 近锚、连续、唯一的证据 |
| 重复口号/段首套话 | 保持或仅试探，不远跳 | 后续区分词、上下文或人工定位 |
| 读错一个数字/单位 | 不把冲突数字当强锚点；不弹窗训导用户 | 后续可靠非冲突语境重新定位 |
| 短暂脱稿或观众提问 | 保持位置，不能断言一定是用户自由发挥 | 当前授权仍有效且出现唯一的回稿证据 |
| 用户向前/向后手动定位 | 立即手动接管 | 用户显式重新开启语音 |
| 强证据近距离重读 | 有界回退 | 足够长度、稳定/终态证据、局部唯一性 |
| 含英文缩写/专有名词 | 复用原稿范围绑定的已确认读法 | 禁止全文盲目拼音替换 |

数字等价与事实保护应共用语义规则，但输出职责不同：匹配层可识别“3.5 秒 / 三点五秒”等值，整理层不能因此允许把“3.5 秒”改成“35 秒”。百分比、负号、小数点、量纲、版本号、序号与时间必须有反例集合。

已确认读法现为替换 token 路径。若未来需要用户在原文读法和别名间自由切换，可试验**局部有界的两条候选路径**，分别评分；不把两种 token 顺序拼接成更长脚本，也不全局替换输入。此项放 P2，不能抢占坐标和生命周期修复。

### 7.7 性能与线程

先测量，不先重构。当前 DP 输入上限与脚本窗口本身有界；更换 GPU 算法或增加模型通常不是第一步。[S05]

优先观测：音频采集到发送、入站事件队列年龄、归一化/匹配耗时、决策到显示的延迟。当前队列/匹配/采集统计可以扩展，不能当作完整的端到端延迟。[S04]

只有证据表明有瓶颈时再实施：

- 以稿件 revision 缓存 canonical script，避免每事件全文构建；检查当前 `scriptSegments` 比较与 token anchor 线性查找的实际代价。
- 使用可索引的 token 原文位置，必要时二分找锚点。
- 同 item 的可修订 snapshot 可在校验 wire sequence 后合并为最新 revision；final、失败、手动事件和生命周期事件不合并、不丢弃。
- 如移出 MainActor，任务必须携带 generation + version + revision，提交时再次验证；旧任务即使完成也不能改变视图。
- 不积压逐字动画；显示刷新可以合并，但不能伪造尚未识别的前进位置。

## 8. 阶段六：异常恢复与控制权

### 8.1 用用户动作定义恢复，不用技术状态堆按钮

| 失败 | 立即行为 | 可见动作 | 禁止 |
|---|---|---|---|
| AI 网络/限流失败 | 原稿仍可读，候选保留有效部分 | 直接开台 / 重试整理 | 让原稿开台一起不可用 |
| 麦克风拒绝或设备失效 | 降级手动，说明具体链路 | 手动提词 / 检查输入设备 | 显示 ASR 未就绪掩盖设备问题 |
| ASR 断开 | 冻结语音推进权并清理自有资源 | 手动提词 / 重试语音 | 后台旧回包重启跟读 |
| 跟读位置不明确 | 原位保持，不抢焦点 | 手动上下行 / 从所选句开始 | 用无依据的大跳跃掩盖不确定 |
| 用户手动滚动/点选 | 同步换 generation，切手动 | 回到朗读位置 / 开启语音 | “回到朗读位置”顺便开麦 |
| 停止资源失败 | 保持真实占用提示 | 重试关闭 | 用 4 秒提示消失伪装释放成功 |
| 保存失败 | 保留内存原稿/候选/恢复入口 | 重试保存 / 复制稿件 | 清掉唯一可恢复内容或错误态 |

### 8.2 保留现有生命周期状态机

`off → starting → following → stopping → off/pausedByUser` 和 `stopFailed/unavailable` 已存在。[S07]

改造重点不是另写一套状态机，而是补齐界面、coordinator 与 adapter 的一致性验证：

- 人工接管先撤权，再异步释放资源，不能等待网络关闭才停止推进。
- `stopFailed` 不被呈现为 off；仍能关闭舞台并保留资源失败提示/恢复入口。
- 关闭只释放提词器的资源，不终止其他会话或服务。
- 重试使用新的 generation；失败任务不能覆盖后来成功的新会话。
- 复用既有输入完成屏障，不把收到一个旧 final 当作所有已发送 PCM 均已完成。

## 9. 阶段七：关闭、继续与可选复盘

不在读到末行时自动结束、弹总结或关闭舞台；用户在直播中可能继续说话、重录结尾或回答问题。保持现有产品边界。[S01]

正常关闭后保存所用稿件版本、用户阅读位置、显示设置和保存结果。下次提供“继续上次位置 / 从头开始”，恢复手动态，绝不自动恢复麦克风或 ASR。

复盘是工作台里的可选入口，不是台上流程必经页。第一阶段只给有证据的信息：本次使用时长、纠正性接管次数、未确认 final 数、重试/断开次数，以及有明确样本数的延迟统计。没有证据不输出“流畅度 95 分”“表达感染力”“你已经读完 98%”等评价。

原始音频与全文转写默认不留存。若开展真人质量评测，另行明确授权，素材放仓库外，说明保留期限、访问者和删除方式。诊断导出默认仅包含版本、错误码、计数、时间和聚合值；稿件正文、完整 prompt、API key 和绝对私有路径不进入遥测。

## 10. UI 交付规格

### 10.1 三个主界面，不增加庞大导航

| 界面 | 主任务 | 默认可见 | 渐进披露 |
|---|---|---|---|
| 准备工作台 | 准备可讲的稿 | 当前稿、原文编辑、保存状态、开台、可选整理 | 导出、来源、术语/读法、时长详情 |
| 整理候选 | 读一遍并决定采用 | 完整候选、段落用途、少量风险、采用/放弃 | 原文对照、结构编辑、AI 诊断 |
| 提词舞台 | 看下一句并掌控进度 | 正文、必要采集/错误状态 | 控制条、全稿、显示设置 |

试读使用已有 sheet；恢复主要在原界面完成。不要加“诊断首页”挡在开台前。

### 10.2 设计 Token 与组件约束

颜色、字号、间距、圆角、列宽、动效和辅助条槽位都复用 `SpeechRailDesignTokens.Teleprompter` 和现有共享组件。新增值必须集中声明并同步 `docs/developers/macos-app-design-system.md`。

保持正文与操作层的层级；不把每个段落变成多重玻璃卡片。关键状态同时使用文字与图标，不仅依赖绿/黄/红；高对比度和 Reduce Motion 不应丢失信息。

**必须交付的设计状态清单**：空稿、未保存、保存失败、普通稿、整理中、局部回退、候选、采用失败、手动舞台、语音启动、识别待定位、跟随、手动接管、停止失败、只剩末行、重开上次稿。只画三个理想态页面不足以开发。

本轮不包含实际设计图或实机截图；上述是后续设计/开发应覆盖的状态规格。

### 13.2 跟读与协议

| 编号 | 输入/事件序列 | 预期不变量 |

| A01 | raw=3000 scalars，retain=2048，stable=1500 | stableInRetained=548 |
| A02 | stable=0 / nil / 超界 / 负数 | 四类证据与异常分开；不把非法证据降成更宽松策略 |

| A07 | 同坐标稳定前缀在新 revision 被改写 | 异常可见，暂停稳定性驱动推进 |
| A08 | 新 item 已 final，旧 item 迟到 final | 不能改写新状态 |

| A12 | 短距离真正重读与远距离引用旧句 | 前者符合门槛可恢复，后者不自动拉回 |
| A13 | 3.5 秒/三点五秒、50%/百分之五十 | 合法等价保留原文坐标 |
| A14 | 3.5→35、万元→亿元、负号/否定丢失 | 不作为强数值等价；不能静默通过保真校验 |
| A15 | 专有词绑定读法，随后改动原文范围 | 陈旧读法失效或需确认，不能串到另一位置 |
| A16 | 近锚单 token 与远处单 token | 明确短证据策略，不能仅凭“唯一”放开风险 |
| A17 | 事件流限速/阻塞时多次 snapshot + final | 可以合并 mutable snapshot；final 不丢、顺序合法 |

## 14. 指标、样本与候选门槛

### 14.1 不把不同指标混成“准确率”

| 指标 | 定义/分母 | 建议门槛或目标 |
|---|---|---|
| 内容安全 | 保存失败/采用失败/切稿用例中，恢复内容和版本是否一致 | P0 确定性安全用例全部满足 |
| 未授权推进 | 人工撤权后的有效位置改变次数 | 确定性用例为 0；实测观察值为 0 不等于总体风险为 0 |
| 错误跳转 | 与人工标注阅读位置不符、且超过允许试探范围的移动 | 按每 10 分钟和每 100 次推进同时报告；优先不劣于基线 |
| 纠正性接管率 | 为修正系统位置而接管的次数 / 有效跟读分钟 | 对照基线改善；主动翻页/正常看全稿不算算法失败 |
| 回稿成功率 | 有明确回稿证据的 episode 中，限定窗口内恢复的比例 | 初始目标 ≥95%，正式阈值由基线样本确认 |
| 本地事件处理延迟 | 客户端接收事件到可提交决策，不含上游 ASR | 初始 P95 ≤50 ms；不得用它代替端到端延迟 |
| 端到端跟随延迟 | 人工标注实际读到某位置到舞台显示该位置 | 连续中文目标 P95 ≤1.5 s；上游能力不足时先标注，不承诺恒定 |
| 首次可读舞台 | 已有有效原稿时，从开台操作到可手动阅读 | 初始 P95 ≤1 s；排除用户输入与系统授权等待 |
| 手动控制响应 | 用户动作到界面反馈 | 初始 P95 ≤100 ms；撤权须同步，不等待网络清理 |
| AI 可用候选率 | 无结构/来源硬失败、可整体阅读的候选 / AI 整理请求 | 先采集基线；局部原文回退单列，不混入成功 |

这些是**候选门槛，不是性能承诺**。模型、机器、输入语言、麦克风和事件粒度会改变结果。不能在本机达不到上游识别时延时，用 UI 预测滚动伪造低延迟。

### 14.2 采样设计

先跑确定性事件矩阵，再做 opt-in 真人录音与手工界面验收。建议首轮至少 5 位说话人，每人 6 个约 3 分钟场景：连续读、停顿脱稿、重读跳段、数字单位、混合语言专名、干扰/设备变化。它是起步样本，不构成对所有口音或噪声的普遍认证。

标注必须独立于系统输出：记录读者实际读到的位置、read/improvise/reRead/manualJump 意图、输入音频采样时间与预期恢复窗口。现有 replay 文档已强调标签不能挂在系统“已经追上”的时间点，否则延迟虚假为零。[S01]

同一组样本跑 baseline 和 candidate；同时保留逐场景结果、样本数、P50/P95 和失败案例。样本不足或没有成功配对时为 N/A/not_run，不报 0 ms 或 100%。失败 episode 不从成功率分母中删除；延迟仅对可测样本统计，并同时报告未恢复比例。

真实 WAV 按当前 Realtime 契约使用 24 kHz 单声道 PCM16，保存在仓库外；不要把私人录音嵌入测试 fixture。确定性 fixture 可以使用人工构造的非私人文本与事件。

## 15. 发布与回退

- 稿件数据安全优先于源码回滚方便。新增持久化字段应能恢复旧数据，保留旧文件副本或迁移事务；不得让降级版本误读后覆盖新稿。
- 行为策略以一个明确版本记录，回放报告同时写入代码 SHA、策略版本、素材版本和模型/协议身份；不要随处放隐式实验开关。
- 跟读策略灰度通过显式选择的小范围试用进行，不在演讲中切算法。
- 候选版本必须同时通过安全回归、真实质量样本和授权的 UI 验收，再考虑替换默认策略。没有实音频验收时只能声称逻辑修复，不能写“跟读质量已验证”。
- 回退不删除用户稿件、不重置整个应用偏好、不终止其他功能的会话。

## 16. 明确不做与需要单独决策的内容

**本轮不做**：新主题生成、PDF/PPT 原生导入、音视频录制、OBS 控制、云同步、多用户团队协作、演讲人格/情绪评分、默认全局快捷键、LLM 实时游标、自动结束直播。

**仅在证据与需求成立后做**：局部别名多路径匹配、语言专用分词、声学词级时间戳整合、更多文稿格式。当前文本相似度位置不是严格词级声学对齐，不能包装成精准口型同步。

PromptSmart 对停顿/即兴时停止滚动、回稿后恢复的公开产品说明可作为交互参考，但属于厂商能力描述，不是 SpeechRail 的评测成绩，也不能照搬其自动恢复到“用户已经手动撤权”的场景。[E04]

屏幕分享风险必须明确。Apple 将 `NSWindow.SharingType.none` 标为系统不再使用的旧常量，不能承诺靠它防止提词内容被采集。提示用户选摄像头或指定内容窗口，并在其实际直播软件中确认；不引入 FairPlay/DRM 作为普通提词器的解决方案。[E05]
