## 0. 决策摘要

**把语音助手优化为“打开能问、说完能接、插话真停、断声还能打字、结束不丢记录”的对话工具，而不是让用户管理一条 ASR—LLM—TTS 流水线。**

现有基础已经包括：同一个音频引擎里的采集与播放、实时对讲与一问一答、系统 voice processing、Responses 流式回复、单轮增量 TTS、播放预算、代际隔离、文字输入、记录库、人工记忆和真实编排层 fake 测试。核心方向是把这些能力连接得可靠、可理解、可恢复，而不是换框架或重复实现。[S01]～[S12]

优先顺序：

1. **控制与内容安全**：结束只作用于助手自己的会话；插话取消不阻塞接收终态；结束时收下最后一句；旧回复、旧请求、旧启动不得覆盖新状态。
2. **主旅程与信任**：首屏不虚报就绪；真实显示文字/语音模式和模型数据去向；语音失败不阻断可用的文字对话；发送、停止、重播、继续记录都有准确含义和可恢复结果。
3. **对话与朗读质量**：按输入输出模态组织提示词；保护数字、词边界和流式分包一致性；区分已经生成与已经播放；基于真实场景校准接话、插话和长对话上下文。
4. **最后优化性能**：先建立端到端时钟和失败分母，再决定是否改变采集分包、切分等待、事件调度和连接检查策略。不以降低阈值、丢内容或假装成功换取漂亮延迟。

### 1.3 三个必须先补的最小反例

**反例一：文字助手的结束必须命中自身。** 创建纯文字助手，不申请麦克风；点击页面结束。断言助手记录终结且 phase 回到 idle。再让会议占用 coordinator，创建文字助手并结束；断言会议的 occupancy、phase、记录、stopper 调用数全部不变。[S02][S10][S11]

**反例二：插话取消不能等自己的接收循环。** 正在播放 request A，经唯一事件流发送一个非空 hypothesis。fake 服务在 cancel 后立即从同一事件流返回 A 的 cancelled。必须在 deadline 之前正常收下 cancelled、保持连接可用。测试不能直接调用 coordinator.handleTerminal 来绕过生产 receive loop。[S04][S07]

**反例三：相同内容不同分包，应有相同准入结论。** 在默认单 append 上限 512 scalar、整轮上限 4096 scalar 的客户端配置下，输入同一段 600 scalar 的合成短文：一次 delta 到达，与拆成 6 个 100 scalar delta 到达，都应形成合法 TTS append，保留相同的可朗读语义；不是直接拒绝前一种。[S08] 文本选择合成数据，不使用私人正文。

## 2. 产品定位、场景与完整旅程

### 2.1 核心定位

语音助手的主要价值是低摩擦的口头问答、讨论和演练。语音输入与文字输入共用对话资产；语音输出是可控交付方式，不是“已经生成了文本就必须全部念完”。

本轮聚焦三类场景：

| 场景 | 用户需求 | 默认体验 |
|---|---|---|
| 随手提问、边工作边讨论 | 快开始、回答直达、随时插话 | 保留所选对话方式；不用每次挑角色/音色 |
| 汇报演练、方案推敲、学习问答 | 允许停顿、自我修正、回看与继续 | 不急着接话；长内容先概括，用户要求后展开 |
| 不便开口、麦克风占用、语音临时故障 | 不中断已有思路，切文字继续 | 文字路径不依赖 ASR/TTS 和麦克风；恢复语音明确触发 |

不新增三个独立产品模式，也不将“语音助手”扩张为默认联网搜索、执行电脑操作、多 Agent、知识库或常驻录音工具。

### 2.2 用户旅程

```text
进入页面
  ├─ 模型未配置 → 就地配置/检查 → 继续原来的任务
  ├─ 打字 → 创建或继续当前助手记录 → 文本回答
  └─ 开始语音 → 能力与权限检查 → 建连 → 明确显示采集中
         ↓
   发言/输入 → 确认本轮输入 → 生成回答 → 屏幕显示 + 可选朗读
         ↓                     ↘ 停止回答/插话 → 先停输出再接新问题
   语音异常 → 保住内容 → 文字继续 / 明确重试语音
         ↓
   结束本次助手 → 收下已准入尾句 → 保存结果 → 回看/导出/复用
```

“结束”“停止回答”“静音”三个动作必须独立。开始某功能与仅浏览该页面也必须独立；页面可见性不能决定设备归属。[S11]

## 3. 阶段一：首次进入、配置和开始

### 3.1 首屏信息架构

主区只保留：一句任务说明、当前模型配置结论、文字输入框、“开始语音”与“发送”两个与各自输入方式对应的动作。角色/音色/对话方式用一行摘要承载，点击后展开既有 inspector。最近记录保留一条入口；示例收成少量短提示，不用四个复杂场景卡与声学装饰占据首屏。

建议文案：“直接打字提问，或开始语音对话。”未开始时显示“麦克风未开启”；已配置但尚未检查时显示“模型已配置”，不能显示“已连接”。

**能力门禁分离**：

| 操作 | 真正前提 | 不应成为前提 |
|---|---|---|
| 发送文字 | 有效模型配置、可创建/更新当前记录 | 麦克风、ASR、TTS、音色、其他功能的设备租约 |
| 开始语音 | ASR 与所选 TTS 能力/版本有效、麦克风授权、设备可用、模型可达 | 已创建克隆音色、分人能力、用户先完成试听 |
| 明确朗读文字回答 | TTS/播放能力与授权；本轮身份有效 | 静默开启麦克风；默认停止会议 |
| 查看/复制历史 | 当前记录可读取 | 语音服务、模型在线 |

当前生产语音路径绑定 ASR+TTS 是既有边界。本轮先修文字独立可用；“只有 ASR 可用时也能语音输入、文字输出”可以作为后续小范围能力拆分，不以此阻塞核心修复。

### 3.2 模型配置与数据去向

就地配置继续复用现有 LLM 配置系统，不加第二份 endpoint/key 存储。高级页面可显示 Responses 等技术要求，主入口只说明“这个模型服务是否可用于对话”。连接检查应显示检查时间、配置版本与结果，配置变化后旧结果失效。

每次新会话确认实际解析后的 endpoint、模型、协议配置、密钥作用域、角色与记忆快照。运行中的配置变化默认**下次新对话生效**，不暗中将后续文字送到新目的地。安全相关的密钥撤销/失效可以立即阻断请求，但不能自动换备用收件方。

建议数据流说明：“语音由本机 SpeechRail 处理；对话文字与启用的记忆会发送给你配置的模型服务；对话记录保存在此 Mac。”按实际 endpoint 展示“本机地址/局域网地址/外部地址”，但不能仅凭 loopback 就承诺服务绝不代理到外部。第一次向新目的地发送历史或记忆时，明确说明范围并记录用户选择。[S03][S06][S10][E03]

### 3.3 权限与模式

打开页面不申请麦克风。用户按开始语音后再申请，拒绝后仍能打字；不要反复弹授权。模式沿用用户选择：实时对讲需要系统语音处理可用；不支持时提示“当前设备不能启用实时对讲，可改用一问一答”，不是笼统让用户重启语音服务。[S09][E06]

不要为了缩短点击次数，未经同意自动开麦、自动切音频设备、下载模型或结束另一个录音会话。也不要因耳机名称推断回声消除已经通过声学验收。

## 4. 阶段二：说话、打字与输入保真

### 4.1 输入状态必须真实

复用 AssistantSession 中已有的 text-only、mute 和生命周期事实，形成统一的展示投影，不让 View 再从 phase 单独推导采集状态。

| 实际状态 | 主文案 | 输入框/动作 |
|---|---|---|
| 尚未开始 | 麦克风未开启 | 可打字；开始语音 |
| 建连中 | 正在准备语音 | 取消准备；保留文字草稿 |
| 正在采集 | 正在聆听 | 静音；发送文字；结束 |
| 仅文字 | 文字对话 | 开启语音入口，不能把“取消静音”当成开启语音 |
| 用户静音但仍持有设备 | 麦克风已静音 | 说明暂停上传、仍有本地采集；取消静音/结束语音 |
| 语音中断，模型可用 | 语音已中断，可以继续打字 | 重试语音；发送文字 |
| 模型失败 | 这次未能回答 | 保存用户问题；重试回答/修改配置 |

现有 toggleMute 只停止上传，采集仍在，不能把“静音”表述为已经释放麦克风。若要提供“关闭语音”，必须是真正停止采集与连接后保留对话记录的独立动作，而不是换个按钮名。[S02][S04]

### 4.2 打字路径

保持“失败留稿、成功只清空仍与发送快照相同的草稿”的现有约定。补充：模板填入可撤销，不直接覆盖已输入内容；发送中的新输入不丢；中文输入法确认候选不等于发送；多行材料提供自然换行入口，快捷键与系统文本编辑习惯一致。

文字提交的事务边界是：问题保存成功→进入回复队列→UI 回执 accepted。模型稍后失败不应把问题重新插入一行。重试绑定原始 questionID，默认产生新的 reply attempt，而不是复制用户问题。

新问题到来时必须显式选择策略。建议默认“停止当前回答并处理新问题”，共用插话/停止的收尾逻辑；短时间连发可以按明确顺序排队或合并为同一用户 turn，但不能仅取消旧 Task 并覆盖 currentReply。所有入口，包括快捷提示与 ASR final-only，都走同一受控提交入口。[S02][S05]

### 4.3 语音输入与不确定内容

hypothesis 可修改，屏幕标为“正在识别”；final 才能正常触发模型。已有空 final 保留机制继续复用，显示“这一句未识别完整”，并提供“编辑后发送/重新说”，不能与助手“朗读被打断”共用一个模糊标签。[S04][S05]

数字、日期、金额、否定词、人名/项目名出现明显歧义时，优先简短确认，不让提示词一概要求模型根据上下文猜。对普通口头填充词可以宽容；对关键事实不得声称 ASR 相似度就是可信概率。服务未提供置信度或词级时间戳时保持 unknown，不在客户端编造。

## 5. 阶段三：接话、插话与取消

### 5.1 先修正控制时序

当前风险不是缺少 cancel API，而是等待终态的任务挡住终态的接收。目标实现采用**顺序事件归约 + 有所有权的异步副作用**，而不是为每个事件随意启动一个 Task。

```text
接收 hypothesis/final/用户停止动作
  → 同步校验 session/connection/input identity
  → 同步登记 interrupt intent、撤销旧回复输出权、作废旧播放 epoch
  → 接收循环继续处理后续 ACK/terminal
  → 一个有身份、可取消的 effect：等待本地停播屏障 → 发送取消 → 等待匹配 terminal
  → effect 完成结果再次校验身份 → 允许新 TTS，或关闭归属不明的连接
```

必须保留终态等待，不能为了消除等待环直接把“发送取消成功”当作远端已经空闲。已退休请求的 terminal 可以解除它自己的闩，但不能改变新回复的 phase、闭麦开关或 interrupted 状态。控制事件不能被音频背压无限阻塞；音频可以走有界队列，但顺序、预算与请求身份必须保持。[S04][S07]

### 5.2 插话证据分级

**立即实施**：空 snapshot 不触发插话；非空 partial/snapshot 与 final-only 使用同一入口；重复/旧 revision 不重复取消；手动停止总是优先且不依赖 ASR 成功。

**待真实测量后实施**：可在已处理的近端音频上增加低成本语音活动信号，用于更早降低播放音量或提示“正在听你说”。这只是可撤销的提前响应，不等于确认用户换话题。确认打断仍需结合持续近端语音、有效文本、当前输出状态等证据；背景噪声与回声不能直接作为新问题。

不要仅靠“听到的文字与当前助手回答相似”判为回声：用户也可能复述、反问或纠正同一句。更不能让语义分类器或另一个 LLM 阻塞用户点击停止的关键路径。

### 5.3 接话策略

ASR utterance final 表示一段转写结束，不必然表示人已经讲完完整意图。先测清“停顿后继续”“自我修正”“嗯/对等附和”“问题后补一句”的失败分布，再决定是否增加有界 turn aggregation。

建议按简单规则起步：同一用户输入窗口允许合并相邻 final；明确手动发送立即提交；识别正在继续时不抢答；达到最大等待必须给反馈而非无限延长。聚合等待属于新增产品策略，要记录其新增延迟与被抢话率，不自动复制云服务的 semantic_vad 字段。SpeechRail 当前契约没有实现的官方事件和参数不能假装可用。[S04][S15][E04]

## 6. 阶段四：生成回复与流式朗读

### 6.1 提示词按模态组织

保留 VoicePrompt 的集中管理和“角色只管风格”的边界；将固定字符串改为有类型的输入/输出策略，例如输入来源 `keyboard/recognizedSpeech`，输出策略 `textOnly/spokenConcise`，由本轮提交意图决定。

- 语音回复默认短、先回答核心问题，澄清一次只问一件事；用户要求详细说明时允许分段展开，而不是永远一次一步。
- 文字回复允许合适的结构、列表、代码，不套用“用户的话可能转错”或“所有答案都要朗读”的规则。
- 屏幕和记录保存原始生成文本，朗读保存独立的转换映射/状态；不得为了好念改写原始答案。
- 明确当前没有的外部能力，模型不能因“助手”称呼就声称已经查网、读取本机文件或执行操作。
- LLM 的拒绝、incomplete、空输出和中途失败需要在 provider adapter 与编排边界明确分类；本次未完整审查 provider 的所有终态分支，应在工作包中核实，不把“字符串流接口”直接等同于已经存在终态缺陷。[S06][S12]

### 6.2 分包一致性与文本预算

LLM transport delta 和 TTS append 是不同层级。限制应分别命名并执行：单个 provider 事件的防滥用预算、待处理文本预算、整轮输出预算、每次 TTS append 的服务端限额。不要用 TTS append 上限直接拒绝正常较大的 LLM delta。

`append(delta)` 在检查总预算/待处理预算后允许接收合法片段；已有 splitter 再按实际服务端单次限额切分。拒绝路径要保持状态原子性，不能超限后还把全部文本留在无界数组。计量统一 Unicode scalar，与 wire codepoint 一致；不能用 grapheme count 伪装成 codepoint。fake 客户端 ACK 也需同口径。[S07][S08][S13]

在允许预算内，同一文本不同分包应得到相同的内容完整性、符号含义和成功/失败结论；允许产生不同首音时刻，但不能一条成功、一条因为分包大而拒绝。

### 6.3 切分等待与保真

复用已有尾词、数字和 Markdown 保护。新增跨片断言：`Hel`+`lo`、`3.`+`5`、`12`+`万元`、URL/邮箱、版本号、负号、百分比、中文顿号列表、未闭合代码块。

当前 deadline/forced 策略允许降低断点质量；不要把“等得够久”解释成“数字已经完整”。优化为：优先提交确定完成的前缀；对敏感的未完成 token 有界保留；超过更高一级等待/长度预算，明确结束这一轮朗读或提示“请查看文字”，不能编造补全或改变数量含义。该策略只在对照实验显示收益后替换默认，避免通过无上限等待解决保真。

清洗器应保留跨片词边界，不能分别 trim 后把两个英文词粘接；代码/长链接可显示全文，但朗读使用预先定义的安全呈现规则，例如“代码见屏幕”，不私自执行、不另调 LLM 改写事实。规则及跳读提示必须可追溯到原文范围。[S08][S12]

### 6.4 播放完成、内容完成与用户已听见

至少区分：`生成中/生成完整/生成中断`，`待播/播放中/播放被停止/播放失败/播放完成`，`未保存/已保存/保存失败`。这是现有 reply/ledger 的事实投影，不要求建立三个彼此竞争的总状态机。

当前 `.dataRendered` 只表示播放器渲染，不包含其后的信号处理延迟；`.dataPlayedBack` 才考虑下游处理和设备播放延迟。建议对输出进度使用准确命名，并评估以 dataPlayedBack 作为“已播放”证据；播放预算继续使用哪一个回调，要根据延迟、背压与取消测试明确设计，不能无审查地替换所有回调。[S09][E01][E02]

任何回调都不能证明用户真正听懂，也无法证明耳机确实戴在耳朵上。没有可靠的文本—音频对齐时，不按“播放帧数占比”截取同占比字符来伪造已读文本。原始完整回答留在记录中，标注“朗读未完成”；向下一轮模型传递交付状态，避免假定全部已经口头告知。能够获取真实对齐后，再加入保守的已播放文本范围。[S06][E05]

### 6.5 重播与音色变更

重播必须绑定 `playbackInvocationID → originalTurnID`，不能复用“最后生成的回复”作为唯一身份。重播旧回答被停止，只更新本次播放状态，不误标最后一条新回答。纯文字会话中缺少播放通道时给出说明和“启用朗读”动作；不显示可点击但无响应的 play，也不因此偷偷开启麦克风。[S02][S10]

音色变更使用“待下次回答生效”的 pending selection。当前 utterance 绑定启动时的 voice/revision，只有下一个 request 使用新值。保存变更失败时不得声称“第 N 句已切换”，应回滚选择或明确未保存；实际生效的 replyID/ordinal 由创建该次回复时确定，不在跨 await 前后猜当前 ordinal。[S01]

“测试声音”必须走真实 TTS+播放的独立、明确入口，不走 typed question 冒充验证；复用已有试听服务与播放协调，不能同时叠放预览和当前助手回答。

## 7. 阶段五：长对话、记忆与上下文

### 7.1 同一套会话上下文初始化

语音开始和文字开始共同调用一次会话上下文构建，产生角色、模型路由、记忆选择与用户偏好快照。语音重连只重建 transport，不清空历史，也不从全局偏好换模型；文字升级到语音复用当前记录与上下文，或明确作为“新建语音对话”，不能留下未封存旧记录却不告诉用户。[S02][S03][S06]

初始化必须清空上场内存，再加载本场允许的记忆。记忆加载失败时展示“本次未加载记忆”，而不是悄悄使用上场数组。用户在面板停用/删除记忆，应能看到“当前对话是否仍持有此前快照”；需要立即生效时停止当前生成，在下一轮按明确操作重建上下文，不暗中改变已经发出的请求。

### 7.2 有预算的上下文，而不是无限追加

已有历史追加方式应保留原始对话资产，但“全部记录都保存”不等于“每轮请求无限携带全部记录”。建议增加请求组装预算：固定指令+选中记忆+近期完整 turn+必要摘要+输出保留空间。预算来自已确认的模型配置或显式保守设置；未知上下文长度不能猜。[S06][E07]

初期先采用可预测的最近完整 turn 窗口并说明省略范围。随后才评估摘要：保留问题、决定、数值、约束和未完成事项；摘要引用来源 turnID，不覆盖原文；模型不可用时不让摘要成为继续对话的强制阻塞。不要默认启用云端 Conversations 持久化，也不要把记录资产转换成 opaque 服务端 ID 后删除本地历史。

### 7.3 记忆：保留显式写入，增加内容审阅

已有“记住”不应被重做为自动提取所有聊天。点击后出现轻量编辑确认：内容、类型（偏好/事实/约定）、来源、作用范围。助手生成的建议不能未经用户核对被视为用户事实；整段 Markdown 或含指令正文应作为数据处理，不直接成为可覆盖应用规则的 developer 指令。[S10][S12]

记忆读取用清晰的数据边界、长度预算与来源角色；不把嵌入的“忽略之前规则”等字符串当执行命令。删除/停用操作返回结果并可读反馈，不能用 try? 吞掉失败。账户密钥、令牌等秘密不得进入建议保存内容、日志或导出诊断。

## 8. 阶段六：异常、降级与恢复

### 8.1 错误按链路归因

| 失败位置 | 保存什么 | 默认恢复动作 | 禁止行为 |
|---|---|---|---|
| 麦克风权限/输入设备 | 已有文字与草稿 | 打字继续；修改权限或换模式 | 把设备失败都叫“服务未就绪” |
| ASR 中断 | 已确认用户行；未确认可见内容明确保留 | 编辑后发送/重说；重试语音 | 把 hypothesis 当 final 直接交模型 |
| 模型失败/限流 | 用户问题、已生成片段与失败原因类型 | 重试当前回答；稍后重试 | 自动重新发送整段历史到另一个 endpoint |
| TTS 不可用 | 完整文字回答，朗读失败状态 | 看文字；显式重试朗读 | 删除文字答案或自动重复 LLM 请求 |
| 输出设备切换 | 原答案与被停止的播放状态 | 重建成功后等待下一轮；手动重播 | 当作已经播完，旧回调修改新预算 |
| 取消未获终态 | 本地输出已经停止的事实 | 关闭归属不明连接，重试语音 | 直接开始另一 request，放回旧音 |
| 数据库写入失败 | 内存中的待保存内容、明确未保存标识 | 重试保存/复制导出内存内容 | 对外显示“已入库”；误判为网络故障 |
| 记录读取/导出失败 | 原记录不变 | 展示错误并重试 | 把读取异常当成空记录导出 |

故障提示由稳定错误类型映射为普通语言；技术代码、requestID、采样数等放诊断详情，不作为主文案。重试与丢弃要分别表达，不让“知道了”成为唯一出口。

### 8.2 自动重试边界

只对明确可重入、尚未产生用户可见结果的操作做有限重试。已经开始朗读的请求不自动重放；已经保存的问题不因重试重复插入；端点/音色版本冲突不自动选最新；身份不明的取消必须先关闭旧连接。

重连 single-flight 继续沿用，并补充：每个 await 返回后重验租约；只回收自己创建的 source/client；旧连接上传错误不能替新连接写 lastFailure。错误信息的关闭不改变资源或恢复资格。

## 9. 阶段七：结束、记录与继续

### 9.1 结束只作用于本次助手

新增或抽取一个所有界面/菜单共享的**有目标的助手结束入口**。建议由 AssistantSession 暴露会话级动作，再以 `expectedKind + expectedSessionID/leaseID` 调用 coordinator；纯文字直接按自己的 recordID 收尾，无设备就不碰别的 occupancy。[S02][S10][S11]

将页头、底栏、快捷键、换角色新建、退出行为统一路由，不能其中一处走“当前全局会话”、另一处走“当前助手”。回看旧记录与活跃会话并存时，必须持续显示活跃会话状态；记录页的“新建”不能悄悄替换仍在采集的会话。

### 9.2 停止阶段的双重屏障

建议把结束拆为有界的、可验证的阶段：

1. 同步撤销新回复/新播放/新启动权限，固定要结束的 sessionID 与输入连接身份。
2. 停止采集新样本，排完已捕获且被策略允许提交的尾部，确定客户端发送样本水位；取消新上行生产，不把原始 PCM 持久化。
3. 停止本地播放；需要时取消旧 TTS，保持接收循环可处理终态。
4. 对输入请求完成屏障；处于 draining 的旧连接仍接收合法 ASR final，并只归档、不启动 LLM/TTS。
5. 等待应用侧已接受 final 的落库屏障，再封存记录。超时/错误分别记录“尾句未确认/部分未保存”。
6. 关闭连接、确认设备停止、释放匹配租约；只在成功持久化后发布“已保存”。

网络 receipt 证明的是契约规定的输入处理水位，不能代替应用数据库的提交水位。逻辑上已撤权也不能直接当作硬件已释放；当前音频 stop 的异步 teardown 应提供可等待的完成结果，至少不让 UI 提前宣称麦克风已释放。[S03][S09][S11][S15]

### 9.3 记录的状态与“继续”

记录状态至少能表达已结束、部分内容未保存、识别未完成、生成中断、朗读未完成。记录行的 status 不应仅凭单一 isInterrupted 推导全部含义；新增存储字段时使用版本化迁移，旧数据未知就标未知，不从旧时间/布尔值推造新证据。

本轮立即将当前“继续这一轮”改为“用相同设置新建”，匹配现有只预填人设/音色的行为。[S10] 真正的“基于此记录继续讨论”作为独立后续动作：新记录保留 parentSessionID 和选定上下文范围，先展示将发给模型的内容范围；旧记录只读，不重新开麦，不把旧记录拼接成一场无限长会话。

重命名、删除、导出必须在成功后更新界面。删除失败留在原记录；导出重新读取失败不能输出空文件冒充成功；封存失败不发布成功 ID。退出时保留可恢复的未保存文字，但不承诺尚在内存的全部 token 在崩溃后必然存在。[S10][S11]

## 10. UI 交付规格

### 10.1 页面与状态清单

UI 实施必须提交同一个页面的以下状态，而不是多套新的主题：未配置、已配置未开始、启动中、文字对话、语音聆听、生成中、播放中、用户静音、语音故障可打字、保存失败、正在结束、结束回看。

| 区域 | 设计要求 |
|---|---|
| 页面头部 | 当前任务、真实状态、必要设置/结束入口；不重复堆模型状态看板 |
| 对话正文 | 文本为主，partial/final 视觉轻量区分，保持可选择复制；不按每个 token 创建新行 |
| 底部输入区 | 布局稳定；发送、停止回答、语音开关、结束的目标清晰；输入不被状态提示挤出可视区 |
| 辅助侧栏 | 角色、音色、记录、记忆按需展开；窄窗可折叠，但主任务无需打开侧栏才能完成 |
| 异常反馈 | 在相关动作附近显示可执行恢复；全局错误不遮挡正文 |
| 记录阅读 | 资产操作有真实结果；阅读旧记录时不丢当前活跃会话状态 |

### 10.2 滚动与焦点

增加 `followLatest` 展示状态：用户已经在底部时跟随新回复/流式增长；手动向上回看后保持位置，显示“有新回复，回到最新”。新行不得强行把用户拖回底部。统一末尾锚点，流式同一 replyID 不换行身份。

不要在后台语音事件、状态刷新或侧栏展开后随意夺走输入焦点。停止回答快捷键只作用于当前助手，IME 组合态、弹窗和菜单先处理自己的 Esc；隐藏按钮仍有菜单/键盘可达入口。沿用 Apple 原生焦点和 Reduce Motion 行为。[S10][S14][E08]

### 10.3 视觉与可访问性

复用 `SpeechRailDesignTokens`、`SessionPanel`、`SessionStatusBar`、`NoticeBar` 和现有 LayoutContract；新增值先入 Token，不把 500/760/1128 等局部尺寸继续扩散。将大文件按展示责任拆分仅在该区域真正修改时进行，不为“架构美观”先大搬家。

人工/获授权的 UI 检查覆盖最小受支持窗口、宽屏、Light/Dark、高对比度、大字号、Reduce Motion、VoiceOver 与中文输入法。没有实机检查就交付“待验收”，不能说像素级 UI 已完成。

## 11. 工程结构与关键不变量

### 11.1 在现有组件上明确责任

| 层 | 当前落点 | 建议责任 |
|---|---|---|
| 用户动作与展示 | AssistantView / SessionSurfaceViews | 调用有目标的 action，读取统一 presentation，不自行猜设备/连接状态 |
| 会话与输入归属 | AssistantSession / SessionCoordinator | 会话身份、设备租约、文字与语音路径、开始/结束、final 归档 |
| 回复与持久化 | AssistantReplyState / AssistantSession / SessionStore | 回复唯一身份、尝试次数、幂等提交、保存结果、历史投影 |
| TTS 与播放 | AssistantTTSStreamCoordinator / PlaybackLedger / AudioSession | request/epoch、取消屏障、有界预算、真实播放证据 |
| 文本与上下文 | VoicePrompt / SpeechTextBuffer / provider adapter | 模态策略、保真、请求预算、模型路由与记忆快照 |
| 测试与观测 | AssistantSessionTests / 共享 fixture | 生产路径回放，输入输出水位，脱敏计数和真实声学评估 |

拟新增的 `AssistantPresentation`、`AssistantTurnPolicy`、`AssistantContextSnapshot` 等是候选的小型纯值/策略组件，不是必须全部创建的新框架。优先在现有类型中扩展，证明职责需要后再提取。

### 11.2 身份契约

本地建议显式持有：conversationID、connectionGeneration、replyID、replyGeneration、ttsRequestID、playbackInvocationID、playbackEpoch、storeOperationID。每种身份有自己的生命周期，不把“同一 session”当作任意消息都能修改当前回复的许可。

**跨 await 规则**：调用前保存目标身份；外部结果按该身份持久化；返回后重新比较当前身份，只有匹配时更新当前 UI/内存。旧结果可以完成旧记录的收尾，但不得覆盖后来的一场。finalize 的 once-claim 应在第一个 await 前完成，失败后进入可重试保存状态，而不是仅在局部副本里写 isFinalized。

建议状态迁移测试同时断言三份事实：持久化记录、内存对话流、发送给模型的历史。不能只检查其中一份。

### 11.3 必须保持的不变量

1. 结束文字助手不改变任何其他功能的租约、录音、phase 或记录。
2. 一个有效 input item 在一个连接代次内最多归档一次；重试回答不复制用户问题。
3. 旧 generation/request 的任何迟到事件，不得改变当前播放、输入门闩、错误或正文。
4. 接收循环不等待只有自己继续消费才能完成的条件。
5. 取消发送成功不等于远端空闲；本地已停止也不得恢复旧音。
6. draining 阶段可保存尾句，但绝不由尾句自动触发新回答。
7. 生成完成、设备播放完成、记录保存完成各自有证据；不存在一个 Bool 冒充全部成功。
8. 语音服务失效不阻断已满足前提的文字对话；文字操作不隐式获得麦克风。
9. 数据目的地、角色与记忆按声明的会话策略生效，运行中不得静默漂移。
10. 测试、指标、日志不包含私人音频、完整对话、密钥和可复原文本的散列标签。

### 12.2 每包可执行内容与完成定义

**VA-01｜结束必须命中自己。** 先将 View 的 end/restart 入口改为会话级命令，带目标 sessionID/租约断言；纯文字封存使用自身 ID；语音经匹配占用收尾。补“无 occupancy”“会议占用”“正在回看旧记录”“重复点击”四条动作测试。完成定义：A01/A02/A18 通过，会议不被误改，文字助手真结束。回退不能回到不带目标的全局 stop。

**VA-02｜取消不阻塞终态接收。** 把 await terminal 从 receive handler 移出，登记单个取消 effect 与其身份；接收侧始终能处理控制事件。将停止按钮、插话、provider failure 的取消路径统一。完成定义：A03/A04/A08/A55，使用实际事件队列测，不靠 sleep。超时仍 fail closed。

**VA-03｜尾句与封存。** 增加 draining 生命周期、输入与保存水位；停止输出与接受尾句分开；必要时扩展 Realtime 测试 seam 暴露屏障结果。coordinator 封存方法返回成功/失败，不在失败时发布成功 ID。完成定义：A05/A06/A07/A47；只保存尾句，不生成新回复。

**VA-04｜回复事务。** 引入跨入口 turn submission arbitration；在覆盖 currentReply 前完成前任的中断/持久化；跨 await 回写前重新校验；finalization once-claim 以 replyID 为键且可观察保存失败。完成定义：A09/A10/A11/A12，UI/Store/history 三者一致，无重复用户行或孤立旧 partial。

**VA-05｜身份过滤顺序。** 所有 ttsAudio/ttsEnded/onOutcome 在 UI/闭麦副作用前确认 ownership；退休 terminal 只放行本闩；晚到 startup 只关闭自有对象，不无条件清空当前 self。完成定义：A13/A14/A15/A52，新代次不被旧回调污染。

**VA-06｜配置与记忆快照。** 抽统一初始化供 voice/text 使用；冻结实际解析的 route/persona/memory policy；相同会话重连只换 transport。密钥留 Keychain/请求内存，不写存储快照。完成定义：A21/A22/A23/A24，跨场清空、路径一致，目的地切换可见。

**VA-07｜独立文字能力。** 以 LLM/Store 能力而不是语音 BlockReason 决定 typing；语音失败可继续当前文字上下文；升级语音有明确用户意图和租约检查，不另建幽灵记录。完成定义：A16/A17/A19/A20。TTS-only 朗读拆分是可独立延后的增量。

**VA-08｜可信首屏。** 统一 readiness、capture、conversation 与 route presentation；替换硬编码就绪/已连接/本机隐私文案；技术配置渐进展开；“说话即录”仅在实际采集中可用。完成定义：A25/A26/A27，真实页面状态矩阵逐项对应，模型名存在不等于已连接。

**VA-09｜对话编辑体验。** 模板非破坏填入和撤销；followLatest 与稳定 streaming tail；输入法组合态与键盘；失败提供重试当前问题/复制/修正。保留原有发送单飞与条件清稿。完成定义：A28/A29/A30/A31/A32，正文和焦点不被后台更新夺走。

**VA-10｜模态提示词。** 为 textOnly/spokenConcise 生成不同 instructions，保留 persona 风格边界与事实谨慎规则；provider终态处理列入契约审查。完成定义：A33/A34，键入代码问题可正常给代码，语音短答自然，关键数值歧义不猜。

**VA-11｜分包与保真。** 区分 transport/TTS append/total/pending 预算；先准入再切分；按真实 limits 与 scalar 计数；清洗维护边界。完成定义：A35～A39，等价分包不改变正文，超限原子失败且文字回答保留。安全 token 等待策略单独灰度，不靠无限缓冲。

**VA-12｜播放交付。** 明确 rendered/played 回调和终态证据；记录生成/保存/播放不同状态；重播绑定原 turn；voice pending 绑定下一 request 并记录真实持久化结果；真实声音测试不经静默文字路由。完成定义：A40～A44，不能用帧比例伪造已播放文字。

**VA-13｜自然接话。** 第一增量修空 snapshot 与 final-only 不一致；之后用真人语料评估补充信息、停顿、附和和回声。局部 VAD 提前响应/turn aggregation 先作为实验，不直接宣称已有语义断句能力。完成定义：A08/A56/A57/A58，并达到第 15 节设备分层门禁。

**VA-14｜上下文与记忆。** 先增加请求预算和完整 turn 裁剪，再评估有来源的摘要；记忆编辑确认、类型/来源/作用域、停用结果；原始记录不改写。完成定义：A45/A46/A48，预算不足明确处理，不把未播放内容当作已口头交付。

**VA-15｜资产闭环。** 读取/封存/重命名/删除/导出不吞错；当前继续按钮改为复用设置；真正上下文续接使用新记录及 parentID，需范围确认。完成定义：A47/A49/A50/A51。高级续接可后置，但误导标签和失败反馈应本阶段交付。

**VA-16｜资源与观测。** 对 ring/AsyncStream dropped、发送失败、播放排队、取消等待、停止屏障做有界计数与单调时钟；断线时及时结束上传；记录组件不可用也不让主流程崩溃。完成定义：A52/A53/A54；不记录私人 PCM、文本或内容散列。[S09]

**VA-17｜验收资产。** 扩展既有 FakeAssistantLLM 捕获配置与消息角色，修正 fake ACK codepoint；增加可控 DB/播放/收尾 Gate；复用跨端 fixture 并补完整 receive-loop 时序。真实音频仅在用户授权后获取，放仓库外。完成定义：60 场景逐项有证据状态，A59/A60 覆盖长时与设备，没跑的保持 not_run。

**VA-18｜性能与门禁。** 在实测瓶颈上做小增量，可能是 UI 合批、LLM读取与TTS启动有界解耦、采集分包或预检缓存；每项做同机同配置对照。更新 active 文档、测试清单、SwiftPM/Xcode source membership。完成定义：质量不退化，成功分母与资源上限一致，不为延迟目标隐式调用模型或改服务。

### 13.1 里程碑

| 里程碑 | 工作范围 | 可独立交付的用户价值 | 退出门禁 |

VA-17 的基线和 fake 闸门在 M0 即启动，后续随各包扩展，并非要求先完成所有功能才开始测试。VA-16 的最小诊断计数可随 M0 一并增加，不必等到完整监控方案完成。

### 13.2 并行推进原则

`AssistantSession.swift` 是主要冲突热点。建议会话/生命周期主线只有一个写入 owner；UI 可以并行实现纯 presentation 与草稿/滚动策略，TTS 文本缓冲可以并行建立纯测试；涉及共同字段的 edit 串行集成。不要为了并行而创建另一个 AssistantSession 或复制公共类型。

先交能复现 P0 的最小完整回归和修复，再持续追加有独立价值的增量。一个 coherent objective 对应一个 PR，不机械地一个函数/文件一个 PR。VA 编号用于追踪依赖，不意味着必须恰好 18 个 PR。

### 13.3 Git 与执行授权

实施开始时重新读取当时的仓库指令与 base SHA。优先 Native Git；不可用时按既有 GitHub Actions Artifact 获取受版本控制工作树，再经授权的 GitHub API 发布。当前计划交付不授权创建临时 workflow、远端分支或 PR。

使用 feature/fix/chore 分支，不直接写 main。首个完整且完成获授权验证的增量后尽早开 Draft PR；后续 atomic commits 持续追加。日常 push 轻量 read-back 校验 head SHA，里程碑/merge-ready 时才核完整 diff/base-head/tests/checks。无 checks 就写无 checks；没有实测就不称质量通过；未经授权不合并。

现有 Package.swift 使用显式 sources 清单，新提取的生产文件要同时进入正确的 SwiftPM/Xcode 目标，不能出现测试编译的是 A、App 发布的是 B。`.app` 构建使用仓库规定包装脚本，不裸跑 xcodebuild 产生多余应用副本。[S16]

## 14. 60 个可执行验收场景

类型：D=生产组件注入 fake 的确定性测试；U=真实界面人工检查或当前用户另行授权的 UI 自动化；R=当前用户另行授权的真实音频/设备/模型验收。D 不证明声学效果，U 不证明服务质量，R 不取代协议与竞态回归。每项初始状态均为 **not_run**。

| ID | 类型 | 场景与操作 | 必须断言的结果 |
|---|---|---|---|
| A01 | D/U | 无设备占用，创建纯文字助手，按助手页结束 | 自己的记录封存；助手 idle；不调用麦克风/Realtime；不是 no-op |
| A02 | D/U | 会议持有租约时创建文字助手，再结束助手 | 会议 occupancy/phase/记录/stopper 均不变；只有助手结束 |
| A03 | D | 播放中从唯一事件流注入非空 hypothesis；cancel 后同流立即发 terminal | 接收循环不自阻塞；不用等 cancellation timeout；连接可继续 |
| A04 | D | 手动停止时服务不回 terminal 或 cancel 写入失败 | 本地按屏障停止；有界失败并关闭连接；旧音不恢复 |
| A05 | D | 有半句输入，开始结束后才发 final 和 matching receipt | final 写入原记录一次；不新建 LLM/TTS；落库后才封存 |
| A06 | D | 收尾 receipt 已到，但数据库 append 被 Gate 挂起 | 不发布“全部保存”；Gate 释放后正确结束 |
| A07 | D | 收尾超时、空 final、final failed 分别发生 | 区分未确认尾句/识别失败/正常空输入；已保存文字保留 |
| A08 | D | 空 snapshot、重复 revision、final-only 输入出现在回答期间 | 空/重复不触发取消；final-only 经统一接管，不覆盖未收尾回复 |

## 15. 评价指标、样本设计与候选目标

### 15.1 指标口径

| 指标 | 起点/终点或分母 | 必须说明 |
|---|---|---|
| 发送响应 | 用户明确提交→UI 接纳/拒绝反馈 | 不等于模型完成回答 |
| 语音开始耗时 | 用户开始语音→实际采集且 Realtime 配置确认 | 冷/热启动、权限首次提示分别统计 |
| 首字延迟 | 模型请求发出→首个可展示正文 | 空白 token、心跳和推理事件不计正文 |
| 首音延迟 | 标注的用户发言结束→首个有效输出开始播放 | 与 ASR final→首音分开；不能从下行首音包时间冒充设备播放 |
| 手动停止响应 | 用户停止动作→本地停播屏障完成 | 另报告设备输出尾延迟；不要混入远端 terminal 等待 |
| 插话响应 | 标注的近端插话开始→本地停止输出 | 包含检测等待；不能只测 cancel 函数耗时 |
| 远端取消确认 | cancel 发出→匹配 request terminal | 超时也进结果，不从分母删除 |
| 错误插话率 | 非插话样本导致取消数/非插话样本数 | 按回声、噪声、附和分别统计；补每小时误停数 |
| 漏插话率 | 真插话未在评价窗内停止数/真插话数 | 超时窗必须公开且与设备分层固定 |
| 尾句完整率 | 结束时有有效已准入输入且正确归档数/对应样本数 | clear 后正常空输入不纳入；失败/未确认保留独立统计 |
| 文字降级成功率 | LLM/Store 前提满足的语音失败后文字完成数/此类尝试数 | 与模型也不可用的情况区分，不人为美化分母 |
| 内容保真 | 数字/单位/否定/专名等关键单元准确数量/标注数量 | 不用总体 WER 掩盖一个金额错误 |
| 保存一致性 | 用户可见已保存内容可从 Store 读回的次数/相关样本数 | UI、history、Store 分开检查；内存恢复不算已落库 |
| 资源稳定性 | 常驻内存、队列上限、丢样本、活跃任务、设备释放结果 | 配置/基线一致；不把系统缓存涨幅直接当 leak |

同一报告同时列 attempts、successes、failures、timeouts、sampleCount、配置版本与证据等级。没有样本写 N/A；latency 只在有定义的成功事件上计算，同时保留全体失败率，不能删除失败后声称体验更快。

### 15.2 初始候选验收目标

以下为实施时需要确认的工程目标，不是本项目当前性能，也不是行业标准。设备、模型、服务、上下文长度和首次授权都要分组。

| 类别 | 候选目标 | 说明 |
|---|---|---|
| 安全不变量 | 确定性场景 0 次跨会话误停、旧代污染、重复归档或静默成功 | 有限测试集零失败不等于证明现实永不失败 |
| UI 动作回执 | P95 ≤ 100ms | 只要求本地接纳/拒绝反馈，不能等待网络才显示按钮响应 |
| 手动停止本地屏障 | P95 ≤ 150ms | 单独测输入动作到播放层确认停止；硬件尾音单独报告 |
| 纯状态归约 | 单事件 P95 ≤ 10ms | 排除外部 I/O；目标是控制事件不被重任务阻塞 |
| 停止后的尾句处理 | 已有 8s drain 等待作为待评估预算，不扩大为无限等待 | 网络与持久化应有各自超时结果；不保证全部在 8s 内成功 |
| 声学首音/插话 | 先测基线，再制定各设备/模型目标 | 暂不承诺“恒定 1s”“所有设备 2s 内”；关键是安全与内容不退化 |
| 分包保真 | 合法输入的等价分包测试 100% 内容一致 | 指确定性文本语义和准入，不要求每片边界/时刻相同 |
| 功能回归 | P0 场景全部通过，P1 没有未说明的阻断 | 实测状态不混为单元测试状态 |

新算法必须对照旧策略，在相同样本与配置下改善关键体验，且误插话、数字错误、丢句、资源占用不能显著退化。先固定评价窗和允许退化量，再看结果，禁止看见结果后改统计口径。

### 15.3 样本与设备矩阵

建议首批真实验证使用获得授权的录音与真人互动，覆盖普通话、英语、中英混合、较慢停顿、快速补充、低声、数字密集、技术名词。至少覆盖一组耳机、一组内置扬声器和一组实际使用的外接音频设备；具体型号/系统/ASR/TTS/模型 revision 由实测记录，不由方案猜定。

阶段建议：先用小样本发现灾难性问题，再扩展至每个关键现象有足够事件的分层集。若总体收集 200 个插话事件，也不能把其中仅 3 个外放事件概括成“外放已经通过”。条件允许时由不同人标注语音结束、插话意图和正确文本；分歧保留并复核。零错误时附样本量和统计不确定性，不直接宣传 100% 可靠。

重放录音可以验证输入/决策，但不能替代真实扬声器→房间→麦克风闭环的 AEC 和双讲实验。合成 TTS 音频适合补协议和文本边界，不应充当全部真实人声质量证据。

### 15.4 观测与隐私

生产诊断优先有界直方图和计数：接收队列年龄、pending scalar、queued samples、丢块次数、终态等待、错误类型、声音模式、结果类别。身份用于本轮内存关联，报告去标识或用短期随机 ID；不将原始正文、音频、完整 prompt、key、Authorization 或可复原的文本 hash 写进遥测。

样本语料、音频、原始事件与模型输出放仓库外；仓库只保存合成 fixture、schema、工具和脱敏聚合。真人评测先说明用途、保留位置与删除方式，禁止把用户实际会议当默认测试素材。

## 17. 数据迁移、发布与回退

### 17.1 数据策略

现有记录不删除、不重写成新事实。生成状态、播放状态、保存状态、parentSessionID 等新增字段，先确认 Store schema 和查询的真实位置，再设计事务性 migration。旧数据缺失播放证据标 unknown，不从 interrupted=false 推断全文已经播放。

迁移先在合成副本和故障注入上验证，再在获授权后备份用户数据库。新增 migration 不允许静默降级读取后丢弃新字段；需要回滚旧应用时优先停止写入并恢复已验证备份，说明备份之后的新数据如何导出保留，不能直接覆盖。

### 17.2 发布策略

首批安全修复不依赖新的模型/协议。语义接话、提前 duck、摘要和更激进切片策略使用可独立回退的 policy 版本，默认不开未经真实质量验证的策略；数据安全修复不能以“回滚体验”为由重新启用旧的串场或尾句丢失路径。

发布前确认单一 .app 安装、既有服务配置与模型资产不被改变。未授权安装就只交代码与验证结果；未授权 merge/release 不自动推进外部状态。

### 17.3 失败时回退

回退优先退新 policy、不退资产；语音链路不可用就明确进入文字模式；TTS 不可用就保留文字答案；记录写入失败就保留未保存内容与导出出口。取消归属未知时宁可关闭连接，不能为了继续演示跳过屏障。

## 18. 本轮不做与后续决策

本轮不默认引入：常驻唤醒词、后台持续录音、系统级全局裸热键、自动读取文件、浏览器/电脑执行工具、联网搜索、通用 RAG、多 Agent、自动长期记忆、云端会话同步、多说话人实名识别、实时 LLM 声学判断或另一套音频引擎。

保留为后续按证据决策的能力：ASR-only 语音输入、TTS-only 无麦克风朗读、显式按住说话、真实上下文续接、局部 VAD 提前响应、有来源的摘要。这些不应阻塞核心链路安全与默认 UX。

**首批最小有价值增量：VA-01 助手专属结束 + VA-02 插话取消接收环 + VA-03 尾句/保存屏障。它们直接决定“能不能放心开始、打断和结束”；随后再做回复幂等、路由快照与界面优化。**
