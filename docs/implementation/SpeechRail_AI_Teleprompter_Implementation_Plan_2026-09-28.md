## 0. 交接摘要：成功目标与验收标准

本节面向承接实施团队。详细规格以 §3–§15 为准，冲突时以正文为准；数值为 **P：待建基线的工程目标**，不是已有结果。本节是目标与门槛，不是进度；实施进度见文首「交接入口」指向的阶段实施报告。

### 成功目标

1. **稿件可信**：原稿可直接开讲；数字、单位、标识符与高风险语义在生产路径被确定性拦截，有损改写审阅后生效；口语化与精简分离。
2. **跟随可控**：连续跟随与回稿恢复达到门槛，严重误推进与无意回跳在对抗回归中为零；识别正确与显示舒适分开优化；不确定时保持且可测量。
3. **体验与数据安全**：窄栏与快捷恢复可用；手动接管立即撤销推进权，旧回包不得夺回控制；离开功能即释放麦克风；零敏感日志、零 PCM 落盘。
4. **证据可信**：结论绑定提交版本、环境、语言与设备；确定性回放与真实音频、真人验收分开陈述；未达门槛如实声明，不删样本改口径。
5. **交付完整**：按 TP-00→TP-11 分阶段交付并对齐 #104–#114；新增源码在 SwiftPM 与 Xcode 双 target 一致生效；共享调用方回归、迁移与故障恢复齐备。

### 验收标准

逐条满足才算本阶段通过：

- **阶段与范围**：交付阶段及对应 Issue 明确；安全修复可单独完成，不以全部增强完成为前提。
- **稿件加工**：§11.2 确定性高风险用例全部阻断或转审阅；风险误报率与审阅负担有配对数据。
- **语音跟随**：手动操作 P95 ≤ 100 ms；连续跟随 P95 ≤ 1000 ms；回稿恢复 P95 ≤ 2000 ms；超过 3 s 的错误停滞事件低于 1%；严重误推进在对抗回归与保留集为零事件，并报告观测总时长。
- **权限与恢复**：旧 generation、手动接管、关闭语音后越权推进为零；恢复超时样本计入失败。
- **资源与稳定性**：长时无泄漏、无无界队列；未过门禁的自动策略默认关闭。
- **隐私与迁移**：零新增敏感日志与稿件数据丢失；迁移原子、可回退。
- **证据纪律**：结果注明版本、环境、证据等级（E1–E4／P）与未验证边界；真实音频与真人验收未完成前不得宣称语音质量达标。

## 1. 执行摘要与关键决策

### 1.1 三条建设主线

| 主线 | 需要解决的问题 | 本轮交付结果 |
|---|---|---|
| 产品与体验 | 开始复杂、状态不清、提词影响表达 | 原稿直接开讲；准备与正式讲述分离；镜头友好显示；接管与恢复明确 |
| 提词稿加工 | 格式正确但可能事实失真；改写不够顺口；时长不可信 | 数值与关系校验、来源可追溯、差异审阅、读法辅助、独立精简操作、排练校准 |
| 智能跟随 | 短语误跳、修订回跳、脱稿恢复困难、真实质量缺证据 | 消费现有稳定性与时序元数据；分级定位；候选／确认／显示分离；实音频与真人验收 |

### 1.2 立即确定的产品与工程决策

| 编号 | 决策 | 说明 |
|---|---|---|
| D01 | 手动优先，语音主动开启 | 打开舞台、切换显示预设、打开原稿不申请麦克风 |
| D02 | 运行时不调用 LLM | LLM 用于准备与审阅；不实时决定滚动、跳转或续写 |
| D03 | 原文是不可变事实来源 | 候选稿、朗读稿、精简稿是不同版本；不覆盖原文 |
| D04 | 保真口语化与有损精简分开 | “更顺口”不授权删信息；精简必须显式选择并审阅删减 |
| D05 | 优先修复既有 MLX 路径 | 不先换引擎、不新增并行模型进程、不绕开共享资源治理 |
| D06 | 优先消费现有 Realtime 契约 | 已有 `sequence`、`epoch`、`sample_span`、`stable_prefix_codepoints`，不重复造协议 |
| D07 | 定位正确与显示舒适分开处理 | ASR 稳定不代表识别正确，定位成功也不代表立刻移动画面 |
| D08 | 不确定时保持，但必须测量卡住率 | 不能靠“永远不动”换取零误跳 |
| D09 | 手动定位立即撤销语音推进权 | 旧回包不能夺回控制；恢复须用户主动触发 |
| D10 | 保护用户数据，不默认维护历史接口 | 遵循仓库 current-only 策略；持久化迁移仍须无损、原子、可恢复 |
| D11 | 质量按场景、语言与设备声明 | 模型支持某语言，不等于提词跟随已在该语言验收 |
| D12 | 先建立基线，再调阈值 | 本文数值目标是建议验收目标，不是已有性能结果 |

D01、D02、D03、D05、D10 的基础约束来自现有仓库规则和模块设计；本文是在这些边界内细化方案。[R01][R02][R07]

### 1.3 推荐实施顺序

先完成 TP-00 的基线确认；分别推进 #104 保真门禁、#105 远距推进权限、#106 证据透传和 #108 探针修复。#114 可先建立确定性生产回放，但真实时延基线必须等待 #108。随后接入 #107 稳定显示与独立的审阅／体验增强。这里的工作线可独立交付，不构成并行写入同一文件或自动委派的指令。

第一阶段最小可交付闭环：

```text
原稿可直接读
  → AI 修改可审阅
  → 数字与重要信息不被静默改坏
  → 稳定语音证据可推进
  → 远距离短语不能随意跳转
  → 停顿与脱稿保持可读
  → 手动接管后旧结果失效
  → 按所交付阶段取得对应证据；语音质量声明须有真实音频与真人验收
```

## 2. 事实基线、风险与修正

### 2.1 证据等级

| 标记 | 含义 | 可以支持的结论 |
|---|---|---|
| E1 | 固定提交的源码／公共契约 | 当前结构、分支条件、字段与约束 |
| E2 | 前轮独立探针及保存输出 | 局部逻辑可复现，不等于生产 App 行为 |
| E3 | 仓库文档中的既往测试记录 | 某次历史验证范围，不等于本次重跑 |
| E4 | 一手产品／上游技术资料 | 可借鉴的机制，不等于 SpeechRail 已获得同等效果 |
| P | 本文提出的设计与验收目标 | 待实施、待验证，不得作为已有能力宣传 |

前轮能力探测未连通本机服务；本次也没有真实 ASR、麦克风、视觉或长时运行结果。历史单测数量不作为新方案验收成绩。

### 2.2 当前已具备的能力

- 原稿可直接进入手动舞台；语音显式启停；generation 与旧事件失效机制已经存在。
- AI 正常加工采用 grouping／rewrite 分离，本地掌握来源范围，失败窗口保留原文并进入待确认。
- 中文字符、英文完整词与部分数值表达有归一化；定位使用有界半全局编辑距离。
- partial 可暂定推进，final 确认；有追赶、自由发挥和手动状态。
- 舞台已有 1／2／3 条真实排版行、局部快捷键、当前位置映射与末尾不自动打断。
- 会话复用既有音频采集、Realtime 客户端与资源协调；不应建设第二套同类基础设施。[R02][R03][R04][R05]

### 2.3 对前轮结论的必要细化

复核同一基线的公共契约后，以下表述应以本表为准：

| 容易误解的说法 | 本文采用的准确表述 |
|---|---|
| “需要给服务端新增稳定前缀和音频序号” | Realtime 4.1.0 契约已经定义相关字段；先核查生成、校验、透传和消费，补缺口而非另造协议 |
| “当前完全没有对齐时间信息” | 公共服务已有 opt-in Alignment；不等于提词器实时控制链路已使用，也不等于词级在线跟随已验收 |
| “当前客户端没有顺序保护” | 通用客户端已有 sequence validator 与 item／epoch 状态；重点验证提词器消费端是否保留足够证据 |
| “为了兼容增加长期双协议” | 仓库明确采用 current-only；仅在确有需要时做范围有限的迁移，不能默认保留旧 alias |
| “独立探针已证明 App 一定出现问题” | 探针只证明局部门禁或算法行为；macOS 原生回归及端到端发生条件仍待验证 |

契约 4.1.0 明确规定：wire 为 24 kHz mono PCM16，内核为 16 kHz；hypothesis 使用全文修订并可带稳定前缀；只有已证明稳定的文本可发 append-only delta；辅助 Alignment／Diarization 与 final 分离。[R07] 通用客户端已维护连接代次、事件序号与有界 item 状态。[R08]

## 3. 产品定位、场景与功能边界

### 3.1 一句话定位

**面向单人 Apple Silicon Mac 的真人口播、单人直播、课程与产品讲解工具：把材料整理成可信、顺口的讲稿，并以手动可控、语音辅助的方式帮助用户讲完。**

“AI”是加工与跟随能力，不是必须经历的流程。产品成功以用户完成表达任务为准，不以模型调用量、生成字数或自动滚动次数为准。

### 3.2 首批验收场景

| 场景 | 内容特点 | 主要行为 | 优先验收能力 |
|---|---|---|---|
| S1 镜头口播 | 短稿、相对逐字 | 看镜头、停顿、说错重读 | 窄栏、当前短语、下一行提前可见、回本句 |
| S2 课程／产品讲解 | 中长稿、技术词与演示 | 解释、切换内容、短暂脱稿 | 章节位置、自由发挥保持、附近回稿恢复 |
| S3 单人直播 | 较长、夹杂互动 | 回答问题、跳过部分内容 | 手动优先、低误跳、明确恢复、长时稳定 |
| S4 正式发言／汇报 | 数字与措辞重要 | 严谨朗读、控制时长 | 原文锁定、高风险修改审阅、排练计时 |

首批语言验收分为普通话、普通话夹英文术语、英语三个独立通道。语言混合是测试场景，不随意发明 `zh-en` 等服务端未声明的语言代码。

### 3.3 明确不做

第一阶段不新增多人讨论主持、实时问答生成、演讲中 AI 续写、摄像头采集、推流、视频剪辑、声纹身份库、云端稿件同步、全局裸方向键监听。也不将固定速度自动滚动悄悄作为语音失败的替代行为。

提纲式自由演讲列为后续独立模式：只能做要点级辅助，不以逐字定位规则包装“语义理解”。外接镜面提词器镜像、手机遥控、Stream Deck 等待核心闭环验收后另立需求。

### 3.4 用户故事与任务完成标准

| 用户故事 | 完成标准 |
|---|---|
| 我拿到一份材料，想马上读 | 粘贴后直接开讲；AI 不可用也不阻断；不自动使用麦克风 |
| 我想让稿子更顺口，但不能改错 | 能对照原文，定位实质变化；数字与限定条件风险不能隐身 |
| 我只有五分钟 | 区分语速估计与精简建议；不靠虚构时长或删除重要信息宣称达标 |
| 我说错了，想再读一遍 | 可手动回本句；语音识别到明确重读时可受控回退 |
| 我想补充两句 | 系统保持稿件，不因为碰到一个关键词跳到后文 |
| 我回到稿子了 | 附近连续片段足以恢复；位置含糊时继续保持并提供手动定位 |
| 我需要操作演示窗口 | 提词不抢焦点；回到舞台后控制状态清楚 |
| 我关闭语音或舞台 | 立即失去语音推进权，异步释放本功能资源；旧事件不能继续滚动 |

## 4. 用户旅程与交互规格

### 4.1 信息架构

```text
AI 提词器工作台
├─ 稿件列表：草稿／已确认版本／最近阅读位置
├─ 准备区：原稿输入、标题、直接开讲
├─ 可选加工：保持原文／自然朗读／按时长精简
├─ 审阅区：候选全文、实质差异、需要确认的段落
└─ 提词舞台：正文、最小状态、手动控制、显式语音开关
```

内部的 `block_id`、来源区间、schema、匹配分数、模型档位与诊断不得进入默认阅读界面。来源编辑与诊断放入明确命名的高级入口，常用操作仍须键盘与无障碍可达。[R01]

### 4.2 准备页主路径

**主按钮：直接开讲。次操作：整理成朗读稿。**

1. 粘贴或导入现有支持的 TXT／Markdown；输入为空时显示明确提示。
2. 草稿自动保存，不要求先生成活动版本。
3. 直接开讲时建立本次不可变阅读快照；无需 LLM、无需额外标注。
4. 存在未确认 AI 候选时，直接开讲仍使用原稿或已有已确认版本，不能静默采用候选。
5. 关闭舞台后允许继续编辑；运行中固定版本，不把后续编辑实时推入舞台。
6. 重新打开默认恢复该版本最后位置，同时提供“从头开始”。版本变化时按第 6 章的映射规则处理。

### 4.3 三种加工操作

| 用户文案 | 允许行为 | 不允许行为 | 默认确认方式 |
|---|---|---|---|
| 保持原文，只优化阅读 | 派生分段、显示、可选阅读提示 | 改写、删减、改数字 | 正文不变，无需 AI 审阅 |
| 整理成自然朗读稿 | 保真拆句、调整连接词、明确且唯一的指代补足 | 增加事实、摘要、改变不确定性、删条件 | 展示实质差异并确认版本 |
| 按目标时长精简 | 产生删减候选、建议保留重点 | 以“润色”为名静默删减、覆盖原稿 | 显式允许有损操作，并确认删除清单 |

“精简”属于新的内容权限；现有 `tighten` 仅消除冗余措辞的路径不能偷偷承担有损摘要。新增精简操作需要独立契约和回归样例。[R06]

### 4.4 AI 审阅页

默认左侧为候选朗读稿，右侧为“需要确认”的少量段落；原文对照可按段展开。窄窗时改为上下结构，不通过压缩字号塞进双栏。

每个风险条目包含：原句、候选句、变化位置、风险类型、操作。基本操作为“采用本段”“保留原文”“编辑本段”；“不朗读本段”属于明确内容选择，单独记录，不混同“忽略风险”。

风险分级：

- **阻断候选**：非法来源、未知 block、数值／标识符确定性不一致、结构不完整；不能一键全部采用。
- **需要人工确认**：主体关系、否定、条件、归属、复杂读法或语义不确定；逐项确认。
- **普通差异**：连接词、句子拆分等低风险变化；可批量采用，但仍保存来源。

“校验通过”不使用“事实已保证正确”文案。推荐：“未发现可自动检查的问题，仍请核对重点内容”。

编辑候选会使该段校验、标注和读法索引失效。用户编辑造成确定性数字变化时，应再次显示差异；用户确实要修改事实，则走显式修改原稿／创建新事实版本，而非记录成“AI 保真通过”。

### 4.5 显示预设与排版

保留现有行数、字号、透明度与键盘习惯，不重做设计系统。[R02]

| 预设 | 默认方向 | 可调内容 | 验收重点 |
|---|---|---|---|
| 镜头口播 | 靠近镜头、舒适窄栏、三行 | 字号、正文最大列宽、窗口位置 | 视线移动小；下一行可预读；不铺满超宽屏 |
| 讲台阅读 | 较大文字、较高可读性 | 字号、列宽、1／2／3 行 | 远处可读，长句不断义 |
| 自定义 | 延续用户设置 | 复用现有高级选项 | 不被预设或后台事件重置 |

窗口宽度与正文最大列宽分开。现有窗口最大高度等约束不应被预设绕开；如确需扩展全屏，应另立设计决策，不在本轮隐式改变。

三行继续采用“上一行／当前行／下一行”。当前行固定在相同槽位，稿首稿尾留空槽。字号与列宽变化后按稳定的稿件坐标重算行，不按旧行号恢复。

默认强调当前短语，未读内容保持清晰，不将逐字闪烁作为智能效果。阅读提示使用独立 cue 样式，不进入朗读正文或 ASR 匹配索引。

所有新增视觉值进入 `SpeechRailDesignTokens.Teleprompter`，算法阈值进入跟随策略，二者不要混用。[R01]

### 4.6 舞台操作与文案

| 操作 | 行为 |
|---|---|
| 空格／→／↓／PageDown | 下一显示行；不隐式开启语音 |
| ←／↑／PageUp | 上一显示行；进入手动态 |
| Home／End | 首／末位置；进入手动态 |
| 点击“开启语音跟随” | 校验权限与资源，显式开始本次采集 |
| 点击“从这里恢复跟随” | 从当前确认位置开始新语音 generation |
| 关闭语音 | 立即撤销推进权，完成资源释放；稿件不关闭 |
| 查阅全稿／手动滚动定位 | 手动接管；旧识别结果不再推进 |
| Esc／窗口关闭 | 关闭舞台、释放本功能资源、保存阅读进度 |

菜单与快捷键沿用现有作用域；输入框、popover 或设置控件有焦点时不截获阅读键。可增加菜单级“恢复语音跟随”快捷键，但必须核对现有冲突，默认不注册全局热键。

建议状态文案：

| 内部情况 | 用户看到的文案 |
|---|---|
| 已连接，尚无语音证据 | 已就绪，可以开讲 |
| 正在可靠跟随 | 正在跟随 |
| 有声音但定位不明确 | 正在定位；你可以继续讲 |
| 脱稿 | 保持当前位置 |
| 手动接管 | 手动浏览中 |
| 用户主动暂停／关闭语音 | 语音跟随已暂停 |
| 服务或设备失败 | 语音跟随暂不可用，可继续手动看稿 |

不能因“等待识别文本”就断言麦克风没有声音；电平、识别和定位分别判断。常驻界面不显示匹配分数、技术状态机名称或训导式提示。

### 4.7 首次试读与准备检查

首次启用或设备变化时提供可跳过的“读一句试试”，验证三件事：音频进入、识别有结果、正确位置可匹配。单纯麦克风图标亮起不算试读成功。

检查顺序：选择麦克风 → 权限 → 当前档位有效能力 → 资源准入 → `session.updated` 确认 → 开始采集。不得为检查自动下载模型、启动第二服务或静默调用云 ASR。

试读中的 PCM 和识别文本仅在有界内存中存在。试读结束释放资源；保存的可选结果只有设备偏好、语言选择和允许的聚合校准值，不保存完整试读记录。

### 4.8 排练与正式讲述

排练允许用户主动查看预计时长、耗时区间、难读段落与纠正次数。正式讲述只显示必要状态，不弹出评分、节奏指令、自动复盘或“已读完”遮罩。

计时需区分：舞台打开时长、语音有效跟随时长、用于估算的朗读样本时长。暂停语音不等于舞台计时归零。

录制／分享提示应明确选择目标窗口或摄像头，并检查实际采集结果。不得承诺窗口对所有录屏软件不可见；不能依赖 `NSWindow.sharingType` 作为普遍安全保证。[R02]

## 5. 提词稿加工流水线

### 5.1 目标流程

```text
原始材料（不可变）
  → 本地解析：段落、标题、列表、表格、代码、公式
  → SourceUnit + 原始 UTF-16 范围
  → 关键数值／标识符提取与高风险语义标记
  → 复用现有 AI grouping（快速路径另经瓶颈证据评审）
  → 固定 block_id 的保真 rewrite
  → 结构／来源／数值／关系风险校验
  → 仅必要的跨段衔接处理
  → 局部差异与删减审阅
  → 用户确认的朗读版本
  → 本地跟读索引 + 可选阅读标注
```

正文未变化的段落优先保留，不强制润色。现有 grouping／rewrite 严格 decoder、取消、阶段级重试、局部原文回退继续复用。[R06][R10]

### 5.2 输入与内容解析

**P0：先改进现有 TXT／Markdown，不扩展 PDF／DOCX 解析范围。**

1. 保存原始字节解码后的正文，不先做破坏性全局正规化。
2. 为每个来源单元保留原始 UTF-16 半开范围和来源顺序。
3. 识别标题、列表、代码块、表格与普通段落；格式不完整时保留信息，不能因为 Markdown 不标准就删内容。
4. 表头、标题与相邻上下文可供理解，但背景不是本窗口的新事实来源。
5. 本地分段不在数字＋单位、URL、代码标识符中间切断；超长单元使用带 continuation 的明确切分。
6. 指令注入字符串仅视作材料；不执行链接、不访问外部资料、不改变输出契约。

### 5.3 受保护内容：从字符串集合改为出现级结构

建议引入本地 `ProtectedAtom`，每一次出现独立记录：

```text
id / sourceUnitID / occurrenceIndex / sourceRangeUTF16
kind: number | quantity | date | identifier | url | version
rawText
canonicalValue: 精确十进制字符串或结构化标识
unit / scale / currency / precision / sign
readingClass: quantity | year | digits | version | unknown
```

实施规则：

- 不依赖英文 `\b` 判断中文紧邻数字的边界。
- 负号区分 ASCII `-` 与 Unicode `−` 等表现形式，规范值保留正负。
- 用十进制字符串／有理结构，不用二进制浮点近似比较金额与百分比。
- 标识符、版本号、电话号码、前导零数字串与普通数值分开，不能把 `0012` 无条件等价成 `12`。
- 全角字符等价只用于派生匹配层；不得改写原始文本及范围。
- 保护每次出现与上下文，不用 Set 丢弃重复值；允许的冗余消除必须有显式来源映射，不能仅按出现次数机械判真。
- `50 元`、`50 万元`、`50%`、`50 个百分点` 是不同量；单位和量级不得脱离数值。
- `50%` 与“百分之五十”可作为受限等价读法；“大约一半”不是无损替换。

### 5.4 两级校验加人工审阅

#### A. 确定性硬门禁

覆盖结构 schema、block ID、来源覆盖、范围合法、已保护值、用户锁定内容与出现级对应关系。

确定性不一致时输出结构化诊断：`numeric_value_changed`、`unit_changed`、`identifier_changed`、`protected_occurrence_unmapped`、`source_coverage_invalid` 等。以上为建议内部诊断名，不是现有公共错误码。

违反硬门禁的候选不能被标记为“加工成功可直接采用”。用户可以保留原文，或显式编辑并重新校验。不得把失败窗口的原文回退计作 AI 改写成功。

#### B. 高风险语义校验

建立轻量事实描述：

```text
主体 → 指标／动作 → 关系 → 数值／对象 → 单位 → 条件 → 否定 → 时间 → 归属
```

示例：

```text
原文：试运行期间，方案 A 的单次成本不超过 50 元。
主体：方案 A
指标：单次成本
比较：≤
数值：50；单位：元
条件：试运行期间
```

候选“方案 A 单次成本为 50 元”即使保留数值，也丢失范围和条件，应标记需要确认。

实现顺序：先覆盖数字邻近的主体／表头绑定、否定词和限定条件等高风险规则；可选模型检查只用于发现风险，不当作事实证明。不能因第二个 LLM 说“通过”就跳过硬门禁。

#### C. 人工确认

需要人工判断的内容包括：主体价格互换、复杂表格口语化、引用归属、歧义消解、复杂公式、精简时删除的重要条件。记录采用者的操作状态，而非声称算法已证明等价。

### 5.5 保真口语化规则

| 内容 | 允许改进 | 必须保留 |
|---|---|---|
| 长句 | 拆分为更短的语义句 | 条件、范围、因果与否定 |
| 列表 | 用适量连接词串联 | 层级、项目数与对应关系 |
| 标题 | 转成自然过渡或保留为不朗读标题 | 标题的组织作用与主题 |
| 表格 | 明确说明对象、指标、值 | 行列归属、单位、比较条件 |
| 术语 | 附加读法提示 | 正式名称与显示文本 |
| 代码／公式 | 用户选择逐字读、解释或不朗读 | 不擅自解释出原文没有的事实 |
| 原本顺口的句子 | 不改或少改 | 用户措辞与个人表达风格 |

不要为每段自动添加开场白、总结和互动套话。语言切换、事实纠错与扩写都不是默认保真权限。

### 5.6 三种文本层

| 文本层 | 内容 | 所属与使用方式 |
|---|---|---|
| `displayText` | 用户确认、实际显示的朗读稿 | 版本持久化；舞台展示 |
| `acceptedReadings` | 受限等价读法，如数字、缩写或专名别名 | 可选辅助数据；跟读匹配 |
| `cueNotes` | 看镜头、停顿、切换页面等提示 | 单独展示；默认不进入 ASR 对齐 |

同义改写、近音容错和精确数值等价不能混用。用户确认的术语别名需绑定具体词条及源范围，不得全局替换。

### 5.7 时长估算与精简

复用现有 `targetMinutes`、`pace`、`calibrationFactor`、`contentSelection`。[R05]

基础估计：

```text
预计朗读时长
  = 中文有效单位数 / 中文速度
  + 英文词数 / 英文速度
  + 用户明确设置的演示／停顿预算
```

中文与英文计数规则需与数据集一致，但不要求机械复用 ASR 的全部 canonical units。代码、复杂公式和未知读法计入不确定项，优先显示区间而非精确秒数。

排练校准只使用可靠匹配且无明显重读的片段；不要将已知长停顿、脱稿和等待模型的时间错误算作朗读速度。采用保守平滑，不因一次试读永久改变全局节奏。没有足够样本时显示“按通用语速估算”，不假装了解用户。

精简流程：选择目标时长 → 标记必讲／可删内容 → 生成删减候选 → 展示删除清单和保留重点 → 用户确认新版本。无法同时满足时长和必讲内容时，明确提示冲突，不能靠虚构语速解决。

### 5.8 长稿性能与失败恢复

1. 先复用现有窗口恢复和局部重试；确定性分组快速路径不属于 #111 必做项，只有证据表明 grouping 是瓶颈时另立小任务。
2. 保留已确认用户编辑；新建增量调度须先证明既有局部恢复不足，不与精简权限改造捆绑。
3. 新缓存层暂缓。确需引入时，键须包含来源版本、块内容摘要、操作、提示词／schema 版本及模型身份；只保存在允许的本地稿件数据边界，不进入日志。
4. 延续现有严格输出能力选择、有限 JSON mode 退回与业务 decoder；结构化输出不是事实保障。
5. 限流遵守可取消的 `Retry-After`；认证失败、拒绝与结构失败分别显示，不盲目重试。
6. 每窗口先完整验证，再进入待装配结果；全稿采用为原子操作，不把半成品冒充已完成版本。
7. 局部失败只影响该窗口，明确显示原文回退与待确认数量。
8. 用户编辑、切稿或开始运行后，旧加工任务失效，不覆盖新内容。

### 5.9 加工完成标准

确定性高风险回归中，错误必须被阻断或转入显式审阅；合法等价读法能够通过；未改变内容不能大量误报；所有 AI 改动可追溯到来源和用户决定。记录审阅操作次数与误报率，不能用“全部要求人工确认”掩盖自动校验失效。

## 6. 数据结构、坐标与版本管理

### 6.1 设计原则

只扩展实现本轮能力所需的类型，不引入通用工作流引擎、第二套文档库或跨会话用户画像。以下名称是建议的内部设计名；编码时优先复用现有类型，不应按表机械新增所有文件。

| 对象 | 核心字段 | 持久化 |
|---|---|---|
| 来源文档 | documentID、sourceRevision、原文、来源单元 | 本地原子保存 |
| 阅读块 | blockID、blockRevision、sourceRefs、displayText、确认状态 | 本地保存 |
| 关键内容 | ProtectedAtom、语义风险、诊断定位 | 按需保存，重算规则有版本 |
| 阅读辅助 | acceptedReadings、cueNotes、语义边界、绑定 revision | 可派生；可删除重建 |
| 运行快照 | runID、versionID、不可变 blocks、布局索引 | 运行期内存 |
| 跟随状态 | 候选位置、确认位置、显示锚点、事件水位 | 内存，不能保存转写历史 |
| 阅读进度 | versionID、blockID、块内 UTF-16 偏移、更新时间 | 本地最小进度 |
| 校准 | 语言计数规则版本、样本量、聚合语速、可信度 | 用户选择保留，不含音频和全文 |

现有 `TeleprompterV2Store` 与会话逻辑已经存在；迁移基于当前格式扩展，不再平行建设“V3Store”来复制责任。[R05][R11]

### 6.2 四种坐标必须显式区分

| 坐标 | 用途 | 禁止事项 |
|---|---|---|
| 原稿 UTF-16 范围 | 追溯来源、展示原文差异 | 不直接用来索引改写后的文字 |
| 朗读稿 UTF-16 范围 | SwiftUI／AppKit 显示与用户定位 | 不复用原稿偏移，不当作 codepoint |
| ASR Unicode codepoint 范围 | 消费公共 hypothesis／alignment | 不使用 Swift `String.count` 冒充 scalar 数 |
| 音频采样范围 | 事件关联、音频进度与时序 | 不把 24 kHz wire 与 16 kHz 内核样本直接混算 |

每个 canonical unit 必须映射到朗读稿原始显示范围。多个字符折叠成一个数值单位、多个读法映射同一词条时，也须保留完整映射，不能再用统一字符偏移相加推算。

`stable_prefix_codepoints` 是当前原始 ASR 文本的 Unicode scalar 数，不是字节数、Swift Character 数、BPE token 数或稿件 token 数。先在 ASR 文本中定位前缀边界，再转 UTF-16 或 canonical units；渲染时不得切开组合字符或 emoji。

音频范围的时钟域、采样率、epoch 起点必须从当前 machine schema 和实现确认。内部统一记录 `sampleRate`／`clockDomain`，跨域转换使用有状态、整数时间轴映射。没有词级证据时，音频范围只表示输入覆盖，不是“每个字说出的精确时间”。[R07]

### 6.3 来源引用示例

下面是**建议的本地对象示例，不是已经上线的 API 请求**。合成原文与显示正文均为“试运行期间，方案 A 的单次成本不超过 50 元。”，假设它是来源文档的第一个单元：

```json
{
  "block_id": "b_017",
  "block_revision": 4,
  "source_refs": [
    {"unit_id": 0, "source_revision": 2, "utf16_start": 0, "utf16_end": 25}
  ],
  "display_text": "试运行期间，方案 A 的单次成本不超过 50 元。",
  "disposition": "accepted",
  "accepted_readings": [
    {"display_utf16_start": 20, "display_utf16_end": 24, "spoken_forms": ["五十元"], "kind": "quantity"}
  ],
  "cue_notes": [],
  "validation": {"rule_version": "fidelity-1", "status": "reviewed"}
}
```

以上偏移已按所列合成文本计算。生产中的范围仍必须由程序计算和测试，不能由模型生成或人工猜写；模型只能引用程序提供的来源 ID。

### 6.4 冻结版本与恢复阅读位置

- `runningVersion` 固定正文、辅助标注、别名索引和来源关系，直至关闭本次舞台。
- 编辑草稿、后台 AI 返回或重新分组不能改变正在阅读的版本。
- 在同一 version、同一 blockRevision 下恢复精确 UTF-16 位置；范围越界要夹取并提示，不导致崩溃。
- 新版本若对应块文本未变，可迁移位置；文本改变则回该块开头或请求用户选起点，不把旧偏移硬塞进新文本。
- 无法可靠映射时保留旧版本进度，不静默回到随机段落。
- 布局行只是缓存；不能保存行号作为跨字号、跨窗口尺寸的阅读位置。

### 6.5 本地持久化迁移

按“读取旧格式 → 内存迁移 → 验证 → 备份／原子写入新格式”的顺序执行。持久化版本号由实现者依据实际 store 定义选择，本文不预占一个未经核实的版本号。

旧稿件缺少新辅助字段时默认“未生成／待派生”；不因缺字段丢弃稿件。读法别名、布局索引与诊断缓存可重建；原稿、确认正文、来源引用与用户决定不可丢失。

UI 设置增加新键时有明确默认值；不要强制重置用户字号、透明度、窗口位置和行数。文件损坏应保留原文件并提示恢复，不用空白文档覆盖。

## 7. 语音跟随最佳实践及技术选型

### 7.1 一手资料与可迁移结论

| 来源 | 已核实机制 | SpeechRail 采用方式 | 不应推断的结论 |
|---|---|---|---|
| PromptSmart 官方 | 停顿／即兴发挥时停止，回稿后恢复 | 把等待和回稿恢复当正常状态 | 不据此声称中文准确率或误跳率 |
| Elgato 官方使用说明 | 明确选麦克风，等待 Active 后开始 | 准备检查与就绪反馈 | 不复制其硬件或整个软件体系 |
| Elgato Camera Hub 2.0 发布记录 | 短语级高亮与阅读位置调节 | 采用短语提示而非强制逐字跳动 | 不称其为当前最新版本 |
| Apple SpeechAnalyzer | 区分 volatile／finalized，结果可带音频时间范围 | 借鉴事件语义与时间映射 | 不认为任意机器／语言都无需能力检查 |
| UFAL Whisper-Streaming | LocalAgreement 稳定确认思路 | 只在缺少有效稳定证据时设计本地确认 | 不照抄固定等待次数或宣传延迟 |
| MLX Qwen3-ASR 上游 | 稳定前缀、修订控制、独立强制对齐路径 | 核验仓库锁定版本，优先贯通现有能力 | 不把上游最新 README 等同安装版本 |
| OpenAI Realtime 官方 | 按 item 关联结果，不能假设跨轮完成顺序；评测真实语言和复杂字面量 | 完善客户端时序测试与效果指标 | 不把本地 SpeechRail 扩展冒充官方字段 |

资料见 [W01]—[W07]。本表只提炼与方案有关的机制，不复述上游性能排行榜，也不将厂商功能声明当作本项目实测。

### 7.2 引擎选择决策

**主方案：继续使用当前 MLX Qwen3-ASR 生产路径。**

先记录 active profile、实际模型 revision、量化身份和 `engine_revision`，再查实际安装引擎是否输出稳定前缀。若上游支持但锁定版本不支持，单列受控升级任务；不得用 `len(text)` 冒充稳定前缀长度。[R09][W06]

**备选：Apple SpeechAnalyzer，仅作为独立评估项。**

必须共用业务侧跟读接口和同一评测集，并核查系统版本、支持 locale、模型资源与隐私边界。若要把模型推理引入 macOS App，需要先修改现有“App 不加载模型”的架构决策；不能在一个普通优化 PR 中绕过服务层边界。[R01][W04]

**不作为首发主链：实时声学强制对齐。**

公共服务已有可选 Alignment，但启动它会改变资源和内存处理路径。先用于显式授权的排练后分析或离线评测，不让实时滚动等待它，也不据“对齐成功”判断讲者一定说了稿上每个字。[R07][W06]

### 7.3 本轮智能化边界

- 自动化的是“根据证据判断读到哪里”，不是“替用户决定讲什么”。
- ASR 稳定性、文字相似度、位置连续性、显示动作四个层次分开。
- 精确数字、单位和否定不启用激进语义近似。
- 不使用全稿强制提示让 ASR 输出预期答案，再拿该答案证明用户已读到那里。
- 不用“AI 已理解你的意思”替代不确定状态。

## 8. 智能跟随架构与决策算法

### 8.1 分层结构

```text
MicrophoneCapture / SessionCoordinator
             │
             ▼
既有 Realtime 服务与 ASR worker
  delta / hypothesis / final / failure
             │
             ▼
RealtimeASRClient：协议、序号、epoch、revision 校验
             │
             ▼
TeleprompterEvidenceAdapter（建议新增或并入现有 adapter）
  稳定前缀、输入音频水位、去重、坐标转换
             │
             ▼
TeleprompterAligner
  连续匹配 / 重读候选 / 附近回稿 / 远距候选
             │
             ▼
TeleprompterFollowController + FollowPolicy
  决定是否确认、是否允许回退、是否允许跳转
             │
             ▼
TeleprompterViewportPolicy（建议新增纯策略）
  行边界、迟滞、预读内容、减少动效
             │
             ▼
StageView：仅渲染与分发用户操作
```

先通过现有 `TeleprompterRealtimeClientProtocol` 注入 fake client 验证生产编排，不创建只在测试中使用的“替代生产逻辑”。[R02][R11]

### 8.2 消费已有契约，不重复造协议

基线契约已经定义：

```text
公共 envelope：event_id / session_id / sequence
hypothesis：task_id / epoch / utterance_id / revision / text
            sample_span / stable_prefix_codepoints
final：item_id / transcript / 可选 commit_event_id
```

`completed` 不能因提词器需要，就被当作必然携带所有 hypothesis 元数据；未见过 hypothesis 的 final 必须有明确处理路径。[R07]

实施步骤：

1. 从 worker 输出到服务端 hypothesis，核对稳定前缀来自哪种真实证据。
2. 核对服务端字段是否符合当前 machine schema 与字段责任表。
3. 核对 `RealtimeASRClient` 和通用 metadata 已保留哪些信息；不要重复复制 sequence validator。
4. 对提词器确实需要且尚未保留的信息增加类型化传递。
5. 让 reducer 接收经过验证的 evidence，而不是自由拼接的原始字符串。
6. 同步检查会议、字幕、语音助手等共享客户端调用点，避免修改 Event 后遗漏分支。

### 8.3 建议内部证据对象

```text
FollowEvidence
  runGeneration
  scriptVersionID
  sessionID
  eventSequence
  itemID
  taskID? / epoch? / revision?
  kind: stableDelta | hypothesis | final | failure
  textSnapshot
  stablePrefixCodepoints?
  audioSpan? { start, end, clockDomain, sampleRate }
  receivedAtMonotonic
  stabilitySource: backendVerified | locallyConfirmed | none
```

这是内部对象，不是新增 wire schema。可选字段必须保留“未知”语义，不能填 0 冒充真实 epoch／音频起点。`receivedAt` 是接收时间，不是发音时间。

### 8.4 事件处理不变量

1. generation 或 scriptVersion 不匹配：立即忽略，不能更新位置、预览或状态。
2. 公共 envelope 序号违规：使用现有协议失败路径；不要在 reducer 私自猜测缺失事件。
3. 同一 item 的旧 revision／重复 event：不重复应用。
4. hypothesis 按全文替换；delta 仅追加一次。两者并存时不能把同一稳定前缀累计两次。
5. 稳定前缀范围必须在当前原始文本内；若声称稳定的旧前缀发生变化，记录契约不一致并暂停自动推进，不静默夹取成“合法”。
6. final 只确认对应 item；旧音频的 final 不能因到达较晚就夺走新位置。
7. 无 hypothesis 的 final：利用现有 item／commit／音频账本能证明的关系；无法证明时只允许安全局部匹配，不授予远距跳转权限。
8. 本地去重按 event／item／revision，不按全文相等；用户真说了两次“非常”，不能被当作重复网络包删掉。
9. 音频水位必须来自输入覆盖，不把不断增长的 eventSequence 当成新增语音。
10. 正常停止后的终态可用于关闭屏障，但手动接管已撤销其推进权。

### 8.5 三个位置

| 位置 | 含义 | 更新条件 |
|---|---|---|
| `hypothesisPosition` | 当前猜测的位置 | 合法 partial／hypothesis 可更新，不直接持久化 |
| `committedPosition` | 已有足够证据的阅读位置 | 稳定证据＋匹配正确性＋移动权限通过 |
| `viewportAnchor` | 实际屏幕阅读锚点 | 已确认位置、布局与用户动作共同决定 |

不要直接把 `position = partialMatch` 作为最终 UI 状态。低证据猜测仅可在当前可见范围内做轻量提示，不能移动整页或抢走下一句。

确认位置不是永久单调：用户重读可以合法回退。但回退必须有独立的重读决定，不能由普通 partial 修订或匹配失败自动触发。

### 8.6 跟随状态与推进权限

保留现有生命周期状态机，阅读状态可按下表细化；同义状态不再平行维护第二套布尔变量。

| 状态 | 进入原因 | 自动移动权限 | 离开方式 |
|---|---|---|---|
| Manual | 尚未开语音、用户手动操作 | 无 | 显式开启／恢复 |
| Ready | 已就绪，尚无定位证据 | 无 | 收到有效语音证据 |
| Tracking | 连续证据明确 | 局部确认推进 | 证据不足、用户接管或失败 |
| Holding | 停顿或短暂不确定 | 无新证据不推进 | 新有效证据；不强制断开采集 |
| OffScript | 连续语音明显不属于附近稿件 | 无 | 找到可靠回稿候选或手动定位 |
| Reacquiring | 正在验证回稿候选 | 不直接跳转 | 达到回稿证据条件 |
| Unavailable | 服务／设备／协议失败 | 无 | 明确重试或继续手动 |

`Holding` 不应让每次呼吸停顿都断开 ASR。`Manual`／用户暂停则按既有约定释放本功能资源；不能把短暂停顿和主动停用混淆。

### 8.7 四类匹配动作

#### A. 连续跟读

先搜索当前位置与相邻语义句，允许口头禅、少量改词、插入和删除。优先“连续、附近、唯一”的路径，不能让远处高分短语压过当前位置附近合理路径。

#### B. 明确重读

识别新音频中的当前句／上一句重新出现，结合新音频水位、句首片段和连续证据确认。仅因 ASR 把上一版本改短不能判定重读。用户点击“回本句”是强证据，立即生效。

#### C. 附近回稿

脱稿时保持位置；读回当前或附近句子后可自动恢复。需要排除重复模板句，利用前后短语和当前位置先验；不强制用户逐字重复一个预设口令。

#### D. 远距重新定位

跨多个句子或章节的候选单独评估。要求更长且稳定的连续证据、候选间足够差距、合理的章节关系；必要时由用户显式选章节。一个远处唯一关键词不能获得普通连续跟读权限。

### 8.8 分级搜索与排序

建议保留现有有界编辑距离，增加搜索层级与动作类别，避免第一阶段直接引入不可解释的复杂学习系统。

```text
L0：当前语义句及紧邻范围
L1：附近段落（用于小范围跳读、重读、回稿）
L2：当前章节的候选定位
L3：全稿检索，仅用于显式定位或候选提示，不默认自动跳转
```

候选排序至少考虑：编辑匹配分数、匹配长度、当前位置连续性、距离、罕见片段信息量、重复位置竞争、文本稳定性和动作类别。参考表达式：

```text
rank = lexicalFit + continuity + informativeEvidence
       - jumpPenalty - ambiguityPenalty
```

这不是概率公式，系数不能直接据经验硬编码上线。使用独立开发集调优，保留测试集验收。中文字符数和英文词数不能共用未经验证的最小长度阈值。

初始实现可延续当前搜索边界作为计算上限，再以语义句范围收紧候选；不得简单扩大到全稿来“修复回稿困难”。[R03]

### 8.9 推进决策伪代码

```text
onEvidence(e):
    reject stale generation / wrong script / invalid envelope
    update bounded item state using delta-or-replacement semantics
    classify stability and new-audio evidence

    if user has manual authority:
        keep manual position; do not auto-resume
        return

    candidates = align within the permitted search tier
    decision = decide(candidates, committedPosition, history, stability)

    if decision is low-evidence or ambiguous:
        update local preview only; keep committedPosition and viewportAnchor
    else if decision is continuous advance:
        advance committedPosition to evidence-supported end
    else if decision is repeat or reanchor:
        require corresponding stronger evidence before changing position

    derive viewportAnchor from committedPosition and layout policy
    persist only allowed reading progress, never ASR text
```

`history` 是有界运行期匹配上下文，不是完整转写库；每次手动接管、版本变化和 generation 更新都清理或退休旧历史。

### 8.10 稳定确认策略

优先使用后端经过验证的稳定前缀。如果只有可修订结果，才使用本地连续一致确认。两次一样的快照不自动等于两次独立证据：需检查新音频覆盖和新增有效匹配内容。

不要在已经稳定的前缀上再次无条件等待多个完整窗口。确认策略应同时测量延迟和错误推进，不为追求低延迟绕过歧义保护。

长时间没有新稳定文本不等于用户脱稿：可能是识别服务延迟。应分别识别“有音频但无文本”“有文本但不匹配”“没有语音活动”，使提示和降级原因准确。

### 8.11 视觉跟随策略

- `viewportAnchor` 以实际排版行为单位更新，跟读坐标仍是朗读稿 UTF-16 范围。
- 当前短语可轻量突出；下一行持续可读。预读内容不等于已读进度。
- 只有证据支持已跨过行边界，才更新当前行；处理好 end-exclusive 边界，避免漏行／多进一行。
- 正常 partial 修订不触发整行后退；合法重读与手动操作可以回退。
- 避免同一行多个字符变化重复触发整窗动画；状态角标变化不能重排正文。
- 遵守 Reduce Motion；动画不承担唯一状态信息。
- 重排字体／列宽时保持来源锚点，不恢复旧屏幕行号。
- 停顿时允许迟到结果补齐“停顿之前确实已读”的位置，但不能推算尚未说出的内容。
- 默认不根据预计语速前移确认位置，也不靠定速滚动掩盖 ASR 延迟。

### 8.12 必须解决的反例

1. 当前在稿首，说到后文唯一出现的“稳定性”：不得跨 100 个单位自动跳转。
2. 两段都包含“下面介绍三个重点”：缺乏消歧证据时保持，而非取第一或最高相似段。
3. partial 前进后 final 纠正文字：不出现无意的画面往返。
4. 用户连续说“先看成本。先看成本。”：第二次确有新音频，应考虑重读，而非按相同字符串去重。
5. 中文数字与英文术语混读：受限读法可对齐，数值或单位不同不能被近音匹配抹平。
6. 关闭语音后收到 drain final：只完成资源清理，不改变舞台位置和手动状态。
7. 同一稿件不同 revision 的回包：不能更新新运行快照。
8. 相同音频重复发来的快照：不能累计成远距跳转所需的多份证据。

## 9. 音频链路、资源与延迟治理

### 9.1 复用与边界

复用现有 `MicrophoneCapture`、`RealtimeASRClient`、`SessionCoordinator`、能力绑定、Resource Governor 和单服务约束。提词器不直接加载模型，不注册第二个 ASGI worker，不在前台和服务端各做一遍互相冲突的语音分段。[R01][R05]

语音跟随默认不请求 Alignment、Diarization、TTS；不得为“智能化”自动开启这些额外资源。跨 lane 并发只按 active profile 真实声明执行。

### 9.2 配置与语言

- wire 固定为当前契约规定的 24 kHz mono PCM16；内核重采样由服务端负责。[R07]
- 主语言使用当前 resolver 接受的语言值；自动检测按正式字段默认语义表达，不发未支持的任意 alias。
- 中英混读先作为实际评测场景，不能认为强制 `zh` 必然最优；比较合法配置后决定默认行为。
- 术语通过现有 `keywords`／服务端适配链传递，限定长度和数量；优先词条，不发送整份稿件作为预期转写。
- 术语表中的用户输入仍是数据；不能进入系统指令角色。
- 语言和词表在开启本次跟随前确认；运行中修改是否允许，以当前 schema 为准，不随意热更新。

### 9.3 VAD 与声音来源

公共契约未实现官方 `speech_started`／`speech_stopped` 事件；不能在 UI 或测试中假装这些事件存在。使用已有 SpeechRail endpointing 扩展时按其真实支持范围配置。[R07]

麦克风电平可用于“收到声音”的反馈，不是说话人身份和稿件位置证据。VAD 也不能证明讲话的是目标用户。

第一阶段限定用户明确选择的麦克风，不自动混入系统音频。扬声器播放、旁人说话与回声纳入测试。不要用未经校验的 VAD 激进裁剪上行 PCM，以免吞掉起始音节和轻声内容。

### 9.4 设备切换和中断

当前客户端对 wire 格式与会话边界已有约束；优先在保持同一 wire 格式的前提下处理设备重建，不能把所有设备切换都粗暴变成重开服务。[R08]

发生拔插、采样率变化、蓝牙重连或输入中断时：

1. 立即禁止无新有效音频的自动推进，保留当前稿件位置。
2. 检查能否在既有会话边界内安全恢复采集与时间轴。
3. 不能保证连续时，进入明确暂停／不可用状态，清理本功能资源。
4. 用户显式重试后，建立新的语音 generation；若需重建连接，按正式生命周期执行。
5. 不因系统默认麦克风变化，静默改用另一输入源并继续推进。

### 9.5 延迟预算与调优顺序

```text
端到端跟随延迟
  = 采集／传输缓冲
  + 等待解码窗口
  + 模型推理
  + 稳定证据等待
  + 事件与匹配队列
  + 渲染确认
```

当前 worker `chunk_duration_ms` 的默认值为 1000，但它不是端到端延迟，也不代表恒定延迟。[R09]

调优顺序：先测量 → 清理重复等待与队列堆积 → 区分发送 chunk 和模型解码窗口 → 比较实际支持的窗口配置 → 比较经过认证的模型／精度档位 → 重验准确性与稳定性。

不在文档中指定未经实际引擎确认的最小窗口。候选窗口、音频块大小和本地确认策略通过配置化实验表确定；只测试合法参数，不在错误时静默夹取为另一个设置。

### 9.6 背压与有界性

- 当前 item 的可修订 hypothesis 可以 latest-wins，但要保留使稳定信息可解释的完整快照。
- delta 不能直接丢弃；先安全合并为当前文本状态，再合并下游展示通知。
- final、failure、取消屏障和资源终态不能作为普通预览丢弃。
- 匹配计算过慢时，取消旧候选工作，只应用与当前 revision 对应的结果。
- 缓存和队列都有字节／项目上限；超限进入明确降级，而非无限增长。
- 长稿索引按固定版本构建一次；不要每个 partial 对整稿重新 canonicalize 或重排全部文本。
- 无模型、无音频、无舞台时，提词器不能继续保留本功能采集或上传任务。

### 9.7 诊断与隐私

生产诊断只记录有界聚合值：队列年龄、匹配耗时、位置动作类别、拒绝原因、错误数量与资源释放状态。沿用现有脱敏观测机制，不记录原始音频、Base64、完整 prompt／transcript、声纹、实名或绝对模型路径。[R01]

识别文本、item ID、用户术语和由正文派生的标识不得进入通用日志或错误遥测。为调试所需的细粒度回放，只允许使用明确授权的离线测试材料，放在仓库外；不能把生产会话“顺手录下来”。

同一设备内可用单调时钟测队列与渲染间隔；跨进程时间需明确关联方法。没有真实音频时间标签时，仅报告采集／发送／接收等分段延迟，不伪称“发音到逐字高亮延迟”。

#### 开发集

建议先准备不少于 6 位明确同意的成年讲者，每人完成 3 段约 4 分钟的任务，形成约 72 分钟材料。任务覆盖普通话口播、中英技术讲解与带停顿／重读／脱稿的自然表达。该规模只是启动建议，不是统计充分性的保证。

#### 发布保留集

建议扩展到至少 12 位讲者、累计不少于 8 小时，并覆盖普通话、混合术语和英语。开发／保留集按讲者及稿件划分，防止同一声音、同一模板同时进入调参和验收。

另做单次 60 分钟以上的连续运行，并多轮启停检查。具体材料长度和使用权限由实施时明确，不把本计划视作录音许可。

素材存放在仓库外受控位置。仓库只保存无敏感内容的 manifest、构造型测试片段和匿名聚合结果；不提交音频、完整真实转写或模型 snapshot。测试 runner 从外部素材读取，不扩展生产会话的录音能力。

#### 标注内容

- 稿件版本与人工确定的阅读位置变化。
- 正常读、停顿、重读、脱稿、回稿、跳读等意图。
- 首个足以定位的回稿片段及其音频时间。
- 系统动作应该发生、可以发生或不能发生的区间。
- 干扰声音与设备事件。

时间标签由人工核验；强制对齐可辅助，但不能成为唯一真值。不能把待测 ASR 的输出直接当作标准答案。

### 11.6 指标定义

| 指标 | 定义 | 防止自欺的约束 |
|---|---|---|
| 严重误推进 | 未获用户授权且没有对应已读证据，越过至少一个完整未读语义句，或跳到错误章节 | 按事件数与运行时长报告；不能只看平均位置误差 |
| 正常跟随延迟 | 人工标注的可识别片段结束，到正确确认位置反映到 UI 的时间 | 不因下一句本来可见就记为 0 |
| 错误停滞 | 正常可匹配朗读中超过预设时限仍不确认推进 | 必须与误推进一起报告 |
| 回稿恢复延迟 | 第一个可辨识回稿片段结束，到恢复可靠跟随 | 含糊短语另报；超时算失败，不删除样本 |
| 无意回跳 | 没有重读或手动意图的反向整行动作 | 以动作与音频标注联合判断 |
| 人工纠正 | 为修正系统错误而手动定位／恢复的次数 | 正常翻章和用户主动跳读单独计数 |
| 稿件硬错误漏检 | 构造的确定性数值／单位／标识符错误未阻断或提示 | 全部人工确认不等于自动检测成功 |
| 风险误报率 | 正常无损改写被要求人工处理的比例 | 防止审阅流程退化为全量逐句确认 |
| 任务完成率 | 用户完成指定表达且未因提词问题中断重来 | 区分内容口误与工具故障 |

所有延迟报告 P50／P95、样本数、语言、设备、模型与运行条件；超时和未匹配数量单列。若失败样本超过 5%，不能仅对成功子集给一个看似达标的 P95。

### 11.7 建议初始质量目标

以下数值是 **P：待建立基线并确认的工程目标**，不是实测承诺，也不是行业统一标准。

| 项目 | 建议初始门槛 | 判定方式 |
|---|---|---|
| 确定性高风险用例 | 全部应阻断或明确转审阅 | P-02～P-10 等逐项核验 |
| 旧 generation／手动接管 | 零越权推进 | L1＋L2 强制门禁 |
| 正常手动操作 | P95 ≤100 ms | 目标设备，输入到正确画面 |
| 无歧义连续跟随 | P95 ≤1000 ms | 真实音频，按语言独立报告 |
| 附近回稿恢复 | P95 ≤2000 ms | 有明确定位片段的样本，失败不隐藏 |
| 正常朗读错误停滞 | 超过 3 秒的事件比例应低于 1% | 按可匹配片段统计，标明分母 |
| 严重误推进 | 对抗回归零事件；保留集观察零事件 | 同时报总时长，不声称真实发生率为零 |
| 长时资源 | 无本功能持续泄漏、无无界队列增长 | 多轮启停＋长时测试 |
| 体验改进 | 人工纠正不多于基线，任务完成率不降低 | 同一材料的配对比较 |
| 隐私与持久化 | 零新增敏感日志、零稿件数据丢失 | 检查输出、权限与迁移故障测试 |

“8 小时观察到零严重事件”不能证明真实误跳率为零。作为简单近似，在独立稳定事件过程假设下，零事件的 95% 上界约为 `3 / 总小时数`；8 小时约为 0.375 次／小时。该计算用于提醒样本边界，不作为产品性能宣称。

若达不到语音门槛，可以继续发布手动与稿件加工改进，将新自动策略保持实验状态；不能通过删除困难样本或改口径宣布通过。

### 11.8 评测与消融顺序

```text
A：原始基线
B：A + 修复保真门禁（加工单独评估）
C：A + 稳定性证据消费
D：C + 分级定位／远距权限
E：D + 三位置与显示迟滞
F：E + 读法词表／经过验证的音频参数
```

每次只改变一个主要因素；同一批输入按 1 倍速重放。比较延迟、误推进、停滞、回跳和人工纠正，不只比较 CER／WER。确定默认策略后，在保留集执行一次冻结版本验收；测试集不能反复用于调参。

| 输出 | 脱敏聚合结果；不能默认输出音频、完整正文或转写 |
| 失败 | 失败样本、超时、资源中断有单独状态，不归为 0 错误 |

<a id="s14"></a>
## 14. 迁移、发布与回退

### 14.1 发布阶段

| 阶段 | 可以交付的内容 | 进入下一阶段的条件 |
|---|---|---|
| G0 基线冻结 | 文档、生产反例测试、匿名指标格式 | 风险与现有能力盘点完成 |
| G1 安全修复 | 硬门禁、远距权限、手动越权保护 | 确定性与生产 seam 回归通过 |
| G2 智能跟随候选 | 稳定证据、重定位、三位置显示 | 音频回放优于或不弱于基线；无安全回归 |
| G3 体验整合 | 审阅、显示预设、试读与排练 | 目标任务、可访问性、数据迁移实测 |
| G4 受控正式发布 | 已验证的语言／设备／场景 | 保留集、长时与真人门禁完成，限制说明齐全 |

任何阶段都可独立交付已验证价值，不必等待提纲语义跟随或新 ASR 引擎。P0 修复不应被大型界面重构长期阻塞。

### 14.2 功能控制

避免永久保留“旧协议／新协议”“旧 store／新 store”“旧算法／新算法”三套双轨。

允许少量本地、期限明确的实验策略控制，例如自动远距重定位、未验收的轻量提示；由开发／测试入口管理，不在普通用户首屏暴露大量算法开关。正式验收后选择一条默认路径，清除过渡代码。

安全硬门禁和旧 generation 失效不能作为可被普通用户关闭的“实验功能”。语音不可用时降级手动，而不是自动退回已知会误跳的旧策略。

### 14.3 数据迁移验收

发布前对无敏感测试稿件执行：旧版本读取、新格式写入、中途失败、损坏恢复、新版本位置迁移、回退只读。验证源文、确认稿、来源映射和用户选择逐项保留。

备份保存在同一安全的本地数据边界，不能把用户稿件打包进公开 issue 或 CI artifact。可派生缓存失效后重建，不能以“重建缓存”为名删除原稿。

### 14.4 回退优先级

1. **推进安全**：停止新自动决策，保留当前稿件与手动操作。
2. **资源正确**：撤销 generation，释放本功能采集、上传和占用；不停止不属于提词器的其他任务。
3. **数据完整**：不删除／降级重写用户文档；旧程序不支持新格式时只读或导出。
4. **代码范围**：只撤回本工作包的差异，不回滚并行项目的整文件。
5. **证据保留**：保留匿名失败统计与版本号，修复后以同一案例验证。

### 14.5 用户说明应包含什么

说明支持的语言／场景、手动接管与恢复、语音需要显式开启、稿件加工可能需要审阅，以及录屏选择目标窗口的边界。不使用“绝不误跳”“识别百分百准确”“任意脱稿都能自动找回”等未经证据支持的表述。

## 15. 风险、待决事项与完成定义

### 15.1 主要剩余风险

| 风险 | 控制方式 | 未消除的边界 |
|---|---|---|
| 保真校验误报过多 | 分层校验、出现映射、审阅负担评测 | 复杂语义不能完全自动证明 |
| 跟随过于保守 | 同时测错误停滞与纠正次数 | 低质量音频下仍可能需要手动 |
| 误把第三方声音当用户 | 明确输入源、干扰评测、限制远距权限 | 不声称已具备可靠说话人身份识别 |
| ASR 稳定但识别错误 | 稳定性与匹配分开，数值严格、距离约束 | 稳定前缀不是正确性概率 |
| 新协议接线影响其他功能 | 共享调用方回归、单一契约 | 跨功能集成必须实际验证 |
| UTF-16／codepoint 混用 | 显式类型与 Unicode 反例 | 不能依赖人工偏移编写 |
| 大稿与慢模型积压 | 有界队列、取消旧工作、分段测延迟 | 不能靠无限缓冲维持表面顺滑 |
| 未经授权收集敏感素材 | 生产不录制、外部授权数据集、脱敏输出 | 评测便利不能扩大数据权限 |

### 15.2 实施时需要确认但不阻塞方案形成的事项

| 事项 | 本方案默认决策 | 何时确认 |
|---|---|---|
| 实际基线是否变化 | 以本提交为分析证据，执行前重新固定工作基线 | TP-00 |
| `stable_prefix_codepoints` 运行时证据 | 先审计已有链路，不假定全部丢失或全部可用 | TP-00／05 |
| 当前模型档位与引擎版本 | 使用 active profile 的真实身份，不指定新下载 | TP-00 |
| 镜头预设具体字号／列宽 | 复用现有 Token，按真实视觉调优 | TP-09 |
| 自动远距重定位默认开关 | 默认保守；未过门禁不开放 | TP-06／11 |
| 精简操作的内容权限 | 显式有损操作，候选审阅后生效 | TP-04 |
| 新 ASR 后端 | 不进入第一阶段，先独立评估与 ADR | 核心闭环验收之后 |
| 精确声学跟随 | 第一阶段不作承诺，Alignment 作为独立选项 | 后续专项 |

### 16.3 关键验收案例的 Given／When／Then

**案例 A：远处唯一短语**

- Given：锚点位于稿首，后文第 100 个 canonical unit 附近唯一出现“稳定性”。
- When：用户在脱稿补充时只说出“稳定性”。
- Then：可内部产生远距候选，但不能确认或移动到后文；当前稿件位置保持。
- And：当用户明确选择后文段落，再开启跟随时，该短语可以成为新局部上下文的一部分。

**案例 B：数字关系变化**

- Given：原文为“方案 A 为 50 元，方案 B 为 80 元”。
- When：候选把 A／B 数值互换。
- Then：仅证明两个数值都存在不够；关系风险必须可见，不能自动判定保真。

**案例 C：真正重读与 ASR 修订**

- Given：用户已读完一句，画面已确认。
- When 1：同一音频的 hypothesis 被修订变短。
- Then 1：不把这次修订当作用户重读，不整行回跳。
- When 2：新的音频表明用户从本句开头重新说起。
- Then 2：满足重读证据后允许合法回退；不能用“显示绝不后退”阻止真实行为。

**案例 D：手动接管**

- Given：正在语音跟随且有未结束的 item。
- When：用户按上一行。
- Then：立即进入手动位置，旧 generation 失去推进权；随后收到的 final 只参与旧资源收口，不能夺回舞台控制。

**案例 E：无稳定元数据**

- Given：本轮后端只有合法可修订全文，没有有效稳定前缀。
- When：客户端接收快照。
- Then：保持 unknown／none，按已验证的保守本地策略处理；不得把整份文本长度标成 stable。

**案例 F：实际音频与确认延迟**

- Given：人工标注用户在某一时间说完可唯一定位的短语。
- When：模型和控制器处理后更新 UI 确认位置。
- Then：记录完整延迟；如果未定位或超时，记录失败，不能从 P95 样本中无声移除。
