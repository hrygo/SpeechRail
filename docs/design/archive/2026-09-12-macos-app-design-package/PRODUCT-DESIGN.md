# SpeechRail macOS App 产品与交互设计方案

## 1. 产品定位

SpeechRail 的 macOS App 不应该只是 CLI 的 GUI 包装，而应成为：

> **一个面向普通创作者的本地声音工作台：创造声音，把故事演出来。**

它在产品层承担两类职责：

1. 把 SpeechRail 本地语音引擎变成无需终端即可使用的能力。
2. 提供以“文字音色设计 + 多角色故事配音”为核心的创作工作流。

Sona 继续承担实时语音助手、会议、实时字幕和会中工作流；SpeechRail App 聚焦声音资产与故事演播。

## 2. 目标用户

首版面向：

- 有小说、故事、脚本内容，需要快速制作有声内容的人。
- 不希望学习 Python、端口、模型仓库等工程概念的人。
- 重视隐私，希望在 Apple Silicon 本机完成处理的人。

不把开发者排除在外，但开发者能力退居高级入口。

## 3. 信息架构

### 配音台

作品级工作空间。

包含：

- 原文 / 演播稿切换
- 角色归属
- 当前角色音色
- 发声片段状态
- 局部生成与重生成
- 多版本试听
- 整篇生成
- 连续播放
- 导出

### 音色库

声音资产中心。

包含：

- 内置音色
- 用户自定义音色
- 搜索 / 标签 / 试听
- 文字描述设计声音
- 后续可扩展参考录音克隆

### 我的作品

保存创作上下文：

- 原始小说文本
- 演播标注
- 角色表
- 角色 → 音色绑定
- 每个发声片段对应的生成版本
- 用户最终选中的音频
- 导出记录（如需要）

## 4. 新建作品流程

### 4.1 粘贴小说

允许：

- 直接粘贴正文
- 后续支持 TXT / Markdown 导入

默认不要求用户先按剧本格式整理。

### 4.2 智能整理

目标：识别：

- 旁白
- 对白
- 可能的说话者
- 未命名角色
- 无法确定说话人的片段

输出不是“重写后的剧本”，而是原文之上的结构化标注。

### 4.3 角色校对

高频操作必须可就地完成：

- 更换说话者
- 合并角色别名
- 从一个角色拆出新角色
- 拆分旁白与对白
- 将片段恢复为旁白
- 人工确认后锁定归属

## 5. 文字音色设计

这是 SpeechRail App 首版最重要的差异化能力。

### 5.1 两类起点

- 旁白声音
- 角色声音

角色声音优先面向故事人物。

### 5.2 用户输入

用自然语言描述，例如：

> 年轻男性，声音清亮但不尖细，带一点未经磨平的粗粝感。咬字清楚，自然直接，适合一个好奇、倔强、还有少年气的旅人。

不要求用户理解模型 Prompt 工程。

### 5.3 风格示例

示例可以包括：

- 少年冒险者
- 沉稳旁白
- 神秘反派
- 温柔伙伴
- 古风角色
- 冷静守门人

示例只是可编辑起点，不是不可变模板。

### 5.4 候选生成

默认先生成一个候选；用户可继续生成，最多并排比较约 3 个。

比较时应固定试听文案，减少文本差异对判断的干扰。

### 5.5 换文本验证

用户选中候选后，再用另一段文本试听，检查跨文本一致性。

必须明确区分：

- 设计候选试听
- 保存为音色资产
- 使用音色执行实际配音

### 5.6 保存并绑定

音色保存后，可：

- 仅保存至音色库
- 保存并立即绑定当前角色

## 6. 多角色演播工作台

### 6.1 文稿优先

中央区域是连续可读的小说/演播稿，不采用聊天气泡或巨型任务卡。

角色标记使用：

- 文本名称
- 颜色辅助

不能只用颜色，因为需要兼顾可访问性。

### 6.2 角色侧栏

显示当前作品的角色：

- 旁白
- 角色名
- 角色描述
- 绑定音色
- 试听
- 更换声音
- 设计新声音

### 6.3 单段详情

选中片段后，右侧 Inspector 展示：

- 发声者
- 台词
- 演绎备注
- 当前音色
- 音频版本
- 重新生成
- 恢复旧版本

## 7. 音频版本与一致性

每个生成结果至少关联：

- 原文/台词内容 Hash
- 角色 ID
- 音色 ID / Revision
- 有效生成参数
- 创建时间

这样 UI 才能可靠判断：

- 当前音频仍然有效
- 文字已修改
- 音色已更换
- 参数变化需要重新生成

旧结果保留为候选，而不是被新结果覆盖。

## 8. 全篇生成

用户只需要理解三个动作：

1. 试听当前段
2. 生成选中段
3. 生成全部待完成段落

全篇生成支持：

- 实时进度
- 已完成段落立即可试听
- 单段失败不毁掉整个任务
- 用户取消后保留已完成结果
- 后续继续生成剩余片段

## 9. 播放体验

连续播放必须处理角色切换之间的自然衔接。

特别是：

> “别动。”林川压低声音说，“门外有人。”

不能因为内部被拆成三个生成片段，就出现三个明显的机械停顿。

需要区分：

- 同一句内切换
- 句末停顿
- 段落停顿
- 章节停顿

首版不需要多轨 DAW，但连续播放的听感必须像完整作品。

## 10. 导出

主操作：**导出完整合并音频**。

次级操作：

- 分段导出
- 后续可扩展字幕 / 文本等伴随文件

导出前执行完整性检查：

- 是否存在未生成段落
- 是否存在正文已修改但音频未更新
- 是否存在角色已换音色但仍使用旧版本
- 是否存在未分配声音的角色

不能静默跳过问题段落。

## 11. 视觉语言

### 原则

- 原生 macOS 感
- 浅色为首轮设计基线
- 支持系统深色模式
- 大面积留白
- 内容优先于装饰
- 系统材质适量使用
- 波形只在有交互意义时出现
- 不用夸张 AI 霓虹风

### 视觉层级

1. 小说正文
2. 当前角色和当前音色
3. 生成 / 播放状态
4. 高级技术信息

## 12. 隐私与本地原则

- 默认本地推理
- 不因“智能整理”默认上传小说正文
- 用户保存的作品和音色资产需有明确持久化语义
- 日志默认不记录敏感正文 / 参考音频路径等信息
- 局域网暴露属于高级能力，不进入普通创作主流程

## 13. 与 Sona 的边界

SpeechRail App：

- 音色资产
- TTS/ASR 的轻量直接使用
- 小说演播
- 本地引擎运行入口

Sona：

- 实时语音助手
- 会议助手
- 实时字幕
- Inner OS

避免两个产品在会议和实时助手场景上重复建设。

## 14. 后续收口顺序

### P0

- 角色校对异常态
- 局部音频版本管理
- 生成失败与恢复
- 导出完整性检查

### P1

- 菜单栏
- 空状态 / 首次启动
- 音色验证状态体系

### 暂缓

- 设置
- 模型/Profile 管理
- VoiceDesign/Base 技术配置

待相关 SpeechRail PR 合并后，从源码重新分析。
