## 0. 这份文档补的是哪一种错

前面的检查都是**按格子对**：三条闭环 × 五个阶段有没有画板、每一页有几个状态、缺能力时有没有出口。
这类检查会漏掉一种错误——**每一步都有落点，但连起来走不通**。

所以这一层换成按**路径**对：把「我要做成一件事」写成一串连续的动作，逐步问三个问题：
这一步之后他人去了哪、这一步写进了哪张表、这一步失败时他退到哪。

先给结论：**8 条旅程（3 条主旅程 + 1 条首次使用 + 4 条跨模块衔接）逐格核过，全部有落点**。
其中 6 条完全落在已有画板上；2 条（助手记忆、会议中断）在 2026-09-18 这一轮补了画板；
另外 4 处不对齐落在规格或文档层面——其中 2 处是「规格已定、稿上不单独出板」的 ○。逐条列在第 9 节。

这份文档同时是**验收清单**：第 10 节给的是可以照着测的判据，不是形容词。

## 1. 先说清是谁

产品是**本机单用户**工具，所以不编造用户画像：角色就是**三种情境下的同一个人**——
「我，在这台 Mac 前说话的人」。

| 角色 | 情境 | 他要的 | 他不要的 |
|---|---|---|---|
| **A · 独处对话** | 手上在干别的，想用语音一问一答 | 快、能插话打断、它记得住上次说过的事 | 一套要先配半天的对话界面 |
| **B · 在会里** | 线上会 / 线下会 / 访谈 / 听课 | 完整文本 + 纪要 + 谁说的 + 会后搜得到 | 事后才发现有一半声音根本没录上 |
| **C · 在听** | 外语、听不清、需要留痕 | 一眼看得见、贴在屏幕上、不打扰别人 | 字幕弹出来还要切回某个 App |

三者的分工写在 `SESSIONS-SPEC §2.2`（三个「会话时刻」），这里只强调**别用错工具**的三句话：
只要文字不要分人 → 别开会议，用实时字幕；要完整记录与分人 → 别用字幕带，用会议助手；
要的是对话本身而不是文本 → 用语音助手，它才接大模型。

## 2. 旅程的七个段落（本文的坐标系）

闭环稿的五个阶段是**画板**的坐标系；旅程要多两段，因为它们发生在「产物之后」的那几天里。

| 段 | 名字 | 它回答 | 对应闭环阶段 |
|---|---|---|---|
| E0 | 起念 | 他为什么**现在**要用它 | —（不进稿） |
| E1 | 进入 | 从哪进、App 要不要在前台、要不要先授权 | ① 入口 |
| E2 | 前置 | 服务 / 档位 / 模型 / 占用：缺什么、影响谁、出口在哪 | ② 前置与受阻 |
| E3 | 这一轮的设置 | 音频来源 / 分人开关 / 人设与音色 / 对讲模式 | ②（部分） |
| E4 | 主交互 | 一来一往 / 边听边记 / 贴屏跟随 | ③ 主交互 |
| E5 | 会中插曲 | 打断 / 私密提问 / 换音色 / 回看 / 中断 | ③④ |
| E6 | 交还 | 结束、屏障、确认、不静默抢麦 | ④ 交还与守卫 |
| E7 | 产物与复用 | 落库、导出、回看、继续、维护 | ⑤ 产物与回看 |

E7 内部再分「产物」与「复用」：这两件事之间常常隔着好几天，而**隔了几天**正是「记录是资产」
这条判据要解决的问题——所以每一步的判据里都要写清「重开 App 之后还在不在」。

> **下面五节的步骤表（§3–§7）与覆盖对账（§8）同时是方案正文的一部分**：规范位置在
> `SESSIONS-SPEC.md` §16.2.1–§16.2.6。两处内容相同——**改一处就要在同一次里改另一处**。

## 3. J1 · 语音助手：从起念到下一轮

| 步 | 用户动作 | 稿上的落点 | 数据落点 | 失败与退路 |
|---|---|---|---|---|
| E0 | 手上在忙，想直接问两句 | 不占界面 | — | 不需要它时用键盘；产品不做「按住说话」 |
| E1 | 侧边栏「语音助手」（⌘6） | `语音助手 · 对话页 · 未开始（先定人设与音色）` | — | 切页**不会**自动开始（§5.4） |
| E2 | 还没配大模型 | 同一页换成 `… · 未配置模型` | — | 结论条说清「ASR/TTS 现在就能用，助手需要一台本机 OpenAI 兼容服务」，唯一出口是设置 · 会话；对话流保留为可读灰态，不是空白 |
| E3 | 选人设与音色（**只在这一步**） | 未开始态：人设 chip + 音色（可试听） | `session.persona_id / persona_title / voice_id` | 人设进 system prompt，开始后只读（§14.4）：中途换会让前缀缓存整段失效 |
| E3 | 点「开始对话」 | `… · 对话中` | `session.state='recording'`、`started_at` | 麦克风被占 → 走会话占用守卫，不静默抢 |
| E4 | 一问一答（外放，半双工） | `… · 对话中` | `line(role='user'/'assistant', status='final')` | 它说话时闭麦；回声由闭麦挡住，不靠 AEC 猜 |
| E5 | 换成实时对讲（耳机） | `… · 实时对讲（耳机 · 可打断）` | 同上 + 模式随会话记 | 换输入设备要重开会话（服务端首个 PCM 之后不收改格式），记录不丢，那一轮标「换设备」 |
| E5 | 插话打断它 | 同上：那一句挂「被打断」 | `line.interrupted=1` | 不是错误：正文保留到停下为止，可重放（§14.5） |
| E5 | 换音色（随时可换） | `… · 换音色（下一句生效）`；两个「换」的差别见 `换音色 vs 换人设（影响面）` | `session_change(kind='voice', at_ordinal)` | 被拒（音色不存在 / 档位不支持）时这一句仍用旧音色说，并给出可读原因 |
| E5 | 「这个记一下」（长期信息） | `… · 记忆（跨会话 · 下一轮生效）` ★本轮新增 | `assistant_memory(kind, body, source_session_id)` | 写入要用户确认，不静默积累；**本轮只读、下一轮生效**——记忆也进 system prompt |
| E6 | 结束对话（⌘⏎ 或状态带） | 同一页换成 `语音助手 · 记录库 · 刚结束` | `session.state='archived'`、`ended_at` | 结束时把没定稿的那一行定稿；结束**不删**记录 |
| E7 | 回看 / 复制全文 / 导出 | 记录库：列表（含搜索）+ 选中 + 详情 | 读 `line` 按 `ordinal` 排 | 导出走系统保存面板，不画伪保存（§6.2 第 3 条） |
| E7 | 「继续这一轮」 | 回到 `… · 未开始`（**新一轮**） | 新 `session` 行，预填当时的音色与人设 | 换人设只能在这里换——同一轮内不给出口，这是有意的 |
| E7 | 重命名 / 从记录库移除 | 记录库的详情区 | `session.title`；移除走 `ON DELETE CASCADE` | 移除先确认；移除的是这一段，不是记忆（两者分开存） |

**这条旅程最容易做错的一处**：把人设做成「随时可调的风格滑块」。用户要的其实是「换一个角色」，
而它的代价（前缀缓存整段失效、每一轮重算）会在几轮之后才显形——所以锁必须画在明面上，
出口（新开一轮）必须紧挨着它。

## 4. J2 · 会议助手：从选来源到下一次检索

| 步 | 用户动作 | 稿上的落点 | 数据落点 | 失败与退路 |
|---|---|---|---|---|
| E0 | 线上会要开始了，一半声音在电脑里 | 不占界面 | — | 只要文字不要分人时，用实时字幕（§2.2） |
| E1 | ⌘⇧N（全局）或会议页「开始会议」 | `会议助手 · 会议页 · 空态（选音频来源）` | — | ⌘⇧N 是唯一「动作会换页」的情况；App 不必在前台（P6） |
| E3 | 选来源：麦克风 / 本机音频（按 App 多选）/ 两者混音 | 同一块板的三选一 | `session.audio_source`；每行 `line.source` | 未授权 → 该来源变受阻行 + 出口；列表为空 → 写「没有可抓的 App」；都能就地换回来 |
| E3 | 打开分人（档位允许时） | 同一块板的开关 + `分人 · 说话人标签（会议与字幕共用）` | `session.diarization='active'` | `light` 档位置灰并写明原因；降级时正文继续落盘、标签停更 |
| E4 | 开始会议，边听边看 | `… · 录制中` | `line(role='speaker', speaker_label, source, t_start/t_end)` | 每行标来源（麦克风 / 本机音频 / 混音），所以回看分得清「对方说的」与「屋里说的」 |
| E5 | 会中私下问一句（⌘⇧I） | `… · 录制中 · 内心 OS` | `inner_os_exchange` + `inner_os_evidence`（**与正文分开存**） | 没证据就说没证据（给已听时长与段数）；模型没配 → 同一条结论条；生成中可取消，取消不影响录制 |
| E5 | 把某条答案写进纪要 | 同上：「写进纪要」 | `inner_os_exchange.in_minutes=1` | **默认不进纪要**是结构决定的：纪要只读 `line` |
| E5 | 声音断了（服务重启 / 睡眠 / App 退出） | `… · 录制中断（服务或来源断了）` ★本轮新增 | `session_interruption`（见第 9 节 R1） | 正文照旧落盘；「继续这一段」新开一路音频并写下中断区间；**不静默续录** |
| E5 | 被 tap 的 App 退出了 | 同上的说明行 | 同上（`reason='source_lost'`，自动接回） | 这是唯一会自动接回的一种：按 Bundle ID 接回，录制不打断，只记一条区间 |
| E6 | 结束会议 | `… · 整理中` | `session.state='processing'` | EOF 屏障：等分人水位对齐再封存；未对齐时保留正文并标 `timing_quality='unavailable'` |
| E7 | 等待纪要（可离开这一页） | `… · 整理中`（进度条 + 已封存的转录） | `minutes(status='generating')` | 整理失败也不丢转录——它已经在库里 |
| E7 | 看纪要 / 换版本 | `… · 已归档（改名与导出）` | `minutes(version, body, is_latest)` | 重新生成只**新增版本**，旧版仍可回看与导出 |
| E7 | 改说话人名字 | 正文里的说话人 chip + 分人那块板 | `speaker_name(label, display_name)` | 只改显示名：`line.text` 一个字不动，历史引用按新名渲染 |
| E7 | 导出 Markdown / SRT / 纯文本 / JSON | 同一页的导出 | 只读库，产物落文件 | 走系统保存面板；导出物保留来源列与说话人显示名 |
| E7 | 回看很久以前的会 | 会议列表（含搜索）+ 详情 | 读 `session` / `line` / `minutes` | 检索口径见 `SESSIONS-SPEC §16.4` |

## 5. J3 · 实时字幕：从贴屏到记录库

| 步 | 用户动作 | 稿上的落点 | 数据落点 | 失败与退路 |
|---|---|---|---|---|
| E0 | 听不清 / 听外语 / 要留痕 | 不占界面 | — | 要分人与完整记录时用会议助手 |
| E1 | ⌘⇧L（全局）或菜单栏 | `浮层 · 字幕带 · 跟随中` | — | 浮层**不激活** App、不抢焦点；App 可以在后台（P6） |
| E2 | 麦克风没授权 / 服务没就绪 / 被别的会话占着 | `浮层 · 字幕带 · 受阻` | — | 三种受阻共用同一条带子，各给一个出口；**保留最后一句字幕**（可读、可复制） |
| E3 | 打开分人标签（档位允许时） | `分人 · 说话人标签（会议与字幕共用）` | `session.diarization`、`line.speaker_label` | 与会议是**同一条链路**：同一个扩展、同一套匿名标签、同一处改名 |
| E4 | 边说边看 | `浮层 · 字幕带 · 跟随中` | `line(status='partial'→'final')` | 未定稿的行显示「正在识别…」；定稿即落库 |
| E5 | 上滚看刚才那句 | `浮层 · 字幕带 · 回看` | — | 上滚即停止跟随并出现「回到最新」；它不持焦点，`esc` 关不掉它 |
| E5 | 换字号 / 钉住位置 / 复制一段 | 悬停工具条（同一块浮层） | 字号与位置进 `@AppStorage`（每屏一套） | 大字档是同一块浮层的档位，不是另一个模式 |
| E6 | 点浮层上的 ✕ | `实时字幕 · 记录库 · 刚结束（已保存）` | `session.state='archived'` | 这是字幕闭环**唯一**的结束点；结束即保存 |
| E7 | 在记录库里搜 / 筛 / 星标 | `实时字幕 · 记录库 · 回看中` | `line.starred`；筛选按 `speaker_name` | 说话人显示名可以在这一页改，正文不动 |
| E7 | 导出 SRT / 复制全文 | 同一页的页脚 | 只读库 | SRT 用 `ordinal` 与相对秒，不用墙钟时间 |
| E7 | 清空记录 | 同一页的页脚 | 逐条删除（先确认） | 破坏性确认写清影响面；导出可以留副本 |

## 6. J0 · 第一次使用（横切三条闭环）

这条旅程不属于任何单一功能，但它是**唯一一条一定会走一遍**的路，也是最容易在实现里各写一套的路。

| 步 | 用户看到 | 稿上的落点 | 系统在做什么 | 判据 |
|---|---|---|---|---|
| 1 | 装完打开，首次进入会话模块（库为空） | `会话 · 首次使用 · 空态引导（三能力起点）` | 读取 sessions.sqlite3 确认无记录 | 展示本地引擎就绪态、三能力起手入口与隐私承诺，不直接抛出空白或历史记录 |
| 2 | 服务没起 | 三个会话页各自的空态 | `/health` 不可达 | 每个会话页给「去服务状态」，不是一句「失败」 |
| 3 | 服务起来了，第一次点麦克风类动作 | `会议助手 · 会议页 · 空态（选音频来源）` | 请求系统麦克风授权 | 拒绝 → 该来源变受阻行 + 出口；不静默降级、不留空音轨 |
| 4 | 第一次用到分人 | 同上的开关 + 分人那块板 | 读档位能力 | `light` 档：开关置灰并写明「需要 balanced 或 quality」 |
| 5 | 第一次进语音助手 | `语音助手 · 对话页 · 未配置模型` | 读设置里的大模型配置 | 说清三件事：缺什么、影响哪些功能、下一步点哪（P7） |
| 6 | 在设置里填地址、选模型、检查连接 | `设置 · 会话（配置大模型）` | 拉模型列表；密钥进钥匙串 | 三种可判定结论（已连接 / 可达但模型没加载 / 连不上），不是转圈 |
| 7 | 用出第一条记录 | 三块记录库画板之一 | 建库、`user_version` 迁移 | 重开 App 记录还在；库文件在 `~/Library/Application Support/SpeechRail/` |
| 8 | 想知道东西存在哪 | `设置 · 会话` 的「记录库位置」只读行 | — | 给「打开数据目录」与「备份库文件…」，并且**明说**不保存音频 |

## 7. 四条跨模块衔接

三条闭环共用一根脊柱（第 7 节的四条 + 分人），它们是旅程里真正的交叉点：在这里各说一套，
用户就会在同一台 Mac 上遇到三种解释。

| # | 衔接 | 规则 | 落点 |
|---|---|---|---|
| X1 | 会议录制中按 `⌘⇧L` | **不开第二条会话**：麦克风是会议的。字幕带以受阻态出现，两个出口——「打开会议转录」或「结束会议并启动字幕」（后者走守卫） | `浮层 · 字幕带 · 受阻`（第三条文案，见第 9 节 G3） |
| X2 | 会议吃本机音频（腾讯会议 / QQ 音乐） | 按进程 tap 取音：不装虚拟声卡、不抓整机、不改变本机原有播放；来源 App 退出按 Bundle ID 接回 | `会议助手 · 会议页 · 空态（选音频来源）` + 中断态 |
| X3 | 会议与字幕都要分人 | 只有一条链路：同一个扩展、同一套会话内匿名标签、同一处改名、同一套降级话术 | `分人 · 说话人标签（会议与字幕共用）` |
| X4 | 助手 ↔ 会议互斥 | 谁在用麦克风常驻可见；切换是一条有确认、有出口的流程，不是一次被拒绝的点击 | `会话占用 · 结束会议并切换` |

## 8. 覆盖对账：旅程 → 稿 / 规格 / 数据

判据是**每个 E 段都必须能在稿上指出落点**，而每个落点都要有规格与数据。下表是逐段核过的结果
（`●` = 稿上有画板；`○` = 规格已定、稿上不单独出板）。

### 9.1 两处产品口径（G5）

| 项 | 决定 | 理由 |
|---|---|---|
| 导出物命名 | `<kind>-<标题或首句摘要>-<yyyyMMdd-HHmm>.<ext>`，文件名里不用 UUID | 用户要在 Finder 里认出它；UUID 只在库内做主键 |
| 会话列表搜索 | 匹配 `session.title` + `line.text` + `minutes.body` | 想不起会议名时，人一定是从内容找 |
| 记录库搜索 | 匹配 `line.text` + 说话人显示名；筛选是 `starred` 与说话人 | 与列表搜索不同层：一个是「找哪一场」，一个是「找哪一句」 |
| 索引 | 优先 FTS5；本机 SQLite 编译选项不支持时退回 `LIKE` + `line_by_session` | §15.5 的 FTS5 未实测不该变成阻塞：检索是产品能力，索引是实现细节 |

### 9.2 对 §15 的增量修订 R1（中断）

```sql
-- 会话里断过的区间。R1 是**加法**：既有列一个没改，也不需要迁移（schema 还没实现）。
CREATE TABLE session_interruption (
  id         TEXT PRIMARY KEY,
  session_id TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
  at_ordinal INTEGER NOT NULL,                 -- 断在哪一行之后（与 line.ordinal 同轴）
  reason     TEXT NOT NULL,                    -- 'service_lost' | 'sleep' | 'source_lost' | 'unexpected_exit'
  resumed_at REAL,                             -- 空 = 没有续接，这一段到此为止
  created_at REAL NOT NULL
);
-- 会话怎么结束的。NULL 视为 'user'，所以既有行为不用改。
ALTER TABLE session ADD COLUMN end_reason TEXT;  -- 'user' | 'interrupted' | 'unexpected_exit'
```

写这两处是为了让「未正常结束」**在界面以外也成立**：记录库里那条「未正常结束」不是 UI 状态，
而是查得到的事实。若你不同意，删掉它们不影响其它表（`session.state` 仍能表达归档）。

## 10. 验收判据（照着测）

每条都是「做什么 → 应该看到什么」，不写形容词。完整口径以 `SESSIONS-SPEC §16` 为准。

**J1 语音助手**

- 未配大模型时打开助手页：看到结论条 + 可读灰态对话流 + 禁用的控制行，**没有**弹窗。
- 会话中的人设：是只读行（值 + 锁 + 新开一轮的出口），没有任何方式在本轮改它；音色仍可换，换完下一句生效并标「第 N 句起」。

- 记忆：本轮改动**不影响本轮**后续回答；新开一轮后生效；移除一条记忆后，历史对话里那句话仍在。

**J2 会议助手**

- 只选本机音频开会：转录里**没有**自己的声音；每行都带来源标签。
- 档位是 `light`：分人开关置灰并写明原因，两边（会议与字幕）说法一致。
- 降级发生时：正文继续写、标签停更、已给出的标签保留，记录里能查到这次降级。
- 结束会议：先封存转录再生成纪要；整理失败时转录仍在，可以只导出 SRT。
- 中断：断点后的正文没有凭空多出来；「继续这一段」之后记录里有一段中断区间，导出物里也标出来。
- 重新生成纪要：旧版本仍可选中与导出。
- 改说话人名字：所有该说话人的行一起变，导出物里是新名，历史证据引用也按新名渲染。

**J3 实时字幕**

- ⌘⇧L：浮层出现且**不激活** App、不抢焦点；当前页面不变。
- 上滚：停止跟随并出现「回到最新」；`esc` 不关闭浮层。
- 受阻时：最后一句字幕保留、可复制；出口指向系统设置或服务状态。
- 点 ✕ 结束：记录库里刚结束的这一段已选中；导出 SRT 的序号与时间码来自 `ordinal` 与相对秒。
- 清空记录：先确认，确认文案写明影响面与能否恢复。

**J0 首次使用 / 跨模块**

- 三条受阻（未授权 / 未就绪 / 被占用）永远是同一条结论条 + 一个出口，措辞随能力变、形状不变。
- 会议录制中按 ⌘⇧L：不开第二条会话，浮层给出占用说明与两个出口。
- 助手与会议之间切换：出现确认（含时长与后果），取消后状态一点不变。

### 13.4 这一轮**没有**改的两处（留给用户裁决）

   只有『开始字幕』」，并把死胡同按钮改成「打开记录库」。补一块独立空态板是新增画板，不在
