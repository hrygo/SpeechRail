## 闭环的判据

一条闭环画完了没有，看两端在不在稿里：**从哪进**、**产物落在哪**。中间五种情况都要有落点：

| 阶段 | 必须回答 |
|---|---|
| ① 入口 | 从主窗口、菜单栏还是全局快捷键进？App 需不需要在前台？ |
| ② 前置与受阻 | 权限、服务、档位、模型没配或被占用时，影响是什么、唯一出口在哪？ |
| ③ 主交互 | 一来一往 / 边听边记 / 贴屏跟随时，用户看到什么、能做什么？ |
| ④ 交还与守卫 | 结束时怎么收尾（EOF 屏障、确认、不静默抢麦）？ |
| ⑤ 产物与回看 | 产物是什么、落在哪、怎么再打开、怎么导出、怎么移除？ |

三条闭环共用**同一根脊柱**（系统级入口 / 大模型在哪配 / 记录落在哪 / 谁在用麦克风）。脊柱不画，
三条路径就会在「麦克风被占」这类交叉点上各说一套。

| # | 需求 | 落点（画板） | 设计决定 |
|---|---|---|---|
| 1 | 会议不只吃麦克风，还要吃本机音频（腾讯会议 / QQ 音乐…） | `会议助手 · 会议页 · 空态（选音频来源）` | 音频来源升级成**开始会议前必须先答的一件事**：麦克风 / 本机音频（按 App 多选）/ 两者混音；来源是会话级设置并随记录存。macOS 26 的取音路径是系统按进程 tap（不是虚拟声卡），tap 默认不静音原输出——**不改变你听到的内容** |

| 3 | 会议与字幕都要对接 SpeechRail 的分人能力 | `分人 · 说话人标签（会议与字幕共用）` + 两侧的 ③ 状态格 | 只有**一条**链路：同一个分人扩展、同一套会话内匿名标签、同一处改名、同一套降级话术。三种状态都画（档位不支持 / 已启用 / 降级），因为「降级时正文不许丢」才是产品判断 |
| 4 | 助手随时换音色与角色风格（见 Sona） | `语音助手 · 对话页 · 未开始（先定人设与音色）` + `… · 换音色（下一句生效）` + `换音色 vs 换人设（影响面）` | 关键不是选择器而是**边界**，而且两条边界不一样：**音色随时可换、下一句生效**（它只影响 TTS）；**人设只在会话开始时定、会话内只读**（它进 system prompt，中途换会让大模型的前缀缓存整段失效——用户 2026-09-17 收口）。要换人设就新开一轮，从记录库「继续这一轮」也是一轮新会话，所以那里可以换。两者随记录存。第五轮又补了一块对比板，把两者的影响面写成 7 行表（见上文第五轮表第 2 条） |

## 本次追加的两条判据（用户 2026-09-17）

**① 记录是资产，落在本机 SQLite。** 会议记录与纪要、字幕会话、语音助手的对话与记忆都写进同一个
本机数据库，长期保留；导出才生成文件。因此三个产物页一律是**记录库**：列表（含搜索）+ 选中 +
详情，能继续、能重命名、能导出、能移除（移除前确认）。设置页也不再写「记录是本机文件」，
改成本机数据库 + 备份方式。

**② 页面不是一次性画面。** 三条闭环各自**只有一个产品页**加一条浮层，其余都是这一页的状态：

```
未配置 / 空态 / 未开始  →  进行中  →  刚结束（还没整理完）  →  归档 · 从库里再来一轮
```

结束时不是把用户留在一块「结束页」上，而是同一页换成「刚结束」这一态，产物直接落进页内那个长期
存在的资产区。所以：

- 画板名一律是「页 · 状态」（`会议助手 · 会议页 · 整理中`、`实时字幕 · 记录库 · 刚结束（已保存）`），
  不是一个个孤立的时刻；
- 总览页上多了一张**状态演进**表（每格写着「这一态里换掉什么」）和一张**固定 / 可变**表，
  合起来就是「改交互时重画什么、什么不动」的书面答案：改的是状态内容，页骨架与资产区不动；
- 生成器里这两张表是 `CLOSURE_STATES` / `CLOSURE_FIXED_VARIABLE`，改状态先改那里。
