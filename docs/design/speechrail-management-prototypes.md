# SpeechRail macOS App 管理、运行监控与模型下载文字原型

## 1. 原型目标

这是一份文字模式的交互原型，不是 SwiftUI 实现代码，也不是像素级视觉稿。
它把每个功能的定位、用户用途、开发者证据、状态变化和确认文案固定下来，供后续
SwiftUI 原型和 UI test 使用。

设计依据：

- 原始 macOS App 设计包中的创作者工作流、音色创作、试听、保存、绑定和作品语义；
- SpeechRail 作为单人 Apple Silicon Mac 本地 ASR/TTS 服务的产品定位；
- 当前 `/health`、`/metrics`、XPC operation 和模型仓储契约；
- 原生 macOS 的侧边栏、分栏导航、独立 Settings 和菜单栏入口习惯，参考
  [Apple Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)、
  [NavigationSplitView](https://developer.apple.com/documentation/swiftui/navigationsplitview)、
  [Settings](https://developer.apple.com/design/human-interface-guidelines/settings) 和
  [MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra)。

## 2. 产品骨架

管理能力不能挤掉音色创作。控制中心的一级导航如下：

```text
SpeechRail

创作
├── 配音台
├── 音色创作
├── 音色库
└── 我的作品

服务
├── 总览
├── 运行监控
├── 模型管理
└── 预检与诊断
```

窗口职责：

```text
控制中心窗口：创作区 + 服务区 + 技术详情
菜单栏：当前服务状态 + 高频服务操作
Settings：应用偏好，例如开机启动、通知、外观和隐私
```

### 2.1 双受众原则

所有服务页面先显示解释层，再通过“技术详情”展开证据：

```text
解释层：服务现在是否可用？发生了什么？下一步做什么？
证据层：profile、health 字段、metrics、operation phase、revision、hash 结果
```

不提供“普通用户模式 / 开发者模式”切换，避免同一个产品维护两套信息架构。

## 3. 管理控制台

### 3.1 功能定位

```text
总览
让 SpeechRail 在这台 Mac 上准备好

管理本机语音服务、能力档位和运行状态。
不会上传音频，也不会改变你的创作内容。
```

普通用户需要知道：

```text
现在能不能使用？如果不能，需要做什么？这个操作会不会影响我的作品？
```

开发者需要知道：

```text
当前 profile、ASR/TTS/Realtime readiness、服务状态和最近 operation。
```

### 3.3 未准备和降级状态

```text
● 还没有可用的语音能力

SpeechRail 已安装，但本机模型还没有准备完成。

接下来需要：
1. 下载并校验模型
2. 运行一次预检
3. 启动语音服务

[去模型管理]  [运行预检]
```

```text
● 部分能力需要准备

语音转文字可以使用。
文字转语音模型尚未就绪，因此音色创作和语音生成暂不可用。

[下载缺失模型]  [查看诊断]
```

技术详情必须解释影响范围，例如：

```text
reason = tts_model_missing
missing_capability = text_to_speech
required_artifact = tts-1.7b-base-q8
```

### 3.4 profile 应用确认

```text
切换到 quality

这会改变 SpeechRail 使用的语音能力配置。

会发生：
• 使用 quality 档位的模型和能力
• 根据当前服务状态执行必要的切换操作
• 已下载的模型不会被删除

可能影响：
• 正在处理的请求可能需要等待或重新开始
• 如果模型未下载，会先进入模型准备流程

[取消]  [检查并应用]
```

“下载并校验”和“应用此档位”必须是两个不同动作。

### 3.5 音色创作连接

音色创作继续作为一级入口，页面不显示内部 worker 术语：

```text
音色创作

当前语音服务：可用
VoiceDesign 模型：已准备

[开始创作]
```

依赖缺失时：

```text
还不能开始音色创作

VoiceDesign 模型尚未准备完成。
已有音色和作品不会受到影响。

[下载 VoiceDesign 模型]  [返回]
```

## 4. 运行监控

### 4.1 功能定位

```text
运行监控
确认本机语音服务现在是否稳定

这里显示 SpeechRail 最近一段时间的运行状态。
它反映服务是否可用、是否繁忙以及哪里需要处理，
不代表语音内容本身的质量评分。
```

普通用户看到“现在能不能继续使用”；开发者看到“变慢或失败的具体原因”。
它是本机服务看板，不是多实例、集群或用户行为分析平台。

```text

服务没有故障，但新的请求可能需要等待。

```

```

```

## 6. 统一交互和安全规则

- 运行态 mutation（启动、停止、重启、应用 profile）和模型 mutation（下载、校验、发布）
  需要明确的操作反馈；长操作显示 operation phase。
- 下载只通过受控的 XPC / managed CLI / `model_store` 执行，UI 不访问任意 URL、不接受任意
  repository、revision、路径或 shell 参数。
- “已校验”只表示制品完整，不代表当前服务正在使用，也不代表推理质量已经验证。
- 页面离开或 App 退出后不把监控样本写成历史数据库；模型 operation 重开 App 后通过
  model status 重新核验。
- 不把缺失指标渲染成零值，不把服务不可达渲染成正常，不把内部错误码作为唯一说明。
- 支持深色模式、动态字体、键盘焦点、VoiceOver 标签和减少动态效果。

## 7. 原型验收标准

普通用户在每个页面都应能回答：

```text
这个页面是做什么的？
我现在处于什么状态？
下一步应该点击什么？
这个操作会不会影响我的作品或正在运行的服务？
```

开发者在展开技术详情后应能回答：

```text
状态来自哪个 health / metrics / operation 事实？
当前 profile 和模型 revision 是什么？
失败发生在下载、校验、发布、服务切换还是运行阶段？
是否可以安全重试或回退？
```
