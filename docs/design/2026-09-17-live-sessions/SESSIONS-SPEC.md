## 2. 产品定位

### 2.1 修订的边界

2026-09-15 包 §2.1 写过：「不把 App 变成会议 / 实时字幕 / 语音助手客户端——那是调用方
（Sona、LiveKit/Pipecat、Open-WebUI 等）的职责。」

这条边界现在**部分撤销**，理由要说清楚，否则只是"想加功能"：

- 当初的理由是**能力不在服务契约里**。服务只有 REST 的合成/转写与 Realtime 的 ASR/TTS 子集，
  App 里画会议与对话只能是空壳。这个前提今天仍然成立——但**三个能力所依赖的服务入口已经全部存在**：
  `/v1/realtime`（流式 ASR + VAD + 分人扩展）、`/v1/audio/speech`（TTS）、`/v1/voices`（音色库，App 已有）。
- 边界里有两处按用户 2026-09-17 的裁决**收窄**了，必须一起说清，否则「不撤销」会与 §14 打架：
  - **不撤销**：App 不做 LLM 推理服务（P7，外部依赖）；App 不做声纹库、不做跨会话身份
    （服务只给 session-scoped 匿名 label）。
  - **收窄**：~~不做会议业务数据库~~ → App 自己建**本机 SQLite 库文件**存会话资产，
    但**不装数据库服务**（P8、§3.2-S6，D1 已裁决）；~~不做系统声音采集~~ → App 按**进程 tap**
    采集本机音频（§14.1），但**不抓整机、不装虚拟声卡、不改变本机原有播放**。
- 协议边界一字不动：`/v1/realtime` 仍然只有 ASR/TTS 子集与 SpeechRail 扩展，不承载 LLM response、
  tool call 或应用级打断策略（`contracts/realtime-openai.md`）。**会话编排在 App 里，不在服务里。**

### 2.2 三个"会话时刻"

App 原先回答两个时刻：**引擎时刻**（我能不能现在用它）与**创作时刻**（把文字变成声音）。
本模块补上第三个：**在场时刻**——我此刻正在说话，机器正在听。

| 能力 | 一句话定义 | 什么时候用 | 不用它的路径 |
|---|---|---|---|
| 语音助手 | 和一个本机大模型用语音一来一往 | 单人、免手、要的是对话本身 | 不需要语音时，Open-WebUI 类界面更合适 |
| 会议助手 | 把一段多人谈话变成可检索的文本和纪要 | 会议、访谈、听课 | 只要文字、不要说话人标签时，用实时字幕的记录库 |
| 实时字幕 | 半透明的字幕带贴在屏幕上，边说边看 | 听不清、跨语言、需要留痕 | 要完整记录与分人时，用会议助手 |

### 2.3 明确不做

| 不做 | 理由 |
|---|---|
| 声纹库、实名说话人、跨会话身份 | 服务只输出 session-scoped 匿名 label（项目约束），App 不越权攒身份 |
| 保存原始音频 | 服务不保存 PCM，App 同样只留文本（§9） |
| 大字镜像提词（物理分光镜） | Sona 的舞台提词还包含镜像翻转与视线导轨；本轮只做字幕带的三档字号（§6.3.1），镜像另议 |
| 云 LLM 托管与模型下载 | 大模型由用户自己的、**兼容 OpenAI 且支持 Responses API** 的服务提供（本机或局域网）；App 只做配置与连接检查（不指定具体推理产品，用户 2026-09-18） |
| 多轨混音编辑与视频时间线 | 两路音频是**同时送识别**（§14.1），不是可编辑的多轨；音频本身不落盘，因此没有时间线可编 |
| 抓整机音频、虚拟声卡 | 本机音频按**进程 tap** 取（§14.1）：不装驱动、不抓整机、不改变本机原有播放 |
| 通话中替用户说话（代答） | 内心 OS 的答案**不读出来**（§14.2）；TTS 只服务语音助手这一条闭环 |

> 移除过时项两处（2026-09-17 复核）：原「Inner OS（会中私密研判）」一行已由 D4 裁决纳入（§14.2），
> 原「采集电脑播放的声音（系统声音）」一行已由用户第三批需求 1 改为按进程 tap 取音（§14.1）；
> 两者留在此处会与 §14 直接打架，因此删除而不是改写。

## 4. 设计原则

P1–P6 追加在 2026-09-15 包 §4 之后，编号连续；该包的四条原则继续有效。

**P5 · 麦克风只有一个所有者，所有权必须常驻可见。**
本机只有一个麦克风，服务只有一个 ASR worker，batch 与 streaming 冲突时服务直接返回 `backend_busy`。
所以"谁在听"不是内部状态，而是这个 App 的**首要事实**：它常驻在侧边栏底部（与"服务是否就绪"同级），
切换它是一条有确认、有出口的流程，而不是一次被拒绝的点击。

**P6 · 会话要能离开窗口。**
三个能力里有两个的真实用法不发生在主窗口：字幕要贴在屏幕上看，会议录起来之后用户会去干别的活。
所以：字幕带是浮层（NSPanel），会议录制中有跨窗口的常驻入口（菜单栏 + 侧边栏状态区），
主窗口里的页面承担"回看、搜索、导出、配置"这些真的需要大窗口的事。

**P7 · 大模型是外部依赖，未配置是一个正常状态。**
SpeechRail 只负责 ASR/TTS/分人；对话与纪要靠用户自己的、**兼容 OpenAI 且支持 Responses API** 的服务。
没配、配错、服务没起，都要**在触发它的地方**说清三件事：缺什么、影响哪些功能、下一步点哪里。
不把"未配置"渲染成错误，不静默降级成"助手不说话"。

**P8 · 会话的产物是长期资产，落在本机 SQLite 库里。**（2026-09-17 用户裁决，取代本条原「产物是文档、
落在本机文件里」的结论）
不保存音频；转录、纪要、字幕与对话记录写进这台 Mac 上的一个 SQLite 数据库，App 与服务重启都不丢，
检索走数据库索引，能改说话人显示名、能在记录库里继续、能导出 Markdown/SRT/纯文本。
SQLite 不是"一个需要先装的数据库服务"：库文件由 App 自己建，随 App 数据目录走，备份就是备份那一份
库文件加一份导出物。这条同时覆盖了 Sona 用 PostgreSQL 那件事（S6）：能力照迁，依赖不照迁。

## 5. 信息架构与导航

### 5.1 侧边栏：新增「会话」组

13 条一级路由，三个分组。新组插在「创作」之后、「引擎」之前——它是"用引擎"的事，
和"管引擎"的页面不是同一件事，但也不该把已有用户最熟的创作页顶下去。

| 分组 | 路由 | 侧边栏标签 | 变化 |
|---|---|---|---|
| 创作 | `dubbing` | 配音台 | 不变 |
| 创作 | `voiceDesign` | 音色创作 | 不变 |
| 创作 | `voiceClone` | 音色克隆 | 不变 |
| 创作 | `voiceLibrary` | 音色库 | 不变 |
| 创作 | `works` | 我的作品 | 不变 |
| **会话** | `assistant` | **语音助手** | **新增** |
| **会话** | `meeting` | **会议助手** | **新增** |
| **会话** | `captions` | **实时字幕** | **新增** |
| 引擎 | `overview` | 服务状态 | 快捷键改（见 §5.2） |
| 引擎 | `monitoring` | 运行监控 | 快捷键改 |
| 引擎 | `models` | 模型 | 快捷键改 |
| 引擎 | `diagnostics` | 诊断 | 快捷键改 |
| 引擎 | `developerDocs` | 开发者文档 | 快捷键改 |

侧边栏底部从**一个**状态区变成**两个**常驻行（顺序即优先级）：

```
● 服务已就绪 · Quality            ← 现有：引擎是否可用
◉ 实时字幕进行中 · 12:04          ← 新增：谁在用麦克风（空闲时显示「麦克风空闲」）
```

两条都是入口：点第一行进「服务状态」，点第二行进**当前会话所在页**（空闲时进实时字幕页）。
这是原则 P1 的落点，也是与 Sona S1/S2 的分界。

### 5.2 快捷键

`⌘1–⌘0` 只有十个槽位，十三页必须有人让位。让位规则：**创作页一个都不动**（它们的使用频率最高，
而且用户已经形成肌肉记忆），**会话组拿数字键中间三格**，**引擎页改用助记组合**（它们最低频）。

| 分组 | 页 | 现在 | 本包 |
|---|---|---|---|
| 创作 | 配音台 / 音色创作 / 音色克隆 / 音色库 / 我的作品 | ⌘1–⌘5 | **不变** |
| 会话 | 语音助手 / 会议助手 / 实时字幕 | — | **⌘6 / ⌘7 / ⌘8** |
| 引擎 | 服务状态 / 运行监控 | ⌘6 / ⌘7 | **⌘9 / ⌘0** |
| 引擎 | 模型 / 诊断 / 开发者文档 | ⌘8 / ⌘9 / ⌘0 | **⌘⇧M / ⌘⇧D / ⌘⇧H** |

新增的全局动作（进 `SpeechCommands`，与页面无关）：

| 命令 | 快捷键 | 说明 |
|---|---|---|
| 开始 / 暂停实时字幕 | `⌘⇧L` | 全局；字幕带出现或隐藏，不改变当前页面 |
| 开始会议 | `⌘⇧N` | 全局；直接开始录制并切到会议助手页（这是唯一"动作会换页"的情况，见 §5.4） |
| 结束当前会话 | `⌘⇧.` | 会话进行中才可用；会议走确认（§6.4） |

### 5.3 会话所有权模型

三个能力共用一个三态模型，所有权**不跟随页面**：

| 状态 | 含义 | 权威显示位置 | 其他位置 |
|---|---|---|---|
| 空闲 | 没有会话占用麦克风 | 侧边栏会话行「麦克风空闲」 | 三页各自的空态 |
| 占用 · 字幕 | 字幕带在收声 | 侧边栏会话行（含时长） | 字幕页、菜单栏面板、字幕带自身 |
| 占用 · 会议 | 会议在录（可能正在整理） | 侧边栏会话行（含时长） | 会议页的 live 状态带、菜单栏面板 |
| 占用 · 助手 | 助手会话在跑 | 侧边栏会话行（含阶段） | 助手页的会话状态带、菜单栏面板 |
| 整理中 | 会议已停，纪要/分人在收尾 | 侧边栏会话行「正在整理会议…」 | 会议页 |

#### 5.3.1 设备按功能启用、功能离开即释放（用户 2026-09-18 裁决）

**App 不做常占。** 麦克风、系统录音（本机音频）与音频引擎都**不随 App 启动而存在**，只在会话期间存在；
会话离开（归档 / 中断 / 整理）就释放。

| 项 | 决定 | 用户看到什么 |
|---|---|---|
| 空闲 | 不打开麦克风、不建系统录音 tap、不跑音频引擎 | 启动 App 后系统不出现麦克风使用指示；侧边栏写着「麦克风空闲」 |
| 获取 | 用户点「开始对话 / 开始会议 / 打开字幕带」之后才申请权限并获取设备 | 首次会弹对应授权；被别的 App 占着时给受阻结论与出口，**不建空记录** |
| 释放 | 会话结束（含中断、整理阶段开始之前）即释放 | 结束后 5 秒内麦克风指示消失；本机音频的采集进程随之退出 |
| 权限 | **按需申请**：麦克风在第一次开始会话时；系统录音只在用户第一次选「本机音频」来源时 | 只用字幕的用户**不会**看到"系统录音"授权弹窗 |
| 界面 | 字幕带浮层、菜单栏面板、已注册的全局热键都**不持有设备** | 关掉浮层不等于结束会话（§5.5.3 的口径不变）；反过来，没有会话时侧边栏不出现占用行 |

**受阻态因此多一类，但不新出板**：除了既有的「麦克风未授权」「语音服务未就绪」「会议正在录制」，
现在还有「设备被别的 App 占着」；四者**共用同一条受阻形状**（§16.3 的处置），只换文案与出口。
稿上不需要新增画板；既有的侧边栏「麦克风空闲」一行本来就是这条规则的落点。

理由与 §5.4 同源：占用是用户借给 App 的硬件，不是 App 启动后的默认状态。这条规则也是
§5.3 那张所有权表的**前提**——"空闲"一行说的是"此刻没有会话持有设备"，而不是"App 持有但没有采"。
实现口径（获取/释放的时点、原型、验收判据）见
[`../2026-09-18-session-layer/TECHNICAL-DESIGN.md`](../2026-09-18-session-layer/TECHNICAL-DESIGN.md) §3.5。

### 5.4 切页与所有权解耦

**点击侧边栏 = 看，不等于开始。** 这是与 Sona 最直接的行为差异（S3.2 的 S2）：

- 切到「语音助手」不会自动开始对话；页面给出空态与一个主按钮「开始对话」。
- 切到「实时字幕」不会自动开始字幕；页面给出记录库与主按钮「打开字幕带」。
- 切到「会议助手」不会自动开始会议；列表顶部有「开始会议」。
- 唯一的例外是 `⌘⇧N`（开始会议），它是动作不是导航，且会切页——因为会议一开始就必须看得见。

理由：切页是浏览行为，一天会发生十几次；开始会话是占用硬件的动作，一天可能只发生两三次。
把两件事绑在一起，得到的就是 Sona 的 toast 拦截。

## 6. 逐面规格

### 6.1 语音助手（`assistant`，⌘6）

**这一页要回答的**：现在机器在听吗、它正在干什么、刚才那句说了什么、下一句怎么说。

**这一页只有一块产品页，五种态**（用户 2026-09-17：页面不是一次性画面；2026-09-18 补齐第 5 态）：
`未开始（定人设与音色）→ 对话中 → 实时对讲 → 换过音色 / 记忆 → 刚结束（记录库）`。
五种态都发生在同一页上——页头、右侧资产栏位不动，变的是页头下面那条结论区与中间的主区。
**人设与音色在「未开始」态定**；没配大模型时，这个未开始态换成下面的受阻态（同一个位置，
同一个形状）。右侧那一栏在「记录 / 记忆」之间切：记录是这一轮说了什么，记忆是跨轮次仍然成立的事
（§16.5）。

结构（自上而下三块）：

1. **会话状态带**（1 张卡）：状态点 + 阶段文字（`正在聆听` / `正在思考` / `正在说话` / `已暂停`）
   + 真实电平（复用 `Level Meter` 组件，来自麦克风 `averagePower`）+ 会话时长（等宽数字）
   + 尾部动作 `静音麦克风`、`结束对话`。
   阶段不用进度条（进度条会承诺一个服务端给不出的完成度）；用状态点 + 文字，切换时走系统动效。
2. **对话流**（左，吃满剩余宽度）：一轮一行，用 `Turn Row` 组件。行内是
   说话人标签（`你` / `助手` + 音色徽标）+ 文本 + 时间；悬停时行尾出现 `重播`、`复制`。
   最后一行是实时行（`正在识别…` + 电平），它只在本轮未定稿时出现。
   对话流是**滚动容器**，默认贴底；用户上滚后出现「回到最新」，不自动抢回（与 2026-09-15 包
   §7.6 的时间窗控件同一条交互语言）。
3. **底部控制区**（两行，2026-09-18 第五轮改）：

   - **第一行是输入**：文本输入框（占位 `打字问也行…`）+ 发送。语音仍是默认路径，但**打字是一条
     随时可用的替代路径**（用户 2026-09-18）——麦克风被占、环境吵、只想安静问一句，都不该逼人换
     工具。**打字提问不朗读回复**（「我在打字」本身就说明在静音场景），每条回复仍可点 `重播`；
     想边听边说就切到实时对讲。这一条同时是麦克风受阻时的实际出口，所以它与语音入口同屏，不藏在
     二级面板里。
   - **第二行是会话控制**：`静音麦克风` + `一问一答（外放）` / `实时对讲（耳机）` 分段控件（默认
     一问一答）+ 音色胶囊（值 + chevron，点开是音色选择：**可选可试听**，复用音色库那套）。
     页头的 `音色与风格` 通向 `换音色 vs 换人设（影响面）`：两个动作在界面上长得像、代价完全不同，
     所以要先说清代价再换（见 §14.4）。

   > 2026-09-17 收口两处：这里的 `按住说话` / `免持` 与 Inspector 的 `允许插话打断` 开关，
   > 都被 §14.5 的两种对讲模式取代——**模式本身就是打断开关**，另设一个开关只会和模式矛盾。
   > 稿上的落点已经同步（共用屏 `screenAssistant` / `screenAssistantBlocked` 的底部控件）。

**右侧 Inspector（360pt，开发者详情打开时才出现技术项）**：大模型（`已连接 · 模型名` /
`未配置` / `不可达`）+ 音色（`下一句可换`）+ `人设（本轮已定 · 只读）` + `打断：实时对讲时生效`
+ 上下文（`12 轮`）+ **输入（`语音或打字`）**。开发者详情打开时才出现服务端 VAD 与冷却 250 ms
这类技术事实（**只读事实，不是开关**）。
旁栏还要回答一个用户一定会问的问题：「打字提问时为什么不朗读」——见上面第 3 条的规则。
回声与自打断是 Sona 花了大力气的地方（`echo_allow_barge_in` 默认关闭）；App 侧把这件事交给模式：
一问一答时它说话就闭麦（半双工），实时对讲时打断就是这一模式的定义，回声由系统 AEC 兜（§14.5）。

**人设的锁是产品约束，不是省事**（用户 2026-09-17）：会话开始后再换人设，等于换了 system prompt，
大模型的前缀缓存（prefix cache）从改动点之后整段失效，之后每一轮都要重算——用户感受到的是
「莫名其妙变慢、还变贵」。所以：**人设在「开始对话」那一步定，会话中途只读**；要换就新开一轮
（从记录库「继续这一轮」也是一轮新会话，因此那里可以换）。音色不在此列：它只影响 TTS 合成，
不进 prompt，因此仍然可以随时换（§14.4）。

**受阻态**（首次使用几乎必然遇到）：正文顶部一条结论卡（`StatusConclusion`，tone=attention）：

```
还没有配置对话模型
语音识别和语音合成现在就能用；助手需要一台兼容 OpenAI 的服务：
把地址、模型与密钥填进设置即可，地址是本机还是局域网都行。
对接要求只有一条：服务要实现 Responses API（只支持 Chat Completions 的服务接不上）。
[打开设置…]   [了解如何配置]
```

> 2026-09-18（用户第五轮第 8 条）：**界面上不出现具体推理产品的名字**（原来的文案举了 oMLX 做例子）。
> 只说「兼容 OpenAI」，并把必须支持 **Responses API** 这一条写成可判定的一句话——它是唯一会
> 让「地址、密钥都对、模型也在，却接不上」的原因，所以必须写在用户看得见的地方，
> 而不是只留在开发文档里（设置里新增的「接口」一行与「检查连接」的第四种结论都是这一条的落点）。

下方对话流保留为**可读的灰态**（不是空白），底部控制行禁用并保留说明——用户看到的是"缺一件事"，
不是"这个功能没做"。

### 6.2 会议助手（`meeting`，⌘7）

**这一页要回答的**：这一次会议现在记到哪了、是谁说的、会后我拿到了什么、上一次会议在哪。

结构（2026-09-18 第五轮**重构**，用户「会议助手整体布局需要重新构思」）：

```
页头 → 状态带 → 主区（转录 + 会议信息栏）→ 贴底的内心 OS 抽屉
```

原来的「左侧会议列表（260pt）+ 右侧正文」形态被去掉：会议**库**是记录库的事，会议页要回答的是
「这一场现在记到哪了」，那一列挤进来只会让转录（真正的主对象）每次都被压窄。

**内心 OS 是组件，不是模式。** 它默认收起成贴底的一行（`内心 OS` + `只你可见` + `已问 N 次 ·
M 条已写进纪要` + `⌘⇧I` + chevron），任何时候都能展开或收起；展开时转录仍在上面，提问不打断录音。
这就是它必须做成组件而不是状态的证据——原来那一版把 OS 画成一个**独立版面**，想看回答整页就得
换掉、转录被挤走，与「边听边记」的用法正好相反。四种状态共用这一套骨架，改交互改的是抽屉的内容，
不是重画一整页。

| 状态 | 主区（转录 + 会议信息栏） | 关键动作 |
|---|---|---|
| 空（还没有会议） | **音频来源必须先答**（§14.1）：`麦克风`（单选）与 `本机音频`（按 App 多选）；勾选多个来源时机内自动合流——**「混音」是行为，不是第三个选项**。下面接三种受阻各一条出口（未授权 / 列表为空 / 来源中断）+ 右侧「本次会议」摘要 + 下方记录库空态（含档位能否分人的说明） | 选来源、`开始会议` |
| 录制中 | 状态带（红点 + `正在录音` + 标题 + 时长 + 电平 + `3 位说话人 · 分人已开` + `148 段已存好`）+ 转录流（**来源标签** + `说话人 chip` + 时间码 + 文本；未定稿的一行显示 `正在识别…`）+ 表头 `标注说话人` + 右栏会议信息（时长 / 转录 / 说话人 / 音频来源 / 分人 / 保存位置 / 整理）+ OS 抽屉**收起态** | 结束会议、点说话人标签改名或合并、展开 OS（`⌘⇧I`） |
| 录制中 · 内心 OS **展开** | 同一页、同一个骨架，抽屉展开成两栏（§14.2）：**左**是本场的问答历史（3 条，兑现收起态里那个「已问 3 次」）+ 输入框 + 追问提示；**右**是带证据的答案卡（证据 / 不确定度 / 可直接念的措辞）+ `继续追问` / `复制` / `写进纪要`；转录仍在上面 | 提问、追问、写进纪要、取消生成 |
| 录制中断 | 状态带换成 `录制中断`（原因 + 停在哪一刻 + 已存好段数）；转录在断点处标一行 `00:12:40 起中断 · 这一段没有文本`；右栏给 `继续这一段` / `结束并整理`；下方一张 3 行的表说明四种断法各自的出口（§16.7） | 继续这一段（显式续接）、结束并整理 |
| 整理中 | 同一条状态带换成 `正在整理会议…`（等最后半句分完人 + 纪要生成）+ 转录流仍可读；`查看纪要` 占位不可点 | 等待，或先看已完成的文本 |
| 会后 | 正文区顶部 `纪要` / `转录` 分段控件；**右栏换成说话人编辑面板**（§6.2.1）+ 纪要版本（`最新 · 第 2 版` / `第 1 版`） | 重新生成纪要、版本切换、导出、批量标注说话人 |

> 「内心 OS」的入口就是贴底那一行的 chevron（+ `⌘⇧I`）——它是页骨架的一部分，两稿共用。
> 2026-09-18 之前这里记的一条「入口还没接上」的偏差已经作废：那次重构把 OS 从独立版面变成了
> 骨架里的组件，入口随骨架一起落在共用屏上，不再有需要手工补的按钮。

三条设计判断：

1. **说话人改名是元数据编辑，不是文本编辑。** 行内说话人 chip 可点开改名（`说话人 A` → `张工`），
   改名后该说话人的所有行一起变；正文文本不受影响。这与服务的"正文不可变 + 分人原位修订"公理一致
   （`contracts/realtime-openai.md` §Diarization 扩展、Sona 的 `apply_speaker_patches`），
   界面上也必须看得出这个区别：**文本没有编辑入口，说话人有**。
   **会中与会后是同一件事的两种节奏**（用户 2026-09-18 第五轮第 7 条）：会中点一下就改（快，
   趁还记得），会后可以批量（改名 / 标记为「我」/ 合并 / 拆出）。两处都不改正文。
2. **纪要带版本。** 会议头右侧是 `版本` 菜单（`最新` / 历史版本 / `重新生成`），重新生成不覆盖旧版。
3. **导出走系统保存面板**（Markdown / SRT / 纯文本 / JSON 四种），不做自绘下拉里的伪保存。

#### 6.2.1 说话人标注面板（会后，右栏）

分人只输出**本场会话内的编号**（`说话人 A / B / C / D`），把编号变成真人是用户的事。会后这一栏
就是那件事的主入口（会中的轻量入口是转录表头的 `标注说话人` 与每一行的说话人 chip）：

| 元素 | 内容 | 规则 |
|---|---|---|
| 说话人行 | `说话人 A` chip + 显示名 + 状态胶囊（`已标注` / `待标注` / `已合并`）+ 铅笔 | 4 位是默认上限；`已并入 A` 的行保留可见，合并可回溯 |
| 改名输入 | 输入框（值 = 正在编辑的这一位）+ `已有：` 后面是可点的既有名字 | 输入框下方的 `已有` 是**同一场里的名字**，点一下即填——同一个人不需要输两遍 |
| 归属动作 | `标记为「我」` / `与 A 合并` / `从 C 拆出…` | 「我」只标记本机麦克风那一路（说话人 B 在稿里就是这个位置）；拆出需要选一段区间 |
| 保存 | `保存` | 未保存时离开这一场要确认；保存写的是 `speaker_alias`，正文与时间码不动 |
| 纪要版本 | `最新 · 第 2 版` / `第 1 版` | 重新生成只新增版本，不覆盖；旧版本仍可回看与导出 |

**降级时的样子**：档位不支持分人（`light`）时，这一栏不出现说话人列表，只说一句「这台 Mac 现在的
档位不标说话人；正文照常记录」，并且**不给一个永远点不动的开关**（§14.3 的三种状态之一）。

### 6.3 实时字幕（`captions`，⌘8）

分成**两个界面**，这是本模块最重要的形态判断。

#### 6.3.1 字幕带（浮层，`⌘⇧L`）

一个**非激活**浮动面板：不抢焦点、不激活 App、可以覆盖在别人全屏演示之上，但可交互（能滚动、能复制）。

| 项 | 规格 |
|---|---|
| 尺寸 | 默认 760 × 内容撑高（最少 2 行、最多 4 行）；宽度可拖 420–1200；位置记忆每屏一套 |
| 默认位置 | 主屏底部居中，距屏幕底 96pt（避开 Dock 与常见视频控制条） |
| 材质 | 系统浮动层材质（`NSVisualEffectView` 侧 `hudWindow` / `.glassEffect`），**不是**自绘半透明色块；稿里以 `surface/panel` + 1px `border/separator` 表示，实现取系统材质 |
| 文本 | 行首可选说话人 chip（分人档位时）+ 正文。字号三档：紧凑 17 / 标准 20 / 大字 26（映射系统 `.title2` / `.title` / `.largeTitle`） |
| 行为 | 贴底跟随；上滚回看时**停止跟随**，出现 `回到最新`；`esc` 不关闭（它不持有焦点），`⌘⇧L` 暂停/继续 |
| 悬停工具条 | 悬停才出现的一条细工具条：`暂停` / `复制这一段` / `字号` / `钉住位置` / `导出 SRT…` / `关闭`。不做常驻工具栏——它是一个贴在屏幕上的薄片，不是一个窗口 |
| 受阻 | 麦克风未授权 → `麦克风未授权，字幕带已暂停  [打开系统设置]`；服务未就绪 → `语音服务未就绪  [去服务状态]`。两种情况都保留最后一次的字幕文本（可读、可复制） |
| 在用时长什么样 | 稿上有一块专用浮层板 `浮层 · 字幕带 · 贴在画面上（在用时）`：正在播放的画面 + 浮在最上面的半透明带子 + 悬停工具条 + 两行字幕。**只有盖在别的内容之上，才看得出它是「薄片」而不是「一张卡片」**（用户 2026-09-18 第 9 条：单看一块 760×80 的卡，评审时会被当成普通卡片） |

大字档是同一块浮层的字号档位，不是另一个模式：**不做镜像翻转、不做视线导轨、不做全屏提词**（§2.3）。

#### 6.3.2 记录库（页面 `captions`）

浮层负责"此刻看得见"，页面负责"以后找得到"：

- 工具栏：搜索 + 筛选（`全部` / `仅星标` / 说话人）+ 字号档 + 计数。
- 转录列表：`说话人 chip` + 时间码 + 文本 + 星标；双击复制单行（沿用 Sona 的既有习惯，`SubtitleStream.tsx:696`）。
- 页脚：`导出 SRT`（系统保存面板）、`复制全文`、`清空记录`（破坏性确认）。
- 一条常驻说明：`字幕记录只保存在这台 Mac 上；原始音频不留存。`

### 6.4 会话占用与交还（守卫）

任何会**中断**正在进行的会话的动作，都走同一种确认形态（sheet，不是 alert——需要说明与选项）：

```
结束会议并切换到语音助手？

正在录制的「周会 · 分人」还有 00:12:40 的转录没有整理。结束后仍会生成纪要，
但麦克风同一时刻只能由一个会话使用。

[结束会议并切换]   [取消]        ☐ 以后不再询问
```

- 触发点：侧边栏切到另一个会话页时点主按钮、`⌘⇧N`、菜单栏「开始…」、字幕带的「开始会议」。
- **不触发**的情况：只在会话页之间浏览（§5.4）、会议已结束后切页、助手正在说话时切到会议助手页。
- `以后不再询问` 只对**助手/字幕**生效；会议录制永远确认（防误停）。
- 取消后停留原处，不改变任何状态（Sona 的 toast 也做到了这点，区别是这里给出的是完整出口）。

### 6.5 设置 · 会话（第 4 个页签）

参数分三组，默认只露出会影响默认行为的几项：

**大模型（对话与纪要）**

| 行 | 控件 | 说明 |
|---|---|---|
| 服务地址 | 文本字段 `http://127.0.0.1:8000/v1` | 兼容 OpenAI 的服务地址，**本机或局域网都行**；不接受 URL 里带 key |
| 接口 | 值 + 胶囊 `Responses · 必须` | **助手与纪要都走 Responses API**；只提供 Chat Completions 的服务接不上。这一行是只读事实，不提供降级选项 |
| 模型 | 值 + chevron | 从该服务的模型列表里选；空列表时给「没读到模型，检查服务是否已加载模型」 |
| 密钥 | `已存入钥匙串` + `更换…` | **只存钥匙串**，不落配置文件、不进日志（项目约束） |
| 连接 | `检查连接` + 结果（`已连接 · 12 ms` / `服务可达，但这个模型没加载` / `接口不对：没有 Responses API` / `连不上`） | 一次点击检查**两件事**：服务通不通、接口对不对。四种结论都可判定，不显示"测试失败" |

一条常驻说明：`对话与纪要都要靠一台兼容 OpenAI、支持 Responses API 的服务；SpeechRail 只提供
识别、合成与分人。` 设置页另有一张「对接要求」卡把要求写成可核对的清单：接口 = Responses API（必须）、
模型列表 = `GET /v1/models`、鉴权 = Bearer（密钥存钥匙串）、部署位置 = 本机或局域网。

> 2026-09-18（用户第五轮第 8 条）：**不出现具体推理产品的名字**。第四种结论（接口不对）是新加的——
> 「地址、密钥、模型名都对，却接不上」在真机上最可能的原因就是对方只实现了 Chat Completions，
> 这条如果不写在界面上，用户只能猜。

**语音助手**：默认人设（值 + chevron，**只在新对话开始时预填**；开始之后本轮不再变，见 §14.4）、
默认音色（开始后仍可换，下一句生效）、对讲模式（`一问一答` / `实时对讲` 分段控件）。
这三项都是「新会话的预填值」，库里记的是每次会话的实际取值（§15.4）。

**实时字幕**：默认字号（三档）、字幕带位置（`屏幕底部居中` + `重置位置`）、分人标签开关
（默认关；档位不支持时禁用并写明 `需要 balanced 或 quality 档位`）。

**会议**：会议分人开关（同上档位门禁）、纪要模型（`同大模型` / `单独指定…`）、
记录库位置（只读：`本机数据库（SQLite）` + `打开数据目录` + `备份库文件…`），
以及一条**只读**事实行：`不保存音频：会议只保留文本与说话人归属。`

**通用**：`中断时用系统通知告诉我`（默认**关**；口径见 §6.8）。

### 6.8 系统通知（用户 2026-09-18 裁决：只留一件）

系统通知有打扰成本，也有授权成本（第一次发要弹系统授权）。所以**只在"用户已经离开 App、但必须知道"
的一件事上发**，其余一律留在 App 内说。

| 事 | 发不发 | 文案 | 点了去哪 | 理由 |
|---|---|---|---|---|
| **中断需要人决定**（服务断了 / 睡醒了） | **发** | `会议中断了 · 还有 12:40 没整理` | 打开该会议页 | 用户可能已经离开 App；而"不续接、不封存"这两件事必须有人决定 |
| 会话结束 | 不发 | — | — | 结束不是坏事，会话占用行与记录库已经说了 |
| 纪要就绪 | 不发 | — | — | 不紧急；用户没离开时它本来就在眼前 |

三条附带规矩：

1. **`source_lost`（被 tap 的来源 App 退出）不发**：它是四类中断里唯一自动接回的一种，没有需要人做的事。
2. **默认关**，设置 → 会话里一行开关。第一次真的发生「中断需要人决定」时，先走 App 内结论条，
   并在结论条上问一次"以后要不要用系统通知告诉我"——与 R4 同一条规矩：不要在用户表现出兴趣之前申请。
3. **App 在前台时不发系统通知**，只出结论条（同一个原因不该用两种打扰方式各说一遍）；
   通知正文里**不出现转录原文**——锁屏上出现会议内容，等于把用户的会讲给了路过的人看。

## 8. 键盘与无障碍

| 动作 | 键 | 说明 |
|---|---|---|
| 开始/暂停字幕带 | `⌘⇧L` | 全局，不需要 App 在前台（走菜单命令） |
| 开始会议 | `⌘⇧N` | 全局 |
| 结束当前会话 | `⌘⇧.` | 会话进行中 |
| 内心 OS（会中私密问答） | `⌘⇧I` | 会议录制中；开/关右侧 OS 面板（稿上写在提问行里） |
| 静音麦克风 | `M` | **仅当会话页或字幕带/菜单栏面板有焦点时**（沿用 Sona 的 `M`） |
| 对话页：结束并发送 | `⌘⏎` | 与配音台的 `⌘⏎` 同义 |
| 字幕记录库：复制选中行 | `⌘C` | 列表选择态 |

**这三个动作故意不给全局键**（第三批新增，2026-09-17）：`音频来源`、`对讲模式切换`、`换音色`。
它们是会话内的设置，不是会话的启停；给它们全局键会让「敲错一个组合键就改了采集路径」变得可能。
三者都是页面里的标准控件，Tab 可达、`⌘⇧M`/`⌘⇧D`/`⌘⇧H` 这类引擎页的助记键不与之冲突。
**人设没有键，因为它在会话中不可改**（§14.4）：`⌘⇧I` 是 OS，不是人设。

> 「全局」这三个字有实现代价，必须在编码前定死：SwiftUI 的 `.keyboardShortcut`（现 App 只有这一种，
> `App.swift:183`）**只在 App 是前台时生效**，而字幕与会话的真实用法恰恰是 App 不在前台（P6）。
> 真正的全局键需要 `RegisterEventHotKey`（Carbon，无需辅助功能授权）或全局事件监听（需要授权）。
> 当前仓库没有任何全局热键机制（2026-09-17 实测：`rg RegisterEventHotKey|addGlobalMonitor` 在
> `macos/` 下 0 命中），因此这是**新增能力**，不是配置项——见 D9。

无障碍要点：

- 字幕带是状态变化频繁的窗口，必须给 VoiceOver 一个 **polite live region** 语义（新行播报），
  而不是每次变化重读整块；字幕文本可选中、可复制。
- 说话人改名必须能用键盘完成（chip 是按钮，回车进入编辑，esc 取消）。
- 会话所有权变化（谁在用麦克风）不能只靠颜色：状态行始终是「状态点 + 文字」。
- 会议 live 状态带与字幕带都尊重 `Reduce Motion`（电平与点数不脉动）。
- **人设的只读要用语义表达，不是只画一把锁**：`人设` 行给 `.accessibilityValue("本轮会话已定，只读")`
  并把出口（新开一轮）做成可达按钮，否则 VoiceOver 用户只会听到一个点不动的控件。
- **「被打断」不是错误**：那一行用 status/attention 呈现，无障碍标签读「这一句被打断，正文保留到停下为止」，
  不要读成失败。
- **来源标签要读得出**：转录行上的 `麦克风` / `本机音频` 与说话人 chip 是两个独立语义，不要合并成一个标签。
- **内心 OS 的答案与转录是两棵列表**：VoiceOver 顺序要先转录后 OS，并且 OS 面板要有
  「只有你看得到」这一句作为区域的描述，而不是藏在视觉里。

## 9. 数据、隐私与边界

| 项 | 决定 | 依据 |
|---|---|---|
| 原始音频 | **不落盘**（除音色克隆页既有的"临时文件立刻删除"） | 项目约束；Sona 同款公理 |

| 说话人身份 | 只存 session-scoped 匿名 label 与用户手写的显示名；不做声纹库、不做跨会话身份 | 项目约束 |
| 大模型密钥 | 钥匙串；不写配置文件、不进日志、不进导出物 | 项目约束 |

| 语音助手（说） | TTS：Realtime 的 TTS 子集或 `/v1/audio/speech` | light/balanced 用默认音色；**VoiceDesign 音色需 quality** | 音色选择器把不可用音色标出来（复用音色库既有画法） |
| 语音助手（对话） | **服务之外**：用户的 OpenAI 兼容服务 | 无 | 「还没有配置对话模型」+ 去设置（P7） |

第三批追加的四条（逐一给出契约依据，2026-09-17 核对 `contracts/realtime-openai.md`）：

| 能力 | 依赖 | 契约事实 | 不满足时用户看到 |
|---|---|---|---|
| 会议/字幕（本机音频） | **服务之外**：Core Audio 进程 tap → 本地混音 → PCM16（16k 或 24k） | 服务只声明「输入为 PCM16，支持 `16000` 或 `24000` Hz；24 kHz 在会话内有状态降采样为内部 16 kHz，首个 PCM 后不得改格式」（`session.update` 行） | 未授权 → 该来源变受阻行 + 打开系统设置；不静默留空音轨 |
| 助手（实时对讲打断） | Realtime 的 `input_audio_buffer.speech_started` + `response.cancel` | 「检测到有效人声输入后立即原子取消当前 TTS 响应并释放硬件排队槽位」，随后进入 `realtime_vad_bargein_cooldown_ms`（默认 250ms）冷却（§全双工打断） | 无需用户处理：被打断是这一模式的定义，不是错误 |
| 助手（换音色） | `session.update.voice` | 「接受已注册 voice 与 13 个 OpenAI 标准 voice 别名并驱动 TTS 合成；配置入口即校验：未知 voice → `voice_not_found`，已注册但当前权重不支持 → `voice_not_available`，非字符串或空白 → `invalid_voice`。**失败均保持 session 可用**」 | 这一句仍用旧音色说 + 一条可读结论 + 可用 preset 列表 |
| 会议（内心 OS） | **服务之外**：用户的 OpenAI 兼容服务 | 契约里没有这一条，App 自己编排（同对话） | 同「还没有配置对话模型」，出口是设置 · 会话 |

三条硬约束写进界面：

1. **`/v1/realtime` 不做 LLM**（`contracts/realtime-openai.md`）。所以对话必须由 App 编排：
   ASR → 大模型 → TTS 三段在 App 侧串起来。界面上的后果是**阶段是 App 的事实**（§6.1 的阶段栏），
   服务端不提供"正在思考"这种状态。
2. **`backend_busy` 是正常返回，不是异常**：batch 转写与 streaming 不能并行（项目约束）。
   会话页在开始前先读 `/v1/models` 与 `/readyz`；真的撞上 `backend_busy` 时按 §6.4 的所有权守卫处理，
   不显示原始错误码（错误码进 Inspector）。
3. **首个 PCM 之后不能改采样格式**（契约明写）。所以「换输入设备」在实现上只有一条路：**重开会话**。
   界面必须把这件事说在换设备的地方（§14.5），并保证记录不丢、当前这一轮标成「换设备」；
   不能做成「换个下拉框就接着录」——那样第一次换设备就会静默失败。

### 11.1 Token 口径（用户 2026-09-17：确保采用统一的设计 token）

**① 稿侧实测：闭环稿引入的颜色与文本样式都是既有 token 的引用，不是新值。**
2026-09-17 核对（`figma-kit/main.js` 闭环段落逐项抽取）：闭环屏幕用到的颜色共 **9 个**
（`accent/rail`、`border/separator`、`surface/content`、`surface/field`、`surface/railTint`、

**结论：颜色新增 0、数值 token 新增 0、文本样式新增 2。**

**② 稿上的布局常数不算 token，落地一律取 token。**

#### 12.1.1 本批实测与两处口径修正（2026-09-18）

**怎么验的**：用 `say` 生成两段中文语音 → `afconvert` / `ffmpeg` 转 16 kHz 单声道 PCM16 →
用**同一份仓库源码**编译成命令行程序，喂给**本机正在运行的服务**（`quality` 档，实测 `version 2.7.0`），
再看库里落了什么、SRT 导出来长什么样。全程不碰麦克风、不接管界面，所以不需要任何 UI 自动化授权。

实测结论（全部 PASS，2026-09-18）：

- **事件顺序与契约一致**：`session.created(speechrail/qwen3-asr-1.7b)` → `session.updated` →
  `speech_started` → `partial`* → `speech_stopped` → `committed` → `completed`，两次说话各一条 `completed`。
- **两句话落成两行**，`t_start/t_end` 单调、相邻不重叠（`[0.00–4.10]` / `[4.10–9.15]`），
  库里没有 `partial` 行，`timing_quality` 为 NULL，SRT 段数与行数一致，库可整体备份（126,976 字节）。
- **中途有一处真问题被这条链路抓到**：本机服务配了 `SPEECHRAIL_API_KEY`，而最初的客户端实现没带
  `Authorization`——握手直接被关掉。凭据解析因此从 REST 客户端里抽出来（`SpeechRailAPICredentials.swift`），
  WebSocket 与 REST 共用同一份，避免两处各读一次环境变量再漂移。
- **第一次启动会慢**：`/health` 里 streaming 是 `cold_evicted`，第一段音频要等模型加载（本次数十秒）。
  字幕带在这一段里显示的是"已连上、还没出字"，不会报错——这是对的，但**用户感知到的首句延迟**需要真机复看。

两处**按实测修正的口径**：

1. **本轮没有收到任何 `.segment` 事件**（两次说话都没有）。也就是说 §15 的 `timing_quality='aligned'`
   在这条链路上今天拿不到值，`t_start/t_end` 只能来自客户端自己的音频 / VAD 边界——落地实现就是这么写的，
   并且如实把 `timing_quality` 留空。**段级时间码与分人是同一条链路的事**，随阶段 4 一起做（§5.7 已如此写明）。
2. **导出物不再给无归属的行加「说话人：」前缀**（SRT 每行都写这一栏是噪声，不是信息）。
   §16.4 的"保留说话人显示名"仍然成立：有分人标签或用户改过名时才出现那一栏。

其它同批改动：`NSMicrophoneUsageDescription` 三处已改成覆盖"克隆 + 会话"的文案（原句只提克隆，
会话上线后那句会直接骗用户）；`AGENTS.md` 的边界句与 `docs/developers/macos-app-audio-capture.md`
（新增 §3.7 会话级采集）已同步；电平曲线抽成 `AudioLevel` 供采集与音色克隆共用
（`IMPLEMENTATION-READINESS` §2.2 第 5 项的"抽取"落地）。

**未验证（要如实说）**：没有启动 App 看浮层的几何、材质、悬停工具条与滚动跟随——那要占用前台窗口，
需要当次授权；浮层宽度是否真的能从边缘拖动（`.resizable` + borderless 在 macOS 26 上的行为）
与三档字号的实际观感同样待复看。没有跑任何自动化测试（`scripts/macos_app_test.sh` 等 UI 自动化
按项目硬约束需要用户逐次授权）。

**下一步**：阶段 4（会议与字幕接分人扩展、段级时间码、`speaker_name` 改名）与阶段 5
（语音助手 + 设置第 4 页签的 Responses API 配置）。

#### 12.1.2 审查修订（2026-09-18，第二轮）

落地之后做了一次逐行审查，并**用同一份仓库源码**写了一个定点核对程序，把"启动受阻"这条
支路跑出来（不碰麦克风、不碰窗口、不碰服务）。四条不符合预期的行为都复现了，已在本轮修掉：

| # | 修之前的样子 | 修法 |
|---|---|---|
| 1 | `⌘⇧L` 遇到服务未就绪 / 麦克风未授权时，浮层以**空白**出现：不写受阻原因、相位卡在 `preparing`，`✕` 与 `⌘⇧L` 都按不动 | 受阻原因在 `CaptionSession.beginCapture()` 落进 `blocked` 再抛（协调器只负责退回占用）；本地状态回 `idle`；`✕` 一律收得起来 |
| 2 | 浮层上的 `✕` 会打到别人的会话上：会议占着麦克风时点它，会议被推进"整理中" | `finish()` 只在占用是 `.captions` 时调 `stopCapture`，否则只收起带子 |
| 3 | 受阻后的「重试」是死按钮：占用还在自己手里时走 `requestStart` 只会拿到 `.alreadyActive`，界面仍显示在跑 | `retry()` 改按**占用归属**分派：占用是自己就走续接（新 epoch），不是自己才走守卫 |
| 4 | 未接线的能力静默成功：`begin(.meeting)` 拿占用、起走时，但没有任何采集 | 未接线的 kind 抛 `CapabilityNotWired`（钩子契约是"抛错 = 受阻"，返回 `Void` 等于说"已经在录了"） |

  `CaptionSession.committedItemIDs`，两处注释一并改正。
- **Distribution 构建拿不到麦克风**：`Distribution.xcconfig` 开了 hardened runtime，而

- **环形缓冲容量**：`PCMRing(capacity:)` 收的是**字节**，`Int(sampleRate)` 只有半秒
  （与"容量 1 秒"的注释相反）——已改成 32,000 字节；`macos-app-audio-capture.md` §3.7 的
  "40 ms 的 drain"改成 100 ms（与块大小同一个数），"如实计数"改成如实描述（没有计数器）。
- **字幕带上的电平柱**：稿是 `levelBars(foot, ratio, 14, 13)`——14 根、中间高两端低；
  实现画成了 3 根递升的柱子（把"14 根"读成了"14pt 的组宽"再除以 4）。已按稿重画。
- **工具条的两处几何**：内部间距 4 → 稿的 6；「字号」补上稿 `sizeTag` 的 padX 8 / padY 3。

**功能缺口已补（2026-09-19，未真机验证）**：会议页录制态缺稿上的「静音麦克风」——已实现，
落点与口径如下，等一次真实麦克风会话复验。

1. 闸门在采集侧（`AudioSourceCoordinator.gate(microphone:)`）：静音时把麦克风每一块换成**等长静音**
   （`AudioChunk(pcm: Data(count:), level: 0)`）再往下走。**不丢块**是刻意的：混音器按 40 ms 栅格
   合流，缺格会被补静音并记进 `gapCount`，状态带上就会假报「N 处补过静音」——那是给真断源
   （来源 App 退出、设备被拔）准备的事实。等长静音不改变栅格、时间轴与分人链路。
2. 会话层（`MeetingSession.toggleMicrophoneMute()`）只在 `phase == .recording` 且来源里**确实有**
   麦克风时生效；纯本机音频的会议不摆这个开关（没有麦克风可静，摆上就是死按钮）。
   静音与暂停是两件事：静音只关麦克风那一路（本机音频照旧进转录），暂停是整条上行都停。
3. 界面按稿 `screenMeetingRecording` 的页头：`静音麦克风` / `取消静音` 只在这一处给
   （状态带不给第二份，沿用 `main.js:3394` 的口径）。状态带标题在静音时改说
   「正在录音 · 麦克风已静音」；暂停与静音同时成立时标题让给「已暂停」，静音改列进事实行。
4. 静音状态随设备走：`startPipeline` 与 `releaseCapture` 都把它清回 `false`，中断态因此不会
   留一个亮着的假开关（中断会释放设备，§9 第 8 行）。

**这一轮同时记下一条做不到的事（不是本轮引入）**：**旧记录的说话人不能改名或合并**。

（`labeling.begin(sessionID:)`）；回看旧记录时既没有那一场的实例，改名也没有落点。
用户 2026-09-18 那条「讲话人支持会中和会后人工标注」里的"会后"，落到实现上是
**这一场刚结束、还停在这一页时**（归档态），不是"以后翻到哪一场都能改"。

#### 12.1.7 §8 键盘表逐条核对（2026-09-19）

顺手把 §8 那张键表逐条对到了实现（判据是"按下去真的有事发生"，不只看有没有 `keyboardShortcut`）：

| 键 | 状态 | 落点 |
|---|---|---|
| `⌘⇧L` 开始/暂停字幕带 | **已接** | 菜单命令（`App.swift:412`）+ `GlobalHotKeyCenter`（不需要 App 在前台） |
| `⌘⇧N` 开始会议 | **已接** | `GlobalHotKeyCenter`（送到会议页选来源，不替用户选） |
| `⌘⇧.` 结束当前会话 | **已接** | 菜单命令（`App.swift:417`）+ 热键；会议走确认 |
| `⌘⇧I` 内心 OS | **已接** | `GlobalHotKeyCenter`（只在会议录制中生效） |
| `⌘⏎` 对话页：结束并发送 | **本轮接上** | 助手页合成器那颗`发送`（`AssistantView`，与配音台同义）。带修饰键，不与输入框抢键 |
| `M` 静音麦克风 | **未接** | 见下 |
| `⌘C` 字幕记录库：复制选中行 | **未接** | 记录库今天有`复制全文`（整条记录），行级选中复制没有。它要一张"当前选中行"的焦点模型，等她与记录库一起改 |

**`M` 为什么没顺手加上**：它能挂的地方只有两种。其一是 SwiftUI 的 `keyboardShortcut("m", modules: [])`——
不带修饰键的快捷键是窗口级 key equivalent，**比第一响应者先吃到按键**，用户在合成器里打一个
「m」会被它吞掉（这是真事故，不是小瑕疵）。其二是 `NSEvent.addLocalMonitorForEvents(matching: .keyDown)`，
它**可以让事件穿过**：命中条件不成立时把事件原样返回，用户照常打字。正确形状是后者，条件为
「无 command/control/option 修饰 + `NSApp.keyWindow?.firstResponder` 不是 `NSText`（编辑中的
输入框/编辑器）+ 确实有一段会话在跑」，命中才消费这一次按键。
**它必须在有屏幕的时候做**（要真的在输入框里打一串带 m 的字验证没被吞），所以排进下一次真机走查。
另外 `M` 今天的作用域比 §8 写的窄：`CaptionSession` 没有静音能力，
所以"字幕带/菜单栏面板有焦点"这一条暂时无对象——要么给字幕加静音，要么把 §8 那一格的适用范围收窄到会议/助手两页，**待裁决**。

##### 12.1.8.1 锁屏期间的替代走查：把真实视图离屏渲染成 PNG

锁屏拿不到屏幕，但 `NSHostingView` 不需要屏幕。于是搭了一个**只在 `/tmp` 里存在**的渲染工装
（从不 `orderFront` 的 borderless 窗口 + `cacheDisplay`，不抢前台、不解锁、不写用户数据：偏好
与记录库都落在临时目录，`AppModel` 走 DEBUG 的 fixture 客户端），把三个会话页的**真实视图**
渲染成 2400×1800 的 PNG，两档宽度（内容区 880 / 1200）× 浅色与深色。

**它能证明什么**：版面结构与块序、折行与截断、卡片边界、文案落在该落的地方、深浅两套下文字的
对比度（按像素量过，不是"看着还行"）。

| 不改变听感 | tap 的 `muteBehavior` 默认 `CATapUnmuted`：抓取不影响本机原有播放 | 同上（`CATapDescription.h`） |
| 回退路径 | 若 process tap 不可用（系统版本/权限），退回 ScreenCaptureKit（`capturesAudio` macOS 13+，`captureMicrophone` macOS 15+） | 同上（`SCStream.h`）。**待实测**：两条路径的授权提示与音频时钟差异 |
| 权限 | 首次使用请求系统授权；拒绝 → 该来源在列表里变受阻行并给出口，**不留空音轨、不静默降级** | 与麦克风授权同一套结论条（§6.4） |
| 来源中断 | 被 tap 的 App 退出后按 Bundle ID 自动接回；中断区间在记录里标注 | `processRestoreEnabled` 的语义 |
| 记录 | 每段转录标注来源（麦克风 / 本机音频 / 混音）；导出物保留来源列 | 回看时要能区分「对方说的」与「屋里说的」 |

### 14.2 内心 OS（会中私密问答）

形态与契约照 Sona 的 Inner OS（`sona/src/sona/meeting/inner_os/`）：单连接、私密、答案带证据。

| 项 | 决定 |
|---|---|
| 可见性 | 答案只发给发起提问的那个连接：**不进会议音频、不进转录**；默认**不进纪要**——「写进纪要」是一个显式动作 |
| 答案形状 | 证据（哪一段 / 谁说的 / 时间点 / 内容哈希）+ 事实 + 判断（带不确定度与依据）+ 可直接念的措辞（draft）+ 限制说明 |
| 意图 | `fact` / `analysis` / `draft` / `mixed` 四类，与 Sona 一致 |
| 上下文 | 只用本次会议的转录；**不联网检索**。没有证据就说没有证据，并给出已听时长与段数 |
| 落点 | 问答是资产：写进本机 SQLite（独立于会议正文），会议记录里可回看；不混进纪要除非显式「写进纪要」 |
| 依赖 | 大模型（§6.5）；未配 → 同一条结论条 + 唯一出口 |
| 与分人联动 | 证据里的说话人用会话内匿名标签；用户改名后引用显示新名，历史引用不改写 |
| 取消 | 生成中可以取消；取消不影响录制与已经写进去的转录 |
| 形态（2026-09-18 第五轮第 5、6 条） | **贴底的抽屉组件**，不是独立版面：收起态一行常驻（`内心 OS` + `只你可见` + `已问 N 次 · M 条已写进纪要` + `⌘⇧I` + chevron），展开成两栏。收起时不占主区、不离开转录；这是「随时可展开可关闭」的实现口径 |
| 展开态的两栏 | 左：**本场的问答历史**（每条带状态：`已答 · N 处证据` / `已写进纪要`）+ 输入框 + 追问提示。右：答案卡（证据 / 不确定度 / 可直接念的措辞）+ `继续追问` / `复制` / `写进纪要` |
| 为什么要有历史 | 收起态写着「已问 3 次」，展开却看不到那 3 次，用户就没法追问「刚才你那条」——多轮在这里不是附加项，是那个数字的兑现 |
| 追问 | 接着上一问的上下文（同一连接、同一会话），不必重复背景；生成中可取消，取消不影响录制与已写进去的转录 |

### 14.3 分人：会议与字幕共用一条链路

| 项 | 决定 |
|---|---|
| 链路 | 同一个 `/v1/realtime` 分人扩展（`session.speechrail.diarization.enabled`，`max_speakers` 4）；两侧同一套会话内匿名标签、同一处改名、同一套降级话术 |
| 开关粒度 | 每个会话一个开关、**默认关**；打开时才声明分人，未声明就按无分人跑 |
| 档位门禁 | `light` 不分人（开关置灰并写明原因）；`balanced` / `quality` 分人。档位差异**如实发布**，不预支能力 |
| 降级 | `diarization_overloaded` / `finalization_timeout` 等触发单次 active→degraded：正文继续落盘、标签停止更新、已给出的标签保留，这一刻写进记录 |
| 结束 | `speechrail.diarization.finish` 屏障：等分人水位对齐再封存，末段不丢（EOF 屏障，§10） |
| 边界 | 不做声纹库、不做跨会话身份、不留 embedding；说话人是谁只由用户手写的显示名决定 |

### 14.4 语音助手：音色随时可换，人设只在会话开始时定

> **2026-09-17 用户裁决（推翻本条此前的「人设下一轮生效」）**：新会话开始后**不允许换人设**。
> 理由是大模型的前缀缓存：人设一变就等于换了 system prompt，缓存命中区间从改动点之后整段失效，
> 之后每一轮都要重算前缀——用户看到的是「莫名变慢」，还白花算力。音色不在此列，因为它只影响
> TTS 合成，不进 prompt。

| 项 | 决定 |
|---|---|
| 人设 | **会话开始时定，会话内只读**。人设是 system prompt 的一部分，只在「开始对话」那一刻写入一次；开始之后界面给的是**锁 + 一个出口**（新开一轮），不是选择器 |
| 音色 | 会话内可换，**下一句生效**（只影响 TTS，不进 prompt）：走 `session.update` 的 `voice`；被拒时这一句仍用旧音色说，并按 `voice_not_found` / `voice_not_available` 给出可读结论与可用 preset |
| 人设的出口 | 「新开一轮对话」（含从记录库「继续这一轮」——那也是一轮新会话，所以**那里可以换人设**）。换之前把当前记录先落库，记录不丢 |
| 记录 | 音色与人设随这段记录存：音色带「第 N 句起」· 人设带「本轮定」；从记录库继续时预填当时的设置 |
| 界面口径 | 人设的控件是只读行（值 + 锁 + `新开一轮…`）；**不给它快捷键**（§8）；VoiceOver 读「本轮会话已定，只读」，出口按钮可达 |
| 不做的 | 人设不是系统提示词的入口：它只改「怎么答」，不改「知道什么」；也**不是**中途可调的风格滑块 |

稿上的落点：`语音助手 · 对话页 · 未开始（先定人设与音色）`（定）、
`语音助手 · 对话页 · 换音色（下一句生效）`（换音色）与 `换音色 vs 换人设（影响面）`（讲清两个
动作的差别）三块板。

#### 14.4.1 两个「换」的影响面（用户 2026-09-18 第五轮第 2 条）

这两个动作在界面上长得像（都在右栏、都叫「换」），代价却完全不同，所以规格里也只给一张对比，
不给一句可以套用两次的解释：

| 维度 | 换音色 | 换人设 |
|---|---|---|
| 改的是什么 | 它说出来的声音 | 它每次开口前读的第一段话（身份、语气、答多长） |
| 什么时候生效 | 下一句 | 下一次开始对话；本轮不动 |
| 会变什么 | 只有声音不同；字、记录、纪要一个字都不动 | 之后每一轮的语气、长度、用词、答法 |
| 要付什么代价 | 几乎没有（一次 `session.update`） | 它得把开头重读一遍：第一句明显变慢，之后每轮都慢一点，且每轮都要重算前缀 |
| 改错了怎么办 | 换回来就行，从下一句恢复 | 本轮改不回来；换回来也要新开一轮 |
| 记录里怎么标 | 「第 13 句起：温柔讲解」（`session_change(kind='voice', at_ordinal)`） | 「本轮：耐心讲解」（会话级字段） |
| 刚才聊的还接得上吗 | 接得上：同一轮，上下文都在 | 不带过去：记忆与记录保留，这一轮的对话上下文不延续 |

**两条实现约束**（都来自上表，不是风格问题）：

1. 人设的**值**在会话创建时确定并写进会话行；会话内不接受修改请求——接口收到则返回
   `persona_locked`（可读结论 + 出口），不静默忽略。
2. 音色的每次变更都要落一条 `session_change`：界面上「第 N 句起」这句话必须有数据支撑，
   否则回看时无法解释前几句为什么是另一个声音。

用户可见的文案只写**现象**（「它会重新读一遍开头：你会觉得它突然变慢」），机制（前缀缓存、system
prompt）留在本节与代码注释里——这是用户 2026-09-18 第 4 条「面向终端用户」的落点。

### 14.5 语音助手：一问一答（外放）与实时对讲（耳机）

| 项 | 决定 |
|---|---|
| 两种模式 | 差别是**能不能打断它**。一问一答（外放）：半双工，输出期闭麦；实时对讲（耳机）：全双工，随时插话 |
| 打断实现 | **服务端已有**：`speech_started` → 原子取消正在播的 TTS（`response.cancel`），随后 250ms 冷却（`realtime_vad_bargein_cooldown_ms`），防 TTS 尾部回声反复触发（依据 `contracts/realtime-openai.md`「全双工打断（Barge-in）」） |
| 被打断的呈现 | 那一句在记录里标「被打断」，保留已经生成的正文，并可重放；不把它渲染成错误 |
| App 侧回声防护 | 系统 AEC（`AVAudioEngine` 的 `setVoiceProcessingEnabled`，macOS 10.15+）；外放时也可用实时对讲，但明确建议耳机 |
| 换设备 | 服务端在**首个 PCM 之后不接受改采样格式** → 换输入设备要重开会话；记录不丢，当前这一轮标「换设备」 |
| 控件收口 | 底部控制行只有**这一条分段控件**（`一问一答（外放）` / `实时对讲（耳机）`）。§6.1 原来的 `按住说话` / `免持` 与 Inspector 的 `允许插话打断` 开关**都不再存在**——模式就是打断开关，两个开关表达同一件事必然打架（2026-09-17 收口） |
| 默认 | 默认**一问一答**：耳机场景需要用户自己选（系统并不知道你戴没戴），选完这一项随会话记住 |

## 15. 数据模型（本机 SQLite）

> 状态：**已采纳（用户 2026-09-18，D8）**。§9 定了产品口径（什么该存、什么不该存），本节是它的
> 表结构；库文件位置、访问方式与迁移策略见 §15.1，阶段 2 可以按它开工。
> **两条加法增量**：§15.6 的 R1（中断）与 §15.7 的 R2（唯一序号 / 纪要队列列 / 打字来源取值）。
> 两者都是加法，不改变 §15.2 任何既有列的语义；因为 schema 还没实现，没有迁移成本。
> **未验证事项**：本机的 SQLite 版本与编译选项（FTS5 是否可用）尚未实测，见 §15.5。

### 15.1 库文件与打开方式

| 项 | 决定 | 理由 |
|---|---|---|
| 文件 | `~/Library/Application Support/SpeechRail/sessions.sqlite3` | 与既有 `.../SpeechRail/Works/` 同层；在仓库外（项目约束：数据不落仓库） |
| 访问 | 系统 `SQLite3`（`import SQLite3`） | **不加 SwiftPM 依赖**：Xcode 工程当前没有任何 package 依赖（2026-09-17 实测 `project.pbxproj` 无 `XCRemoteSwiftPackageReference`），为了一个本地库引入 GRDB 会同时动 `Package.swift` 与工程文件 |
| 打开 | `PRAGMA journal_mode=WAL`、`foreign_keys=ON`、`synchronous=NORMAL` | WAL 让「录制中写入」与「页面里查询」不互相阻塞 |
| 并发 | 单写者：写入走一个串行队列，读可以并发 | 与「一次只有一个会话占麦克风」的所有权模型一致 |
| 迁移 | `PRAGMA user_version`；开库时若低于当前版本，在**一个事务**里逐级升 | 不需要迁移框架；版本号是唯一的迁移依据 |
| 备份 | 库文件用 `VACUUM INTO '<目标路径>'`；设置里的备份入口产出整个**数据区**的副本（含 `Works/` 与 `voices/`） | 比复制文件可靠：不用同时凑齐 `-wal`/`-shm`，拿到的一定是一致快照。哪些目录算数据区、重装/卸载/迁移各自动什么，见 [`runtime-deployment.md`](../../operations/runtime-deployment.md) 的「app home 目录契约与重装语义」 |
| 移除记录 | 删 `session` 行，靠 `ON DELETE CASCADE` 带走它的行、纪要、OS 问答 | 破坏性动作，界面必须先确认（§6.3.2 的「清空记录」同款） |
| 数据上限 | 无自动过期：记录是资产 | 用户显式移除是唯一出口 |

**这个库住在"数据区"里。** 换服务版本、重装 App、`service uninstall` 都不动它；"想清干净重来"也只删可
重建区（`runtime/`、`models/` 等）。桌面 App 的用户资产只有长期保留才成立，所以这条不是运维偏好，
是 §9「记录是资产」的直接推论。

### 15.2 表结构

```sql
-- 一次会话 = 一条记录。三种能力同表，用 kind 区分：它们的产物长得一样，只是来源不同。
CREATE TABLE session (
  id               TEXT PRIMARY KEY,            -- UUID；导出物与引用用它
  kind             TEXT NOT NULL,               -- 'meeting' | 'captions' | 'assistant'
  title            TEXT,                        -- 用户可改；空则从首句生成
  state            TEXT NOT NULL,               -- 'recording' | 'processing' | 'archived'
  created_at       REAL NOT NULL,               -- Unix epoch（UTC）
  started_at       REAL NOT NULL,
  ended_at         REAL,
  engine_profile   TEXT NOT NULL,               -- 'light' | 'balanced' | 'quality'
  audio_source     TEXT NOT NULL,               -- 本次选的来源配置：'microphone'|'system'|'mixed'
  diarization      TEXT NOT NULL DEFAULT 'off', -- 'off' | 'active' | 'degraded' | 'unavailable'
  diarization_note TEXT,                        -- 降级/不支持的原因（直接拿来写界面文案）
  llm_endpoint     TEXT,                        -- 只记主机与路径，不记密钥
  llm_model        TEXT,
  persona_id       TEXT,                        -- assistant：本轮人设，**会话内不可变**（§14.4）
  persona_title    TEXT,
  voice_id         TEXT                         -- 起始音色
);

-- 转录 / 字幕 / 对话正文：三种记录同表。ordering 用 ordinal，不靠时间排序。
CREATE TABLE line (
  id             TEXT PRIMARY KEY,
  session_id     TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
  ordinal        INTEGER NOT NULL,              -- 会话内稳定序号；SRT 序号用它
  role           TEXT NOT NULL,                 -- 'speaker' | 'user' | 'assistant'
  speaker_label  TEXT,                          -- 分人匿名标签 'A'…'D'（会话内唯一）
  text           TEXT NOT NULL,
  t_start        REAL,                          -- 相对会话开始的秒
  t_end          REAL,
  source         TEXT NOT NULL,                 -- 这一行来自哪一路：'microphone'|'system'|'mixed'
  status         TEXT NOT NULL DEFAULT 'final', -- 'partial' | 'final'
  interrupted    INTEGER NOT NULL DEFAULT 0,    -- 助手的这一句被打断（§14.5）：不是错误
  device_switch  INTEGER NOT NULL DEFAULT 0,    -- 换设备后的第一行
  starred        INTEGER NOT NULL DEFAULT 0,    -- 字幕星标
  timing_quality TEXT,                          -- 'aligned' | 'unavailable'（来自 attribution_units）
  created_at     REAL NOT NULL
);
CREATE INDEX line_by_session ON line(session_id, ordinal);

-- 会话内的设置变更点。「音色第 N 句起生效」是一条记录，不是一个被覆盖的字段。
CREATE TABLE session_change (
  id          TEXT PRIMARY KEY,
  session_id  TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
  at_ordinal  INTEGER NOT NULL,
  kind        TEXT NOT NULL,                    -- 目前只有 'voice'
  value       TEXT NOT NULL,
  created_at  REAL NOT NULL
);

-- 说话人显示名：只有「匿名标签 → 用户手写的名字」。改名只改这里，正文一个字不动。
CREATE TABLE speaker_name (
  session_id   TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
  label        TEXT NOT NULL,
  display_name TEXT NOT NULL,
  updated_at   REAL NOT NULL,
  PRIMARY KEY (session_id, label)
);

-- 纪要带版本：重新生成只新增版本，不覆盖旧版。
CREATE TABLE minutes (
  id           TEXT PRIMARY KEY,
  session_id   TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
  version      INTEGER NOT NULL,
  body         TEXT NOT NULL,                   -- Markdown
  model        TEXT,
  prompt_chars INTEGER,                         -- 只存长度：项目约束不允许记录完整 prompt
  is_latest    INTEGER NOT NULL DEFAULT 0,
  created_at   REAL NOT NULL,
  UNIQUE (session_id, version)
);

-- 内心 OS：与会议正文分开存，所以「默认不进纪要」是结构决定的，不是靠约定。
CREATE TABLE inner_os_exchange (
  id          TEXT PRIMARY KEY,
  session_id  TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
  asked_at    REAL NOT NULL,
  at_ordinal  INTEGER,                          -- 提问时的转录水位
  question    TEXT NOT NULL,
  intent      TEXT,                             -- 'fact' | 'analysis' | 'draft' | 'mixed'
  answer_text TEXT,
  draft_text  TEXT,                             -- 可直接念的措辞
  confidence  TEXT,                             -- 'low' | 'medium' | 'high'
  limits_note TEXT,                             -- 限制说明；「没有证据」时写已听时长与段数
  model       TEXT,
  status      TEXT NOT NULL,                    -- 'generating'|'ready'|'cancelled'|'failed'
  in_minutes  INTEGER NOT NULL DEFAULT 0        -- 「写进纪要」是显式动作（§14.2）
);

CREATE TABLE inner_os_evidence (
  id            TEXT PRIMARY KEY,
  exchange_id   TEXT NOT NULL REFERENCES inner_os_exchange(id) ON DELETE CASCADE,
  line_id       TEXT REFERENCES line(id) ON DELETE SET NULL,  -- 指回那一行
  speaker_label TEXT,                            -- 渲染时经 speaker_name 解析成新名字
  t_start       REAL,
  quote         TEXT,                            -- 引用片段原文
  content_hash  TEXT
);

-- 助手的长期信息：与某一次会话解耦，所以会话被移除时它仍然留着。
CREATE TABLE assistant_memory (
  id                TEXT PRIMARY KEY,
  kind              TEXT NOT NULL,               -- 'fact' | 'preference' | 'summary'
  body              TEXT NOT NULL,
  source_session_id TEXT REFERENCES session(id) ON DELETE SET NULL,
  active            INTEGER NOT NULL DEFAULT 1,
  created_at        REAL NOT NULL,
  updated_at        REAL NOT NULL
);
```

### 15.3 四条要靠结构（而不是靠约定）保证的事

1. **「默认不进纪要」由表决定**：内心 OS 住在 `inner_os_exchange`，纪要生成只读 `line`；
   要进纪要必须写 `in_minutes = 1`，那是一个显式动作。
2. **改名不改正文**：显示名在 `speaker_name`，`line.text` 与证据引用一个字都不动；
   历史引用因此在新名字下显示新名，在老记录里也显示当时的引用原文。
3. **换音色可回溯**：`session_change` 让「第 N 句起」是一个可查的事实，而不是被最后一次选择覆盖掉的字段。
4. **不存的东西没有列可写**：没有 audio / embedding / 实名 / 密钥 / 完整 prompt 的列。
   这不是纪律问题，是**没有地方放**。

### 15.4 不落库、走别处的东西

| 项 | 落点 | 理由 |
|---|---|---|
| 大模型密钥 | 钥匙串（`SecItem`），不进库、不进配置文件 | 项目约束 |
| 大模型地址与模型名（默认值） | `@AppStorage`（与现有设置同一套）；库里只记每次会话用过的那一份 | 它是偏好，不是资产；库里那份是为了复现 |
| 默认音色与人设 | `@AppStorage` | 同上；每次会话的实际取值进 `session` |
| 字幕带位置与字号 | `@AppStorage`（每屏一套位置） | 与窗口几何同类 |
| 分人开关的默认值 | `@AppStorage`；每个会话实际是否启用记进 `session.diarization` | 默认值与事实分开 |

### 15.5 未验证（编码前要实测一件）

- **FTS5 是否可用**：`PRAGMA compile_options` 在系统 SQLite 上确认。v1 建议先用
  `LIKE` + `line_by_session` 索引（个人量级：几万行仍是毫秒级），把 FTS5 留作实测变慢之后的
  一次迁移——这是**性能取舍，不是功能缺口**，所以不阻塞阶段 2。
  **已实测（2026-09-18，macOS 26 系统 `sqlite3`）：`ENABLE_FTS5` 在编译选项里，可用。**
  v1 仍按上面的建议走 `LIKE`；FTS5 现在是"随时能上"的备选，不是未知数。
- **内心 OS 的上下文窗口**：超长会议往模型里塞多少（最近 N 分钟 / N 段 / 摘要 + 最近一段）
  以及截断阈值，需要阶段 7 用真实会议实测后定；`inner_os_exchange.limits_note` 已经预留了
  把「已听范围」写给用户的位置。

### 15.6 增量修订 R1 · 中断（2026-09-18，随旅程复核新增）

```sql
-- 会话里断过的区间。R1 是**加法**：既有列一个没改，schema 也还没实现，所以没有迁移成本。
CREATE TABLE session_interruption (
  id         TEXT PRIMARY KEY,
  session_id TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
  at_ordinal INTEGER NOT NULL,   -- 断在哪一行之后（与 line.ordinal 同轴）
  reason     TEXT NOT NULL,      -- 'service_lost' | 'sleep' | 'source_lost' | 'unexpected_exit'
  resumed_at REAL,               -- 空 = 没有续接，这一段到此为止
  created_at REAL NOT NULL
);
-- 会话是怎么结束的；NULL 视为 'user'，所以既有行为不用改。
ALTER TABLE session ADD COLUMN end_reason TEXT;  -- 'user' | 'interrupted' | 'unexpected_exit'
```

为什么要它：「未正常结束」必须是一个**查得到的事实**，而不是只有界面记得的一件事。
记录库那一行标识、导出物里的中断区间、以及「这一段到底录没录上」的判断，都要能从库文件本身回答
（口径见 §16.7）。

### 15.7 增量修订 R2 · 唯一序号、纪要队列与打字来源（2026-09-18 裁决）

> 来源：[`../2026-09-18-session-layer/TECHNICAL-DESIGN.md`](../2026-09-18-session-layer/TECHNICAL-DESIGN.md) §6.3。
> 用户 2026-09-18「全面采纳」裁定并入本节。R2 与 R1 一样是**加法**：既有列一个没改、schema 还没实现，
> 所以没有迁移成本。三条都是"规格要求了、但表上没地方放"的补位，不是新需求。

```sql
-- ① 序号唯一：把「重复的 completed 不产生第二行」从约定变成结构。
--    （技术方案 §5.2 的账本规则；取号与插入必须落在同一个事务里）
DROP INDEX IF EXISTS line_by_session;
CREATE UNIQUE INDEX line_by_session ON line(session_id, ordinal);

-- ② 纪要队列：让"排队 / 在跑 / 失败过"在库里说得出口。
--    技术方案 §5.8 要求「单飞 + 租约回收 + 失败给可读原因」，原来的表只有 body NOT NULL，排队无法表达。
ALTER TABLE minutes ADD COLUMN status         TEXT NOT NULL DEFAULT 'ready';  -- 'queued'|'running'|'ready'|'failed'
ALTER TABLE minutes ADD COLUMN lease_until    REAL;   -- 租约到期时间；过期即可被下一次启动回收
ALTER TABLE minutes ADD COLUMN attempts       INTEGER NOT NULL DEFAULT 0;
ALTER TABLE minutes ADD COLUMN failure_reason TEXT;   -- 直接拿来写界面文案

-- ③ 打字输入是一等路径（§6.1、§16.2.1 的 E4）：这一行来自键盘，不来自任何一路音频。
--    只扩 line.source 的取值域；session.audio_source 不动（它描述"这次选的采集来源"）。
--    line.source 的取值：'microphone' | 'system' | 'mixed' | 'keyboard'
```

**`body` 一并改一处**：§15.2 的建表语句里 `minutes.body` 从 `TEXT NOT NULL` 改为 `TEXT`（可空）——
`status='queued'` 的行本来就还没有正文。因为 schema 尚未实现，这是**改建表语句**，不是给既有库做迁移。
真出现老库时，`ADD COLUMN … DEFAULT 'ready'` 会把既有行填成 `ready`，不会把它们判成"没整理出来"。

**为什么 `interrupted` 不是 `state` 的取值**（与 §15.6 配套，实现时最容易搞错的一点）：中断是**事件**、
不是**阶段**。库里 `session.state` 仍然只有 `recording` / `processing` / `archived` 三种；"这次断过"
由未闭合的 `session_interruption` 行（`resumed_at IS NULL`）推出。界面上那个"已中断"的标识是查出来的，
不是存出来的——这样"这一段到底录没录上"永远能从库文件本身回答。

## 16. 用户故事旅程与端到端全流程（2026-09-18 追加）

这一节不是新功能，是把前面 15 节按**路径**再核一遍：三条闭环各自的五个阶段都有落点，
不代表连起来走得通。所以 §16.1–§16.2 给坐标系，**§16.2.1–§16.2.6 是三条主旅程的逐步正文**
（每一步：用户做什么 → 稿上的落点 → 数据落点 → 失败与退路），§16.3 起钉住那一次复核中
**新定下来的产品口径**。

> 用户 2026-09-18：「用户旅程也需要落到方案里。」——所以步骤表在**本节正文**里，不再只放在
> 旁边的 [`USER-JOURNEYS.md`](../2026-09-17-session-closures/USER-JOURNEYS.md)。那个文件保留
> 四样此处不重复的东西：角色与情境定义（§1）、缺口表（§9）、可测验收判据（§10）、逐轮复核记录（§12）。
> **改步骤表改本节**；改判据或缺口改那一份。

### 16.1 旅程的七个段落

E0 起念 → E1 进入 → E2 前置 → E3 这一轮的设置 → E4 主交互 → E5 会中插曲 → E6 交还 →
E7 产物与复用。§4 的 ①—⑤ 是**画板**的坐标系，旅程比它多两段：E0 不占界面，E7 的后半段
（回看、继续、改名、导出、移除）发生在几天之后。E7 内部把「产物」与「复用」分开看，
因为这两件事之间隔着的那几天，正是 P8「记录是资产」要解决的问题——所以每一步的判据里
都要回答「重开 App 之后还在不在」。

### 16.2 三条主旅程 + 一条横切 + 四条衔接

| 组 | 内容 |
|---|---|
| J1 / J2 / J3 | 语音助手 / 会议助手 / 实时字幕各自从起念到复用 |
| J0 首次使用 | **横切**三条闭环，只有一条路：服务 → 授权 → 档位 → 大模型 → 第一条记录。它的价值是防分裂——三类受阻永远是同一条结论条 + 一个出口，措辞随能力变、形状不变 |
| X1–X4 衔接 | 抢麦克风 / 本机音频 / 分人共用 / 助手↔会议互斥（§16.3 与 §14.1–14.3） |

#### 16.2.1 J1 · 语音助手：从起念到下一轮

| 步 | 用户动作 | 稿上的落点 | 数据落点 | 失败与退路 |
|---|---|---|---|---|
| E0 | 手上在忙，想直接问两句 | 不占界面 | — | 不需要它时用键盘；产品不做「按住说话」 |

| E3 | 选人设与音色（**只在这一步**） | 未开始态：人设 chip + 音色（可试听） | `session.persona_id / persona_title / voice_id` | 人设进 system prompt，开始后只读（§14.4）：中途换会让前缀缓存整段失效 |

| E7 | 回看 / 复制全文 / 导出 | 记录库：列表（含搜索）+ 选中 + 详情 | 读 `line` 按 `ordinal` 排 | 导出走系统保存面板，不画伪保存（§6.2 第 3 条） |

**这条旅程最容易做错的一处**：把人设做成「随时可调的风格滑块」。用户要的其实是「换一个角色」，
而它的代价（前缀缓存整段失效、每一轮重算）会在几轮之后才显形——所以锁必须画在明面上，
出口（新开一轮）必须紧挨着它（§14.4）。

### 16.3 X1 · 会议录制中按 `⌘⇧L`：不开第二条会话

本机只有一个麦克风、一个 realtime worker（P5）。第二条会话要么拿到 `backend_busy`，
要么拿到一条没有声音的音轨——两者都不是用户能理解的结果。所以字幕带以**受阻态**出现：

```
会议正在录制 · 麦克风归会议所有
[打开会议转录]   [结束会议并启动字幕]
```

两个出口都是有意义的动作：前者切到会议页（那里的转录比字幕带更全），后者走会话占用守卫（§6.4）。
第三条受阻文案与既有两个（麦克风未授权、语音服务未就绪）**共用同一条带子的形状**，不新造一种。
稿上落在 `浮层 · 字幕带 · 受阻`：文案口径在这里定死，但**不单独出板**——浮层是全量稿与闭环稿
共用的件，改它会同时动到已经交付的 48 板（同 `HANDOFF.md` 已知偏差 5 的处置）。

### 16.4 导出物命名与检索口径

| 项 | 决定 | 理由 |
|---|---|---|
| 导出物命名 | `<kind>-<标题或首句摘要>-<yyyyMMdd-HHmm>.<ext>`；文件名里不用 UUID | 用户要在 Finder 里认出它；UUID 只做库内主键 |
| 会话列表搜索 | 匹配 `session.title` + `line.text` + `minutes.body` | 想不起会议名时，人一定是从内容找 |
| 记录库搜索 | 匹配 `line.text` + 说话人显示名；筛选是 `starred` 与说话人 | 与列表搜索不同层：一个是「找哪一场」，一个是「找哪一句」 |
| 索引 | 优先 FTS5，不可用时退回 `LIKE` + `line_by_session` | 与 §15.5 同一条取舍：检索是产品能力，索引是实现细节，FTS5 的可用性不该阻塞阶段 2 |

导出物内容口径（与 §9、§15 一致）：SRT 用 `line.ordinal` 与**相对会话开始的秒**（不用墙钟时间）；
Markdown 纪要带元信息（时间、时长、档位、是否分人、来源）；转录保留来源列与说话人显示名；
JSON 是完整记录，但里面**没有**密钥、音频与完整 prompt——因为它们本来就没有列可写（§15.3 第 4 条）。

### 16.5 助手的长期记忆（`assistant_memory` 的产品规则）

记忆是「跨轮次仍然成立的事」，与「这一轮说了什么」分开存——删掉一段对话不该让助手忘掉你的偏好。

| 项 | 决定 |
|---|---|
| 写入 | 助手在会话里**提议**，用户确认后才落库；不静默积累（用户下次只会觉得「它怎么知道这个」） |
| 生效 | **只在下一轮**：它与人设进的是同一段 system prompt，中途改同样会让前缀缓存整段失效（§14.4 的同一条推理）。本轮用的是会话开始时那一份的注入结果 |
| 可见 | 助手页右栏「记录 / 记忆」两个标签，同一个栏位（资产区常驻）；每条带来源会话，可停用（`active=0`）或移除 |
| 边界 | 移除一条记忆不改任何一段历史记录（那段对话里它仍然在）；删掉一段对话也不删记忆（`source_session_id` 是 `ON DELETE SET NULL`） |
| 不做 | 跨设备同步、自动长期画像、以及「这条记忆影响了哪一句」的归因展示——v1 都不做 |

稿上：`语音助手 · 对话页 · 记忆（跨会话 · 下一轮生效）`（2026-09-18 补）。
它是这一页的第 5 种态，不是新页面：页头、结论区、主区都不动，右栏从「记录」切到「记忆」。

### 16.6 破坏性确认（移除一条记录 / 清空字幕记录）

同一张浮层（sheet，不是 alert——它需要说明与选项），四件事必须写出来：

1. **影响面**：移除的是哪一条、多少行（`line` 的条数）与多少个纪要版本；
2. **能不能恢复**：本机库没有软删除，移除即不可恢复——除非有库文件的备份；
3. **替代动作**：`先导出…`（Markdown / SRT / 纯文本）；
4. **默认按钮是取消**，破坏性动作不是默认项。

清空字幕记录另加一句：导出 SRT 可以先留一份。这两处在稿上**不单独出板**（沿用既有 sheet 形状），
但文案口径以本节为准。

### 16.7 会议中断：四类断法与处置

| `reason` | 触发 | 处置 | 库里 |
|---|---|---|---|
| `service_lost` | 语音服务重启或不可达、streaming worker 被回收 | 收声先停，正文照旧；「继续这一段」新开一路音频并把中断区间写进记录 | 一条 interruption |
| `sleep` | 系统睡眠 / 合盖 | 醒来即中断态：麦克风与 tap 都要重新拿一次，**不自动续** | 同上 |
| `source_lost` | 被 tap 的 App 退出；**或采集流自己结束**（设备被拔 / 引擎停了） | 前者按 Bundle ID **自动接回**（`processRestoreEnabled`）、录制不打断；后者进中断态等用户选「继续这一段 / 结束并整理」 | 同上（前者不需要人决定） |
| `unexpected_exit` | App 退出或崩溃 | 下次启动：把仍是 `recording` / `processing` 的会话封存为 `archived`，`end_reason='unexpected_exit'` | 一条 interruption + 封存 |

**共同规则：不静默续录。** 断点之后如果悄悄接着写，记录里会出现一段没有来源的文本，
事后没人分得清那是「这段没人说话」还是「这一段根本没录上」。所以续接一定是一个动作，
并写一条中断区间；导出物里也看得出来（`line.t_start` 在断点处是跳的，这就是可见证据）。

### 16.8 文案口径：面向终端用户（用户 2026-09-18 第五轮第 4 条）

按旅程逐屏走的时候，最容易被看出来的问题不是功能缺了，而是**界面上写着实现细节**。所以定一条
写文案的规矩，它比单个措辞重要：

> **界面上写用户看得见的现象；机制写在本规格与生成器的代码注释里。**

按这条规矩改过的词（都是本轮实际改的）：`SQLite` → 「本机数据库」；`封存` → 「存好」；
`落盘` → 「写进记录」；`元数据修订` → 「只改标注与版本」；`水位` → 「余量 / 那半句分完了」；
`system prompt` → 「它开口前读的第一段话」；`前缀缓存整段失效` → 「它得把开头重读一遍：你会觉得
它突然变慢」；`capability` → 「这台 Mac 现在的档位用不了」；`recording` → 「录制中」。

第七轮（双视角审查，§17）把这条规矩补到"每一处"：上面那批改完仍有漏网的，都在这一轮清掉——
`prompt` → 「音色只影响朗读」；`系统提示词` → 「归『记忆』那一栏管」；`Bundle ID` → 「它重新出声
就自动接回」；`服务端 VAD` / `首个 PCM` / `系统 AEC` / `EOF 屏障` / `全双工` / `tap` →
「你一开口就停」/「换设备重开这一段」/「系统回声消除」/「结束那一刻补上最后半句」/「你随时能
插话」/「来源 App」；`preset` → 「内置声音」；`数据库` → 「记录库」。

保留的技术说法只有一处例外：**档位**（`light` / `balanced` / `quality`）——它是这台机器上一个
用户可切换的运行选择，不是实现名，所以保留，且必须配一句人话说明后果。

**第六轮（§12.1.8）对这条规矩的两处修订**：

1. **「分人」从所有用户可见处清掉**：它就是用户点名"看不懂"的那个词。统一说「谁在说话 /
   说话人 / 说话人区分」。唯一的例外是开发者文档（`DeveloperDocsContent` / `DeveloperDocsView`），
   那里描述的是服务契约里的 `diarization` 能力名，读者是调用方。
2. **「档位」在会话页退出**：会议 / 字幕右栏与导出物里改说「识别精度」——用户在这一屏要判断的是
   "认得准不准、能不能标出谁在说话"，不是运行选择的工程名。「档位」留在设置与模型页，
   那里用户已经是在挑运行选择本身。完整术语表见 §12.1.8。

同一轮定下的还有两条**结构**规矩（它们不是措辞，改的是交互本身）：

1. **同一个动作在屏上只画一次**。结论条（`conclusionBand`）在就绪态**不再重复页头或右栏的
   动作**——原来「开始对话 / 开始字幕 / 开始会议 / 继续这一轮 / 新开一轮以生效 / 复制全文」
   都在屏上出现两次，实施时无法判断哪个是唯一主动作。结论条只在**受阻态**与**需要切换**时带
   按钮；就绪态它只说明影响，动作留在页头（或者记录卡自己的页脚）。
   - **允许的例外只有一处**：会议中断页的「继续这一段」在页头出现一次，在断法表的每一行再出现
     一次——表格在这里是**文档**（"这种情况下你的出口是什么"），逐行给同一个出口是有意的。
   - **两个主按钮是允许的**：会议页的「重新生成纪要」与行内编辑器的「保存」、对话页的「结束对话」
     与合成器的「发送」——它们是页级动作与组件内动作，不是两个相互竞争的入口。
2. **术语只留一套**。资产是「记录」（对话记录 / 会议记录 / 字幕记录），放记录的地方是「记录库」；
   原来同时使用的「记录窗 / 会话记录 / 字幕会话」在这一轮全部归一。检查器的标题也跟着类型走
   （本次对话 / 本次会议 / 本次字幕），不再统一叫「本次会话」。

**两处本轮新定的文案**（技术方案 §5.8 与 §3.5 的落点，2026-09-18）：

1. **纪要没整理出来**。原来规格里没有这一句——界面上只有 `正在整理会议…`，失败后什么都没变，
   用户会以为这段会白录。定成：

   | 位置 | 文案 | 出口 |
   |---|---|---|
   | 会议页状态带 | `纪要没整理出来 · 转录已经存好了` | `重新生成纪要` |
   | 记录库里那一行 | 副标题 `没整理出纪要` | 打开后同上 |

   正文里给一句人话原因（`模型没接上` / `等超时了` / `它不肯写`），**不出现错误码**；
   原始原因进开发者详情。措辞上**必须先说"转录已经存好了"**——用户真正怕的不是没纪要，
   是这段会白录。

2. **两条系统权限弹窗的文案**。`GENERATE_INFOPLIST_FILE` 里现在写的是**音色克隆专用**的一句，
   会话要用它就必须改；系统录音是新增的键：

   | 键 | 文案 | 什么时候出现 |
   |---|---|---|
   | `NSMicrophoneUsageDescription` | `SpeechRail 要用麦克风把你说的话变成文字，以及和语音助手对话。声音只在这台 Mac 上处理，不会存成音频。` | 第一次开始任一语音会话 |
   | `NSAudioCaptureUsageDescription` | `SpeechRail 要采集这台 Mac 正在播放的声音，用来把会议或视频里的声音变成文字。` | **只在第一次选「本机音频」时** |

   这两句是用户在系统弹窗里唯一看到的话，所以按同一套规矩写：说清"拿来干什么"与"声音去了哪"，
   不写机制（没有 `AEC` / `tap` / `PCM`）。系统弹窗不画板，实现以这两句为准。

**侧边栏常驻一条定位语**：三个能力在「会话」组里是同级项，第一次打开的人必须能在原地知道该用
哪个。所以 `main.js` 的 `buildShell` 在「会话」分组里常驻一句「要文字用字幕，要纪要用会议，要
对话用助手」——它属于导航，不写在某一页的说明卡上（§17 第 1 条）。

## 18. 非主框体：可以收起的面板（2026-09-18 第八轮）

用户原话：「语音助手，『本次对话』面板需要可收起，举一反三，其他非主框体，也通用要求。」
这一节是那条要求的**规范位置**：先定义什么算非主框体，再定收起之后必须成立什么，最后才是
某一个面板上那枚按钮。稿上的落点两块：`非主框体 · 收起规则（通用）`（判据 + 清单）、
`语音助手 · 对话页 · 对话中（本次对话收起）`（规则落到一屏上的样子，不是另画一屏）。

### 18.1 定义

- **主框体**：这一屏正在做的事，以及做它必须看见的东西——页头、状态带、主内容区
  （对话滚动区 / 转录区 / 字幕正文）。
- **非主框体**：贴在主框体旁边的辅助面。判据只有一条——**关掉它，主任务照样能做完**。
  满足这条的都要能收起；不满足的（例如「结束对话」这种整页唯一的出口）不许做成可收起的。

### 18.2 六条判据（缺一条就不算「可收起」）

| # | 判据 | 说明 |
|---|---|---|
| ① | 有收起态 | 收起是面板的**正常状态**：不是被窗口挤没的，也不是把功能藏起来 |
| ② | 控件贴着分界线 | 内容列**首行尾端**一枚 `sidebar.right` 图标按钮（28pt，复用 `Control.iconButton`，不新增数值 token）。**不是工具栏项**——工具栏里每件动作的落点由系统按「固定项 + 浮动间隔」分配，锚不住这条分界线（REDESIGN-SPEC §11.6 第六十二轮的离屏实测：同一枚按钮在四档窗口宽下漂移 76.5 → 316.5pt） |
| ③ | 一处唯一 | 面板自己不再画第二个收起按钮：同一个动作一屏只出现一次（§3.2-S6），由离线门禁守着 |
| ④ | 收起后主框体吃满 | 让出来的宽度归主任务：对话行、转录、字幕按新宽度重排；不留空栏，也不退化成分隔线 |
| ⑤ | 不看面板也不会做错事 | **这是收起的前提**：关键状态在主框体里也要有一份（会议怎么记的 / 来源是什么 / 这一轮的人设与音色）。做不到，这个面板就不该允许收起 |
| ⑥ | 记得住 | 收起态按屏记忆、跨启动保留；菜单项与快捷键给键盘路径，不逼人去画布上找那枚图标 |

### 18.4 两条边界

- **收起 ≠ 关掉功能**：面板收起时任务照跑（继续对话 / 继续录 / 继续看字幕），没有任何能力
  随面板一起消失。
- **开发者详情与面板的关系**：`⌥⌘I` 的「显示开发者详情」住在面板里——面板收起时它跟着收走，
  展开时回来；**不因此拦住收起**（收起优先，详情只是面板里的一层）。两个快捷键不合并：
  `⌥⌘I` 管详情，`⌘⌃I` 管面板。

  **一个全局开关**，而 §18 要求面板可视性**按屏**记忆（会议页收起的面板不该影响助手页）。
  实现时两者要分开：面板可视性按路由存，开发者详情仍是一个全局开关。

## 20. 第十轮：深入旅程摩擦点消解与操作通道优化（2026-09-18）

在第九轮完成中栏列表归一化（280pt）与 J0 空态引导板补齐的基础上，进一步下钻至高频真实使用场景（公共场合打字输入、复杂会议音频采集心智、会议整理紧急交付）的三处摩擦点：

### 20.1 J1 语音助手打字输入隐私与外放焦虑消解
- **痛点**：语音助手的输入框原文案为 `"输入消息（回车发送）…"`，用户在图书馆、开放办公室或公共场合打字输入时，由于助手默认会调用 TTS 外放合成声音，存在强烈的“突兀外放”社交顾虑与心理摩擦。
- **改法**：输入框 placeholder 精细化改为 `"输入消息（↵ 发送 · 静音不外放）…"`（`main.js:3334`），给打字用户确定性的静音安全预期（键入交互静默，麦克风对话才外放），化解打字输入时的外放焦虑。

### 20.2 J2 会议助手音频来源选择与混音交互理顺
- **痛点**：原来源选择配置卡片中，前三行为可选项（麦克风、系统音频/应用采集），第四行却伪装成了未选状态的提示卡片，视觉状态令人困惑，给用户造成“第四个来源为什么不能勾选”的认知负担。
- **改法**：重构为说明行 `["Ready", "自动混音", "多来源同时勾选时自动合流处理；转录中为每一句独立保留专属来源标签。", "生效中"]`（`main.js:4494`），明确表达这是底层混音引擎的自动行为，消除伪来源的认知摩擦。
  > **2026-09-19 更正**：这一行的说明句后来被证明是一句做不到的承诺——合流之后只有一条流，
  > 逐句的来源在链路上无从判断，实现里只能整行记 `mixed`。应用侧已把这句话改成如实口径，
  > 稿侧（`main.js:4494` 那一行）待同步；要不要真的逐行标，见 §13.2 的 D11。
