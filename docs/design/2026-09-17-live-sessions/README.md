# SpeechRail macOS App · 实时会话模块（语音助手 / 会议助手 / 实时字幕）

> 版本：Proposal v1.0.0 · 2026-09-17
> 状态：`proposed` —— 本包描述**目标形态**，不代表当前实现。

## 这个包是什么

把 Sona 的三个能力——**语音助手**、**会议助手**、**实时字幕**——迁进 SpeechRail 的 macOS App。
不是把 Sona 的 Web 控制台搬成原生窗口，而是回答三个问题：

1. 这三个能力在 SpeechRail 的产品里分别是什么**时刻**（而不是三个功能页）？
2. 本机只有一个麦克风、一个 ASR worker，**谁在用**这件事怎么让用户随时看得见、交还得了？
3. 大模型是**外部依赖**（SpeechRail 只管 ASR/TTS/分人）时，没配置、不可达该怎么呈现？

## 配套稿：会话闭环（2026-09-17）

本包描述这三个能力**按页面**的完整形态（48 板全量稿里的一篇）。同一批能力另有一份按**路径**组织的稿：
[`../2026-09-17-session-closures/`](../2026-09-17-session-closures/README.md)——只画三条闭环
（入口 → 前置与受阻 → 主交互 → 交还与守卫 → 产物与回看），并补两条判据：

1. **记录是资产**：会议记录与纪要、字幕会话、助手对话都落在本机 **SQLite** 库、长期保留，
   产物页一律是「记录库」。这条取代本包原来的 P8「产物是本机文件」与 §13 的 D1 待裁决。
2. **页面不是一次性画面**：每条闭环只有一个产品页加一条浮层，其余都是这一页的状态；
   改交互改的是状态，页骨架与资产区不动。

用户 2026-09-17 随后又加了两条约束，其中一条改的是**产品规则**（不是文案）：

3. **新会话开启后不允许换人设**——人设进 system prompt，中途换会让大模型的前缀缓存从改动点
   之后整段失效。音色不受此限（它只影响 TTS）。落点：本包 §6.1 / §7.1 / §8 / **§14.4**，以及闭环稿
   新增的 `语音助手 · 对话页 · 未开始（先定人设与音色）` 一态。
4. **统一设计 token**：会话模块不新开视觉语言。稿侧核查数字与实现规则见本包 **§11.1**。

编码前的对账（屏 → 组件、状态 → 契约、数据模型、快捷键、两侧缺口、以及必须先定的 D7/D8/D9）
在闭环包的 [`IMPLEMENTATION-READINESS.md`](../2026-09-17-session-closures/IMPLEMENTATION-READINESS.md)；
本包新增 **§15 数据模型（本机 SQLite，草案）**，供该处引用。

两份稿共用同一个生成器（`../2026-09-15-macos-uiux-redesign/figma-kit/`，`build.js` = 全量稿，
`build-closures.js` = 闭环稿）。本包的 48 板导出物是 D1 裁决**之前**生成的，仍带旧的「本机文件」字样。

## 与 2026-09-15 包的关系

本包**不重写**视觉语言。颜色、间距、圆角、字体层级、组件契约仍然只有一处事实来源：
[`../2026-09-15-macos-uiux-redesign/REDESIGN-SPEC.md`](../2026-09-15-macos-uiux-redesign/REDESIGN-SPEC.md) §5
与 [`../../developers/macos-app-design-system.md`](../../developers/macos-app-design-system.md)。

本包只做三件事：

1. **修订边界**：撤销 2026-09-15 包 §2.1 第 2 条（「不把 App 变成会议 / 实时字幕 / 语音助手客户端」）。
   那一条在当时是对的——能力不在服务契约里；现在它们要作为产品能力进来。
2. **新增信息架构**：侧边栏新增「会话」组（3 条路由），并给出与之配套的快捷键重排。
3. **新增界面**：3 个页面 + 4 个浮层状态 + 1 个占用守卫 + 设置第 4 个页签 + 一组新组件集。
   全部生成进**同一份** Figma 文件、同一个生成器。

## 落地顺序（建议）

1. **所有权先行**：`SessionCoordinator`（谁能用麦克风）+ 侧边栏底部的会话状态区。这是三个能力的共同地基，
   也是"不照搬 Sona"最关键的一步——Sona 用模式切换命令 + toast 表达互斥，App 用常驻可见的所有权表达它。
2. **实时字幕**：唯一只依赖 ASR 的能力，能最快跑通"采集 → Realtime → 上屏"整条链，且不依赖大模型。
3. **语音助手**：接上大模型与 TTS，验的是"未配置 → 配置 → 通话"这条首次使用路径。
4. **会议助手**：最后做，因为它同时依赖分人档位、纪要模型与产物存储三个决定。

每一步都应保持 App 可构建、可回退；服务侧协议与档位不在本包范围内。
