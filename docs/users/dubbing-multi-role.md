# 多角色短脚本：逐句选声、停顿与局部返修

短剧对白、课程对话、访谈演示——几个人轮流说话，但不必开一次整本书的分析。配音台的「多角色脚本…」
就是为这件事准备的：粘贴脚本，给每个角色选一个声音，逐句试听，只重做你不满意的那一句。

## 从粘贴脚本开始

在配音台点「多角色脚本…」，把对话稿粘进去，给每个角色选音色，然后「开始制作」。

- 不需要 LLM 配置，也不需要先有一件已保存作品。
- 分段只来自文稿本身：按换行与句末标点切。**不自动改写原稿，也不猜哪个角色念哪一句**——
  谁念哪一段，永远是你自己点的。
- 一个默认角色就够开始，逐句再按需覆盖。
- 角色可以先不选声音，只是那种角色的段落暂时不能生成；界面上会写明是哪个角色还没选。

## 逐句选声与停顿

每段下面有两个控件：

- **角色**：这一段由谁念。「跟随默认角色」是显式选择，不是隐式继承。
- **停顿**：这一段说完之后留多长静音，0 到 2 秒常用档位，步进 100 毫秒，上限 5 秒。

停顿是**装配时插进去的静音**，不是控制标记：它不进正文、不进模型，最后一段之后的停顿也不会
写进成品——句间停顿说的是「两句之间」，不是成品尾巴。

## 局部返修

点「重做这一段」只重新生成这一段：其他段落、已采用的版本、候选版本与撤销记录全部原样保留。
试听、采用、撤销采用、清理未采用候选，都与单声音项目是同一条路径。

## 什么时候会要求你重新生成

改一处不会让整个项目作废，但会诚实地标出受影响的部分：

| 情况 | 会发生什么 |
|---|---|
| 换了某个角色的声音 | 只有那个角色的旧版本标为「需要重新生成」，其他角色的已采用版本不动 |
| 音色被改过（同一音色，参考变了） | 用到它的旧版本同样标为「需要重新生成」 |
| 改了某一段的正文 | 只有这一段需要重新生成 |
| 某一段的角色还没选声音 | 这一段标为「需要重新生成」并说明原因 |

界面上不会出现「自动换一个声音」这种动作。删角色时如果还有段落指着它，会先让你改派段落——
静默换声比拒绝更糟。

## 导出

导出三份文件，出自同一次采用决策，因此一一对应：

| 文件 | 内容 |
|---|---|
| `<名称>.wav` | 成品音频，按段落顺序拼接，段间含你设的停顿 |
| `<名称>.txt` | 正文，每段一行，与音频第几段严格对齐 |
| `<名称>.segments.json` | 片段清单：顺序、角色、声音、候选、时长、停顿 |

还有段落没有采用有效版本时，导出会整次失败并告诉你，不会跳过那一段拼出一个「看起来完整」的成品。

## 边界

- 语速只有 1.0x 一档可调；参考音色（克隆）只支持 1.0x，角色绑到克隆音色时语速被固定。
- 没有视频时间轴、自动翻译、配乐混音、跨平台 UI。
- 有声书的全书分析是另一条路，这里不重复它；两个流程共用同一套候选、采用、撤销与播放。
