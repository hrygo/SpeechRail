# 会议纪要与模型服务

会议结束后，App 使用「设置 → 会话」里的模型服务整理纪要。默认沿用共用配置；
若启用了「会议纪要」专用配置，则使用该配置中的服务、模型和密钥。
不需要为纪要另外选择某个品牌的 provider。

模型服务须提供兼容 OpenAI 的 Chat Completions 或普通 Responses 文本接口，
并且模型能按提示返回符合纪要结构的 JSON。服务不必支持后台任务或强制 JSON Schema。
App 会适配接口及格式能力，再核对结构与引用；结构不合要求的输出不会作为成功纪要保存。
存在引用问题的候选会保留供你复核，并明确标记未通过引用核对。
「检查连接」确认短文本通路，不保证会议纪要的质量、长度或生成时间。

整理失败不会删除文字记录。修正模型服务配置后，点击「重新生成」会创建新版本，旧版本仍保留。
若网络中断或 App 退出导致无法确认上一请求的结果，App 不会自动重复提交；
确认需要再次整理时，可以显式重新生成。

文字记录与纪要保存在本机。生成时，文字会发送到配置的模型服务；请求使用 `store=false`，
这不代表 provider 不会按自身政策保留数据。需要所有内容留在本机时，应配置在本机运行的模型服务。
