# 会议纪要与模型服务

## 说话人归属

会前可选「预计发言人数」：默认「不确定」，也可选 2 人、3 人、4 人、超过 4 人。
开启「会议显示说话人」后生效；不确定可直接开始。选择 2/3/4 人会限制本场可确认身份数，
不要求凑足人数；不确定采用服务通过认证的容量，超过 4 人仍最多确认四位，额外声音保留未识别。
人数是上限提示，不是实际人数保证；填少可能增加未识别占比，填多不会自动提高准确率。
中途新增或证据不足的短插话不会被强塞给已有身份。选择只作用于本场，续接沿用，下一场恢复
不确定；原会议记录不会因此重新归属。客户端与服务会核对有效上限，无法执行时保留文字并说明原因。

开启「会议显示说话人」后，一场会议最多确认 4 位稳定发言人。会议可以超过 4 人，
超额、过短或证据不足的发言仍完整记录，归属显示为「未识别」，不会硬归给已经确认的人。
这四位不保证是整场发言最多的四位；身份确认后不按发言占比轮换。未识别可能包含多位
发言人，也可能包含已确认者的模糊片段，不能把它算成一个共同的第五人。

会议只使用具备声音匹配与拒识能力、且通过独立质量认证的分人后端。未就绪时继续记录
文字并说明原因，不改用无法拒识的四槽分人。断线续接缺少声音身份延续证明时，新发言
保持未识别，先前归属保留；开始新会议才重新建立自动身份。

「文本占比」以整场定稿正文的有效 Unicode 字符计算，排除空白与标点。逐词归属中的
未识别、缺口和未归属行全部保留在分母内，不把已确认的四位重新归一化为 100%。
文字长度不是发言时长；当前面板不宣称提供真实说话时长占比。

说话人名字是用户对本场匿名标签的命名，不是身份识别。
身份在容量以内也不保证每句话归属正确；核对归属时应以实际发言为准。
原始音频不随会议记录保存，因此仅凭保存的文字与标签无法重新运行声学分人。
新会议的归属处理不会重写已保存的历史会议。

## 纪要模型服务

会议结束后，App 使用「设置 → 会话」里的模型服务整理纪要。默认沿用共用配置；
若启用了「会议纪要」专用配置，则使用该配置中的服务、模型和密钥。
不需要为纪要另外选择某个品牌的 provider。

正常结束并完成文字封存后，App 自动发起整理，并切换到「纪要」显示排队、整理或失败状态。
未配置模型时给出设置入口；历史会议重新生成也显示对应会议的进度，重试不会提交到另一场会议。
整理期间可先导出文字记录或停止整理；当前整理结束或停止后再开启下一场会议。

纪要正文按标题、列表、引用、强调等 Markdown 语义排版；复制与导出保留 Markdown 源文。
重新生成只新增版本，不覆盖原始文字记录或旧纪要。

模型服务须提供兼容 OpenAI 的 Chat Completions 或普通 Responses 文本接口，
并且模型能按提示返回符合纪要结构的 JSON。服务不必支持后台任务或强制 JSON Schema。
App 会适配接口及格式能力，再核对结构与引用；结构不合要求的输出不会作为成功纪要保存。
存在引用问题的候选会保留供你复核，并明确标记未通过引用核对。
「检查连接」确认短文本通路，不保证会议纪要的质量、长度或生成时间。

整理失败不会删除文字记录。修正模型服务配置后，点击「重新生成」会创建新版本，旧版本仍保留。
若网络中断或 App 退出导致无法确认上一请求的结果，App 不会自动重复提交；
确认需要再次整理时，可以显式重新生成。

文字记录与纪要保存在本机。生成时，文字会发送到配置的模型服务；请求使用 `store=false`，
这不代表 provider 不会按自身政策保留数据。需要所有内容留在本机时，应配置在本机运行的模型服务。
