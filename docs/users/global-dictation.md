# 全局听写：把识别写进任何应用

全局听写让 SpeechRail 的识别能力在**其他应用里**可用：在任意输入框里按一次
`⌘⇧D` 开始录音，再按一次结束，整段识别完成后，文字写回开始录音时那个应用的
焦点控件。它不打开主窗口、不切换前台、不移动光标。

这是「输入入口」，不是第四个会话页面。听写不产生独立记录，也不进会议、字幕或
助手的历史。

首次使用前需要在「系统设置 → 隐私与安全性 → 辅助功能」里允许 SpeechRail：识别
不需要它，把文字写进别的应用需要。没授权也能用，但每次都会退化成「已复制」。

## 1. 开始与结束

| 动作 | 结果 |
|---|---|
| 按 `⌘⇧D`，或从菜单栏选「开始听写」 | 记录当前前台应用，开始录音，屏幕底部出现浮层 |
| 再按一次 `⌘⇧D`（菜单栏此时显示「结束听写」） | 停止录音，整段上传识别，然后写回目标控件 |

浮层显示当前阶段：正在听写（带目标应用名）、正在识别、正在写入，最后是结果。
结束或失败后浮层在约 6 秒后自动收起，也可以点「关闭」。录制中浮层只报状态、不给
「关闭」——那会让人以为可以中途作废，而这一段其实一定会被识别并交付。

**录音期间不要切换应用。** 写入前会重新核对前台应用是否还是开始时那个；如果
已经切换，文字不会被塞进别的窗口，而是降级为「已复制」。

## 2. 三条硬规则

- **一次只跑一段。** 识别或写入还没结束时再按热键，不会排队也不会打断，只提示
  「上一段还在识别，完成后会自动交付」。
- **迟到的结果不落地。** 每次开始都换一个会话标识，识别与写入的每一步 `await`
  之后都先核对它，因此旧结果既不会插进新目标，也不会重复插入。
- **识别成功不等于写入成功。** 写入前重新核对目标应用，先直接写选中文本，失败再
  读字段全文、把选区（没有选区就是末尾）换成新文字，两条都不成立就明确说明原因，
  把文字放进剪贴板，而不是假装写入成功。

## 3. 写不进去时会怎样

浮层标题会变成「已复制，请手动粘贴」，并说明具体原因：

| 原因 | 含义 | 怎么办 |
|---|---|---|
| 结束时的前台应用已经不是开始时的那个 | 录音期间切换了应用 | 切回目标应用后手动粘贴 |
| 目标位置不接受文字输入 | 焦点不在可编辑控件上，或该控件不支持代写 | 把光标放进输入框后重试 |
| 没有辅助功能授权，无法代写 | 系统未授予辅助功能权限 | 在「系统设置 → 隐私与安全性 → 辅助功能」中允许 SpeechRail |
| 写入目标失败 | 权限与目标都正常，但代写被拒绝 | 手动粘贴，或换一个输入框重试 |

剪贴板只写不恢复旧内容：一次迟到的恢复会冲掉用户之后复制的东西。超长文字只放
前 20000 个字符，避免把整本书塞进别人的剪贴板历史。

识别这一侧失败时标题是「听写未完成」，原因同样写在浮层里：没有识别到文字、
麦克风未授权、采集没有起来、单段超时，或服务正忙。

## 4. 上限、冲突与拒绝

- **单段最长 5 分钟。** 到上限时采集侧真的停掉设备并报「太长」，不会把录音截断成
  一段看起来完整的片段。
- **不抢占麦克风。** 会议助手、实时字幕、语音助手或提词器正在使用麦克风时，
  听写会直接拒绝并说明是谁在占用，不排队、不中断别的会话。
- **没有目标就不录。** 开始录音时找不到可写入的前台目标（包括 SpeechRail 自己在
  前台），不会占用麦克风。
- **服务忙就等。** 识别走与字幕、会议相同的服务准入；服务正忙时提示等当前会话
  结束，不重试、不降级到别的模型。

## 5. 隐私边界

听写复用会话层的麦克风采集：只有从开始录音到停止之间才占用设备，录音只用于这一
次识别，不落盘、不进入作品库、不产生历史记录。识别由本机服务完成，不经过云端。
