# 会议与字幕：找回未保存的文字

本说明对应 R07 开发分支，整包审查与 CI 尚待完成。

会议页与字幕页会显示需要处理的记录。字幕浮层的「未保存文字」按钮也能打开相同操作，
无需等待鼠标悬停。存在多场记录时，按日期选择要处理的那一场；开启新场不会把旧场的操作
改成新场的保存或结束。

## 保存失败时

选择「重试保存」。App 使用原来的内容和保存身份重试，不要求再说一次，也不需要再次收到
识别结果。重试失败时，未保存内容仍可复制；已接纳的文字不能通过结束操作跳过。

「复制未保存文字」只复制所选记录尚需处理的内容。复制成功不会自动清除保存失败或结束记录。
这些尚未落库的恢复命令保留在当前 App 进程内；退出 App 前应重试成功或自行保存复制的文字。

## 部分文字未完整保留时

保存积压超过限额时，后来的文字可能无法接纳。提示会明确区分这类情况与普通保存失败。
能恢复的预览可能只包含最近一句；一句过长时也可能只保留开头，复制内容会写明限制。
重试已有内容成功，也不意味着这些文字已经完整保存。

选择「按不完整记录结束…」会要求确认。确认后，App 会：

1. 等待本场已接纳的文字保存完成；存在保存失败时，仍要求先重试。
2. 将仍可恢复的预览保存到单独的恢复内容中。
3. 将这场记录标为「中断后结束」，保留已保存的文字，不自动生成纪要。
4. 确认完成后释放这场记录占用的恢复限额，允许后续新建。

若确认期间又出现新的未完整保存内容，旧确认不会将它清掉；刷新提示后重新确认。
恢复预览写入或结束确认失败时，原来的恢复目标继续保留，可以再次尝试或先复制。

## 回看恢复内容

会议和字幕记录中的恢复内容单独显示，可选择文字或使用「复制恢复内容」。
它包括没有拿到完整定稿的预览，以及不完整结束时保留的预览说明。
这些材料不计入正式纪要、复制全文、默认导出或正式搜索索引。

完整结束的消费与封存联合屏障仍由 R08 跟进。实现边界与验收进度见
