# 有声书一键配声准备实施计划

**目标**：默认一键完成全书声音分配，精细选声与音色创作由创作者主动打开；完成配声后不自动生成章节音频。

**Active goal**：让创作者在全书分析后，一键完成角色配声准备，无需逐个配置；精细调音保留为可选操作，章节音频另行启动。同时符合 UX/UI 与性能验收标准。

**架构**：沿用 Registry 的纯规划、Store 的原子提交与 Workflow 编排。推断的人物重要程度只影响分配优先级，不等于用户要求独占声音。既有绑定、人工独占、音色归属与制作验收边界保持有效；配角共享由一键动作明确接受，同章撞音与版本变化集中确认。

**技术栈**：Swift、SwiftUI、XCTest，macOS 26.0 / arm64；无新依赖、无持久化迁移。

**需求来源**：2026-10-20 用户截图与“应提供一键方案，精心创造角色音色时再手工调”；用户明确“不一键开始生成”。

## 约束

- 只修改配声准备逻辑与对应文案，不执行真实模型调用、安装或服务操作。2026-10-20 用户已明确授权本次临时测试窗口的 UI 自动化验收。
- 人工指定的独占政策、已有绑定及必需声音属性不自动放宽；目录过滤为空时不借用其他书籍声音。
- 同章撞音和引擎版本变化仍需明确确认，确认界面按问题分组，不列出整本人物名单制造负担。
- 自动配声不得调用章节渲染、试听渲染或音色创建。精细创作仍使用现有菜单入口。

## 审查重点

- 已分层的 54 个角色只剩少量合格声音时，推断主角不应把整批规划卡死。
- 人工独占或既有绑定确实占满容量时，原选择保持不变并显示可行动的提示。
- 一键接受配角共享，不代表接受同章撞音或引擎版本变化。
- 重复点击、取消与切换书籍不得重复提交或污染当前书籍的提示。
- 准备完成后停在可制作状态，不启动音频生成；分析结束时不得用再次确认覆盖原本的配声阻断原因。
