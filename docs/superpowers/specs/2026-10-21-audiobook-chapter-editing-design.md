# 有声书分析前章节编辑设计

日期：2026-10-21。状态：用户已确认，已实施，定向验证通过，独立审查问题已修复。

## 目标与范围

用户要求：导入后、分析前，可以手工修改章节标题和正文，后续流程以用户保存的内容作为唯一真源。用户已明确不需要浏览器草图，沿用现有界面风格。

本功能承接加工文本管线：原始导入资料保持只读参考；活动工作修订提供后续分析、角色证据、试听、发音词条命中、合成、重录及文字元数据的内容。用户正文保存不得再次从原文加工，也不得再次自动连行、繁简转换或纠错。

用户已确认以下交互与保存规则。此次范围是实现与定向验证；不含新的发布、安装、真实作品迁移、真实音频生成或 UI 自动化。

## 使用方式

- 在“准备与角色”中，当前章节正文面板提供可见的“编辑章节…”按钮；“整理章节”菜单提供同名入口。现有分析后的“重命名章节…”行为保留。
- 弹出沿用现有设计系统的章节编辑面板：上方“章节标题”单行字段，下方“正文”多行编辑器，底部“取消”和“保存更改”。使用原生编辑、选择、复制粘贴及撤销能力，复用现有输入框、字体、间距和面板 Token。
- 编辑器加载活动工作修订中本章实际参与分析和朗读的全文，包含段落、对白、标题行等实际正文；不从参考原文恢复排版。导入时已排除的目录区间不进入编辑器。
- 面板说明：“保存后的内容将用于后续分析与配音。原始导入内容保留供参考。”标题字段说明：“章节标题用于目录和导出；正文中的标题行可在下方单独修改。”标题元数据不自动插入朗读正文。
- 保存前正文只是草稿。显式保存成功后统一刷新章节、正文和字数，后续操作使用新版本；无变化时不创建修订。保存失败保留草稿和错误提示，面板不提前关闭。
- 标题去除首尾空白后不能为空；正文仅空白时不能保存。正文其余内容按用户输入的 UTF-8 精确保留，遵循现有导入/工作文本预算限制；超限明确提示，不截断。
- 编辑期间不能启动分析、制作、章节整理或切换作品/章节。取消或关闭时，有修改则提供“继续编辑／放弃更改”；无修改直接关闭。保存期间禁用重复保存及交互关闭，完成后释放编辑状态。
- 支持键盘焦点移动、清晰的无障碍标签、取消快捷键及保存快捷键；多行正文输入中的回车始终用于换行。

## 可编辑条件与冲突处理

正文编辑仅用于已具有有效工作修订、尚未开始分析且活动修订没有分析、制作、候选或资产等派生记录的作品。加载或运行中不能打开编辑器。旧参考作品先使用已有的显式“准备工作文本”操作；不得隐式迁移。

已开始分析的作品继续支持原有标题重命名，但不开放正文修改，也不隐式清除分析或音频。本方案不新增“清空分析后编辑”操作。

UI 禁用只是提示。Store 保存必须在事务内再次检查条件与预期版本，防止打开编辑面板后另一路开始分析或修改章节。过期草稿不能覆盖新内容：提示重新载入，保留现有草稿用于手工核对，不自动合并。

## 保存与数据不变量

### 草稿快照

加载草稿时冻结 book ID、source ID、source SHA-256、chapter ID，以及章节顺序、标题、范围、排除区间、跳过状态组成的布局摘要。所有保存、异步回调及取消均绑定该身份，不依赖后来选择的作品或章节。标题重命名也要检查预期标题/布局，避免两个编辑入口互相覆盖。

### 仅修改标题

正文未变化时，只在带版本检查的事务中更新当前章节标题和作品更新时间，不创建工作 source，不重建 atom，不改写正文或任何已有音频。保存后的章节元数据用于后续目录、分析上下文和导出。

### 修改正文

1. 基于已校验的活动工作快照，将选中章节范围替换为用户保存的正文。章节范围之外的工作字节逐字保留。
2. 保留当前章节顺序、全部标题和跳过标记，不重跑自动分章。按 UTF-8 字节长度重新计算本章及后续章节范围，保持原章节覆盖关系；中文、emoji、组合字符不能用 Swift 字符数代替字节数。
3. 编辑器不包含本章导入时排除的目录。正文发生修改时，保存的可见正文整体替换本章工作范围，本章排除区间清空；被排除的导入内容仍保存在原始参考修订与旧工作修订。其他章节的排除区间只按位移重定位。只改标题或无变化保存不触及这些字节。
4. 生成新的不可变 working source 和映射文件；建立新 source 下的章节、atom 与初始旁白身份。ID 不跨 source 复用，避免旧证据和旧坐标被误认成新内容。选中章节通过新旧章节对照重新定位。
5. 原始导入文件、参考文本、先前工作修订及其派生行/音频引用全部保留。旧状态沿用已有 source 工作状态快照机制封存，禁止删除旧章节行或覆盖旧文本资产。
6. 新文件先写入独立路径，再读回核验 UTF-8、大小、SHA-256、映射与全部章节/atom 范围。在一个无异步悬挂的数据库事务中，比较预期 source、布局与可编辑条件，登记新 source 及其行并切换活动指针。任何校验、取消、磁盘或事务失败都保持原活动修订；未提交文件不被视为活动数据。
7. 切换后以活动 source 隔离所有派生读取，重置当前修订的初始分析状态、选择缓存和选角确认，不复用旧角色证据或音色确认。历史音频继续通过原来的生产修订读取，不被新正文冒充为有效音频。

文件暂存、事务、缓存刷新应复用现有工作修订机制的公共内部步骤，但不得调用从原始参考重新加工的 `prepareWorkingRevision` 来实现用户编辑。

### 来源映射

来源坐标始终指向严格解码后的原始参考 UTF-8。未改变且可精确追踪的字节保留真实对应关系；用户替换的内容标记为非逐字对应，关联被替换内容的参考范围或合法锚点，不能伪造一一对应偏移。裁切跨章节的非逐字映射时必须采用明确的区间/锚点分配规则，保证单调、有界和完整工作字节覆盖，不能按字符数比例猜测参考偏移。

在现有 `isGenerated` 表达非逐字来源的基础上，明确区分用户编辑与导入排版生成的来源语义；具体字段形式由实施者选择，但必须可序列化、可校验，并能读取现存 v7 来源映射。加工版本描述初始加工算法；工作 source ID 和 SHA 区分每次正文修订。不因新增来源语义无必要地改数据库 schema。

## 全流程唯一输入

保存后统一从 `workingSourceSnapshot` 读取新工作修订。正文面板、分析 primary/context、角色证据、试听、发音词条匹配、合成与重录使用其内容与坐标；章节标题使用对应新章节元数据。不得在任何消费者里回退原文、读取旧缓存，或将用户保存的换行再当导入排版自动加工。

编辑没有改变服务模型、档位、声音或公共 ASR/TTS 协议，不涉及服务端或公共 OpenAPI 扩展。若保存因新修订产生新 atom，旧 atom 的说话人归属不能自动按位置套用。

## 实施落点

- `AudiobookBookWorkspaceView.swift`：入口、编辑面板、草稿呈现和关闭确认；必要时拆独立视图，避免主页面继续膨胀。
- `AudiobookWorkflowModel.swift`：编辑生命周期、可用条件、冻结身份、加载/保存编排、缓存及选择刷新；全部入口共享互斥状态。
- `AudiobookProjectStore.swift`：受版本与阶段约束的草稿读取、标题保存和新工作修订提交。将可复用的修订写入步骤提取为内部能力，不改变现有显式准备/恢复语义。
- `AudiobookSourceIndex.swift` 或独立纯计算模块：工作正文替换、章节范围和来源映射重定位，所有范围检查使用 UTF-8。
- 现有 Store、Workflow、SourceIndex 测试及工作文本消费者回归；同步架构与 macOS 有声书开发文档的稳定行为合同。

## 定向验证与交付边界

使用临时作品库、fake LLM/TTS 和合成测试文本，不接触真实作品库：

1. 修改章节标题与正文后，重开 Store 仍读到新内容；原始参考、旧 source 内容及已有历史音频引用保持不变。
2. 多次编辑、无变化、仅标题、取消、空输入、超预算、保存失败和重新尝试有正确结果；失败不切换活动指针，不丢草稿。
3. 中文/繁体/emoji/组合字符、增删自然段、章节开头/结尾、被排除目录和跨映射区间的替换：章节覆盖、atom 取文、映射边界及后续章节偏移准确，顺序/标题/跳过状态保留。
4. 用彼此不同的参考文本、旧工作文本、用户编辑文本作为哨兵，检查保存后的分析请求及后续 TTS 请求读取用户文本；发音词条命中和元数据也基于新内容。重复调用不会重新从原文加工。
5. 草稿打开后发生 source/标题/布局变化、开始分析或产生派生记录时，Store 拒绝过期保存；旧异步回调不能覆盖新选择，运行状态正确释放。
6. 原有分析后标题重命名、拆分/合并、准备工作修订与历史生产版本读取的相关回归保持通过。

构建只使用仓库 macOS 包装脚本；不运行接管前台的 UI 自动化，不生成真实声音，不安装制品，不迁移真实作品。报告分别说明确定性验证、构建结果及未做的人工界面验证。

## 回退

实现尚未发布时可弃用功能分支；保存实现不能覆盖 v4.1.0 的已安装 App 或服务。正文保存采用新增修订、活动指针切换和现有工作状态快照，保留恢复旧工作修订的依据；不使用旧数据库备份覆盖用户后续数据。公开的“撤销上次正文保存”入口不在本次范围。
