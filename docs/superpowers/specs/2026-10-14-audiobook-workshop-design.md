# 有声书工坊产品与交互设计

有声书工坊面向把 TXT 电子书制作成多角色有声书的个人用户。在 SpeechRail macOS App 的创作区，以一本书为一个项目，保留原文，统一管理章节、人物、声音、制作进度和收听位置。用户可以自动准备全书、确认关键问题、试听后逐章制作，随后在 App 内收听或导出到其他设备。

本规格定义待实施的产品行为。产品方向及书面规格已于 2026-10-14 经用户确认符合预期。浏览器草图使用虚构书籍和示意进度，不代表实际合成、音质或播放能力已通过验收。

## 1. 产品目标与已确认选择

成功结果是一本忠实原文、人物声音可辨且贯穿全书、可以中断后继续制作、可以持续收听和导出的有声书。

| 事项 | 已确认选择 |
| --- | --- |
| 来源 | TXT 电子书 |
| 内容关系 | 忠实原文，以角色声音和朗读表达演绎内容 |
| 人工参与 | 自动准备，确认角色表、声音和不确定的对白归属 |
| 声音来源 | 音色库优先，主要人物可设计专属声音 |
| AI 服务 | 沿用 App 的 AI 设置，允许用户选择本机或外部服务 |
| 分析节奏 | 先完成全书分析，再开始正式制作 |
| 页面结构 | 书籍工作台：章节、原文和人物同屏 |
| 存疑对白 | 暂停对应章节，其他已确认章节可制作 |
| 成品使用 | App 内听书，支持整本和分章节导出 |

首版围绕小说的旁白、人物对白和跨章节角色展开。中文 TXT 小说是主要设计与验收样例；导入文字不等于所选声音已具备相应语言的可用性和朗读质量。

## 2. 产品入口与页面结构

创作区增加“有声书工坊”入口。角色声音通过现有音色库和音色设计流程选择、试听、确认，完成后返回原书籍及原角色。书籍是工坊内的完整作品，不把每个角色片段拆成“我的作品”中的独立条目。

| 页面或工作台模式 | 首屏内容 | 主要动作 |
| --- | --- | --- |
| 工坊书架 | 书名、制作阶段、待确认数、已完成章节和最近收听位置 | 导入 TXT、继续准备、继续制作、继续听 |
| 书籍工作台的准备模式 | 左侧章节，中间原文，右侧人物声音及当前待确认事项 | 确认角色、选声音、定位疑义、试听 |
| 书籍工作台的制作模式 | 章节状态、当前任务和已完成结果 | 制作已确认章节、暂停、继续、重试、局部返修 |
| 听书模式 | 当前章节、播放进度、章节目录和继续听入口 | 播放、暂停、跳转、倍速、导出 |

准备与制作是同一书籍工作台的模式，不重复创建项目。听书模式返回时保留所选章节和准备位置。书架按当前阶段给出一个明确的继续动作，不要求用户理解任务 ID、模型 revision 或制作配方。

宽窗口显示章节、原文与人物三栏；中等窗口优先保留原文，人物面板可按既有布局策略收起，通过明确的“人物与声音”按钮恢复。待确认数量、定位按钮和键盘入口保持可见。全书角色合并、拆分、来源区间、制作条件和追溯详情放入命名明确的菜单或详情区。

视觉、控件、焦点、无障碍和动效遵循[macOS App 设计系统](../../developers/macos-app-design-system.md)。运行时视觉值复用集中 Token，内容面板采用内容表面，窗口和导航采用系统层级。网页草图只表达产品布局。

## 3. 完整用户流程

**导入 TXT → 核对章节 → 分段分析全书 → 确认角色与声音 → 试听片段 → 逐章制作 → 听书或导出。**

1. 用户选择文件，查看文字编码、书名和章节预览，确认导入。
2. 用户点击“分析全书”。界面展示实际选用的 AI 服务、将处理的章节和当前进度。文件选择和预览本身不发送正文。
3. 应用按章节和有限正文窗口分析，汇总人物、别称、对白归属及需要确认的事项，持续保存检查点。
4. 所有正文窗口处理完成并通过本地校验后，用户确认全书角色表与声音。未解决的说话人归属继续保留在对应章节。
5. 用户选择一个包含旁白和主要角色的片段，试听并确认声音；可替换声音或为主要人物设计专属声音。
6. 用户点击“制作已确认章节”。符合条件的章节进入队列，存疑章节显示“确认说话人后继续”。
7. 已完成章节立即可以收听。任务暂停、应用重开或服务恢复后，从有效检查点继续。
8. 全书完成后可导出整本；也可明确选择导出已完成的章节。

“全书分析完成”表示全部窗口有可校验的处理结果，不等于全部说话人都已确定。处理失败或缺失的正文窗口不能伪装成完成；允许生成其他章节的前提仍是全书分析完成、全书角色声音已确认，以及所选章节的归属问题已解决。

## 4. TXT 导入与原文保真

项目保存原始文件、解码后的不可变正文及内容摘要。后续再次导入同名文件不会覆盖已保存来源。章节、人物和朗读片段记录相对于正文的稳定来源区间。

导入支持严格 UTF-8、带 BOM 的 UTF-16 以及 GB18030 解码。自动检测不能静默接受替换字符或删除无法解码的字节；无法明确判定时展示编码选择与正文预览，由用户确认。规范化的来源表示与原始字节同时保留，来源偏移以规范正文的 UTF-8 字节区间表示，并校验字符边界。

章节识别以文本中的标题和分隔为依据，导入预览可以纠正划分。没有可靠章节时保留一个“全文”章节，用户可在章节设置中划分。章节标题默认由旁白朗读；目录、附言、广告或重复文字不由 AI 自动删去。用户明确排除的范围单独记录，在正文检查和导出前呈现；首版默认全部保留。

AI 输出角色、来源区间和分析标注，不能生成一份替代原文的改写稿作为合成正文。待合成文本从应用保存的来源区间提取。所有正文区间按原始顺序覆盖，不能遗漏、重叠或重复消费；空白、标点和格式标记有明确归属，不伪造需要朗读的词。

例如原文 `“你也看见灯了？”他问。` 分为人物对白和旁白叙述两个朗读范围。人物名字和角色标签是元数据，不附加到朗读内容。“他说”“他问”等叙述仍保留。

文本来源完整性与实际说出的内容是两个验收维度：区间校验能够证明应用没有丢改原文，音频是否漏读、错读数字或人名仍需输出检查与听审。

## 5. 全书分析与人物管理

### 5.1 分段分析与全书汇总

全书分析由有界请求完成。每次请求只包含当前正文窗口、必要的相邻上下文和相关角色摘要，正文窗口、上下文、输出 token 与重试次数均有显式上限。复用现有 LLM 客户端、配置解析与结构化输出能力，不新增传输实现。

分析流程分为人物线索提取、全书角色归并和对白标注。全书汇总完成前，角色名称和合并关系是候选；用户确认后形成角色基线，随后才进行正式制作。对跨窗口引用、姓名冲突、代词、多层引号和身份不明的发言保留来源依据及待确认状态。

模型提供的置信度只是分析线索，不能当作已经测得的正确率。待确认集合结合结构校验、角色冲突和上下文疑义形成；所有段落都可从原文定位并修改归属，不能宣称高置信度段落必然无误。

检查点包含正文摘要、窗口范围、分析策略版本、角色表版本和所选 AI 配置身份。取消后停止提交新窗口，旧任务返回值不得写入新分析代次。暂态失败只恢复失败窗口，保留已校验结果；鉴权失败或服务明确拒绝时暂停任务并给出处理入口，不静默换服务。修改影响分析的配置时，先展示受影响范围再开始新代次。

### 5.2 全书角色表

人物有稳定的角色 ID，姓名、称呼和别称只是该角色的显示属性。每个项目有独立角色表，包含一个旁白角色和已识别的人物。

角色表显示名称、别称、声音、首次出现位置、使用章节和待确认事项。自动推荐声音依据有来源的人物描述和可选音色信息；不把猜测的年龄、性别或性格包装成原著事实。推荐结果由用户试听确认。

合并角色、拆分同名人物、调整对白归属和更名通过角色设置完成。更名或补充别称不改变声音；合并和拆分先展示来源与影响范围，再生成新的分配版本。角色分析摘要只用于处理本书，不写入跨书人物身份库。

### 5.3 声音与演绎

每个角色绑定可用音色及其版本。旁白和主要人物应通过试听具有可辨性；多个次要人物是否共用声音由用户可见地选择，不静默合并角色。定制声音经过现有设计、试听、确认及入库流程，只有成为可合成音色后才进入制作。

制作条件固定音色身份、模型绑定、可支持的生成参数和已观察的制作配方。种子只按对应音色能力使用，不能给不支持的路径强加 caller seed。固定这些条件有助于一致性，但不保证跨长篇的实际声线完全不漂移。

首版以固定角色声音、自然朗读、人物可辨性和段落衔接作为演绎目标。当前合成能力不接受通用逐句情绪 `instructions`；人物音色设计与逐句情绪控制是不同能力。细腻情绪、声线稳定性和长时音质必须以真实试听验收，不因角色标注或生成成功而宣称成立。

## 6. 存疑对白与人工确认

待确认项展示原文、前后上下文、推荐人物和“选择其他角色”入口。用户可选择已有角色、创建缺失角色、按人物设置处理合并，或保留待确认。显式指定旁白也是一次可记录的人工选择。

一个未解决的对白暂停对应章节的正式生成；其他已确认章节可进入制作队列。不能把“未知”默认为旁白或某个人物后继续。用户解决该章全部归属问题后，章节变为可制作，应用提供明确的“继续这章”动作。

批量操作只适用于用户明确选择、来源和角色关系清楚的事项，操作前显示数量和范围。确认结果留在当前书籍的标注版本中，支持撤销；正文不随角色选择而变化。

## 7. 章节制作与局部返修

### 7.1 制作粒度与队列

用户操作单位是章节，实际生成和恢复单位是有来源的朗读片段。片段按说话人边界切分，只在同一角色、连续来源及相同制作条件下合并相邻短段；不能跨越旁白或另一角色，也不能直接套用仅按标点合并的文稿切分策略。

每个片段有来源范围、角色分配版本、声音条件、请求身份、音频资产及回执。渲染结果持久化成功并校验音频及索引一致后，才记录片段完成。章节完成要求所有应朗读范围都有有效音频，并按来源顺序构成完整章节。

默认一次制作一本书，同一 TTS 能力 lane 内串行生成。队列服从服务端资源准入，不通过额外模型进程或 ASGI worker 提高吞吐。声音试听与正式生成使用明确的创作准入所有权，争用时展示等待或可恢复状态。

“暂停制作”停止提交新片段，当前请求按已具备的取消契约处理。已保存结果保留；收尾期间显示“正在暂停”，不能把尚未持久化的结果视为完成。重开应用后校验来源、分配版本、音色与模型条件，再复用有效结果；缺失、损坏或过期结果有明确的重做入口。

### 7.2 修正与影响范围

| 修改 | 音频影响 |
| --- | --- |
| 书名、显示名、补充别称 | 正文、角色 ID 和声音不变时保留音频 |
| 某句说话人归属 | 重做受影响片段，更新所在章节与整本导出 |
| 某个人物的声音或声音版本 | 标出该人物关联的片段与章节，重做相应结果 |
| 角色合并或拆分 | 按新的分配和声音条件计算受影响片段 |
| 模型、运行配方或全书生成策略变化 | 以真实配方判定范围，可能涉及全书，不能承诺局部复用 |
| 明确替换正文来源 | 建立新的来源版本与分析代次，不能覆盖原书来源 |

旧音频和已发布的章节版本保留为可恢复历史。新片段作为候选，试听、采用和撤销有固定身份；自动流程可提交首次合格结果，人工返修通过显式采用替换。候选采用后才原子更新章节当前版本，旧回调不能覆盖新版本。

待重做的章节不能冒充当前标注版本的成品。已存在的历史完整版本可以明确标为“之前的版本”收听；整本导出必须选择自洽的当前制作版本，不能混入过期候选或跳过缺失段落。

## 8. 听书体验

听书按已完成章节播放，提供播放与暂停、前后跳转 15 秒、章节选择、播放倍速以及继续听。播放倍速作用于播放器，不改变已生成音频，不受克隆音色生成速度只支持 `1.0` 的约束。

播放以本地文件和实际解码时序为依据，不把整本音频载入一个 `Data`。书籍、章节版本和朗读片段共同标识当前播放身份。进度保存包含章节、片段、片段内位置和对应音频版本，暂停、切换章节或离开工坊时及时提交。

收听的章节被返修后，优先恢复到同一来源片段；片段已经替换时从该段起点继续并说明章节已更新，不沿用可能错位的旧章节秒数。未完成或待更新的当前版本不能被播放入口当作有效成品。

书籍收听、角色试听、配音试听共用一个播放所有权。开始角色试听时暂停听书并保存位置，结束后提供继续听入口。离开工坊释放播放资源；制作任务由项目任务 owner 管理，界面切换不丢检查点。关闭 App 时停止提交任务并保存状态，下一次打开由用户继续制作。

正文查看用于核对和定位源片段；进度与章节边界由实际音频时序产生，不用文本字数推测时长或制造逐词字幕。

## 9. 成品导出

首版详细设计采用两种出口：整本 M4B（AAC 音频和章节目录）与分章节 MP3。它们是本规格的工程设计选择，实际文件和目标播放器的兼容性是交付门槛。

| 出口 | 允许条件 | 文件内容 |
| --- | --- | --- |
| 整本 M4B | 所有章节在同一有效制作版本下完成 | 按原文顺序的整本音频、章节名称与真实章节时间、书名和用户提供的作者信息 |
| 分章节 MP3 | 用户明确选择已完成且有效的章节 | 按章节序号命名的音频、章节清单、导出范围说明 |

整本导出不能跳过未确认、失败、缺失或待更新的章节。部分导出明确显示“已完成章节”和实际数量，清单保留未导出章节及原因，不能称为完整有声书。

章节时间由实际音频采样数、统一采样率及最终编码结果计算。拼接前核对音频格式和制作版本；格式转换仅按明确媒体策略执行，不通过修改扩展名伪造编码。以媒体探测验证音轨、时长、章节顺序和时间范围，再进行目标播放器检查。

编码、拼接和章节封装由受约束的本机媒体适配器执行，调用既有媒体工具能力；不可用时保留原始音频和项目，报告“导出工具不可用”并提供重试。首版不依赖请求路径下载工具或模型。整本拼接采用文件流，不能把全书 PCM 累积到内存。

用户选择本地目标位置，先生成临时产物并校验，成功后提交目标文件。取消、磁盘不足或编码失败不改动来源和已有成品。覆盖同名成品需明确选择具体目标；导出默认只包含音频与必要书籍元数据，不带私有服务配置、凭据或完整分析输入。

FFmpeg 的 MOV/MP4 封装支持章节轨道，元数据格式能够表达章节起止时间；这些支持本方案的封装方向，不证明 SpeechRail 已完成对应实现。[FFmpeg 格式与元数据文档](https://ffmpeg.org/ffmpeg-formats.html#Metadata)。Apple Books 的官方导入说明明确包括 MP3 有声书，分章节 MP3 可作为兼容性验收的一条路径。[Apple Books 导入说明](https://support.apple.com/en-gb/guide/books/ibkseed72068/mac)。来源核验日期为 2026-10-14；整本 M4B 的目标播放器验收仍须使用实际制品。

## 10. 项目数据与职责边界

### 10.1 应用和语音服务

> 🧠 **From Hindsight memory (SpeechRail 组件职责与权威边界)** — 项目既定分工将 LLM 编排、播放和应用状态留在调用方，语音服务负责语音生成与准入。本设计沿用这一分工，已与仓库指令和 macOS 状态所有权文档核对。

App 负责导入、章节识别、全书 AI 分析、人物管理、任务检查点、文件资产、听书和导出。SpeechRail 服务继续通过现有公共接口提供音色发现、设计、合成、能力快照及渲染回执，不成为书籍数据库或 LLM 编排服务。

建议增加独立的书籍功能 owner，以窄接口依赖能力读取、音色读取、LLM 客户端、片段合成、项目存储和共享播放。界面读取 owner 的投影，不在 `AppModel`、视图和后台任务中建立多份可变项目状态。后台任务和代次归功能 owner，不能绑定到会随页面切换销毁的视图任务。

### 10.2 数据结构与保存

| 对象 | 必要身份与内容 |
| --- | --- |
| 书籍项目 | 项目 ID、不可变来源摘要、规范正文、章节顺序、分析版本、角色基线、制作版本 |
| 章节 | 稳定 ID、来源范围、标题、待确认事项、制作状态和当前音频版本 |
| 人物 | 稳定角色 ID、名称、别称、来源证据、音色绑定与版本 |
| 朗读片段 | 来源区间、朗读角色、分配版本、声音及生成条件 |
| 生成候选 | 片段身份、固定条件、音频摘要、实际时长、回执、采用状态 |
| 检查点 | 已校验窗口、队列位置、已持久化片段、请求与分析代次 |
| 收听位置 | 书籍、章节版本、来源片段、片段内播放位置 |
| 导出记录 | 制作版本、实际章节范围、格式、目标产物摘要与校验结果 |

书籍元数据采用独立本地 SQLite 存储，来源与音频采用项目专属文件目录，均位于仓库外的应用数据区。数据库和文件以事务日志衔接：音频先写临时资产、校验后提交引用，恢复时核对日志和资产摘要。未引用资产只在明确的恢复或清理流程处理，不删除未知文件。

> 🧠 **From Hindsight memory (高 ROI 进化方案全量实施)** — 既有创作设计强调音频与索引一致、候选采用和撤销、回执追溯。本模块沿用这些原则，书籍与多角色状态采用独立结构。

现有文稿配音项目保持其原有数据格式。有声书拥有新的持久化模型，避免把全书多角色状态塞进共享单一配方的旧项目。删除书籍是独立、明确的操作，展示项目资产范围；来源原文件、导出到其他位置的成品和现有配音作品不能被连带删除。

### 10.3 AI 与能力准入

工坊增加明确的 AI 模块身份，默认继承 App 的全局配置，不要求新填一套密钥。配置解析和兼容差异留在既有客户端及 adapter 内，书籍业务依赖结构化分析接口。

首次分析沿用 App 已有的正文发送说明流程，明确实际服务和处理范围。用户选择外部服务时才按该设置发送分析输入；本机配置不可用时不能自动改用另一外部服务。日志只记录任务阶段、数量、耗时和稳定错误，不记录正文、完整 prompt、音频、凭据或私有路径。

生成前按有效能力快照核准音色、可支持参数、模型绑定和实际可用条件；请求固定相应版本。音色变更、删除、服务重启或档位变化出现冲突时暂停受影响任务，展示“制作条件已变化”和恢复选项。应用不得悄悄选择默认音色或自动切换运行档位。

## 11. 状态与错误处理

书籍的“分析状态”“制作进度”和“可收听版本”分别表达，不用一个 `completed` 同时代表三者。

| 场景 | 产品表现与恢复 |
| --- | --- |
| TXT 编码无法确定 | 保留文件，展示预览与编码选择；确认前不发送正文 |
| 章节识别不可靠 | 保留全文，在章节设置中纠正来源划分 |
| AI 请求失败或结果覆盖不合法 | 全书分析保持未完成，定位失败窗口，保留有效检查点 |
| 全书已分析，部分说话人未确定 | 对应章节待确认，其他已确认章节可制作 |
| 语音服务不可用或资源繁忙 | 队列等待或暂停，有限恢复，已生成资产保留 |
| 音色或生成条件冲突 | 暂停受影响部分，由用户选择有效条件并重做对应范围 |
| 某片段合成失败 | 章节未完成，只重试失败片段，不拼接残缺成品 |
| 音频到达但保存失败 | 保留可恢复结果，显示保存失败；不能显示完成 |
| 应用退出或任务取消 | 保存已提交检查点，撤销旧回调写入权限，重开后继续 |
| 返修完成但尚未采用 | 当前成品不变，提供对比、采用与撤销 |
| 导出失败 | 原项目与此前成品保持有效，清晰展示失败步骤和重试入口 |

重试区分鉴权、配置、结构、暂态网络、限流和资源忙碌。恢复有共享的有限尝试预算，可取消，尊重 `Retry-After`；不能无限递归重试或换模型掩盖问题。所有状态更新先核对项目、正文、分析或制作代次及请求身份。

## 13. 验收条件

### 13.1 确定性验证

实施阶段使用合成的小说文本、fake LLM 和 fake 语音后端验证以下行为，不依赖真实书籍、网络或模型下载：

| 维度 | 必须证明的结果 |
| --- | --- |
| 导入与来源 | 编码预览、正文完整保留；百万字合成 TXT 可有界分段处理，区间无缺失、重叠和重复 |
| 角色与对白 | 别称归并、同名拆分、代词疑义、嵌套引号与跨窗口对白可定位；未知不默认成旁白 |
| 全书分析门槛 | 处理失败不能宣称全书完成；全书分析完成而归属未定时仅暂停对应章节 |
| 声音与返修 | 条件固定并可追溯；局部归属改动、角色声音改动和全局条件改动具有不同的失效范围 |
| 保存与恢复 | 取消、迟到回调、重复提交、磁盘不足、资产缺失和重启均不产生伪完成或静默覆盖 |
| 播放 | 唯一播放身份，文件播放、跳转、倍速、保存进度和返修后的定位恢复按真实媒体时序工作 |
| 导出 | 未完成全书拒绝整本出口；部分导出范围明确；媒体格式、时长、章节名称和时间可验证 |

百万字是设计验收样例规模，不是当前已测得的性能、耗时或成本承诺。网络请求、元数据和音频处理必须有界；播放与拼接不得加载整本音频到内存。

### 13.2 实际体验与媒体兼容

真实体验需分别验收人物可辨性、旁白与对白衔接、跨章节声线稳定性、原文及数字人名的朗读准确性，以及长书制作中断后的可恢复性。试听样例应包含旁白与多个角色，不能仅用一个短句替代长篇验收。

整本 M4B 以实际目标播放器的导入、目录跳转和时长为门槛；分章节 MP3 以真实解码、播放和章节排序为门槛。文件探测通过与实际播放器体验分别记录。

UI 自动化、前台操作、真实模型与质量基准按相应专项授权执行。设计阶段的浏览器草图、源码核对和文档检查不替代这些验收。
