# SpeechRail macOS 设置模块：一般用户优先的 UI/UX 重构

## 1. 设计结论

SpeechRail 的设置窗口应成为“偏好与连接入口”，而不是第二个服务控制台。
它首先帮助绝大多数用户完成三件事：决定 App 怎么启动、决定创作默认值、让助手与会议能力可用。
端点、协议、运行档位、模块覆盖和诊断证据属于渐进式披露的高级信息，不应成为首次配置的认知门槛。

保留 macOS 原生 `Settings` scene、现有 UserDefaults 键、`SessionPreferences` 的单一偏好声明点和
`LLMKeychain` 的安全边界。本次设计只重构信息架构、文案、状态呈现、视图边界和交互路径，不改变
SpeechRail REST/WebSocket 契约，不加载模型，不改变服务生命周期。

推荐的顶层页签为：

```text
通用   创作   助手   服务
```

现有“会话”页签改名为“助手”，使普通用户能用产品能力而不是内部会话模型理解这一页。

## 2. 当前问题与证据

当前设置实现位于 `macos/SpeechRailApp/SpeechRailApp/SettingsView.swift`，视图同时负责：

- 设置窗口与四个页签的编排；
- 通用、创作和服务偏好；
- 大模型全局配置、密钥草稿与连接检查；
- 三个功能模块的专用配置覆盖；
- 助手、实时字幕、会议、记录库和通知偏好；
- 设置行、卡片、分隔线和辅助说明的视觉结构。

这导致几个一般用户可感知的问题：

1. “助手”页同时出现服务地址、模型、密钥、Responses API、模块覆盖、角色、字幕、会议和数据库操作，用户必须先理解系统内部边界才能找到常用设置。
2. 全局配置、专用配置和实际生效配置的关系依赖长段说明文字，状态不够聚焦。
3. 当前连接检查在新密钥检查成功后会自动写入 Keychain；行为本身安全，但按钮和结果文案没有把“测试并保存”作为一个明确动作表达。
4. 当前 UI 测试 `testSettingsContainAppPreferencesOnly` 仍按旧的三页签描述，而源码已有第四个“会话”页签，测试事实已经漂移。
5. `SettingsView.swift` 接近千行，视图重建边界和功能边界不清晰，后续修改容易影响不相关页签。

`SessionPreferences` 已经把偏好与历史会话实例区分开；地址、模型、角色、音色、对讲模式、字幕/会议分人、会议来源、纪要模型、通知、人设和自定义人设均有明确持久化边界。该边界是本次重构的稳定基础。

## 3. 目标与非目标

### 3.1 目标

1. 让一般用户无需理解服务端实现，就能完成常见设置。
2. 让每个设置项清楚表达当前状态、影响范围和下一步动作。
3. 把 AI 服务连接从“技术表单”改为可理解、可恢复的连接流程。
4. 用渐进式披露承载模块专用配置和诊断信息，默认保持界面安静。
5. 通过 focused view boundary 拆分 `SettingsView`，降低 SwiftUI 无关重建和后续维护成本。
6. 保持 macOS 26 原生控件、键盘导航、VoiceOver 语义、Reduce Motion 和系统外观适配。
7. 保留已有用户设置和安全存储，不要求用户重新填写已有偏好或密钥。

### 3.2 非目标

- 不新增或修改 SpeechRail 公共 API、Realtime wire、MCP 契约或 Python 服务行为。
- 不把模型下载、profile 切换、服务启停和运行监控搬进设置窗口；这些仍属于控制中心的服务页面。
- 不在设置窗口显示 API key、`Authorization`、原始音频、完整转写、绝对路径或完整日志。
- 不改变 `SessionPreferences` 的 UserDefaults key，不迁移历史记录库，不删除自定义人设。
- 不为旧 UI 布局保留兼容分支；只保留数据与安全存储兼容。
- 不在本次任务中运行未经当前用户明确授权的 XCUITest、桌面自动化或前台窗口走查。

## 4. 一般用户优先的体验原则

### 4.1 先任务，后技术

页面标题、分组标题、按钮和状态结论使用用户语言：

| 技术表达 | 设置页默认表达 | 技术详情中的表达 |
|---|---|---|
| LLM | 对话服务 | 大模型服务 / provider |
| endpoint / base URL | 服务地址 | Base URL |
| API key | 密钥 | Bearer credential / Keychain |
| module override | 按功能单独设置 | Module override |
| profile | 运行档位 | Active profile |
| worker | 服务组件 | Worker |
| Responses API | 支持对话的接口 | Responses API |

技术词只在必要时作为副说明或“开发者详情”出现，不能成为普通用户必须先学会的主标题。

### 4.2 每个设置项都回答三件事

- 现在是什么状态；
- 改动影响什么；
- 用户下一步可以做什么。

例如，“密钥”不是只显示一个输入框，而是显示“未保存 / 已保存”，并把“检查并保存”“清除”作为明确动作。

### 4.3 默认安全、明确写入

- 密钥始终只进 Keychain，不进 UserDefaults、日志、URL 或报告。
- 用户输入新的密钥后，主动作明确写成“检查并保存”，不让“检查连接”隐式完成持久化。
- 清除密钥属于可逆性较低的操作，使用清晰的动作名称和结果反馈；不使用模糊的“重置”。
- 备份记录库和打开数据目录保留，但明确说明它们处理的是本机记录，不会上传音频。

### 4.4 渐进式披露

常用设置默认可见；模块覆盖、接口要求、服务版本、运行档位和诊断上下文默认折叠。
展开高级区后，用户仍能看到当前值的继承关系和实际生效结果，不能只看到一组孤立输入框。

### 4.5 原生、可达、可恢复

- 使用系统 `Tab`、`Toggle`、`Picker`、`Slider`、`TextField`、`SecureField` 和 `ProgressView`。
- 所有动作既能用鼠标，也能用键盘焦点和 VoiceOver 访问。
- 错误说明现象、影响和下一步，不只显示技术错误字符串。
- 状态不只依赖颜色；必须同时有文字和可访问值。
- 不增加装饰性动效；连接检查和展开状态只使用系统反馈，并尊重 Reduce Motion 设置。

## 5. 信息架构

### 5.1 通用

保留两组：

1. **启动与窗口**
   - 启动时读取服务状态；
   - 说明“关闭后仍可从控制台手动刷新”。
2. **开发者详情**
   - 默认展开技术详情；
   - 说明这是控制中心诊断信息的默认展示偏好，而不是服务开关。

这一页不出现端口、模型、密钥或服务生命周期控制。

### 5.2 创作

保留创作默认值：

- 默认音色；
- 默认语速；
- 说明新打开的配音台如何使用这些值，以及页面内逐条覆盖的关系。

语速继续使用带刻度的原生 `Slider`，显示 `0.5×–2.0×` 范围和当前值；不新增自绘推子或独立字号。

### 5.3 助手

按一般用户完成任务的顺序排列：

#### A. 对话服务

页面顶部首先给出一个连接状态区：

```text
对话服务                         已连接 / 尚未配置 / 检查中 / 连接失败
让语音助手、会议纪要和 AI 提词器知道该使用哪台对话服务。

服务地址                         [                         ]
模型                             [                         ]
密钥                             已保存到安全保管库   [更换] [清除]

                              [检查并保存] / [检查连接]
```

规则：

- 已有保存密钥且没有新草稿时，动作是“检查连接”；
- 有新密钥草稿时，动作是“检查并保存”，连接成功后才写入 Keychain；
- 未配置地址或模型时，状态区给出“先填写服务地址和模型”的具体提示，并禁用检查动作；
- URL 含凭据时，在字段附近直接说明“地址里不要放密钥”，不等待网络请求后才报错；
- 检查结果保留在同一状态区，显示结果标题、用户可读细节和必要的下一步动作；
- `Responses API` 只作为“该服务需要支持 Responses API”的副说明，放在连接帮助文本或高级详情中。

#### B. 新助手默认值

- 默认角色；
- 默认音色；
- 对讲模式。

每项使用“标题 + 行内说明 + 控件”的结构。对讲模式的两个选项直接说明“能否打断”和是否建议耳机，不使用“半双工 / 全双工”作为主文案。

#### C. 字幕与会议

- 字幕默认字号；
- 字幕说话人标签；
- 会议说话人标签；
- 记录库操作；

记录库区域必须明确“不保存音频，只保留文字与说话人归属”，打开目录和备份动作分开呈现。

#### D. 通知

保留中断通知开关，说明只在需要用户决定时通知，且不把记录原文写入通知。

#### E. 高级：按功能单独设置

默认折叠。展开后按 `LLMModule` 的稳定顺序呈现：

1. 语音助手；
2. 会议纪要；
3. AI 提词器。

每个模块先显示继承状态：

- 跟随全局；
- 使用专用配置；
- 专用配置不完整，当前回退到全局。

打开专用配置后才显示服务地址、模型和专用密钥。模块详情中不重复全局帮助文案；只解释“这个覆盖只影响哪项功能”。

### 5.4 服务

这一页是只读事实与报告偏好，不是控制中心：

1. **本机服务**：端口、产品定位、最低系统、版本；
2. **诊断报告**：是否包含运行档位与版本；说明报告永远不包含凭据、原始音频、完整转写或绝对路径。

服务启停、模型下载、档位切换、预检和运行监控继续从主控制中心进入。

## 6. 视觉与布局契约

### 6.1 结构

- 保留系统 `Settings` scene 与 `Tab` API；不引入第二套侧边栏导航。
- 每个页签使用统一的 `settingsPane`、`settingsSection`、`settingsRow` 和状态区结构。
- 页签内容可滚动；页签切换不改变窗口宽度，也不因为某一页短暂加载而跳动。
- 常用设置优先位于滚动顶部；高级内容展开后自然增加高度，不截断说明。

### 6.2 Token

- 颜色、间距、圆角、字体和控件高度继续来自 `SpeechRailDesignTokens`；优先使用系统语义色和原生控件。
- 只有跨多个设置组件复用的新值才能进入 `SpeechRailDesignTokens.Settings`；单个页面的临时数值不得散落在视图中。
- 设置页使用内容地板、无装饰性阴影的卡片和系统焦点环；不要把技术状态做成高饱和品牌面板。
- 连接状态可以使用系统语义色，但必须同时显示文字结论和无障碍 value。

### 6.3 文案

- 标题使用普通用户语言和句式，不使用内部命名。
- 按钮名称描述结果：“检查并保存”“检查连接”“清除密钥”“打开数据目录”“备份记录库”。
- 帮助文本优先说明影响和下一步，避免把协议说明写成一段长技术说明。
- 失败文案保留服务返回的稳定用户信息，但不展示完整错误、路径或凭据。

## 7. 状态与交互契约

### 7.1 全局 AI 服务状态

状态区至少支持以下状态：

| 状态 | 条件 | 用户看到的结论 | 主动作 |
|---|---|---|---|
| 未配置 | 地址或模型为空 | 还没有配置对话服务 | 填写字段后检查并保存 |
| 可检查 | 地址、模型完整，尚无结果 | 可以检查连接 | 检查连接 / 检查并保存 |
| 检查中 | 请求进行中 | 正在检查连接 | 禁用重复提交，显示进度 |
| 已连接 | 检查成功 | 对话服务已连接 | 检查连接 |
| 连接失败 | 请求失败或协议不匹配 | 连接未通过，并说明下一步 | 修改配置后重试 |
| 保存失败 | 检查成功但 Keychain 写入失败 | 连接已通过，但密钥未保存 | 重试保存，不伪装成已保存 |

### 7.2 专用模块状态

模块覆盖状态必须和全局状态分开表达：

- “跟随全局”不是错误，也不是未配置；
- 专用配置开启但不完整时，明确写“当前回退到全局”；
- 专用连接检查只影响该模块，不清除或覆盖全局结果；
- 清除专用密钥后，模块回到“继承全局密钥”，不改变地址和模型字段。

### 7.3 草稿与持久化

- 文本设置继续即时写入 `SessionPreferences` / `UserDefaults`，保持现有行为。
- 新密钥草稿只保存在视图状态；显式“检查并保存”成功后才写 Keychain。
- 切换页签或关闭窗口不会把未提交密钥草稿写入磁盘。
- 连接结果和保存错误属于临时视图状态，窗口重开后重新读取安全保管库状态，不伪造上次检查成功。

## 8. 实现边界与文件职责

实现阶段预计按以下职责拆分；具体文件名可在实现计划中微调，但不得重新把所有页面拼回一个大视图：

| 文件 | 职责 |
|---|---|
| `SettingsView.swift` | 设置 scene 内容、页签路由、共享异步状态协调、公共绑定入口 |
| `SettingsComponents.swift` | 设置页 section、row、label、value row、状态区和字段布局 |
| `SettingsAssistantPane.swift` | 对话服务、助手默认值、字幕/会议、通知和高级模块覆盖 |
| `SpeechRailDesignTokens.swift` | 仅新增跨设置组件复用的 token；不存储业务状态 |
| `SessionPreferences.swift` | 保持偏好声明、持久化键和解析行为；除必要的 presentation helper 外不承担 UI |
| `LLMProvider.swift` | 保持配置校验与连接结果类型；若调整显式保存语义，只补纯规则，不读写 UI 状态 |
| `SpeechRailMacControlTests/LLMProviderTests.swift` | 覆盖服务地址 query/fragment 的本地无效判定，避免凭据或无效参数进入请求 |
| `SpeechRailAppUITests.swift` | 更新四页签和一般用户主路径断言，不扩大到真实服务或真实密钥 |
| `SpeechRailMacControlTests/SettingsKeyDraftPolicyTests.swift` | 覆盖草稿、检查、显式保存和保存失败的纯规则 |
| `docs/developers/macos-app-design-system.md` | 若 token 或设置组件契约变化，同步更新 active 设计系统与验证矩阵 |

不修改服务端、协议契约、模型目录、Keychain 之外的凭据存储或历史记录格式。

## 9. 可访问性与键盘

- 设置页各行使用“标题 + 副说明”作为同一个控件的 label，不把副说明变成独立可访问元素。
- `Toggle`、`Picker`、`Slider`、`TextField`、`SecureField` 有清晰的 label、value 和状态说明。
- 连接状态不只用颜色表达；VoiceOver 能读出“已连接 / 连接未通过 / 正在检查”等结论。
- 密钥字段不把实际值暴露给 accessibility tree；只读“已保存到安全保管库”等状态。
- 键盘可以在页签、字段、检查按钮、清除按钮和高级折叠区之间顺序移动。
- 高级模块展开/收起不改变焦点到不可见控件；加载或失败不会把焦点强制跳到窗口顶部。
- 不依赖 hover 提示完成任何关键动作；`.help` 只提供补充说明。

## 11. 回退与风险

- 本次不改变持久化 key，因此代码回退不会要求数据迁移。
- 视图拆分可以按文件回退；若新连接交互引入问题，可先恢复原有连接检查路径，但必须保留密钥不落日志和不进 URL 的安全边界。
- 主要风险是设置窗口内容变长、模块覆盖文案仍然过于技术化，以及原生 `TabView` 在窄窗口下的可读性。实现阶段应优先用系统滚动和自然增高解决，不通过固定高度裁切文本。
- 当前工作树已有并行 UI、提词器和设计系统改动；实现阶段不得覆盖这些改动，设置相关编辑需与其分离。

## 12. 设计审阅状态
