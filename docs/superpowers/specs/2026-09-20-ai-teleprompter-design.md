# SpeechRail AI 提词器设计规格

## 1. 规格目的

本规格定义一个面向直播、演讲和录制场景的 macOS App AI 提词器。它解决的不是“把文字放在屏幕上”，而是让用户在使用 OBS、抖音直播伴侣、Zoom 等外部软件进行**窗口采集**时，能够只给自己看到稿件，并根据实际讲话进度自动跟读。

本规格先定义用户价值、产品边界、用户旅程、模块职责、数据流、失败出口和执行阶段；它不把尚未实现的能力写成当前产品承诺。

## 2. 背景与当前基础

SpeechRail macOS App 当前已有三类可复用基础：

- `SessionCoordinator` 统一管理会话占用、麦克风租约、开始/停止和中断状态；
- `RealtimeASRClient` 连接现有 `/v1/realtime`，接收实时 ASR 事件；
- `CaptionBandWindowController` 已实现跨空间、非激活、可交互的字幕浮层。

相关实现与契约入口：

- `macos/SpeechRailApp/SpeechRailApp/SessionCoordinator.swift`
- `macos/SpeechRailApp/SpeechRailApp/RealtimeASRClient.swift`
- `macos/SpeechRailApp/SpeechRailApp/CaptionBandWindow.swift`
- `macos/SpeechRailApp/SpeechRailApp/SessionDomain.swift`
- `macos/SpeechRailApp/SpeechRailApp/AppRoute.swift`
- `docs/design/2026-09-17-live-sessions/SESSIONS-SPEC.md`
- `docs/design/2026-09-18-session-layer/TECHNICAL-DESIGN.md`

这些文件和文档只用于确定边界。实现前仍以当前代码、契约和实测为准。当前工作区存在其他未提交的 macOS 合同对齐与 UI 改动；本功能不得覆盖或整文件替换这些并行变更。

## 3. 用户与问题定义

### 3.1 目标用户

- 直播主播：需要看稿，但不希望观众看到提词内容；
- 课程、产品或技术演讲者：希望保持自然表达，不想频繁低头翻稿；
- 录制者：使用外部摄像或直播软件录制，需要一个低干扰的本机提词窗口。

### 3.2 用户要完成的任务

用户需要在不改变直播软件窗口采集链路的前提下完成以下闭环：

```text
导入/粘贴稿件 → AI 整理 → 用户审核 → 打开舞台提词
→ 讲话 → 自动跟读/手动接管 → 结束并保存进度
```

### 3.3 核心成功标准

1. 用户能在几分钟内从一份 TXT、Markdown 或粘贴文本进入可提词状态。
2. AI 整理不会静默改写用户原稿；用户可以查看、编辑和撤销整理结果。
3. 用户正常表达、漏读、跳读或重复时，提词器不会因为短暂 ASR partial 而乱跳。
4. 用户始终可以用键盘或鼠标暂停自动跟随、上一段、下一段和回到当前段。
5. 直播软件只采集用户指定的直播窗口；提词窗口不作为直播画面内容。
6. 提词器不播放声音、不操作摄像头、不保存音频/视频、不改变直播输出路由。
7. AI、ASR、权限或服务失败时，用户仍可切换到手动提词模式。

## 4. 产品决策

以下决策作为 v1 的基线：

| 编号 | 决策 | 结果 |
|---|---|---|
| D1 | 提词器属于 macOS App 客户端会话层 | 用户稿件、AI 编排、窗口和跟读状态不进入 Python 服务 |
| D2 | AI 只在准备阶段运行 | 直播过程中不逐句调用 LLM；运行时使用 ASR 与本地确定性匹配 |
| D3 | 首版稿件由用户提供 | 支持粘贴、TXT 和 Markdown；AI 从主题生成完整稿件留到后续版本 |
| D4 | 首版只做窗口采集安全路径 | 明确要求直播软件使用摄像头/窗口采集，不承诺整屏采集下的绝对隔离 |
| D5 | 直播链路不由 SpeechRail 托管 | 不推流、不录视频、不播放 TTS、不控制摄像头和直播软件 |
| D6 | 音频只在跟读会话中存在 | 麦克风仅在用户点击开始后启用；原始 PCM 不落盘 |
| D7 | 自动跟读必须可接管 | 任何低置信度匹配都保持当前段并显示不确定状态，不强行跳转 |
| D8 | AI 结果需要用户确认 | AI 返回结构化分析；用户确认后才成为活动稿件版本 |
| D9 | 提词运行不进入现有转录记录库 | 统一使用会话占用管理，稿件进度和运行状态由 `TeleprompterStore` 保存 |
| D10 | v1 不增加全局提词快捷键 | 只提供舞台窗口内快捷键，避免与现有 Carbon 快捷键和直播软件冲突 |
| D11 | UI 使用统一设计 token | 颜色、间距、圆角、字体、尺寸、表面和动效优先消费 `SpeechRailDesignTokens` 或 macOS 系统语义值，不在功能视图散落视觉常量 |

## 5. 范围

### 5.1 v1 包含

- AI 提词器 App 路由和稿件库；
- 粘贴、编辑、导入 TXT/Markdown；
- AI 分段、关键词、语义锚点和停顿提示；
- 原稿与 AI 结果对照审核；
- 活动稿件版本快照；
- 独立舞台提词窗口；
- 字号、透明度、宽度、窗口位置和显示段数设置；
- 实时 ASR 驱动的自动跟读；
- 不确定状态、断连状态和手动模式；
- 键盘快捷操作；
- 本机稿件、版本、设置和最后进度保存；
- 直播窗口采集安全说明。
- 使用系统统一设计 token 的准备页、状态区和舞台窗口。

### 5.2 v1 不包含

- 根据主题自动生成完整演讲稿；
- 音频或视频录制、编辑、导出；
- OBS/直播平台插件、推流和场景控制；
- 观众侧字幕或直播画面叠加；
- 实时 LLM 改写、实时问答或自动补写下一句；
- 摄像头眼神校正、硬件遥控器和多用户协作；
- 整屏采集下的绝对不可见承诺。

## 6. 需求场景

### 6.1 直播前准备

用户新建稿件，粘贴或导入正文，点击“AI 整理稿件”。系统展示分析状态和结果，不覆盖原文。用户可以逐段编辑、合并、拆分、接受或撤销建议，随后生成一个不可被后台静默修改的活动版本。

### 6.2 直播中自动跟读

用户打开舞台提词窗口，按照提示在直播软件中选择摄像头或目标直播窗口。用户点击“开始跟读”后，App 申请麦克风权限、连接本地 SpeechRail ASR，并把当前段置于视觉中心。

ASR completed 文本经过规范化和序列匹配后，系统只在匹配满足顺序和置信度要求时推进。当前段大字高亮，上一段和下一段弱化显示，并提供整体进度。

### 6.3 脱稿、漏读和重复

- 漏掉短语但保留段落核心内容：允许继续匹配；
- 临时换一种说法：通过关键词和替代表达进行候选匹配；
- 明显偏离稿件：保持当前段，进入“不确定”；
- 重复上一段：不自动回退；用户可手动回退；
- 用户手动前进或回退：重置匹配窗口，避免旧 ASR 文本立即把位置拉回去。

### 6.4 运行失败

麦克风未授权、服务未就绪、Realtime 连接断开或模型不可用时，页面和舞台窗口均显示可理解的受阻原因，并提供“切换手动模式”“打开系统设置”“重试”和“结束提词”等出口。

### 6.5 稿件中途修改

运行中的活动版本不可原地修改。用户需要先暂停提词，再编辑并生成新版本；新版本经确认后才能替换活动稿件。当前运行结束后，最后使用的版本和段落进度写入本机存储。

## 7. 用户故事与验收结果

| 用户故事 | 可观察结果 |
|---|---|
| 作为主播，我想导入已有稿件 | TXT/Markdown 能进入编辑器，原文内容可回看 |
| 作为演讲者，我想让 AI 帮我分段 | AI 返回结构化段落、关键词和锚点，失败时有确定性分段回退 |
| 作为用户，我想审核 AI 结果 | AI 不直接替换原稿；用户确认前活动版本不变化 |
| 作为主播，我想只自己看到提词 | 舞台窗口独立于直播目标窗口，并显示窗口采集安全提示 |
| 作为演讲者，我想自然表达 | ASR partial 不推进；completed 匹配有顺序约束和迟滞 |
| 作为用户，我想随时手动控制 | 空格暂停，方向键上一段/下一段，支持鼠标按钮；快捷键状态可见 |
| 作为直播用户，我不希望提词器影响直播 | 不播放 TTS、不启动摄像头、不推流、不写视频，不修改直播输出路由 |
| 作为隐私敏感用户，我想控制稿件外发 | 只有用户主动点击 AI 整理时才发送到已配置的 Responses-compatible endpoint；运行时不发送稿件给 LLM |
| 作为没有 AI 配置的用户，我仍想提词 | 纯文本分段和手动跟读仍可用 |

## 8. 用户旅程

| 阶段 | 用户动作 | 系统状态与反馈 |
|---|---|---|
| 创建 | 打开“AI 提词器” | 显示新建、导入、粘贴和最近稿件 |
| 准备 | 导入或粘贴文本 | 原稿可编辑，未分析状态清晰可见 |
| 分析 | 点击“AI 整理稿件” | 显示正在分析；不成功时保留原稿并提供纯文本回退 |
| 审核 | 查看段落、关键词、停顿 | 用户接受、修改或撤销；生成活动版本 |
| 预演 | 打开舞台窗口 | 显示字号、透明度、窗口位置和直播采集提醒 |
| 开始 | 点击“开始跟读” | 申请权限、获取会话租约、连接 ASR；失败不创建空运行记录 |
| 演讲 | 正常讲话 | 当前段高亮、进度推进、状态带显示跟读/不确定/手动 |
| 接管 | 按暂停或方向键 | 自动推进停止，用户明确控制位置 |
| 结束 | 点击结束 | 停止采集，关闭 ASR，释放设备，保存进度 |
| 回看 | 再次打开稿件 | 可以从上次位置继续或从头开始，不读取原始音频 |

## 9. 产品交互规格

### 9.1 准备页

准备页包含：

- 稿件列表和新建入口；
- 标题、正文编辑器；
- 导入 TXT/Markdown；
- “AI 整理稿件”按钮；
- AI 分析结果与原稿的段落对照；
- 关键词、替代表达和停顿提示；
- 接受、撤销、编辑和生成活动版本；
- 打开舞台提词；
- 进入手动模式。

AI 分析结果不能以“保证语义正确”的口径展示，只能标为“建议”。用户确认后，界面明确显示活动版本号和更新时间。

### 9.2 舞台窗口

舞台窗口是用户在直播时真正使用的界面：

- 独立于控制台主窗口；
- 默认置顶、跨空间显示、尽量不抢主 App 焦点；
- 支持宽度、字号、透明度、行距和位置记忆；
- 当前段居中并高亮；上一段和下一段弱化；
- 显示段落进度、跟读状态和低置信度提示；
- 提供暂停、上一段、下一段、重置跟读和结束按钮；
- 支持键盘操作，并为 VoiceOver 提供当前段、状态和进度标签。

建议快捷操作：

| 操作 | 默认键 | 说明 |
|---|---|---|
| 暂停/继续 | `Space` | 切换自动跟读，不结束会话 |
| 上一段 | `←` | 手动回退并重置匹配窗口 |
| 下一段 | `→` | 手动前进并重置匹配窗口 |
| 回到当前段 | `R` | 取消暂时的手动滚动 |
| 结束提词 | `Esc` | 释放麦克风并关闭舞台窗口 |

v1 不增加全局提词快捷键。原因是直播软件、系统和现有 SpeechRail 会话已经存在快捷键所有权；窗口内快捷键足以覆盖用户可见的提词控制。后续若增加全局快捷键，必须另立变更并验证冲突、权限和直播软件兼容性。

### 9.3 直播安全提示

开始前必须显示一次简短提示：

> 请在直播软件中选择摄像头或目标直播窗口，不要使用包含提词器的整屏采集。SpeechRail 不负责直播推流，也不会把提词器内容写入直播画面。

舞台窗口应使用独立标题和独立窗口身份。若 macOS 26 SDK 与实际采集链路验证通过，可额外设置窗口的屏幕共享排除属性；该属性只是防护层，不能替代用户正确选择窗口采集。

### 9.4 设计 token 约束

提词器的新增 UI 必须接入现有设计系统，单一事实来源为：

`macos/SpeechRailApp/SpeechRailApp/SpeechRailDesignTokens.swift`

实施规则：

- 间距从 `SpeechRailDesignTokens.Spacing` 取值；页面和窗口尺寸从 `Layout` 取值；字体层级从 `Typography` 取值；控件尺寸和工具栏档位从 `Control` / `Toolbar` 取值；
- 颜色优先使用 macOS 系统语义色和 `SpeechRailDesignTokens.Color`；不在提词器视图中新增 `Color(red:green:blue:)`、十六进制颜色或自挑灰度；
- 容器和嵌套表面使用现有 `Corner`、`ConcentricRectangle` 及 `.speechRailSurface(...)`、`.speechRailContentSurface()`、`.speechRailField()` 等统一 modifier；不在局部重复 `.cornerRadius(...)`；
- 舞台窗口优先使用系统窗口材质、`glassEffect` / `GlassEffectContainer` 和现有浮层层级；不自绘一套新的玻璃、阴影或背景渐变；
- 动效使用现有 `Motion` 语义，并在 `accessibilityReduceMotion` 下退化为即时状态切换；
- 新增确实无法复用的视觉值时，只能先扩展 `SpeechRailDesignTokens.swift`，为 token 写明语义和使用范围，再由视图消费；不能把局部常量留在 `TeleprompterView` 或 `TeleprompterStageView`；
- 复用 `SessionDesignSurface` 等现有组件时，必须保留其 token 接线；当前工作区已有该文件的并行改动，实施时逐段合并，不得整文件覆盖。

设计验收必须覆盖浅色/深色外观、系统强调色、动态字体、键盘焦点、增加对比度、VoiceOver 和减少动态效果。

## 10. AI 分析规格

### 10.1 输入

AI 分析只接收用户主动提交的稿件正文和用户选择的语言/表达偏好。不得自动读取麦克风、直播窗口、剪贴板历史或其他文档。

### 10.2 输出

AI 返回必须符合版本化结构：

```json
{
  "schema_version": "teleprompter.analysis.v1",
  "segments": [
    {
      "id": "segment-1",
      "source_start": 0,
      "source_end": 128,
      "text": "用户确认后的段落文本",
      "keywords": ["关键词"],
      "match_phrases": ["可接受的口语表达"],
      "pause_hint": "short"
    }
  ]
}
```

`text` 必须能追溯到原稿范围或用户后续编辑，不能把 AI 自行扩写的内容默认为用户稿件。未知字段可以忽略；关键字段缺失或 JSON 不符合结构时，进入确定性回退。

### 10.3 调用边界

- 复用 App 已有的外部 Responses-compatible LLM 配置边界；
- 密钥只从 Keychain 或既有凭据提供器读取；
- AI 调用发生在用户点击“AI 整理稿件”之后；
- 直播跟读期间不调用 LLM；
- 不把完整稿件、完整 prompt、密钥或 provider 原始错误写入日志；
- AI 请求失败不阻塞手动提词。

## 11. 跟读与状态机

### 11.1 状态

```text
draft
  → analyzing
  → review
  → ready
  → preparing
  → following
  → paused
  → uncertain
  → manual
  → ended
```

`uncertain` 和 `manual` 是可恢复状态，不是错误。服务断开、权限撤销或音频源丢失进入 `manual` 或 `ended`，由具体失败条件决定。

### 11.2 推进规则

1. partial transcript 只更新“正在识别”预览，不推进活动段；
2. completed transcript 作为主要推进输入；
3. 文本匹配先做 Unicode、标点、空白和常见口语填充词规范化；
4. 候选匹配同时考虑当前段、有限的后续窗口和关键词覆盖；
5. 只有满足最低匹配置信度、顺序约束和迟滞边界时才自动推进；
6. 候选差距不足时停留在当前段并显示“不确定”；
7. 自动推进不能跨越未确认的多个段落；
8. 手动前进、回退或暂停会清空旧匹配窗口，避免旧 transcript 立即反向纠正用户操作；
9. 结束时只保存活动稿件版本和最后位置，不保存原始音频。

阈值和窗口大小必须通过确定性夹具校准，不能由 UI 文案或模型名称推断。

## 12. 数据模型与存储

### 12.1 稿件

```text
TeleprompterDocument
  id
  title
  sourceText
  activeVersionID
  createdAt
  updatedAt

TeleprompterVersion
  id
  documentID
  sourceText
  segments[]
  analysisSource: ai | deterministic | user
  createdAt

TeleprompterSegment
  id
  ordinal
  sourceRange
  text
  keywords[]
  matchPhrases[]
  pauseHint

TeleprompterRunState
  documentID
  versionID
  currentSegmentID
  mode: following | paused | manual
  lastUpdatedAt
```

### 12.2 存储选择

首版使用独立的 `TeleprompterStore`，以版本化 Codable 文件保存稿件和设置，一个稿件一个文件并采用临时文件加原子替换。它不复用 `SessionStore` 的转录记录 schema，避免把“稿件资产”和“语音会话记录”混成一张表。

实时 ASR 只作为运行时输入，不保存原始 PCM。若后续需要演讲复盘，可另行设计“文本记录”功能，不在本规格中隐式增加。

### 12.3 用户可见的持久化

用户可以导出稿件为 Markdown 或纯文本。导出物不得包含 API Key、服务地址中的秘密、原始音频或内部诊断信息。

## 13. 技术架构与模块边界

### 13.1 领域层

新增纯值类型和纯函数：

- `TeleprompterDocument`；
- `TeleprompterVersion`；
- `TeleprompterSegment`；
- `TeleprompterRunState`；
- `TeleprompterNormalizer`；
- `TeleprompterAligner`。

领域层不依赖 SwiftUI、AppKit、URLSession 或具体 LLM。

### 13.2 应用层

- `TeleprompterSession`：负责准备、启动、暂停、跟读、手动接管和结束；
- `TeleprompterAIClient`：负责一次性的结构化 AI 分析；
- `TeleprompterStore`：负责稿件和版本的本机存储；
- `TeleprompterAudioSource`：复用现有麦克风采集约束，只提供实时 PCM，不启用 TTS、摄像头或输出节点，不改变系统输出/直播音频路由；如果设备无法与直播链路并存，则 fail-closed 并回退手动模式；
- `SessionCoordinator`：增加 `teleprompter` 能力的统一占用与释放，但为该能力使用非持久化运行策略；不把提词器错误当成字幕或会议。

提词器应作为新的会话能力接入，而不是给 `CaptionSession` 增加一个布尔模式。字幕是“显示已经说过的内容”，提词器是“显示即将说的内容”，两者的记录、推进和失败语义不同。`SessionCoordinator` 仍是麦克风租约的唯一所有者，但提词运行不创建 `SessionStore` 的转录记录；它只在 `TeleprompterStore` 中保存稿件版本、最后段落和运行状态。

### 13.3 UI 与原生窗口层

- `TeleprompterView`：稿件准备页；
- `TeleprompterStageWindowController`：舞台窗口；
- `TeleprompterStageView`：舞台窗口内容；
- `AppRoute`：增加 `teleprompter`；
- `ControlCenterView`、菜单栏和必要的快捷入口：增加“AI 提词器”。

舞台窗口复用现有字幕窗口的通用窗口策略：非激活、浮动、跨空间、全屏辅助和位置记忆；具体窗口类保持独立，避免把字幕的内容布局和提词的段落布局耦合。

### 13.4 服务边界

v1 不新增 Python 路由、OpenAPI 字段、Realtime 事件或服务端 worker。提词器只消费现有 ASR 子集；稿件、AI 分析、跟读匹配和窗口都属于 App 客户端。

## 14. 失败、降级与隐私

| 故障 | 用户看到的状态 | 可用出口 |
|---|---|---|
| AI 未配置 | “AI 整理不可用” | 使用确定性分段或手动编辑 |
| AI 返回非法结构 | “AI 结果未采用” | 保留原稿，使用回退分段 |
| 麦克风未授权 | “麦克风未授权” | 打开系统设置或进入手动模式 |
| SpeechRail 未就绪 | “语音服务未就绪” | 重试或手动模式 |
| Realtime 断开 | “自动跟读已暂停” | 重连、手动继续或结束 |
| 匹配低置信度 | “请确认当前位置” | 暂停、上一段、下一段 |
| 直播窗口选择错误 | 直播安全提示 | 重新选择摄像头/目标窗口 |

强制约束：

- 不把 API Key 放进 URL、稿件、日志或导出物；
- 不记录完整 prompt、完整 transcript、原始音频或视频；
- 不在 App 启动时申请麦克风；
- 只有用户开始跟读后才获取麦克风；
- 停止、异常和窗口关闭时都必须释放会话资源；
- AI 失败不得阻塞手动提词；
- 自动跟读不确定不得强行跳转。

## 15. 执行计划

### 阶段 0：规格与夹具

冻结本规格，建立文本规范化、AI 分析 JSON、跟读状态和直播安全提示的确定性夹具。此阶段不改运行态。

### 阶段 1：领域模型与跟读算法

新增纯 Swift 领域类型、规范化器和对齐器；先写失败测试，再实现以下行为：

- 中文、英文和中英混合文本；
- 标点和空白差异；
- 漏读、跳读、重复和同义表达；
- partial 不推进；
- 低置信度停留；
- 手动控制后匹配窗口重置。

### 阶段 2：稿件库与 AI 分析

新增 `TeleprompterStore`、导入器、编辑视图和 `TeleprompterAIClient`。实现版本快照、严格结构解码、确定性回退和 Markdown/纯文本导出。

### 阶段 3：实时会话

接入现有 `SessionCoordinator`、麦克风采集和 `RealtimeASRClient`。实现权限、服务未就绪、busy、断连、停止和释放路径。提词模式不启用 TTS。

### 阶段 4：舞台窗口与 App 路由

增加 App 路由、准备页、舞台窗口、窗口位置记忆、键盘控制、菜单栏入口和直播采集提醒。所有新增视觉值先进入统一 token，再接入页面与舞台窗口；完成一次 token 使用审查。必要时补充窗口屏幕共享排除的本机实测。

### 阶段 5：验收

按本规格的用户故事逐项验收：稿件准备、AI 回退、跟读稳定性、手动接管、窗口采集安全、资源释放和隐私边界。UI 自动化、录屏和真机直播验收必须由当前用户单独授权后执行。

## 16. 测试与证据要求

### 16.1 单元测试

- `TeleprompterNormalizerTests`：文本规范化；
- `TeleprompterAlignerTests`：推进、迟滞、低置信度和手动接管；
- `TeleprompterAnalysisDecoderTests`：严格 JSON、未知字段和非法回退；
- `TeleprompterStoreTests`：版本、原子写入、恢复和导出。

### 16.2 集成测试

- fake Realtime ASR 事件驱动提词会话；
- 服务未就绪、busy、断连和结束时的资源状态；
- AI client 的 fake Responses endpoint 和错误映射；
- 稿件版本不在运行中被静默替换。

### 16.3 UI/真机验收

需要用户明确授权后才执行：

- 真实窗口采集下确认提词内容不进入直播目标窗口；
- 多空间、全屏应用、窗口移动和屏幕切换；
- 麦克风权限、服务断开、直播过程中手动接管；
- 停止后麦克风指示和音频资源释放；
- VoiceOver 与键盘路径。

完成声明必须以实际运行结果为依据，不能以编译、静态检查或计划完成代替。

## 17. 兼容、迁移与回退

- 不改变 SpeechRail Python 服务公共协议；
- 不改变现有字幕、会议和语音助手的会话语义；
- 新稿件存储使用独立目录，删除提词器功能不会删除既有会话记录、作品或音色；
- 若 AI 分析或实时 ASR 不可用，功能回退到纯手动提词；
- 若舞台窗口安全实测不满足当前直播环境，保留准备页和手动稿件功能，暂停自动舞台跟读，而不是默许不安全的整屏采集；
- 实施前应以当前工作区为基线创建短期功能分支或等价保存点，绝不回退、覆盖或清理其他未提交改动。

## 18. 规格完成判据

本规格视为可进入实施计划的条件：

1. 用户目标、场景、用户故事和旅程已覆盖直播窗口采集主路径；
2. v1 范围和非目标明确，不包含 AI 自动写稿和直播推流；
3. AI 准备阶段与实时跟读阶段边界明确；
4. 窗口安全、麦克风生命周期、隐私和手动回退均有明确出口；
5. Python 服务公共边界没有被隐式扩大；
6. 每个核心行为都有对应的测试或真机验收证据类型；
7. 新增 UI 已通过统一 token 审查，没有散落的颜色、字号、间距、圆角或材质常量；
8. 没有 `TBD`、`TODO` 或未决的产品裁决项。
