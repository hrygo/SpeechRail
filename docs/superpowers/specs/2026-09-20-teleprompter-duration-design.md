# AI 提词器目标时长设计

> 本文已由 [AI 提词器终版规格](2026-09-20-ai-teleprompter-final-spec.md) 替代。以下内容仅供设计演进追溯，不再作为实施依据；规则和参数以终版为准。

本文件是 [朗读稿与 MapReduce 设计](2026-09-20-teleprompter-reading-preparation-design.md) 的时长子规格。用户要求在执行 MapReduce 前设置朗读目标时长，并使该参数贯穿预检、生成、审阅和跟读。本文给出首版实现决策；未运行真实模型或朗读测量，所有估算系数和阈值均为待校准初值。

## 1. 调研结论（2026-09-20 核实）

| 证据 | 适用结论 | 不应推出的结论 |
|---|---|---|
| [Microsoft Speaker Coach](https://support.microsoft.com/en-us/powerpoint/suggestions-from-speaker-coach) | 其产品建议演讲语速约 100–165 words/min，同时明确个体差异、短时波动和转写延迟影响 | 不能将 words/min 直接当作中文汉字/min；不能保证某个固定值适用于所有人 |
| [Toastmasters，Manage Your Speaking Time，2025-02](https://www.toastmasters.org/magazine/magazine-issues/2025/feb/manage-your-speaking-time) | 实际出声练习、用词量和计时器校正、预留余量有助于控制时长 | 字数估算不能替代排练；现场反应可能导致超时 |
| [英文和普通话时长语料研究，2022](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2022.869049/full) | 韵律边界、停顿及语言差异影响时长 | 不能把专业播音语料速度当用户默认速度；文中 5.31 syllables/s 对应英文语料，并非中文推荐值 |

结论：时长是一个需要校准的产品目标。程序负责计量和比较，LLM 根据明确的局部篇幅预算调整表达。必须分别记录 target、estimate 和 actual，不能让模型自己报告“刚好 20 分钟”作为验收依据。

## 2. 用户如何设置

导入后、点击「整理朗读稿」前，在原稿下方显示一行原生设置：

`目标朗读时长 [20] 分钟   朗读节奏 [自然]`

下面显示：`原稿预计约 24–30 分钟；目标 20 分钟，可能需要减少内容。`

- 目标时长必填，首版为 1–120 分钟的整数；持久化使用整数秒（60–7200）。使用可键盘编辑的数值输入框和 stepper，快捷值为 5/10/15/20/30/60/120 分钟；快捷项按布局收敛，不另造复杂滑块。
- 默认填入按当前语速计算的推荐分钟数 `ceil(estimate_seconds/60)`；不自动套用其他稿件的目标。用户只需改值或点击生成接受预填值，不再弹一次确认。超过 120 的建议不静默夹成 120 并暗示可行，而是显示超范围并提示调整内容。
- 节奏提供「舒缓 / 自然 / 明快」，默认自然；支持可选的「按我的试读估算」。它改变估算与预算，不改变语音设备、ASR 模型或自动滚动速度。
- 定义是“读完当前所选稿件的用时，包含自然停顿”。不包含外部问答、演示、视频播放、休息等议程时间；首版不增加第二套演讲议程预算。用户有 20 分钟发言加 10 分钟问答，应设置 20 分钟。
- 目标是希望接近且尽量不超过的计划用时，不是硬性截断点。未读完达到目标后仍可继续，App 不静音、不删句、不强行滚动。
- 「直接使用原稿」可保留同一时长设置用于预估/跟读，也可不设目标；只有 AI MapReduce 入口要求目标已明确。

界面文字不得出现 token、归约、JSON 或 estimator 等内部术语；完整技术细节进入开发者信息。

## 3. 三个时长与两种上限

| 字段 | 含义 | 权威来源 |
|---|---|---|
| targetSeconds | 用户希望读完的目标 | 用户设置 |
| estimatedSeconds / estimatedRange | 当前文本按当前节奏预计的用时 | 本地版本化估算器 |
| actualElapsedSeconds | 本次实际计时用时 | 单调时钟 |
| importReferenceSeconds | 固定参考系数下的上传容量估计 | 产品导入规则，与个人节奏无关 |
| modelInput/OutputBudget | 一次请求可发送/生成的文本资源 | provider 能力与任务预算 |

主规格的“约 2 小时原稿上限”仍按固定的 250 汉字/min、160 非 CJK 词/min 参考值估计，配合 1 MiB/单元数限制执行；用户选更快节奏不能绕过上传限制。目标 120 分钟上限也不意味着模型能一次输出 120 分钟正文。导入容量估计与个人朗读估计刻意分开命名、保存和展示，前者不能伪装为精确可读时长。

## 4. 本地估算与不确定性

### 4.1 首版计量

先建立仅用于计量的 SpokenMeasure，不改原文或朗读正文：

- C 为预计实际读出的中文等价字数；E 为预计读出的英文等价词数。普通中文按汉字计，英文按词计，两个集合互斥。
- 明确的数字、日期、百分比、单位和缩写可用小范围有测试的朗读规则计算长度；原字符串保持不变。无法唯一解释的数字串、URL、代码和专业缩写记录为 unresolvedPronunciation，不把 20 位数字当一个普通英文词。
- 对原稿，明显格式标记只在计量副本中忽略；结构有歧义时给出粗估与原因，不让时长预检承担 Markdown 语义清洗。表格转述可能重复表头，生成前估算较粗；生成后按实际朗读稿重新计算。
- 其他语言首版不伪装支持中英模型。可按用户试读获得的稿件级比例估计；没有测量时显示“暂无法可靠估算”，仍可明确选择完整整理，生成后人工核对时长。

默认系数是“包含通常句间停顿的有效语速”，不是去除静音后的 articulation rate：

| 节奏 | 中文等价字/min | 英文词/min |
|---|---:|---:|
| 舒缓 | 180 | 110 |
| 自然 | 220 | 140 |
| 明快 | 260 | 165 |

中文系数为产品初值，无直接研究证明其适合本用户；英文取值参考 Microsoft 产品建议范围，但同样需实际试读。初始用时：`D = 60 × (C/r_cn + E/r_en)` 秒。

常见标点停顿已隐含在有效语速中，不再为每个逗号加固定秒数；否则会双重计时。现有 pause_hint 的 short/medium/long 不应被机械换成秒数。明确的额外舞台等待不属于首版计量，作为提示独立存在。

无个人校准时，普通稿展示启发式区间 `[0.8D, 1.25D]`；它是粗略波动带，不是统计置信区间。有大量复杂符号或未确定的结构时显示“粗估，待整理后核对”，不让一个有限区间掩盖未知内容。生成后的 estimate 同样不是实际朗读保证。

### 4.2 可选试读校准

用户可手动开始并结束一段约 60–90 秒的试读，确认读完选中片段；该动作可只使用计时器，不强制调用模型、麦克风或保存音频。试读片段应代表本稿语言、数字和术语比例，不只选最容易的开头。

计算 `k = actual_sample_seconds / base_sample_estimated_seconds`；随后 `D_personal = k × D_base`。k 是针对当前语言混合和节奏的比例，不能从单个混合样本反推出两个独立的中英语速。短于 30 秒、未读完、有明显重来或手动跳段的样本不给出校准值；初始合理性检查为 0.5≤k≤2.0，超出提示重测，不静默夹值。初次校准只收窄误差原因，不擅自缩小波动带；足够重复样本后再用实测误差决定范围。

校准结果需用户选择采用，记录 sample 的版本、语言比例、时长和估算器版本。不存音频或全文转写；常规跟读不会偷偷改写用户的持久化语速偏好。

## 5. MapReduce 前预检

顺序为：输入限制 → 目标数值合法 → 当前内容范围明确 → 时长估算 → 可行性提示 → token/输出预算。时长预检不调用 LLM，不要求先运行 MapReduce 才告诉用户明显的目标冲突。

给目标留 5% 的计划余量：`B = 0.95 × targetSeconds`。它是生成篇幅预算，不是额外加到 D 上的停顿时间，也不能保证现场不超时。

| 条件（首轮启发式） | 展示 | 下一步 |
|---|---|---|
| 目标非数值、≤0、超 120 分钟、内容为空 | 明确输入错误 | 修正前不启动 |
| D/B 在 0.75–1.00 | 与目标大致匹配 | 正常整理，尽量保持自然和完整 |
| D/B 在 1.00–1.15 | 可能略超时 | 可尝试精简表达，展示仍可能超时 |
| D/B >1.15 | 目标明显紧张 | 推荐延长时长或选择要讲的内容；允许“仍完整整理”，结果标为可能超时 |
| D/B <0.75 | 内容可能提前读完 | 保持自然，不补写凑时长；可缩短目标或补充原稿 |
| 结构/发音/语言导致估算不可靠 | 暂无法可靠预估 | 用户可完整整理，必须保留 timing_uncertain 状态 |

1.15 不是“最多可压缩 15%”的事实保证，只是提醒阈值；D 的低估/高估都可能改变结果。未知时不能宣称 impossible，也不能显示精确达标。

### 内容取舍边界

首版默认内容策略为 preserve。目标缩短只允许去掉冗余措辞、调整句法，仍保留事实、例子、条件和立场。主 prompt 的保真规则持续有效。

显著超时时提供「选择要讲的内容」：用户在原稿段落/范围中选择本次纳入和不纳入的内容，程序负责切片，用户不需要手工给 LLM 分片。保留全文原稿，所选范围产生新的 selectionRevision；明确排除的内容记录为 userExcluded，不发送为可改写 targets。若排除内容是必要背景，只在当前范围内已获发送授权时提供为 read_only_context。选区可在来源切片边界细化，但不得改变原文字节。

Map 分别处理每段连续的已选范围，跨 userExcluded 区间禁止合并来源。Finalize 将 userExcluded 与 Map 返回一起完成整稿覆盖记录。每次变更选择重新估算、分配时间和取消旧任务。用户选择是内容范围授权，不授权模型在选中段内部继续删掉事实。

自动生成大幅摘要稿会改变内容策略和遗漏契约，本次不混入保真 MapReduce。用户若需要“把 2 小时材料自动提炼成 10 分钟演讲”，应以独立的“提炼短稿”模式设计，显式列出内容取舍及保留重点；不能由一个目标时长字段静默启用。这里并不阻止实现本轮的完整时长控制。

## 6. 目标如何进入分层处理

### 6.1 预算分配

Prepare 对所选原文的每个 Map 片计算有效朗读量 w_i（单位为预计秒数）。不把 JSON token 数用作内容重要性或朗读时长。先选择表达约束：若总内容明显短于 B，不给所有片分配要求填满的配额；budget 是上限目标，不是必须扩写到的下限。

按 `b_i = B × w_i / Σw_i` 分配局部篇幅预算。保留毫秒或 double 精度，展示才取整；不得每片向上取整导致总预算增加。低权重纯格式/空白在本地归入相邻片；全部无可计量内容转 timing_uncertain，不能除零。

组预算等于其片预算之和，整稿预算等于各组之和。分片变更或恢复拆窗时，原片预算按新的 w 比例重新分配；不能让两个子片各继承整个父预算。上层汇总 `budgetSeconds/estimatedSeconds/deltaSeconds/unresolvedCount`，不再生成一份摘要文本。

例如目标 20 分钟，B=1,140 秒；三个片段原估 360、480、360 秒，分配为 342、456、342 秒。Model 只需在保持内容的前提下稍收紧表达，不能误以为每片都有 20 分钟。若后来拆开第二片，其子预算总和仍为 456 秒。

### 6.2 Map 的 timing context

采用 `preparation.prompt.v3`，输出仍为 preparation.v2，时长统计由程序计算，不加模型自报时长字段。动态 input 追加：

```json
{
  "timing": {
    "global_target_seconds": 1200,
    "local_budget_seconds": 342,
    "pace": {"cjk_units_per_minute": 220, "latin_words_per_minute": 140, "calibration_factor": 1.0},
    "content_policy": "preserve",
    "fit_preference": "prefer_within_budget"
  }
}
```

主规格完整 prompt 已在示例之前纳入以下固定条款；实现时使用完整模板，不再次重复追加：

```text
timing 是应用给出的朗读篇幅计划，不是实际音频时长。global_target_seconds 是整稿目标，本次只使用 local_budget_seconds，不能每个片段都按整稿时长写。
优先完整保留事实、例子和限定条件，在预算内使用自然、紧凑的表达。无法兼顾时优先保真，不删除信息、不加快虚构语速、不加入新内容凑时长，也不加入“停顿若干秒”等文字。
不要报告你计算的秒数、字数或达标结论；应用会独立计量。片段预算较宽时允许更早读完，无需填满。
```

模型只接收本任务必要的节奏数值，样本、个人身份和历史朗读记录不上传。max_output_tokens 单独根据预计输出与 schema 预算设置，不能设成 targetSeconds 或把一分钟当固定 token 数。

### 6.3 Reduce 与总量反馈

Reduce 采用 `reduce.prompt.v2`，输出仍为 reduction.v1。输入追加 timing，包含 `editable_budget_seconds`、`editable_estimated_seconds` 和不可变的 pace snapshot；预算由参与 block 的来源权重分摊，不把整组预算给每一个边界。

主规格完整 Reduce prompt 已纳入以下固定条款，不再次重复追加：

```text
timing 给出本次可编辑正文合计的篇幅预算。改善衔接时避免新增冗长过渡；不能通过删除事实或添加无意义停顿来达成时间。完整性优先，不能保证同时达成时保持或改善忠实表达，由应用报告时间偏差。不要改动非 editable_blocks，也不要自报时长。
```

程序每次接受 patch 后重算受影响块及祖先组的估算用时；一个块在多个接缝参与修改时只在全文统计一次。Reduce 不递归摘要超预算组，不因为剩余时间多就补写。Map/Reduce 局部估计允许有偏差，最终整稿总量是唯一时长对比依据。

## 7. 生成后如何校验和修正

Finalize 完成、用户每次编辑、选择 cue/skip、修改发音读法或采用新节奏后，使用同一版本估算器重算批准正文；review 建议不偷偷计入已确认正文。review 未解决时只展示“已确定部分约…，另有待确认内容”，不能据此判整稿通过。

完整候选显示 target、estimate、粗略范围与差值，状态分为 `within_target/over_target/underfilled/uncertain`。定义：有未决计量问题则 uncertain；否则 D_final>target 为 over_target；D_final<0.75×target 为 underfilled；其余 within_target。within_target 仅表示中心估算不超目标，若范围上沿超目标仍显示“试读可能超时”，不显示“保证不超时”。

超过 B 但未超过 target：提示余量不足，不反复调用模型。超过 target 时提供「再精简表达」「调整时长」「选择要讲的内容」「保留当前稿」。小差异初值 `max(15秒, 目标×5%)` 以内默认仅提醒；明显差异优先让用户选择，不能启动无限自动循环。

用户点「再精简表达」才进行一次有界 time-fit pass，最多重做贡献最大超额的 3 个 Map 片。每片发送原始来源、当前候选和新预算，仍按 preparation.v2 连续覆盖，保留旧版本；优先对冗余表达多的片提出候选，不根据时间差断言哪段内容可删。新结果通过保真/来源检查且时长确有改善后供用户比较；失败或收益不足保留旧稿。

该 pass 完成后不再自动启动 Reduce 链或第二轮时间修正，避免反复扩写/压缩。将受影响接缝标为需审阅；用户可在审阅页看连贯性后采用。重新处理属于新的显式用户动作，与原任务的有限失败重试预算分开计数和显示。

目标更长时默认允许提前结束。补足时长需要用户补充素材或更改任务为扩写，不自动插入空洞句子、重复事实或长停顿。

## 8. 后续试读与正式跟读

### 8.1 试读确认

审阅页提供可选「计时试读」，显示本地估算与实际用时。完整试读可校正当前稿件的预计时长；用户确认后采用校准值。TTS 合成时长不代替真人朗读时长，本轮不新增 TTS 依赖。

### 8.2 运行时用途

开始时冻结 readingVersion、target、pace 和 estimator snapshot。UI 显示「目标 20:00 / 已用 07:10 / 预计剩余 12:30」，而不是显示内部阶段或判断概率。

- actualElapsed 使用单调时钟，从用户开始读稿计起；自然停顿、脱稿和运行中的手动定位时间都计入。用户显式暂停则冻结；服务断开停止运行后冻结，重连由用户恢复。额外休息/问答若不属于读稿应显式暂停。
- 目标剩余为 `max(target−elapsed,0)`，达到后显示超出时长；预计正文剩余由当前确认位置之后的文本用同一估算器计算，二者分开显示，不能混为一个倒计时。
- 初始 `预计完成总用时 = elapsed + estimatedRemainingTextTime`；对齐不稳定时不更新精细剩余预测，显示“位置待确认”，不能把低置信位置当精确百分比。
- 如要在本次运行调整预计剩余，可收集至少 30 秒的连续、稳定、向前跟读区间，计算局部比例 `k_run=区间实际用时/按冻结 pace 估计的区间用时`。采用最近 3 个有效区间比例的中位数，`预计正文剩余=冻结 pace 下的剩余估计×median(k_run)`；个人校准已在冻结 pace 内，不再重复乘一次。未达到样本要求时使用冻结的 pace；剩余稿语言组成明显不同则停止外推当前局部比例。发生跳段、重读、暂停、断连或失配时清除这组近期样本。不自动更新持久化个人节奏。
- 不用 ASR 输出 token 数计算语速；识别乱序、重复、迟到都可能污染它。来源为稳定对齐的正文覆盖和 App 计时，校准只是本次剩余预测，不更改正文或计划目标。
- 手动跳到后文后，已用时间不重置，正文剩余按新位置计算；跳过的内容不算“实际朗读完毕”。运行末尾分别记录正常读完/跳读/提前结束。
- 时间接近或超过目标只做轻量提示；不强制加速滚动、不自动跳句、不运行 LLM 删稿。ASR 对齐继续决定文本位置。

完成后保存目标、实际用时、结束原因和用户选择保留的校准元数据，不保存 PCM 或完整 ASR 文本。部分阅读不能当成完整稿的速度样本。

## 9. 数据、失效与实施位置

| 对象 | 新增内容 |
|---|---|
| DurationGoal | `targetSeconds,goalRevision`；AI 开始前必填，旧稿允许未设置 |
| PaceProfileSnapshot | `paceID,cjkRate,latinRate,calibrationFactor,estimatorVersion` |
| DurationEstimate | `pointSeconds,lowSeconds,highSeconds,uncertaintyReasons,readingRevision`；范围为估算带 |
| SelectionRevision | 所选原文区间与用户排除记录；不修改源文件 |
| TimingBudget | `nodeID,parentID,targetSeconds,estimatedSeconds,allocationRevision`；父子可加总 |
| TeleprompterVersion | 关联 timing snapshot、selectionRevision 和生成后的 estimate |
| RunTiming | 单调计时累计值、暂停状态、最后阅读位置、结束原因；不跨 App 重启延续旧单调时钟 |

目标、节奏、内容选择或源 revision 改变时取消旧 MapReduce 并生成新 allocationRevision；旧结果不能沿用。用户只改确认稿目标时可保留正文并重新估算，不自动重写；若决定重新整理才产生新生成请求。运行中不修改冻结目标，可停止后设置下一次的目标。

主规格 source/domain/store 的迁移增加 optional timing 元数据，旧稿目标缺失不妨碍直接跟读；用户首次对旧稿运行 AI 时填目标。缓存身份包含 goalRevision、pace snapshot、selectionRevision 和 timing allocation，防止不同目标复用旧结果。

建议实现为独立 `TeleprompterDurationEstimator` 与 `TeleprompterTimingPlanner`；会话层负责设置、预检、取消及汇总，Store 保存快照，舞台消费 RunTiming。估算与计划函数纯计算，可使用 fake 数据验证，用户不必手动分段。

## 10. 必要验证与验收

确定性验证：空值/1/120/越界目标；中英文互斥计数；数字与缩写不确定性；自然停顿不重复计时；固定上传上限与个人节奏分离；所有 child budget 总和等于 parent；拆片不复制父预算；Reduce 对共享 block 不重复计量；目标变化取消旧任务；用户排除内容保持完整来源记录；暂停/恢复/跳读/断线单调计时；部分读完不参与全稿校准。

模型评测沿用主规格开发/holdout，新增相同原文的目标比例 0.5/0.85/1.0/1.3（相对于基准估算），以及 Map-only/Reduce 后对比。衡量实际保真、中心估计相对目标误差、预计与真实试读误差、主动标记目标不匹配的行为、无意义补写和隐性删减率。目标比例 0.5 的 preserve 案例允许明确未达标，不能靠漏事实通过。

真人试读需另行获授权执行，记录各语言/节奏/文本类别的 MAE、中位相对误差与 p90 相对误差，按人和稿件隔离校准集/验证集。首轮普通稿预测中位相对误差 ≤15% 可作为产品目标，尚无实测；复杂稿单独报告。无数据前不把估算范围称为 95% 置信区间。

本轮验证仅覆盖设计文档中的 JSON、预算例子的算术和规格一致性，不代表语速参数、真实时长准确率或 MapReduce 时间控制质量已通过。
