# 有声书小说文本切分与工作台空间布局规范

本文档定义 SpeechRail 有声书工坊在文本导入、章节解析、语义断句（Atom 构建）以及工作台阅读画板排版中的技术架构、判断边界与验收规范。

---

## 1. 目标与设计原则

1. **全格式自适应（Universal Format Adaptability）**：
   算法不针对任何单一作品（如《西游记》）设计特例补丁，而是基于全局排版特征探针与语言学标点语义，同时适配古典定宽硬折行小说、现代网络长段落小说、密集极短交替对白、空行分段文本与诗词韵赋。
2. **对白边界高保真（Dialogue Boundary Sacredness）**：
   绝不因消除硬折行而误将不同角色的连续短对白合并。任何说话人切换点必须严格切分独立 Atom，保障 AI 角色标注与人工配声的准确性。
3. **来源区间 100% 无损保真（Lossless Source Coverage）**：
   切分出的 `AudiobookTextAtom` 其 `sourceRange` 组合必须无缝覆盖规范 UTF-8 原文，不产生任何字节空洞或重叠；软换行连接仅在逻辑切分与展示上生效，底层字节索引严格可逆。
4. **高信息密度剧本流排版（High-Density Script Flow）**：
   重构工作台中央画板，将“沉重工单卡片瀑布”升级为“专业紧凑剧本流”，消除横向过度拉伸与内部无意义留白，提升长篇通读与校对效率。

## 2. 常见小说排版范式与拆分边界

| 排版范式 | 典型排版特征 | 经典来源 | 正确切分预期 | 严禁出现的误伤（破坏性退化） |
|---|---|---|---|---|
| **范式 A：古典定宽硬折行** | 每 30~40 字强行插入 `\n`；行末断字断词（如“便\n了。”），标点挂于下行行首。 | 古典名著、早期 BBS/DOS 纯文本 | 识别排版折行并跨行平滑连接，生成完整语义句（30~100 字）。 | 严禁在行末截断处切出 1~3 字的孤立碎片 Atom。 |
| **范式 B：现代长自然段** | 段末才有换行，段内无任何硬回车，单行长达 100~500 字。 | 现代正版网文、电子书标准源 | 按自然句终标点（`。！？`）切分自然句，段首段末与原文一致。 | 严禁贪婪粘连导致单 Atom 超出 160 scalars 上限。 |
| **范式 C：密集交替短对白** | 每人一句，单行独立（如 `“去了？”\n“没去。”`），行内仅 3~8 字。 | 悬疑推理、现代言情、剧本体小说 | 每行对话严格保持为独立的对白 Atom，保留独立指派说话人能力。 | **绝对禁止跨行合并**！禁止将不同说话人的对白串联为一个 Atom。 |
| **范式 D：双换行空行分段** | 首行顶格无空格，段落间依靠 1~2 个纯空行（`\n\n`）区分。 | Markdown 导出、海外译作、EPUB 转 TXT | 以连续空行作为明确段落边界，段内根据行型判决。 | 严禁因无首行缩进空格而把整章误认为一个超大段落。 |
| **范式 E：诗词韵赋与无标点短句** | 单行短小（5/7/14 字），前置深缩进（如 4 空格），行末为逗号或无标点。 | 古典章回体诗赞、拟声描写 | 保持行首行末边界，不强行与前后文粘连为散文句。 | 严禁强求句终标点导致整首诗与前后叙述混为一谈。 |

## 3. 分层自适应切分架构（Four-Stage Segmentation Pipeline）

```
[原始规范 UTF-8 数据]
       │
       ▼
【第 1 阶段：排版特征自适应探针 (Document Format Profiler)】
       │  采样前 200 行统计：行长中位数、定长聚集度、行末非标点率、行首标点率
       │  输出画像：.hardWrapped(定宽折行) 或 .naturalParagraphs(现代自然排版)
       │
       ▼
【第 2 阶段：逻辑段落判定与换行分级 (Logical Paragraph Coalescing)】
       │  识别硬换行（段落结束，强制断开） vs 软换行（排版断行，跨行连接）
       │  绝对保护：独立对白行首、空行、段首全角缩进、章节标题
       │
       ▼
【第 3 阶段：段内语义单元 (Atom) 精准切分】
       │  - 纯对白提取：带说话词(道/说/问/曰:) 或处于行首对白 -> 独立 Dialogue Atom
       │  - 词级引用保护：无说话词且 <=4 字(如「老」字) -> 保留在叙述句中，不剥离
       │  - 句终标点与后置闭合符吸收：。！？配合 ”』）]
       │  - 兜底安全阀：160 scalars 处安全截断
       │
       ▼
【第 4 阶段：无损覆盖性与单调性校验 (Lossless Integrity)】
       │  AudiobookSourceIndex.validateCoverage 保证无空洞、无重叠、无乱码
```

---

### 第 1 阶段：全局排版特征探针（Profiler）

在章节切分或全书索引初始化时，对前 200 个非空行进行 $O(1)$ 毫秒级探测：

1. **行长与离散度**：计算行字符数中位数 $L_{\text{median}}$，以及行长落在 $[L_{\text{median}}-3, L_{\text{median}}+3]$ 区间的占比 $P_{\text{fixed}}$；
2. **行末句终标点缺失率**：统计行末不是 `。！？.!?` 及闭合引号的比例 $P_{\text{non-terminal}}$；
3. **判决矩阵**：
   - 若 $P_{\text{fixed}} \ge 0.60$ 且 $P_{\text{non-terminal}} \ge 0.40$：判定为 **`LineStyle.hardWrapped`**（定宽硬折行文本）；
   - 否则：判定为 **`LineStyle.naturalParagraphs`**（现代自然段排版文本）。

---

### 第 2 阶段：换行符（`\n` / `\r\n`）分类判决

对文本中的每一个换行符执行互斥判决：

#### 规则 2.1：绝对段落硬换行（必须断开）
命中以下任一条件时，判定该换行为真正的段落结束点，**强制切断当前 Atom**：
1. **连续空行**：当前换行与下一个非空白字符之间存在至少一个空行（`\n\s*\n`）；
2. **章节标题行**：下一行满足章节标题规则（`AudiobookChapterPlanner.isChapterHeading`）；
3. **段落缩进标志**：下一行行首为全角空格 `　　` 或制表符 `\t` 或 $\ge 2$ 个半角空格；
4. **独立对话行首（说话人隔离保底）**：下一行首字符为开引号（`“`、`「`、`『`），且当前行以句终标点或逗号结束。

#### 规则 2.2：排版折行软换行（跨行平滑连接）
仅在文档模式为 `hardWrapped` 时生效。当换行处**未命中规则 2.1**，且满足以下条件时，判定为排版硬敲的回车：
1. 当前行末**不是句终标点**（为普通汉字、词语中间、逗号 `，`、顿号 `、` 等）；
2. 下一行首为普通汉字接续，或下一行首为挂行标点（`、`、`，`、`。`、`」`、`”` 等）；
3. **执行动作**：当前 Atom 跨过该换行符继续扫描，直到遇见真正的句终标点或达到长度预算。

---

### 第 3 阶段：段落内的 Atom 精细化切分

#### 规则 3.1：对白台词 vs 词内引用
为消除“见三清称个「老」字”被切断为碎片的缺陷，对引号区间定义两级分类：
- **独立对白台词（Split as Dialogue Atom）**：
  - 引号前紧邻说话引导动词与标点（如 `道：`、`说：`、`问：`、`曰：`、`笑道：`、`喝道：`、`对曰：`、`：`）；
  - 或引号位于逻辑段落行首；
  - 或引号内包含完整的句终标点（`。！？`），且字符数 $> 5$；
  - **动作**：独立切为对白 Atom，供 AI 与用户指派具体角色。
- **词级强调与引用（Keep Inline）**：
  - 引号前无说话动词（如 `称个「老」字`、`叫作「花果山」`、`带『神仙』二字`）；
  - 引号内无任何标点，且长度 $\le 4$ 个字符，闭引号后紧随常规汉字；
  - **动作**：**不独立切分**，直接作为整句叙述的一部分保留在旁白 Atom 中。

#### 规则 3.2：句末标点与后置闭合符完整吸收
- 当遇到句终标点（`。！？；.!?`）时，贪婪吸收其后紧随的闭引号（`”’」』`）、闭括号（`）】]`）及跟随的行内空白；
- 严禁将闭合标点遗留在下一个 Atom 的行首。

#### 规则 3.3：预算与安全截断
- 单 Atom 目标字数 40~120 scalars，硬上限 `AudiobookLimits.maxAtomScalars`（160 scalars）；
- 若叙述段落极长且无句终标点，扫描达到 160 scalars 时，优先在次级标点（`，`、`、`、空格）断开；若通篇无标点，在 UTF-8 scalar 边界安全截断。

## 4. 工作台阅读画板与空间布局重构

针对原界面“卡片笨重、信息稀疏、大面积空旷暗色”的问题，进行界面布局与密度升级：

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│ 顶部状态与主操作栏 (Top Status Bar)                                             │
├───────────────┬───────────────────────────────────────────────┬─────────────────┤
│ 章节导航      │ 原文与说话人归属（剧本流 Compact Script Flow） │ 人物与配声检查  │
│ (260pt)       │                                               │ (320pt 宽屏常驻)│
│               │ ┌───────────────────────────────────────────┐ │                 │
│ 第1回 灵根... │ │ [✓] 旁白 #1  38字               改派说话人▾│ │ 孙悟空 [配声▾] │
│ 第2回 悟彻... │ │ 话表齐天大圣到底是个妖猴，更不知官衔品从... │ │ 旁白   [配声▾] │
│ 第3回 四海... │ ├───────────────────────────────────────────┤ │ 玉皇大帝 [配声▾]│
│ 第4回 官封... │ │ [ ] 孙悟空 #2  18字             改派说话人▾│ │                 │
│ 第5回 乱蟠... │ │ 「大王若是这般远虑，真所谓道心开发也。」    │ │                 │
│               │ └───────────────────────────────────────────┘ │                 │
└───────────────┴───────────────────────────────────────────────┴─────────────────┘
```

1. **从“工单大卡片”重构为“紧凑剧本行（Compact Script Row）”**：
   - 移除原每个 Atom 外层独立的厚重 `CardSurface`；
   - 采用精致轻量行（Row），垂直内边距从 `12pt` 压缩至 `6pt`，单行高度从 80pt 优化至 38~52pt；
   - 将多选 Checkbox、角色药丸、字数以及改派菜单整合于单层或悬浮工具态，一屏浏览量提升 3 倍。
2. **最大阅读行宽控制（Max Reading Width）**：
   - 滚动容器内部限定正文最佳阅读行宽 `maxWidth: 760pt`，彻底消除右侧数百像素的空洞虚空。
3. **三栏自适应常驻（Three-Column Layout）**：
   - 调整 `WindowLayoutPolicy.audiobookInlineCastColumnMinimumWidth` 适配常规桌面窗口（如 $\ge 1080\text{pt}$）；
   - 使“章节目录 (260pt) + 剧本对白流 (Flex) + 人物角色面板 (320pt)”形成黄金三栏比例，布局饱满紧凑。

## 5. 验收与回归验证矩阵

任何文本切分算法的调整，必须通过以下 6 组典型测试用例：

| 验证编号 | 测试用例 | 核心断言与验收准则 |
|---|---|---|
| **TC-01** | 古典硬折行（西游记样本） | `但只註名便\n了。` 必须合并为完整单句，整回 Atom 数量由 449 段收敛至 40~80 段；绝不允许出现“了。”独立 2 字 Atom。 |
| **TC-02** | 词内引用保护 | `見三清稱個「老」字，逢四帝道個「陛下」。` 必须作为完整旁白 Atom，严禁切出「老」字卡片。 |
| **TC-03** | 连续交替短对白 | 连续多行 `“你去？”\n“我去。”\n“何时？”` 必须严格切出 3 个独立对白 Atom，绝对禁止跨行合并。 |
| **TC-04** | 现代长自然段网文 | 单行 300 字段落按句终标点自然切分，单句长度介于 30~100 字，段首段末无异常粘连。 |
| **TC-05** | 空行分隔段落 | 顶格无缩进但以 `\n\n` 分段的文本，段落起止完全准确。 |
| **TC-06** | 来源完整覆盖（Coverage） | `AudiobookSourceIndex.validateCoverage` 断言通过，`reconstructed == originalText` 100% 字符级无损还原。 |
