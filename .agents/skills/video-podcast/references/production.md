# 内容、声音与节目结构

## 简报最小集

记录受众和观看场景、节目承诺、来源、语言、画幅、时长（硬限制或估计）、平台、语音来源、品牌规则、交付路径。缺失的平台规范不要冒充已知事实；需要精确规格时查平台官方文档，记录核验日期。

把信息分为三层：

- 证据：用户材料、已验证的产品事实、采访原文和源时间码。
- 正式内容：口播、字幕、标题、章节名、图表和 CTA。
- 制作指令：镜头、语气、布局、音效、调试和内部备注。

后两者分开存储，渲染器只读取正式内容的白名单字段。新事实需要来源；用户定稿不是任意再创作的邀请。

## 按节目类型选结构

| 类型 | 合适的推进 | 常见误用 |
| --- | --- | --- |
| 产品 / 人物自传 | 自我定位 → 起因 → 能力或经历 → 关键证明 → 收尾 | 堆砌所有参数，忽视“我是谁” |
| 知识讲解 | 问题 → 心智模型 → 例子 → 限制 → 可执行结论 | 把文档逐字念完，画面重复整段字幕 |
| 双人 / 多人访谈 | 议题 → 观点与追问 → 证据 / 分歧 → 章节回顾 | 删掉上下文，强制轮流讲话，伪造同意 |
| 长音频可视化 | 保留原节目 → 章节与字幕 → 必要插图 / 引文 | 高频换图造成疲劳，为凑视频虚构情节 |
| 已有视频再剪辑 | 保持人物与声音连续 → 去无效重复 → 补必要说明 | 只看转写剪辑，误删笑声、迟疑和反讽 |

采访的匿名 diarization label 不是实名。使用用户已确认的说话人映射；未知时保留“说话人 A”等标签，不推断身份。现有录音默认保留原声；改成合成声音、克隆或翻译配音需要用户的相应意图与素材权限。

## 文案与时长

1. 先写内容节拍表，每段说明一个目标和对应视觉，不按固定幕数凑结构。
2. `display_text` 用于屏幕，`spoken_text` 用于发音，`subtitle_text` 用于忠实字幕。三者可有书写差异，不应有事实或语义冲突。
3. 数字、单位、日期、协议、缩写和外语名词建立发音表。例如屏幕 `1:1`，口播“一比一”；字幕可以保留 `1:1`，但不以此掩盖错误发音。
4. 用一段代表性合成 / 录音估计语速；长段和多语种分别取样。时长预算包含呼吸、转场和尾页阅读时间。
5. 超时优先删冗余、分章或重新措辞，再对局部温和调速。调速后重新实测和对齐；不能依赖原始估计。
6. 存在硬时长限制时，所有语音、转场及尾页必须共同满足预算；若内容无法自然容纳，呈现具体取舍，不能静默截掉句尾。

## 尾页是内容的一部分

确定最后一句语音实际结束时间，再安排收尾。可以是观点落点、下一期预告、参考链接、署名或静态停留；CTA 和二维码并非必选。

用户明确需要音色展示时，计算 `available_voices - voices_used_in_programme`，结合剩余时长安排，不能把“全片共 N 种”写成“尾部 N 种”。实时显示实际播放的音色名；间歇保留卡片，播放指示与字幕则按真实语音活动变化。留出稳定阅读时间，不在最后一帧仍有未完句子。

## 低成本预演

先验证最容易返工的东西：开场标题 + 代表人物、最长正文、一次说话人切换、结尾。已有设计定稿直接落实，不制造重复审批。只在缺失的选择实质影响内容、权限或大额成本时停下确认。
