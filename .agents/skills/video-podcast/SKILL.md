# 视频播客生成

把用户的资料、口播或访谈制作成可播放、可复查、可局部重建的视频。观众应容易听懂、看懂，并自然地跟随叙事。保留真实表达的重音、情绪、呼吸和有意义的停顿。

## 先定位任务

从当前文件和对话获取：受众、主题、来源、已有定稿、交付平台、画幅、时长约束、语言、声音来源、视觉资产、交付路径。缺少的信息能合理推断时写明假设并继续；只询问确实改变内容或授权的缺口。

选择入口，不重复已验收的工作：

| 输入 / 请求 | 入口与重点 |
| --- | --- |
| 文稿、资料、产品或人物故事 | 事实梳理 → 口播脚本 → TTS / 录音 → 视频 |
| 单人录音或音频播客 | 转写与对齐 → 轻剪辑 → 章节 / 辅助画面 |
| 多人访谈、远程录音、已有视频 | 对齐源轨 → 说话人映射 → 保留互动 → 画面剪辑 |
| 已有成片的局部问题 | 定位时间码与原因 → 最小修改 → 重建受影响产物 → 回归 |

默认在用户项目的独立制作目录工作，保留源素材和已验收版本。TTS、ASR、图像生成、渲染引擎均可替换；先检查可用能力，不能假定 SpeechRail、特定音色、模型、系统字体或收费服务存在。生成图片时使用当前环境提供的图像生成能力；缺失时复用授权素材或做排版型视觉，并明确实际采用的方式。

## 制作流程

### 1. 建立简报与内容骨架

阅读 [production.md](references/production.md)。确定开场承诺、章节推进、关键例证和收尾动作。产品自传、知识讲解、访谈、叙事播客使用各自结构；不把所有节目改成营销片。

分别保存事实来源、正式口播、屏幕文案、制作备注。已定稿文案保持准确。采访剪辑保留原意和上下文，不制造原说话人没有说过的观点。

短片按内容估算预算，生成或录制后用实际时长校准。长节目先做章节和源时间映射，不用统一倍速硬压进短片模板。CTA、二维码、音色展示、人物形象与 BGM 都是按内容选择的模块。

### 2. 建立单一时间轴与可重建产物

阅读 [pipeline.md](references/pipeline.md)，可从 [episode.template.json](assets/episode.template.json) 建立制作清单。这是字段模板，填写实际素材与时间；不是可直接执行的完整渲染项目。

音频剪辑后的实测区间驱动字幕、说话人状态、镜头、音频可视化与尾页。明确区分源时间和成片时间。场景允许覆盖多个语音片段；多人真实重叠不能简单视为错误。

保留源轨、处理后语音、BGM / 音效、混音母带、时间轴、字幕、预览、最终视频及验收记录。改动只重建依赖它的产物；锁定输入哈希、配音参数、渲染配置与版本，避免旧音频冒充新台词。

### 3. 制作并复检声音

阅读 [audio.md](references/audio.md)。先用代表性片段检验发音、语速、音色和噪声，再扩展全片。缩写、数字、外语专名使用独立 `spoken_text`；字幕保留准确的可读表达。

先解决源音频缺陷与剪切，再处理段间音量和背景声，最后规范母带响度。每次只针对已确认问题调整；响度目标由交付规范和实际听感决定。

对全文做转录差异检查，对风险片段回听。相似度用于排查，不能凭某个阈值宣告口播正确；否定词、数字、专名和语言切换要逐项确认。无法听音或无法转录时，在验收中留下明确未验证项。

### 4. 设计画面与过渡

阅读 [visuals.md](references/visuals.md)。先确定字体、色彩、网格、间距、安全区和动效强度，制作封面、典型正文、多人状态与尾页样张，再渲染短过渡。

用排版、信息层级、连续运动和有意义的声音联动体现制作质量。装饰不遮挡字幕、脸和图表；降低装饰强度后内容应仍然成立。

把最终文字用可控排版绘制，生成图只承担人物 / 背景。独立管理封面、正文、字幕、HUD 与尾页的可见性，防止制作备注和旧场景文字泄露。

### 5. 渲染与整体验收

阅读 [acceptance.md](references/acceptance.md)。先验证短样片，再完成最终编码。检查的对象必须是最终交付文件，而不只是原始语音或预览帧。

技术检查可使用随附的只读工具。以下示例从当前项目根目录执行；本项目使用 `uv` 提供 Python 3.12，其他环境将 `uv run python` 替换为已确认的 Python 3.12+ 解释器：

```bash
SKILL_DIR=".agents/skills/video-podcast"
uv run python "$SKILL_DIR/scripts/inspect_media.py" path/to/final.mp4 --loudness
```

只有明确选定交付目标后才加验收阈值，例如：

```bash
SKILL_DIR=".agents/skills/video-podcast"
uv run python "$SKILL_DIR/scripts/inspect_media.py" path/to/final.mp4 \
  --loudness --target-lufs -16 --lufs-tolerance 1 \
  --max-true-peak -1 --expected-duration 90
```

这些数值只是某类短语音视频的示例，不是所有播客的平台规范。工具只测媒体与响度，不验证发音、画面、二维码或主观听感；退出码 0 不代表整体验收通过。

检查结果记录实际文件哈希、目标、实测、主观复检范围、缺陷及未验证项。交付时提供明确的本地成片链接和必要源文件；若仅完成草稿或局部修复，应准确标注。生成成片不自动包含上传发布。

## 返修决策

| 用户反馈 | 首先确认 | 对应处理 |
| --- | --- | --- |
| 忽大忽小、听着不舒服 | 具体切点；源轨、说话人、BGM 与成片的差别 | 有界片段增益、局部自动化或轻压缩；保留表演动态 |
| 发音不对、字幕对不上 | `spoken_text`、缓存、剪辑后时间、成片转录 | 修复具体文本 / 片段并重建依赖；不靠字幕掩盖错音 |
| 太吵或动效抢眼 | 语音可懂度、文字注意力、节奏重复 | 先削减干扰元素，再评估是否还需要视觉强化 |
| 转场突兀、重影、文字闪烁 | 层可见性、进出状态、声音切点 | 同一转场状态驱动图层；短间隙保留上下文卡片 |
| 长空白、尾部无内容 | 是叙事停顿、素材缺失还是硬编码时间偏移 | 修正时间轴或有目的的收尾；不自动填随机内容 |
| 仅改颜色 / 位置 | 是否影响文本尺寸、二维码或字幕安全区 | 局部渲染与视觉回归；无需重做 TTS |

## 本项目经验的使用边界

需要追溯蒸馏来源时读 [project-lessons.md](references/project-lessons.md)。本 skill 提炼了实际返修经验，并补充可移植的制作规则；SpeechRail 自传中的 90 秒、9 个总音色、6 个尾部音色、科技粒子和 GitHub 尾页均不构成通用要求。
